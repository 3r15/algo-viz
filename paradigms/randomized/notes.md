## 한눈에

**무작위(난수)를 알고리즘의 일부로** 쓴다. 결정적 알고리즘이 특정 입력에서 느리거나 어려울 때,
동전을 던져 그 최악을 흩뜨리거나, 아주 낮은 오류 확률을 감수해 훨씬 빠르게 답한다.

두 갈래가 있다.

- **라스베이거스(Las Vegas)** — 답은 **항상 옳고**, 실행 시간만 무작위(기댓값으로 빠름).
  예: [퀵 정렬](#/algo/quick-sort)의 무작위 피벗, 퀵셀렉트.
- **몬테카를로(Monte Carlo)** — 시간은 **항상 빠르고**, 낮은 확률로 **틀릴 수 있다**.
  예: [밀러-라빈](#/algo/miller-rabin) 소수 판정. 반복하면 오류 확률이 지수적으로 준다.

## 언제 쓸 수 있나

무작위가 이득이 되는 전형적 신호가 있다.

### 1. "나쁜 입력" 이 특정 패턴에 몰려 있다 → 무작위로 흩뜨린다

결정적 규칙(예: 항상 끝 원소를 피벗)은 **적대적 입력**에 저격당해 최악이 된다.
피벗을 무작위로 고르면 어떤 입력이든 **기대 시간**이 좋아진다 — 최악을 "확률적으로" 없앤다.

> [퀵 정렬](#/algo/quick-sort): 정렬된 입력 + 끝 피벗이면 `O(n²)`. 무작위 피벗이면 기대 `O(n log n)`.

### 2. 정답을 "검사" 하긴 쉬운데 "찾기" 는 어렵다 → 무작위 증거로 판정

무작위로 후보(증인)를 뽑아 성질을 확인한다. 성질을 깨는 증거가 충분히 흔하면, 몇 번의 시도로
높은 신뢰를 얻는다.

> [밀러-라빈](#/algo/miller-rabin): 합성수는 증인의 ≥ 3/4 가 잡는다 → `k`번 뽑으면 오판 ≤ `4^(−k)`.

### 3. 한쪽 오류만 있다 → 반복으로 신뢰를 키운다

오류가 **한 방향뿐**(예: "합성" 은 항상 옳고 "소수" 만 확률적)이면, 독립 시행을 반복해
오류 확률을 곱으로 떨어뜨릴 수 있다.

### 성립하지 않는(조심할) 신호

- **오류가 절대 허용 안 되는데** 결정적 대안이 있다 → 몬테카를로 대신 결정적/라스베이거스.
- 난수의 질이 나쁘다(예측 가능) → 적대적 입력이 다시 최악을 유도할 수 있다.
- 오류가 **양방향**이면 단순 반복으로 신뢰를 못 올린다(다수결·증폭 기법 필요).

## 구현 골격

### 라스베이거스 — 항상 옳게, 무작위로 빠르게

```
반복 또는 재귀:
    무작위 선택(피벗·순서 등)을 한다
    그 선택으로 문제를 진행한다      // 결과는 항상 정확
기대 실행 시간이 좋아진다(최악 입력이 사라짐)
```

### 몬테카를로 — 빠르게, 낮은 확률로 틀리게

```
repeat k times:
    무작위 증인 a 를 뽑는다
    if (a 가 반례를 증명) return 확정 답   // 한쪽은 확실
return 아마도-그렇다                        // 틀릴 확률 ≤ p^k
```

| | 시간 | 정확성 | 예 |
|---|---|---|---|
| **라스베이거스** | 무작위(기대 빠름) | 항상 옳음 | [퀵 정렬](#/algo/quick-sort) 무작위 피벗 |
| **몬테카를로** | 항상 빠름 | 확률 `1 − p^k` | [밀러-라빈](#/algo/miller-rabin) |

핵심은 **오류·시간을 확률로 정량화**하는 것이다 — "얼마나 자주 틀리나", "기대 시간이 얼마인가" 를
증명으로 묶는다.

## 잘 맞는 문제

- **소수 판정·소수 생성** — 밀러-라빈(몬테카를로), 암호 키 생성
- **선택·정렬** — 무작위 퀵셀렉트/퀵정렬(라스베이거스)
- **표집** — 저수지 표집(스트림에서 균등 표본), 무작위 셔플(피셔-예이츠)
- **해싱·지문** — 무작위 해시로 충돌을 확률적으로 회피(라빈-카프의 롤링 해시)
- **근사·검증** — 다항식 항등 검사, 최소 컷(카거) 등 "검사는 쉬운" 문제

## 함정

**난수 품질.** 예측 가능한 난수는 적대적 입력에 다시 저격당한다. 암호 맥락은 **암호학적 난수**를 써야 한다.

**"통과 = 확정" 오해.** 몬테카를로의 긍정 판정은 확률적이다. 밀러-라빈의 "소수" 는 "아마도 소수" —
필요하면 증인을 늘리거나 결정적 집합을 쓴다.

**오류 방향을 헷갈린다.** 한쪽 오류(one-sided)인지 양쪽인지에 따라 증폭 방법이 다르다.
한쪽이면 반복으로 곧장 신뢰가 오르고, 양쪽이면 다수결이 필요하다.

**독립성 가정.** 오류 확률 `p^k` 는 시행이 **독립**일 때다. 같은 증인을 다시 뽑으면 신뢰가 안 오른다.
