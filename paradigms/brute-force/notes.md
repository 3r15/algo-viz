## 한눈에

**가능한 모든 후보를 빠짐없이 만들어** 하나씩 확인한다. 영리한 통찰 없이도 정답을 보장하는 —
그래서 가장 먼저 떠올리고, 종종 정답의 기준선(baseline)이 되는 방식이다.

문제는 **후보 수의 폭발**이다. 부분집합이면 `2ⁿ`, 순열이면 `n!`. 그래서 완전 탐색의 기술은
"어떻게 다 훑나" 가 아니라 **"규모를 어디까지 견딜 수 있나, 어떻게 줄이나"** 다.

- **부분집합 열거** — 정수 마스크 `0…2ⁿ−1`, `n ≲ 20` ([비트 조작](#/algo/bit-manipulation))
- **순열 열거** — `next_permutation`·재귀, `n ≲ 10`
- **가지치기** — 유망하지 않은 가지를 잘라 실효 탐색을 줄인다([백트래킹](#/paradigm/recursion))

## 언제 쓸 수 있나

완전 탐색은 **거의 항상 맞다** — 문제는 "쓸 수 있냐(시간 안에 끝나냐)" 다. 판단 기준이 명확하다.

### 1. 입력이 작다 → 지수·계승도 견딘다

`2ⁿ`, `n!` 규모를 입력 크기로 역산한다.

```
n ≤ 20   → 2^n ≈ 10^6   부분집합 완전 탐색 OK
n ≤ 10   → n! ≈ 3.6·10^6 순열 완전 탐색 OK
n ≤ 40   → 2^(n/2)      반씩 나눠(meet in the middle)
```

### 2. 정답 구조가 안 보인다 → 일단 전부 훑어 기준선

그리디·DP 가 되는지 불확실할 때, 작은 입력에서 완전 탐색으로 **정답을 확인**하고 더 빠른 방법을
그에 맞춰 검증한다(브루트포스는 테스트 오라클로도 쓴다).

### 3. 상태를 비트로 압축할 수 있다 → 비트마스크

"방문한 집합", "켜진 스위치" 처럼 상태가 부분집합이면 정수 하나로 담아 열거·DP 한다.

### 성립하지 않는(줄여야 하는) 신호

- `n` 이 크다 → `2ⁿ`·`n!` 폭발. **DP·그리디·수학**으로 지수의 밑을 낮추거나 없앤다.
- 후보 대부분이 제약을 일찍 어긴다 → **가지치기**(백트래킹)로 실효 탐색을 줄인다.
- 절반씩 독립적이다 → **meet in the middle** 로 `2ⁿ → 2·2^(n/2)`.

## 구현 골격

### 부분집합(비트마스크) 완전 탐색

```
for (int mask = 0; mask < (1 << n); mask++) {   // 모든 부분집합
    // mask 의 켜진 비트로 후보를 구성
    for (int j = 0; j < n; j++)
        if (mask & (1 << j)) /* j번 원소 포함 */;
    // 후보를 평가해 답 갱신
}
```

### 순열·조합 완전 탐색

```
sort(a); do { /* 순열 a 평가 */ } while (next_permutation(a));  // n!
// 또는 재귀로 자리마다 후보를 채우며 내려간다(백트래킹으로 가지치기)
```

| 후보 공간 | 크기 | 열거 방법 | 견디는 n |
|---|---|---|---|
| 부분집합 | `2ⁿ` | [비트마스크](#/algo/bit-manipulation) | ≲ 20 |
| 순열 | `n!` | next_permutation·재귀 | ≲ 10 |
| 조합 `nCk` | `nCk` | 재귀·비트 | 경우별 |
| 격자·좌표 | `곱` | 중첩 루프 | 경우별 |

## 잘 맞는 문제

- **작은 `n` 의 최적화** — 부분집합/순열을 다 보고 최적 고르기(작은 배낭·할당·스케줄)
- **상태 압축 DP 의 바탕** — 외판원(Held-Karp `2ⁿ·n²`), 집합 덮개·분할
- **정답 오라클** — 더 빠른 알고리즘을 작은 입력에서 완전 탐색과 대조 검증
- **조합 생성** — 모든 부분집합·순열·조합을 실제로 나열해야 할 때

## 함정

**규모를 역산하지 않는다.** `2ⁿ`·`n!` 을 입력 상한으로 먼저 계산하라. `n=25` 부분집합은 이미 위험하다.

**`1 << n` 오버플로.** `n ≥ 31` 이면 `1LL << n`. 마스크도 64비트.

**가지치기를 안 한다.** 제약을 일찍 어기는 후보를 끝까지 만드는 낭비. [백트래킹](#/paradigm/recursion)으로
가지를 잘라라 — 다만 최악은 여전히 지수임을 잊지 말 것(잘라도 안 줄면 스텝 예산으로 명시).

**중복 열거.** 순열에 중복 원소가 있으면 같은 후보를 여러 번 만든다. 정렬 + 건너뛰기로 중복 제거.

**"느리지만 맞다" 를 과신.** 완전 탐색이 맞다고 제출하면 큰 입력에서 시간 초과. 규모를 넘으면 방법을 바꿔야 한다.
