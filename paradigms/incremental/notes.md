## 한눈에

이미 해결한 부분을 **불변식으로 유지**하면서, 원소를 하나씩 편입시켜 해결 범위를 넓힌다.

```
a[0..i-1] 는 정렬돼 있다     ← 불변식
a[i] 를 알맞은 자리에 넣는다  ← 한 걸음
a[0..i] 가 정렬돼 있다       ← 불변식 유지
```

[분할 정복](#/paradigm/divide-and-conquer)이 "쪼개서 합친다"면 증분법은 **"이미 푼 것을 지키며 넓힌다"** 다.
코드가 단순하고, 정확성 증명이 **루프 불변식 + 귀납**으로 거의 기계적으로 나온다.

## 언제 쓸 수 있나

### 1. 부분 해를 정의할 수 있다

"처음 `i`개만 고려한 답"이 의미를 가져야 한다. 정렬은 자명하고, 볼록 껍질도 그렇다.
반면 "배열 전체를 봐야만 의미가 있는 답"에는 쓸 수 없다.

### 2. 한 원소를 편입시키는 비용이 싸다

편입 비용이 `O(f(n))` 이면 전체가 `O(n · f(n))` 이다.
[삽입 정렬](#/algo/insertion-sort)은 편입이 O(n) 이라 전체 O(n²)이고, 이게 한계다.
**편입 비용을 줄이는 것이 이 유형의 개선 방향 전부다.**

### 3. 불변식을 말로 정확히 쓸 수 있다

이게 실질적인 성립 조건이다. 불변식을 한 문장으로 못 쓰면 구현도 증명도 흔들린다.

```
좋은 불변식 : "a[0..i-1] 는 정렬돼 있고, 원래 a[0..i-1] 의 원소들로만 이루어져 있다"
나쁜 불변식 : "앞쪽이 대충 정렬돼 있다"
```

### 증명이 항상 같은 모양이다

1. **초기화**: 첫 반복 전에 불변식이 성립하는가 (보통 빈 구간이라 자명)
2. **유지**: 성립한 상태에서 한 걸음 나아가도 여전히 성립하는가
3. **종료**: 루프가 끝났을 때의 불변식이 곧 원하는 답인가

[삽입 정렬](#/algo/insertion-sort)과 [버블 정렬](#/algo/bubble-sort) 문서의 정확성 절이
정확히 이 세 단계로 쓰여 있다.

## 구현 골격

```cpp
초기화();                        // 크기 0 또는 1 짜리 해
for (int i = 시작; i < n; i++) {
    // 불변식: [0, i) 에 대한 해가 완성돼 있다
    편입(i);                     // a[i] 를 해에 합류시킨다
    // 불변식: [0, i] 에 대한 해가 완성돼 있다
}
```

**불변식을 주석으로 루프 안팎에 적어 두는 것**이 이 유형의 관례다.
그 두 줄이 코드 리뷰와 디버깅의 절반을 해결한다.

### 편입 비용을 줄이는 방향

| 방법 | 편입 비용 | 예 |
|---|---|---|
| 그냥 훑기 | O(n) | 삽입 정렬 |
| 이분 탐색으로 자리 찾기 | 비교 O(log n), **이동은 여전히 O(n)** | 이진 삽입 정렬 |
| 균형 잡힌 자료구조 | O(log n) | 트리 기반 삽입 |
| 상수 시간 판정 | O(1) 상각 | 볼록 껍질(그레이엄 스캔) |

이진 삽입 정렬이 **전체 복잡도를 못 줄인다**는 점이 중요하다.
비교는 줄지만 배열 이동은 그대로 O(n²)이라, 비교가 아주 비쌀 때만 의미가 있다.

## 잘 맞는 문제

- **온라인 처리**: 데이터가 하나씩 도착하고, 매 시점의 답이 필요하다.
  [삽입 정렬](#/algo/insertion-sort)이 온라인인 이유이고, 병합·퀵 정렬은 그렇지 못하다.
- **거의 정렬된 데이터**: 편입 비용이 작아져 사실상 선형이 된다.
  삽입 정렬의 실제 복잡도는 `Θ(n + 역전수)` 다.
- **기하 알고리즘**: 볼록 껍질(그레이엄 스캔), 점 추가형 들로네 삼각분할
- **자료구조 구축**: 트리에 원소를 하나씩 삽입, 유니온 파인드에 간선 하나씩 추가
- **작은 입력의 마무리**: 실전 정렬은 구간이 16 이하로 작아지면 삽입 정렬로 갈아탄다.
  O(n²)이지만 **상수가 작아서** 그 크기에서는 더 빠르다.

## 함정

**불변식을 정의하지 않고 시작하면** 경계에서 반드시 틀린다.
"`i` 번째까지"가 `[0, i)` 인지 `[0, i]` 인지부터 못 박자.

**O(n²)을 눈치채지 못하기** — 편입이 O(n) 이면 전체가 O(n²)이다.
`n` 이 10만을 넘으면 다른 유형으로 갈아타야 한다.

**"비교를 줄였으니 빨라지겠지"** — 이진 삽입 정렬의 함정. **이동 비용이 지배적**이면
비교를 아무리 줄여도 소용없다. 무엇이 병목인지 먼저 재자.

**안정성을 깨뜨리기** — 삽입 정렬에서 비교를 `>` 대신 `>=` 로 바꾸면 같은 값을 지나쳐
안정성이 사라진다. 부등호 하나가 성질을 바꾼다.
