## 한눈에

질의(query)가 많을 때, **미리 표를 만들어 두고** 질의마다 조금만 계산한다.

```
단순한 방법 :  전처리 O(1)          · 질의 O(n)   × q번  =  O(nq)
전처리 방식 :  전처리 O(n log n)    · 질의 O(1)   × q번  =  O(n log n + q)
```

`q` 가 커질수록 이득이 커진다. 질의가 한 번뿐이면 전처리는 손해다 —
**"몇 번 물어볼 것인가"가 이 유형을 쓸지 말지를 결정한다.**

## 언제 쓸 수 있나

### 1. 질의가 충분히 많다

`전처리 비용 < (단순 질의 비용 − 빠른 질의 비용) × 질의 수` 여야 이득이다.
문제에서 `q ≤ 100000` 같은 제약이 보이면 거의 확실한 신호다.

### 2. 답을 합칠 수 있다(결합법칙)

작은 조각의 답에서 큰 조각의 답을 만들 수 있어야 한다.

> `(A ∘ B) ∘ C = A ∘ (B ∘ C)` 인 연산 — **모노이드**

합·최소·최대·gcd·행렬곱이 모두 여기 해당한다.
"구간에서 서로 다른 수의 개수" 같은 것은 결합이 안 되므로 다른 접근이 필요하다.

### 3. 갱신이 있는가 — 이게 자료구조를 가른다

| | 질의 | 갱신 | 조건 |
|---|---|---|---|
| [희소 배열](#/algo/sparse-table) | **O(1)** | 불가 | **멱등**해야 함 (min/max/gcd ○, 합 ✗) |
| [세그먼트 트리](#/algo/segment-tree) | O(log n) | **O(log n)** | 결합법칙만 있으면 됨 |
| 펜윅 트리 | O(log n) | O(log n) | **역원**이 있어야 함 (합 ○, min ✗) |
| 누적 합 | O(1) | 불가 | 역원 필요 |

**멱등**(`min(x,x) = x`)이 중요한 이유는, 희소 배열이 구간을 **겹치게** 덮기 때문이다.
겹친 부분이 두 번 세어져도 답이 안 바뀌어야 한다. 합은 두 번 더해지므로 못 쓴다.

### 4. 배가(doubling) 가 가능한가

"2배씩 늘려 가며 미리 계산"이 이 유형의 핵심 기법이다.

```
희소 배열   : st[k][i] = a[i .. i+2^k-1] 의 답
이진 상승   : up[k][v] = v 의 2^k 번째 조상
```

둘의 점화식이 사실상 같다.

```
st[k][i] = 연산( st[k-1][i], st[k-1][i + 2^(k-1)] )
up[k][v] =       up[k-1][ up[k-1][v] ]
```

**"2^k 짜리 답 = 2^(k-1) 짜리 답 두 개"** — 대상이 배열 구간이냐 트리 조상이냐만 다르다.
[이진 상승](#/algo/binary-lifting)과 [희소 배열](#/algo/sparse-table)을 나란히 보면 같은 발상임이 보인다.

## 구현 골격

### 배가형

```cpp
// 1. k = 0 층: 크기 1짜리 답
for (int i = 0; i < n; i++) table[0][i] = 기본값(i);

// 2. k 층 = (k-1) 층 두 개를 이어 붙임
for (int k = 1; k < LOG; k++)
    for (int i = 0; i + (1 << k) <= n; i++)
        table[k][i] = 합치기(table[k-1][i], table[k-1][i + (1 << (k-1))]);

// 3. 질의: 길이를 2의 거듭제곱으로 분해
```

바깥 루프가 반드시 `k` 여야 한다. `k-1` 층이 **전부** 완성돼야 `k` 층을 만들 수 있기 때문이다.

### 트리형(세그먼트 트리)

```cpp
build : 리프에 원소를 넣고 아래에서 위로 접는다        O(n)
query : 구간을 O(log n) 개 노드로 분해해 합친다        O(log n)
update: 리프에서 루트까지 경로만 다시 계산한다          O(log n)
```

## 잘 맞는 문제

- **구간 최솟값/최댓값 질의(RMQ)**: 갱신이 없으면 희소 배열, 있으면 세그먼트 트리
- **구간 합**: 갱신이 없으면 누적 합, 있으면 펜윅/세그먼트 트리
- **최소 공통 조상(LCA)**: [이진 상승](#/algo/binary-lifting) O(log n),
  또는 오일러 투어 + 희소 배열로 O(1)
- **k번째 조상 / 함수 반복 적용**: 이진 상승
- **경로 최댓값 질의**: MST + 이진 상승 조합
- **2차원 구간 합**: 2D 누적 합, 2D 세그먼트 트리

**신호**: 입력이 "배열 하나 + 질의 q개" 형태이고, 질의가 구간이나 조상 같은
**구조적인 범위**를 묻는다면 이 유형이다.

## 함정

**갱신이 있는데 희소 배열을 골랐다** — 원소 하나만 바뀌어도 표 전체를 다시 만들어야 한다.
문제에 갱신이 있는지 먼저 확인하자.

**멱등이 아닌 연산에 희소 배열** — 구간 **합**에 쓰면 겹치는 부분이 두 번 더해져 틀린다.
조용히 틀리는 종류의 버그다.

**`log2` 를 부동소수로 계산** — 큰 값에서 반올림 오차로 1 어긋난다.
정수 로그 테이블을 미리 만들거나 `__builtin_clz` 를 쓴다.

**닫힌 구간 `[l, r]` 과 반열린 구간 `[l, r)` 을 섞어 쓴다** — 이 유형 최대의 버그 원인이다.
한 관례를 정하고 끝까지 밀고 가자.

**메모리** — 희소 배열과 이진 상승은 `O(n log n)` 이다. `n = 10⁶`, `LOG = 20` 이면
`int` 기준 80MB. 제한에 걸릴 수 있다.

**전처리가 오히려 손해인 경우** — 질의가 한두 번이면 그냥 훑는 게 빠르고 짧다.
