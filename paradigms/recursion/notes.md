## 한눈에

문제를 **자기 자신의 더 작은 형태로 정의**하고, 그 정의를 그대로 코드로 옮긴다.
정의가 곧 구현이 되는 것이 재귀의 매력이다.

**백트래킹**은 재귀에 "되돌아오기"를 얹은 것이다. 선택을 하나 하고 들어갔다가,
막히면 **선택을 취소하고** 다른 가지를 시도한다.

```
재귀      : 작은 문제로 내려갔다 답을 들고 올라온다
백트래킹  : 후보를 하나 골라 내려갔다, 안 되면 되돌리고 다음 후보
```

재귀는 형식이고, [분할 정복](#/paradigm/divide-and-conquer)·[DP](#/paradigm/dynamic-programming)·
[그래프 탐색](#/paradigm/graph-search)이 그 위에 올라탄다.

## 언제 쓸 수 있나

### 1. 자기 유사성

문제가 **같은 종류의 더 작은 문제**로 표현돼야 한다.

```
정렬(배열) = 병합( 정렬(왼쪽 절반), 정렬(오른쪽 절반) )
방문(정점 u) = u 표시 후, 각 이웃 v 에 대해 방문(v)
```

### 2. 기저 조건이 반드시 도달된다

두 가지를 모두 확인해야 한다.

- **기저가 존재하는가** — 멈추는 지점이 정의돼 있는가
- **매 호출에서 크기가 진짜 줄어드는가** — 줄지 않는 경로가 하나라도 있으면 무한 재귀다

> 그래프에서는 "크기가 준다"가 자명하지 않다. [DFS](#/algo/dfs)가 `visited` 로
> 이미 본 정점을 거르는 것이 바로 이 역할이다. 없으면 사이클에서 영원히 돈다.

### 3. 깊이가 감당된다

재귀 깊이만큼 호출 스택이 쌓인다. `log n` 이면 안전하지만 `n` 이면 위험하다.
정점 10만 개짜리 경로 그래프에서 재귀 DFS 는 실제로 스택 오버플로를 낸다.

### 백트래킹이 성립하려면

**가지치기(pruning)** 가 있어야 실용적이다. 순수한 완전 탐색은 지수 시간이라,
"이 가지는 답이 될 수 없다"를 **빨리** 판정하는 것이 전부다.

## 구현 골격

### 값을 돌려받는 재귀

```cpp
Result solve(작은문제) {
    if (기저) return 직접답;
    return 조합( solve(더작은문제1), solve(더작은문제2) );
}
```

### 백트래킹

```cpp
void backtrack(상태) {
    if (완성됐다) { 답에 기록; return; }
    for (후보 : 가능한선택들) {
        if (!유망한가(후보)) continue;     // 가지치기 — 여기가 성능의 전부

        선택을적용(후보);                   // do
        backtrack(다음상태);               // recurse
        선택을취소(후보);                   // undo  ← 빠뜨리면 상태가 오염된다
    }
}
```

**do → recurse → undo** 삼박자가 백트래킹의 뼈대다.
`undo` 를 빠뜨리는 것이 가장 흔한 버그이고, 증상은 "답이 이상하게 많거나 적다"로 나타난다.

### 반복문으로 바꾸기

깊이가 위험하면 명시적 스택으로 옮긴다.

```cpp
stack<int> st;  st.push(start);
while (!st.empty()) {
    int u = st.top(); st.pop();
    // u 처리
    for (int v : adj[u]) if (!visited[v]) { visited[v] = true; st.push(v); }
}
```

다만 **방문 순서가 재귀 버전과 달라지고**, 종료 시각(post-order)을 얻으려면
정점을 두 번 넣는 등의 장치가 더 필요하다. [DFS 문서](#/algo/dfs)에 이 함정이 정리돼 있다.

## 잘 맞는 문제

- **트리·그래프 순회**: [DFS](#/algo/dfs), [타잔 SCC](#/algo/tarjan-scc) —
  구조 자체가 재귀적이라 재귀가 가장 자연스럽다
- **분할 정복 정렬**: [병합 정렬](#/algo/merge-sort), [퀵 정렬](#/algo/quick-sort)
- **구간을 반으로 접는 자료구조**: [세그먼트 트리](#/algo/segment-tree)의 재귀형
- **조합 탐색(백트래킹)**: N-Queens, 스도쿠, 순열·조합 생성, 부분집합 열거
- **파싱**: 수식·괄호 구조는 재귀적 문법이라 재귀 하강 파서가 딱 맞는다

**신호**: "모든 경우를 시도해 봐야 한다", "조건을 만족하는 것을 전부 찾아라",
"트리/중첩 구조를 따라가라" 가 나오면 재귀·백트래킹을 먼저 떠올린다.

## 함정

**기저 조건 누락 또는 도달 불가** — 무한 재귀의 두 원인.
크기가 줄어드는지는 반드시 손으로 확인하자.

**`undo` 누락** — 백트래킹에서 전역 상태(방문 배열, 현재 경로)를 되돌리지 않으면
형제 가지가 오염된다.

**같은 부분 문제 반복 계산** — 재귀 트리에서 같은 인자가 여러 번 나오면
[DP](#/paradigm/dynamic-programming)로 승격해야 한다. 순수 재귀 피보나치가
O(φⁿ) 인 이유가 이것이다.

**스택 오버플로** — 깊이 `n` 짜리 재귀는 실전에서 터진다. 반복문 전환이나
꼬리 재귀 제거를 고려한다. (C++ 컴파일러의 꼬리 호출 최적화는 보장되지 않는다.)

**참조로 넘길 것을 값으로 복사** — 큰 벡터를 매 호출마다 복사하면 지수 시간이 된다.
`vector<int>&` 로 넘기고 필요한 부분만 되돌리자.

**가지치기 없는 완전 탐색** — 백트래킹이 느린 거의 유일한 이유다.
"지금까지의 부분해가 이미 최적해보다 나쁘면 즉시 반환" 한 줄이 실행 시간을 몇 자릿수 바꾼다.
