## 한눈에

문제를 **같은 모양의 더 작은 문제**로 쪼개고(divide), 각각 풀고(conquer), 답을 합친다(combine).

```
T(n) = a · T(n/b) + f(n)
       └ 쪼갠 개수와 크기 ┘   └ 합치는 비용 ┘
```

[재귀](#/paradigm/recursion)로 구현되지만 같은 말은 아니다. 재귀는 "자기를 부른다"는 **형식**이고,
분할 정복은 "쪼개서 합친다"는 **전략**이다. 분할 정복의 부분 문제들은 서로 **겹치지 않는다** —
겹치면 [동적 계획법](#/paradigm/dynamic-programming)의 영역이다.

## 언제 쓸 수 있나

### 1. 같은 모양으로 쪼개진다

부분 문제가 원래 문제와 **같은 종류**여야 재귀가 성립한다.
"배열 정렬 → 절반 배열 정렬"은 되지만, "배열 정렬 → 최댓값 찾기"는 분할 정복이 아니다.

### 2. 합치는 비용이 감당된다

쪼개는 것 자체는 쉽다. 관건은 **합치기**다.
[병합 정렬](#/algo/merge-sort)이 O(n log n) 인 이유는 병합이 O(n) 이기 때문이고,
합치기가 O(n²) 였다면 아무 이득이 없다.

### 3. 부분 문제가 겹치지 않는다

`mergeSort(0,4)` 와 `mergeSort(5,9)` 는 서로 다른 구간을 본다. 겹치지 않으므로
메모이제이션이 필요 없다. 피보나치처럼 `fib(n-1)` 과 `fib(n-2)` 가 같은 것을 반복해서
계산한다면 그건 DP 로 가야 한다는 신호다.

### 복잡도를 미리 계산하는 법 — 마스터 정리

`T(n) = a·T(n/b) + Θ(n^d)` 일 때,

```
a < b^d  →  T(n) = Θ(n^d)          합치는 비용이 지배
a = b^d  →  T(n) = Θ(n^d log n)    모든 레벨이 비슷 ← 병합 정렬 (a=2, b=2, d=1)
a > b^d  →  T(n) = Θ(n^(log_b a))  잎(리프)이 지배 ← 카라츠바 (a=3, b=2, d=1)
```

**설계 단계에서 이 식을 먼저 세워 보면** 합치기를 얼마나 싸게 만들어야 하는지 바로 보인다.

## 구현 골격

```cpp
Result solve(범위) {
    if (범위가 충분히 작다) return 직접계산();     // 기저 — 반드시 있어야 한다

    int mid = 범위를 나누는 지점;
    Result left  = solve(왼쪽);
    Result right = solve(오른쪽);
    return combine(left, right);                  // 여기가 설계의 핵심
}
```

세 자리를 채우면 된다.

| 자리 | 질문 |
|---|---|
| 기저 | 언제 재귀를 멈추는가? (크기 0 또는 1) |
| 분할 | 어디서 어떻게 쪼개는가? (중간? 피벗 기준?) |
| 합치기 | 부분해로 전체해를 어떻게 만드는가? |

**어디에 일을 몰아넣는가**로 알고리즘 성격이 갈린다.

| | 분할 | 합치기 |
|---|---|---|
| [병합 정렬](#/algo/merge-sort) | 그냥 반으로 (O(1)) | **병합** (O(n)) |
| [퀵 정렬](#/algo/quick-sort) | **분할(partition)** (O(n)) | 아무것도 안 함 (O(1)) |
| [세그먼트 트리](#/algo/segment-tree) | 구간을 반으로 | 두 자식 값을 연산으로 접기 |

## 잘 맞는 문제

- **정렬과 순서 통계**: 병합 정렬, 퀵 정렬, 퀵 셀렉트
- **구간을 반으로 접는 자료구조**: 세그먼트 트리, 머지 소트 트리
- **"왼쪽 · 오른쪽 · 걸치는 경우" 로 나뉘는 문제**: 최대 부분 배열,
  가장 가까운 두 점 쌍(closest pair) — 걸치는 경우를 싸게 처리하는 것이 관건이다
- **곱셈 가속**: 카라츠바(큰 수 곱셈), 슈트라센(행렬 곱셈), FFT
- **분할 정복 최적화 DP**: 결정 지점이 단조로울 때 DP 를 O(n²)→O(n log n) 으로

**병렬화가 자연스럽다**는 것도 큰 장점이다. 부분 문제가 독립적이라 서로 다른 코어에
그대로 던질 수 있다.

## 함정

**기저 조건을 빠뜨리면 무한 재귀다.** 그리고 기저가 있어도 **크기가 줄지 않는 경로**가 있으면
역시 무한이다. 퀵 정렬에서 피벗을 재귀 범위에 다시 포함시키면 정확히 이 일이 벌어진다.

**합치기가 비싸면 이득이 없다.** `T(n) = 2T(n/2) + Θ(n²)` 는 `Θ(n²)` 라서
그냥 이중 루프를 도는 것과 다르지 않다.

**작은 입력에서는 오히려 느리다.** 재귀 호출 오버헤드 때문에 실전 구현은 대부분
길이 16~32 이하에서 [삽입 정렬](#/algo/insertion-sort)로 갈아탄다.

**부분 문제가 겹치는데 눈치채지 못하면** 지수 시간으로 폭발한다. 같은 인자로 몇 번
호출되는지 세어 보는 것이 빠른 진단법이다.

**재귀 깊이**: `log n` 이면 안전하지만, 퀵 정렬 최악처럼 `n` 까지 깊어지면 스택이 넘친다.
짧은 쪽만 재귀하는 기법으로 O(log n) 을 보장할 수 있다.
