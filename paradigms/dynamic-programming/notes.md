## 한눈에

**같은 부분 문제를 두 번 계산하지 않는다.** 한 번 푼 답을 표에 적어 두고 재사용한다.

[분할 정복](#/paradigm/divide-and-conquer)과 형제지만 갈라지는 지점이 분명하다.

| | 부분 문제가 | 저장 |
|---|---|---|
| 분할 정복 | 겹치지 않음 | 필요 없음 |
| **동적 계획법** | **겹침** | **표에 저장** |

DP 문제를 푸는 일의 90%는 코딩이 아니라 **"상태를 무엇으로 잡을 것인가"** 를 정하는 것이다.
상태만 제대로 잡으면 점화식과 코드는 거의 저절로 나온다.

## 언제 쓸 수 있나

### 1. 최적 부분 구조

> 전체 문제의 최적해가 **부분 문제의 최적해로 구성**된다.

[플로이드-워셜](#/algo/floyd-warshall)의 증명이 전형적이다. "`i ⇝ k ⇝ j` 최단 경로를
`k` 에서 자르면 `i ⇝ k` 와 `k ⇝ j` 도 각각 최단이어야 한다" — 아니라면 더 짧은 것으로
바꿔치기해 전체를 더 줄일 수 있으므로 모순.

### 2. 겹치는 부분 문제

> 재귀로 풀면 **같은 인자로 여러 번** 호출된다.

`fib(n)` 을 단순 재귀로 풀면 `fib(n-2)` 가 두 번, `fib(n-3)` 이 세 번… 지수적으로 중복된다.
서로 다른 부분 문제의 개수가 다항 개면 DP 가 통한다.

### 3. 상태에 순서를 매길 수 있다

부분 문제 사이의 의존 관계가 **비순환**이어야 한다. `A` 를 풀려면 `B` 가 필요한데 `B` 를
풀려면 `A` 가 필요하면 표를 채울 수 없다.

> 부분 문제를 정점, 의존을 간선으로 보면 **DAG** 여야 하고, 표를 채우는 순서가 곧
> [위상 정렬](#/algo/topological-sort) 순서다. 플로이드-워셜에서 `k` 루프가 반드시
> 가장 바깥이어야 하는 이유가 정확히 이것이다.

### 성립하지 않는 신호

- 상태 수가 지수적이다(부분집합을 다 기억해야 한다) → 비트마스크로 20개 남짓까지만
- 미래의 선택이 과거 상태를 바꾼다 → 상태 정의가 부족하다는 뜻. 차원을 늘려 본다

## 구현 골격

### 하향식 (메모이제이션)

```cpp
int memo[MAXN];  bool done[MAXN];
int solve(int state) {
    if (기저) return 초깃값;
    if (done[state]) return memo[state];       // 이미 푼 것은 그대로
    done[state] = true;
    return memo[state] = (점화식);
}
```

재귀 그대로라 **점화식을 옮겨 적기 쉽다.** 필요한 상태만 계산하는 것도 장점.
단점은 재귀 깊이와 호출 오버헤드.

### 상향식 (반복문)

```cpp
dp[기저] = 초깃값;
for (state : 의존 순서대로)
    dp[state] = (점화식);
return dp[목표];
```

빠르고 스택이 안 터진다. **슬라이딩 윈도로 메모리를 줄이는 최적화**도 여기서만 된다.

### 설계 체크리스트

1. **상태**: `dp[...]` 가 정확히 무슨 값인지 한 문장으로 적는다.
   *"dist[i][j] = 경유지를 0..k-1 만 쓸 때 i→j 최단 거리"* 처럼.
2. **점화식**: 마지막 선택을 무엇으로 나눌지 정한다. 보통 "쓴다 / 안 쓴다".
3. **기저**: 가장 작은 상태의 값.
4. **순서**: 의존하는 상태가 먼저 계산되도록.
5. **답의 위치**: 어느 칸이 최종 답인가.

이 다섯 줄을 코드 위 주석으로 적고 시작하면 대부분의 DP 버그가 사라진다.

## 잘 맞는 문제

- **경로 세기 / 최적 경로**: 격자 DP, DAG 최장 경로
- **선택형**: 0/1 배낭, 부분집합 합, 동전 거스름돈(최소 개수)
- **문자열 두 개**: LCS, 편집 거리 — `dp[i][j]` 가 기본형
- **구간 DP**: 행렬 곱셈 순서, 팰린드롬 분할 — `dp[l][r]`
- **모든 쌍 최단 경로**: [플로이드-워셜](#/algo/floyd-warshall) — `k` 를 늘려 가는 전형적 DP
- **간선 수를 늘려 가는 최단 경로**: [벨만-포드](#/algo/bellman-ford) — 라운드가 곧 DP 계층
- **배가(doubling)**: [희소 배열](#/algo/sparse-table)의 `st[k][i]` 도
  "길이 2^k 구간의 답"을 저장하는 DP 다

> 마지막 두 개가 시사하는 바가 있다. **그래프 최단 경로 알고리즘 상당수가 DP 다.**
> "간선을 몇 개까지 쓰는가"(벨만-포드), "어떤 정점까지 경유를 허용하는가"(플로이드-워셜)를
> 계층으로 삼은 것뿐이다.

## 함정

**상태를 말로 정의하지 않고 코딩을 시작하면** 거의 반드시 막힌다.
`dp[i]` 가 "i번째까지 봤을 때의 답"인지 "i를 반드시 포함할 때의 답"인지에 따라 점화식이 완전히 다르다.

**계산 순서를 틀리면 조용히 틀린 답이 나온다.** 아직 안 채운 칸을 읽어도 컴파일 오류가 안 난다.
0/1 배낭에서 무게 루프를 역순으로 돌아야 하는 이유, 플로이드-워셜에서 `k` 가 바깥이어야 하는
이유가 모두 여기 있다.

**공간이 먼저 터진다.** `dp[10000][10000]` 은 400MB다. 대부분의 2차원 DP 는 직전 행만
필요하므로 **롤링 배열**로 O(n) 까지 줄일 수 있다.

**메모이제이션의 초기값 충돌**: `memo` 를 `-1` 로 초기화해 두고 답이 실제로 `-1` 일 수 있다면
잘못된 캐시 히트가 난다. 별도 `visited` 배열을 쓰자.

**DP 가 아닌 것을 DP 로 풀려 하기**: 부분 문제가 안 겹치면 [분할 정복](#/paradigm/divide-and-conquer)이고,
교환 논법이 성립하면 [그리디](#/paradigm/greedy)가 더 빠르다.
