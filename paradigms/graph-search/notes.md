## 한눈에

문제를 **정점과 간선**으로 바꿔 놓으면, 나머지는 "다음에 어디를 볼 것인가"를 정하는 규칙 하나로 갈린다.

| 무엇을 먼저 꺼내는가 | 알고리즘 | 얻는 것 |
|---|---|---|
| 먼저 넣은 것 (큐) | [BFS](#/algo/bfs) | 간선 수 기준 최단 경로 |
| 나중에 넣은 것 (스택) | [DFS](#/algo/dfs) | 진입/종료 시각, 구조 정보 |
| 거리가 가장 작은 것 | [다익스트라](#/algo/dijkstra) | 가중치 최단 경로 |
| `거리 + 추정치` 가 작은 것 | [A\*](#/algo/a-star) | 목표 지향 최단 경로 |
| 선행 조건이 없는 것 | [위상 정렬](#/algo/topological-sort) | 작업 순서 |

**골격은 하나고 자료구조만 바뀐다.** 이 유형을 익힌다는 건 알고리즘 다섯 개를 외우는 게 아니라,
"내 문제를 어떤 그래프로 볼 것인가"를 훈련하는 일이다.

## 언제 쓸 수 있나

### 1. 상태를 정점으로, 전이를 간선으로 볼 수 있다

그래프가 문제에 그려져 있을 필요는 없다. **상태 공간 그래프**를 만들면 된다.

```
정점 = 문제의 한 상태     (좌표, 남은 연료, 방문한 집합, 퍼즐 배치…)
간선 = 한 번의 조작       (한 칸 이동, 스위치 누르기, 물 붓기…)
```

"최소 몇 번 만에 X 를 만들 수 있나" 는 거의 항상 **가중치 1 그래프의 최단 경로**,
즉 BFS 다.

### 2. 상태 수가 감당된다

격자 `1000×1000` = 100만 정점은 괜찮다. 하지만 `방문한 집합`을 상태에 넣으면 `2ⁿ` 이라
20개 남짓에서 한계다. **상태를 얼마나 작게 압축하는가**가 실전의 핵심이다.

### 3. 어떤 규칙이 필요한지 판단한다

```
가중치가 없다 (또는 전부 같다)  → BFS
가중치가 0 또는 1              → 0-1 BFS (덱)
가중치가 음이 아니다            → 다익스트라
음수 간선이 있다                → 벨만-포드
목표가 하나이고 좋은 추정이 있다 → A*
모든 쌍이 필요하다              → 플로이드-워셜
사이클이 없다(DAG)              → 위상 정렬 후 한 번 훑기
```

## 구현 골격

모든 탐색이 같은 모양이다. **컨테이너와 우선순위만 바꾼다.**

```cpp
컨테이너 열린목록;
열린목록.넣기(시작);
표시[시작] = true;

while (!열린목록.비었나()) {
    int u = 열린목록.꺼내기();          // ← 여기가 알고리즘을 결정한다
    if (u == 목표) break;              // (필요하면)

    for (auto [v, w] : adj[u]) {
        if (더좋아지는가(u, v, w)) {    // BFS: 미방문 / 다익스트라: 완화 성공
            갱신(v);
            열린목록.넣기(v);
        }
    }
}
```

### 반드시 정할 세 가지

1. **표시(visited)를 언제 하는가** — BFS 는 **큐에 넣을 때** 표시한다.
   꺼낼 때 표시하면 같은 정점이 중복으로 들어가 큐가 O(E) 로 부푼다.
2. **인접을 어떻게 만드는가** — 인접 리스트가 기본. 격자는 `dx[]/dy[]` 로 즉석 계산.
   인접 **행렬**은 O(V²) 라 희소 그래프에서 손해다.
3. **경로가 필요한가** — 거리만 필요하면 `dist` 배열 하나,
   경로가 필요하면 `parent[v]` 를 기록해 거슬러 올라간다.

## 잘 맞는 문제

- **미로 · 격자 최단 경로**: 전형적인 BFS. 벽·순간이동·열쇠 같은 조건은 상태 차원을 늘려 처리
- **연결 요소 세기 / 영역 칠하기**: DFS 또는 BFS 한 번
- **의존 관계 정렬**: [위상 정렬](#/algo/topological-sort) — 빌드 순서, 선수 과목
- **네트워크 최단 시간·최소 비용**: [다익스트라](#/algo/dijkstra)
- **경로 찾기(게임 AI)**: [A\*](#/algo/a-star)
- **순환 참조 · 데드락 탐지**: [SCC](#/algo/tarjan-scc), DFS 사이클 판정
- **최소 연결 비용**: [크루스칼](#/algo/kruskal) — 탐색은 아니지만 같은 그래프 모델 위에 있다

**신호**: "최소 이동 횟수", "도달 가능한가", "몇 개의 덩어리인가",
"A 를 하려면 B 가 먼저" 가 보이면 그래프로 옮겨 볼 때다.

## 함정

**`visited` 표시 시점** — 위에서 말한 그 함정. BFS 에서 pop 시점에 표시하면
시간 초과의 흔한 원인이 된다.

**방향을 헷갈린다** — 의존 관계를 간선으로 옮길 때 `A → B` 가 "A 다음 B" 인지
"A 가 B 를 필요로 함" 인지 헷갈리면 순서가 뒤집힌다. 한 방향을 정해 주석으로 못 박자.

**가중치가 있는데 BFS 를 쓴다** — BFS 는 **간선 개수**를 최소화하지 비용을 최소화하지 않는다.
가중치가 다르면 다익스트라로 가야 한다.

**음수 간선에 다익스트라** — 확정한 정점을 다시 안 보므로 틀린다.
[벨만-포드 문서](#/algo/bellman-ford)에 구체적인 반례가 있다.

**상태 폭발** — 상태에 넣을 정보를 늘리면 정점 수가 곱해진다.
"이 정보가 정말 필요한가"를 매번 되묻자.

**재귀 DFS 의 깊이** — 정점 10만 개면 스택이 넘친다. 반복 버전으로 바꾼다.
