## 한눈에

입력을 **왼쪽에서 오른쪽으로 딱 한 번** 지나간다. 되돌아가지 않고, 지나온 것을 통째로 기억하지도 않는다 —
대신 **"지금까지의 요약"** 만 작은 상태로 들고 간다. 그 상태가 스택일 수도, 두 개의 포인터일 수도 있다.

핵심은 **분할상환(amortized) 논증**이다. 한 걸음마다 일이 몰릴 수도 있지만,
**각 원소가 상수 번만 만져진다**는 걸 보이면 전체가 `Θ(n)` 이다.

- 스택으로 훑기 — 각 원소는 **한 번 push, 한 번 pop** → `O(n)` ([괄호 검사](#/algo/balanced-parentheses)·[후위 표기법](#/algo/postfix-eval))
- 두 포인터로 훑기 — 두 인덱스가 **전진만** 한다 → 이동 총량 `O(n)` ([투 포인터](#/algo/two-pointers))

되돌아가지 않는다는 이 한 가지가, 순진하면 `O(n²)` 일 문제를 `O(n)` 으로 바꾼다.

## 언제 쓸 수 있나

**"현재 위치의 판단이 지나온 것의 작은 요약만으로 결정될 때"** 쓸 수 있다.
전체를 다시 볼 필요가 없어야 한다.

### 신호 1 — 가장 최근 것부터 짝지어진다 → 스택

여는 괄호와 닫는 괄호, 피연산자와 연산자처럼 **중첩(nesting)** 구조가 있으면,
가장 최근에 본 것이 가장 먼저 처리된다(LIFO). 스택 하나면 된다.

> 오른쪽으로 훑으며: 열리는 것은 **push**, 닫히는 것은 **pop 해서 짝을 맞춘다**.
> 끝났을 때 스택이 비어 있으면 성공.

[괄호 검사](#/algo/balanced-parentheses)는 짝만 맞추고, [후위 표기법](#/algo/postfix-eval)은 pop 한 둘을
계산해 도로 push 한다 — 같은 골격의 변주다.

### 신호 2 — 단조성이 있어 포인터가 되돌 필요가 없다 → 두 포인터

**정렬돼 있거나** 어떤 값이 **단조롭게 변할 때**, 한 포인터를 옮기면 다른 포인터는
절대 되돌아갈 필요가 없다. 이 단조성이 "한 번 훑기" 를 보장한다.

> 두 끝(또는 느린·빠른)에서 출발해, 조건을 보고 **한쪽만 전진**시킨다.
> 두 포인터의 이동을 합쳐도 `n` 을 넘지 않는다.

[투 포인터](#/algo/two-pointers)의 "정렬된 배열에서 합이 목표인 쌍 찾기" 가 전형이다 —
합이 크면 오른쪽을 당기고, 작으면 왼쪽을 민다. 되돌림이 없다.

### 성립하지 않는 신호

- 현재 판단에 **먼 과거 전체**가 필요하다(요약으로 안 줄어든다)
- 포인터가 **뒤로 가야** 하는 경우가 생긴다(단조성이 깨진다)
- 앞을 내다봐야(look-ahead) 결정할 수 있다 → 다른 접근이나 전처리가 필요

## 구현 골격

### 스택으로 훑기

```cpp
stack<T> st;
for (auto x : input) {          // 왼→오 한 번
    if (여는 것)      st.push(...);
    else {                       // 닫는 것
        if (st.empty()) 실패;    // 짝이 없다
        auto top = st.top(); st.pop();
        top 과 x 를 짝지어 처리;
    }
}
return st.empty();              // 남으면 짝이 안 맞은 것
```

### 두 포인터로 훑기

```cpp
int lo = 0, hi = n - 1;         // 또는 slow=0, fast=0
while (lo < hi) {
    if (조건 만족)      정답 갱신, 양쪽 조정;
    else if (더 키워야) lo++;    // 한쪽만 전진
    else                hi--;
}
```

두 골격 모두 **루프가 한 번**이고, 안쪽 작업이 각 원소를 상수 번만 건드린다.
그래서 겉보기의 중첩(while 안의 pop, 포인터 이동)에도 불구하고 총합이 `O(n)` 이다.

| | 들고 가는 상태 | 왜 O(n) 인가 |
|---|---|---|
| [괄호 검사](#/algo/balanced-parentheses) | 여는 괄호 스택 | 각 괄호 1 push + 1 pop |
| [후위 표기법](#/algo/postfix-eval) | 피연산자 스택 | 각 토큰 상수 번 push/pop |
| [투 포인터](#/algo/two-pointers) | 두 인덱스 | 두 포인터 전진 총합 ≤ n |

## 잘 맞는 문제

- **괄호·태그·수식의 유효성/평가** — 중첩 구조 → 스택 한 번 훑기
- **정렬된 배열에서 쌍/구간 찾기** — 두 수의 합, 세 수의 합(한 포인터 고정 + 투 포인터)
- **부분 배열/부분 문자열 최적화** — 슬라이딩 윈도우(투 포인터의 변형): 조건을 만족하는
  최소/최대 구간을 창을 늘였다 줄이며 한 번에
- **제자리 재배열** — 0 몰아내기, 중복 제거처럼 느린·빠른 포인터로 `O(1)` 추가 공간에
- **다음 큰 원소(next greater element)** — 단조 스택으로 한 번 훑기

문자열 검색의 [KMP](#/algo/kmp)도 넓게는 이 계열이다 — 텍스트 포인터가 되돌아가지 않아 `O(n)`
(다만 그쪽은 실패 함수라는 [전처리](#/paradigm/preprocessing)가 핵심이라 그 유형으로 분류했다).

## 함정

**스택이 빌 때를 안 챙긴다.** 닫는 괄호가 왔는데 스택이 비어 있으면 즉시 실패다.
끝나고 스택이 남아 있어도 실패(짝 안 맞음). 두 경계를 모두 검사해야 한다.

**투 포인터에 단조성이 없다.** 정렬 안 된 배열에서 "두 수의 합" 을 투 포인터로 풀면 틀린다.
전제(정렬/단조)가 깨지면 되돌림이 필요해져 `O(n)` 보장이 사라진다.

**"한 번 훑기" 를 겉모습으로 착각한다.** while 안에 while 이 있어도, **각 원소가 상수 번만
처리됨**을 보이지 못하면 `O(n)` 이 아니다. 분할상환 논증을 실제로 해 봐야 한다.

**look-ahead 를 숨긴다.** 현재 결정에 "다음 것" 이 필요하면 순수한 한 번 훑기가 아니다.
전처리로 미리 계산하거나(예: KMP 의 실패 함수) 접근을 바꿔야 한다.
