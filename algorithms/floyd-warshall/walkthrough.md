## 어떤 문제인가

[다익스트라](#/algo/dijkstra)는 **한 정점에서** 나머지 전부까지의 최단 거리를 구한다.
그런데 **모든 정점 쌍**의 거리표가 필요하다면?

```
       0    1    2    3    4
  0 [  0    3    2    6    9 ]
  1 [  ∞    0    ∞    3    ∞ ]
  2 [  ∞    1    0    4    7 ]      ← 이런 표 전체를 채우고 싶다
  3 [  ∞    2    1    0    2 ]
  4 [  6    9    8   13    0 ]
```

다익스트라를 정점마다 한 번씩 돌려도 되지만, 놀랍도록 짧은 다른 방법이 있다.
**반복문 세 줄**이면 끝난다.

## 손으로 해보기

### 출발점: 간선만 아는 표

처음엔 직접 연결된 것만 안다. 자기 자신은 0, 간선이 있으면 그 비용, 없으면 `∞`.

기본 그래프(방향 그래프)의 간선:
`0→1(4)`, `0→2(2)`, `1→3(3)`, `2→1(1)`, `2→4(7)`, `3→4(2)`, `4→0(6)`, `3→2(1)`

```
초기      0    1    2    3    4
    0 [   0    4    2    ∞    ∞ ]
    1 [   ∞    0    ∞    3    ∞ ]
    2 [   ∞    1    0    ∞    7 ]
    3 [   ∞    ∞    1    0    2 ]
    4 [   6    ∞    ∞    ∞    0 ]
```

### 핵심 질문

`0 → 1` 은 지금 4다. 그런데 `0 → 2 → 1` 로 가면 `2 + 1 = 3` 이다. 더 싸다!

여기서 우리가 한 일이 뭔가? **"2를 경유해도 되나?"** 를 물어본 것이다.

> 그러면 경유해도 되는 정점을 **하나씩 늘려 가며** 표를 고쳐 나가면 어떨까?

### k = 0 — "0을 경유해도 된다"

모든 `(i, j)` 에 대해 `i → 0 → j` 가 더 싼지 확인한다.

```
0 으로 들어가는 간선이 있는 건 4 뿐 (4→0 = 6)
4→0→1: 6 + 4 = 10 < ∞ → dist[4][1] = 10
4→0→2: 6 + 2 = 8  < ∞ → dist[4][2] = 8
```

### k = 1 — "0, 1을 경유해도 된다"

```
1 로 들어가는 것: 0→1(4), 2→1(1), 4→1(10 방금 생김)
0→1→3: 4 + 3 = 7 < ∞ → dist[0][3] = 7
2→1→3: 1 + 3 = 4 < ∞ → dist[2][3] = 4
4→1→3: 10 + 3 = 13 < ∞ → dist[4][3] = 13
```

### k = 2 — "0, 1, 2를 경유해도 된다"

```
0→2→1: 2 + 1 = 3 < 4  → dist[0][1] = 3   ★ 처음에 본 그 개선!
0→2→4: 2 + 7 = 9 < ∞  → dist[0][4] = 9
3→2→1: 1 + 1 = 2 < ∞  → dist[3][1] = 2
...
```

이렇게 `k` 를 `0, 1, 2, 3, 4` 까지 올리면, 마지막엔 **모든 정점을 경유지로 쓸 수 있으므로**
표가 진짜 최단 거리로 완성된다.

## 아이디어 쌓기

### 1단계 — 표의 의미를 정확히 정한다

이 알고리즘을 이해하는 열쇠는 **`dist[i][j]` 가 무슨 값인지 말로 정하는 것**이다.

> `dist[i][j]` = **중간 경유지를 `0 .. k-1` 중에서만 고를 때**의 `i → j` 최단 거리
>
> (출발점 `i` 와 도착점 `j` 는 이 제한과 상관없다)

`k = 0` 이면 경유가 아예 금지되므로 간선 하나로 가는 경우뿐 — 그게 초기 표다.

### 2단계 — `k` 를 하나 늘리면 답은 둘 중 하나

정점 `k` 를 경유지로 새로 허용했다. `i → j` 최단 경로는 둘 중 하나다.

```
(A) k 를 안 지난다  →  값은 그대로
(B) k 를 지난다     →  i ⇝ k ⇝ j 로 쪼갤 수 있다
```

(B)에서 두 조각 `i ⇝ k` 와 `k ⇝ j` 는 **중간에 `k` 를 쓰지 않는다**
(최단 경로는 같은 정점을 두 번 안 지나니까). 즉 두 조각 모두 "경유지 `0..k-1`" 짜리 값이고,
그건 **표에 이미 들어 있다.**

```
새 dist[i][j] = min( 기존 dist[i][j],  dist[i][k] + dist[k][j] )
                     └─ (A) ─┘         └────── (B) ──────┘
```

### 3단계 — `k` 가 가장 바깥이어야 한다 ★

```cpp
for (k) for (i) for (j)     // ○ 맞다
for (i) for (j) for (k)     // ✗ 틀렸다 (조용히!)
```

`k` 가 안쪽에 있으면 1단계의 정의가 깨진다. 어떤 칸은 `k` 를 반영한 값을 쓰고
어떤 칸은 안 쓴 값을 써서 **계층이 뒤섞인다.**

컴파일도 되고 실행도 되고 대부분의 입력에서 답도 그럴듯하게 나온다. 그래서 **가장 찾기 어려운 버그**다.

### 4단계 — 표 하나만 써도 되는 이유

`k` 단계 이전 표와 이후 표를 따로 둘 필요가 없다. `k` 라운드에서 읽는 값은
`dist[i][k]` 와 `dist[k][j]` 인데, 이 두 줄은 이번 라운드에서 안 바뀐다.

```
dist[i][k] 가 바뀌려면  dist[i][k] > dist[i][k] + dist[k][k]  이어야 한다
                    ⟺ dist[k][k] < 0  ⟺ k 를 지나는 음수 사이클
```

음수 사이클이 없으면 `dist[k][k] = 0` 이므로 `k` 행·열은 그대로다.

## 코드로 옮기기

```cpp
// dist[i][j] = i → j 최단 거리. 없으면 INF, dist[i][i] = 0
void floydWarshall(vector<vector<int>>& dist, int n) {
    for (int k = 0; k < n; k++)          // ← 3단계: k 가 반드시 가장 바깥!
        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                if (dist[i][k] + dist[k][j] < dist[i][j])
                    dist[i][j] = dist[i][k] + dist[k][j];   // ← 2단계
}
```

**다섯 줄이다.** 다익스트라의 우선순위 큐, 벨만-포드의 라운드 관리 같은 게 전혀 없다.
대신 항상 `n³` 번 돈다.

| | 시간 | 음수 간선 | 코드 길이 |
|---|---|---|---|
| 다익스트라 × n회 | O(n·E log n) | ✗ | 길다 |
| **플로이드-워셜** | **O(n³)** | **○** | **5줄** |

정점이 400개 남짓까지는 플로이드-워셜이 실용적이고 훨씬 짧다.

## 자주 하는 실수

**`k` 를 안쪽 루프에 둔다.** 3단계의 그 문제. **이 알고리즘 최대의 함정이다.**

**`INF` 끼리 더해서 오버플로가 난다.** `dist[i][k]` 와 `dist[k][j]` 가 둘 다 `INF` 면
`INF + INF` 가 음수로 뒤집힐 수 있다. 두 방법 중 하나를 쓰자.

```cpp
if (dist[i][k] == INF || dist[k][j] == INF) continue;   // 걸러 내거나
const int INF = 0x3f3f3f3f;                             // 두 배 해도 안전한 값
```

**중복 간선을 덮어쓴다.** 같은 `(u,v)` 간선이 여러 개면 **최솟값**을 넣어야 한다.
그냥 대입하면 나중에 읽은 값이 남는다.

```cpp
dist[u][v] = min(dist[u][v], w);   // ○
dist[u][v] = w;                    // ✗
```

**`dist[i][i] = 0` 을 빠뜨린다.** 자기 자신까지의 거리를 0으로 두지 않으면 전부 틀어진다.

## 스스로 확인하기

1. **`k` 가 바뀌는 스텝**을 찾아보자. 그래프에서 정점 하나가 밝아지고,
   표의 **그 `k` 행과 `k` 열이 강조**된다. 그 두 줄이 이번 라운드의 재료 전부다.
2. **`dist[0][1]` 이 4에서 3으로 바뀌는 순간**을 찾아보자. `k = 2` 라운드에서
   `0→2→1 = 2+1 = 3` 이 발견된다.
3. 표가 **비대칭**인 것을 보자. 방향 그래프라 `dist[0][4]` 와 `dist[4][0]` 이 다르다.
4. `∞` 로 남은 칸을 찾아보자. 방향 때문에 갈 수 없는 쌍이다.
5. 편집기에서 간선 하나를 지우고 실행해 `∞` 가 늘어나는 것을 확인해 보자.

아래 **깊이 보기**에서는 1단계의 정의로부터 `k` 에 대한 귀납 증명을 전개하고,
음수 사이클을 **탐지하는 방법**(`dist[i][i] < 0`)을 다룬다.
