## 한눈에

`n×n` 판에 퀸 `n` 개를 서로 공격하지 않게 놓는다. 한 행씩 내려가며 놓아 보고,
부분해가 이미 규칙을 어기면 **더 내려가지 않고 물러난다**(백트래킹).

- **시간** `O(n!)` 상한. 실제로는 가지치기가 훨씬 많이 잘라 낸다
- **공간** `O(n)` — `col[]` 배열과 재귀 스택 `n` 단
- **완전(complete)** — 해가 있으면 반드시 찾고, 없으면 없다고 결론 낸다
- 되감기와 궁합이 가장 좋은 알고리즘 — **물러남 자체가 스냅샷 되감기와 같은 모양**이다

**언제 쓰나** — 백트래킹을 배우는 표준 예제이자, **제약 충족 문제(CSP)** 의 축소판이다.
스도쿠·그래프 색칠·시간표 배정이 같은 골격이고, 실무의 SAT 솔버·제약 프로그래밍이 이 뼈대 위에 있다.

**언제 안 쓰나** — **해 하나만** 필요하고 `n` 이 크면 백트래킹은 과하다.
`n ≥ 4` 이면 해를 **직접 구성하는 공식**이 알려져 있어 `O(n)` 에 만들 수 있다.
해의 **개수**가 필요하면 `n = 27` 정도가 현재 인류의 한계다(대규모 분산 계산으로 계산됨).

## 동작 원리

두 번의 축소가 핵심이다.

**① 제약을 먼저 챙긴다.** 퀸은 같은 행을 공격하므로 한 행에 둘을 놓을 수 없고,
퀸이 `n` 개·행이 `n` 개이므로 **모든 행에 정확히 하나**다.

```
C(n², n) 가지  →  n^n 가지
4×4:  1820  →  256
8×8:  약 44억  →  약 1670만
```

상태가 `col[0..n-1]` 배열 하나로 줄어든다.

**② 부분해에서 자른다.** `row` 행까지 놓았을 때 이미 충돌이 있으면, 아래를 어떻게 채워도
답이 아니므로 그 부분 트리 전체(`n^{n-row-1}` 가지)를 건너뛴다.

### 공격 판정

같은 열이거나, 행 차이와 열 차이가 같으면(대각선) 공격이다.

```
col[r] == c              같은 열
|col[r] - c| == row - r  대각선  (row > r 이므로 오른쪽은 절댓값 불필요)
```

`0..row-1` 만 검사한다 — 아래 행은 비어 있고, 같은 행에는 하나뿐이다.

### 실행 예 (`n = 4`)

```
col=[0,?,?,?]  1행: 0열(같은 열)✗ 1열(대각선)✗ 2열✓
col=[0,2,?,?]  2행: 0,1,2,3 전부 막힘  →  물러남
col=[0,3,?,?]  2행: 1열✓
col=[0,3,1,?]  3행: 전부 막힘  →  물러남 → 2행 소진 → 1행 소진 → 0행 물러남
col=[1,?,?,?]  1행: 3열✓ → 2행: 0열✓ → 3행: 2열✓
col=[1,3,0,2]  완성.  시도 8번, 물러남 4번
```

`4×4` 의 256가지 중 8번의 배치 시도로 끝났다.

## 정확성

백트래킹의 정확성은 **완전성**(해를 놓치지 않는다)과 **건전성**(찾은 것은 실제 해다)으로 나뉜다.

### 건전성

> `solve(n)` 이 `true` 를 반환한 시점의 `col[0..n-1]` 은 유효한 배치다.

`col[row] = c` 는 `safe(row, c)` 가 통과한 뒤에만 실행되고, `safe` 는 `0..row-1` 의 모든 퀸에
대해 같은 열·대각선을 검사한다. 각 행에 정확히 하나씩 놓으므로 같은 행 충돌은 구조적으로 없다.

배치는 아래 행으로 내려가며 **추가만** 되고(성공 경로에서는 되돌리지 않으므로),
`row = n` 에 도달했을 때 모든 쌍 `(r, r')`(`r < r'`)이 검사를 통과한 상태다.
`safe(r', ·)` 가 `r` 을 포함해 검사했기 때문이다. 따라서 유효하다. ∎

### 완전성 — 가지치기가 해를 버리지 않는다

> **주장.** `solve(row)` 가 `false` 를 반환하면, `col[0..row-1]` 을 접두사로 갖는 유효한
> 전체 배치는 **존재하지 않는다**.

`n - row` 에 대한 귀납법.

**기저** — `row = n`. 함수는 항상 `true` 를 반환하므로 `false` 인 경우가 없다. 자명하게 성립. ✓

**귀납 단계** — `solve(row)` 가 `false` 를 반환했다고 하자. 이는 루프가 `c = 0..n-1` 을
모두 소진했다는 뜻이다. 각 `c` 는 두 갈래 중 하나였다.

- `safe(row, c)` 가 거짓 — `col[0..row-1]` 에 `row` 행 `c` 열을 더하면 즉시 충돌이다.
  따라서 이 `c` 로 시작하는 확장은 유효할 수 없다.
- `safe` 는 통과했지만 `solve(row+1)` 이 `false` — 귀납 가정에 의해
  `col[0..row]`(끝이 `c`)를 접두사로 갖는 유효한 배치가 없다.

`row` 행의 퀸은 반드시 어떤 열 `c ∈ [0, n)` 에 놓여야 하고, **모든** `c` 가 배제되었으므로
`col[0..row-1]` 을 접두사로 갖는 유효한 배치는 없다. ∎

`row = 0` 에 적용하면 — `solve(0)` 이 `false` 면 유효한 배치가 아예 없다.
가지치기가 아무것도 놓치지 않는다는 것이 이것이다.

### 되돌리기의 필요성

> 루프 불변식: `c` 번째 반복을 시작할 때 `col[row]` 는 미정(`-1`)이고,
> `col[0..row-1]` 은 이 호출에 들어올 때와 같다.

`col[row] = -1` 이 이 불변식을 유지한다. 이 줄이 없으면 다음 반복의 `safe(row, c')` 가
**자기 자신이 놓은 퀸**과 비교하게 되어(`col[row]` 는 `safe` 의 검사 범위 밖이지만,
더 아래 행의 `safe` 가 `row` 를 보므로) 건전성 증명의 전제가 깨진다.

**종료성** — 각 호출의 루프는 `n` 번으로 유한하고, 재귀 깊이는 `row` 가 매번 1 증가하므로
`n` 을 넘지 않는다. 따라서 탐색 트리가 유한하고 반드시 종료한다.

## 복잡도

| | 시간 | 공간 |
|---|---|---|
| 최선 | `Ω(n²)` (물러남 없이 바로 찾을 때) | `O(n)` |
| 평균 | 실측이 훨씬 작다(아래) | `O(n)` |
| 최악 | `O(n!)` | `O(n)` |

**상한 `O(n!)`** — 가지치기를 무시하면 `row` 행에서 `n` 개, 다음 행에서 `n-1` 개(같은 열 제외) …
로 볼 수 있어 순열 개수 `n!` 가 상한이다. 각 노드에서 `safe` 가 `O(n)` 이므로 엄밀히는 `O(n! · n)`.

**실제로는 훨씬 작다.** 이 페이지의 생성기가 기록한 스텝 수가 그 증거다.

```
n = 4:   36 스텝  (시도 8번,  물러남 4번)
n = 5:   17 스텝  (물러남 0번 — 운 좋은 크기)
n = 6:  223 스텝  (물러남 25번)
n = 8: 1088 스텝
```

`n!` 이라면 `8! = 40320` 인데 실제 배치 시도는 그보다 훨씬 적다. 가지치기가 지수의 밑을 낮춘다.
다만 **점근적으로는 여전히 지수**이고, 정확한 성장률은 알려져 있지 않다.

**공간** — `col[]` 이 `n` 칸, 재귀 스택이 `n` 단. 판 전체(`n²`)를 들고 다닐 필요가 없다는 것이
"한 행에 하나" 축소의 부수 효과다.

**해의 개수**(참고) — `n = 1..10` 에 대해

```
1, 0, 0, 2, 10, 4, 40, 92, 352, 724
```

`n = 2, 3` 은 0이다. `n ≥ 4` 는 항상 해가 존재한다(구성적 증명이 있다).

## 구현 노트

### 비트마스크로 `safe` 를 `O(1)` 로

세 개의 비트 집합으로 "쓰인 열·쓰인 두 대각선" 을 관리하면 검사가 상수 시간이 된다.

```cpp
void solve(int row, int n, int cols, int diag1, int diag2, int& count) {
    if (row == n) { count++; return; }
    int available = ~(cols | diag1 | diag2) & ((1 << n) - 1);
    while (available) {
        int bit = available & -available;      // 가장 낮은 1 비트 = 후보 한 칸
        available -= bit;
        solve(row + 1, n, cols | bit,
              (diag1 | bit) << 1, (diag2 | bit) >> 1, count);
    }
}
```

`diag1` 을 왼쪽으로, `diag2` 를 오른쪽으로 미는 것이 "대각선이 한 행 내려가며 한 칸 이동" 을
표현한다. 이 형태가 `n = 16` 정도까지의 개수 계산에 쓰이는 표준 구현이다.

**대각선 인덱싱**(비트마스크를 안 쓸 때)은 두 개를 쓴다.

```
↘ 방향:  row - col + (n-1)     범위 0 .. 2n-2
↙ 방향:  row + col             범위 0 .. 2n-2
```

### 대칭성 활용

첫 행의 열을 `0 .. ⌊n/2⌋-1` 로만 제한하면 좌우 대칭해를 중복 세지 않아 **탐색이 절반**이 된다.
개수를 셀 때는 마지막에 2를 곱하고, `n` 이 홀수면 가운데 열을 따로 처리한다.

### 첫 해만 필요하면 백트래킹을 쓰지 마라

`n ≥ 4` 이면 해를 **직접 구성**할 수 있다. `n mod 6 ≠ 2, 3` 인 경우는

```
짝수 위치에 2, 4, 6, …,  홀수 위치에 1, 3, 5, …
```

식으로 배치하면 되고, 나머지 경우도 알려진 보정 규칙이 있다. `O(n)` 이다.
백트래킹은 **개수를 세거나 모든 해가 필요할 때** 의미가 있다.

### 모든 해를 세려면

`return true` 대신 카운터를 올리고 계속 진행한다. 성공 지점에서 멈추지 않으므로
탐색 트리를 전부 돈다.

## 변형과 확장

### 스도쿠

같은 골격이다. "빈 칸 하나를 고르고, 1..9 를 넣어 보고, 규칙을 어기면 물러난다."
후보가 가장 적은 칸부터 채우는 **MRV(minimum remaining values)** 휴리스틱을 얹으면
극적으로 빨라진다. [나이트 여행](#/algo/knights-tour)의 바른스도르프 규칙이 같은 발상이다.

### 제약 전파 — 검사에서 예측으로

지금 코드는 "놓은 뒤 충돌을 검사" 한다. 반대로 **놓는 순간 남은 후보를 줄여 두면**
어떤 행의 후보가 0이 되는 것을 미리 알아채 더 일찍 자를 수 있다(forward checking).
이것이 제약 프로그래밍의 출발점이다.

### 그래프 색칠로 보기

칸을 정점, "서로 공격" 을 간선으로 보면 **독립 집합** 문제다. 스도쿠·시간표·레지스터 할당이
같은 틀에 들어가고, 일반적으로 NP-난해다.

### 국소 탐색 — 큰 n 을 위한 다른 길

`n` 이 수천이면 백트래킹이 아니라 **최소 충돌 휴리스틱**을 쓴다.
무작위 배치에서 시작해 충돌이 가장 줄어드는 이동을 반복하면 `n = 10^6` 도 실용적으로 풀린다.
완전성을 포기하고 속도를 얻는 교환이다.

### 왜 이 알고리즘이 되감기와 잘 맞나

백트래킹의 "물러남" 은 **직전 상태로 되돌아가는 것**이고, 이 사이트의 되감기는
**직전 스냅샷을 다시 그리는 것**이다. 둘이 같은 모양이라, 스크러버를 앞뒤로 움직이면
탐색 트리를 오르내리는 것과 같아진다. `undo` 로직을 만들지 않는다는 이 프로젝트의
설계 원칙이 여기서 값을 낸다.
