## 어떤 문제인가

체스의 **퀸**은 같은 행·열·대각선을 전부 공격한다.

```
. . ♛ . .        ♛ 가 공격하는 칸 = ×
× × ♛ × ×
. × ♛ × .
. × ♛ × .
× . ♛ . ×
```

`n×n` 판에 퀸 `n` 개를 **서로 공격하지 않게** 놓을 수 있을까?

### 모든 경우를 다 보면

`4×4` 판의 16칸 중 4칸을 고르는 방법은 `C(16,4) = 1820` 가지다. `8×8` 이면
`C(64,8) ≈ 44억` 가지. 세어 볼 수 없다.

### 첫 번째 줄이기 — 한 행에 하나씩

퀸은 **같은 행도 공격한다.** 그러니 한 행에 둘을 놓는 배치는 애초에 답이 될 수 없다.
퀸이 `n` 개이고 행이 `n` 개이므로 — **모든 행에 정확히 하나씩** 놓게 된다.

그러면 결정할 것은 "각 행에서 몇 번째 열이냐" 뿐이다.

```
4×4:  4 × 4 × 4 × 4 = 256 가지     (1820 → 256)
8×8:  8^8 ≈ 1670만 가지            (44억 → 1670만)
```

### 두 번째 줄이기 — 막히면 즉시 돌아선다

256가지를 끝까지 만들어 놓고 검사할 필요도 없다.
**2행까지 놓았는데 이미 서로 공격하고 있다면**, 3·4행을 어떻게 채워도 답이 아니다.
그 가지를 통째로 잘라낸다.

> 만들다가 **규칙을 어기는 순간 되돌아간다.** 이게 **백트래킹**이다.

## 손으로 해보기

기본 입력 `4` — `4×4` 판이다. 플레이어와 함께 끝까지 가 보자.

표기: `col[r]` = `r` 행 퀸의 열. 위 행부터 채운다.

### 0행 — 0열에 놓아 본다

```
♛ . . .          col = [0, ?, ?, ?]
```

### 1행 — 0열, 1열은 막혔다

```
(1,0):  0행 퀸과 같은 열      ✗
(1,1):  0행 퀸의 대각선       ✗
(1,2):  안전                  ✓  놓는다

♛ . . .
. . ♛ .          col = [0, 2, ?, ?]
```

### 2행 — 놓을 자리가 없다

```
(2,0):  0행과 같은 열     ✗
(2,1):  1행의 대각선      ✗
(2,2):  0행의 대각선      ✗   ← 0행 퀸이 (0,0), 대각선으로 (1,1),(2,2),(3,3)
(2,3):  1행의 대각선      ✗

네 칸 모두 막혔다  →  2행에는 놓을 수 없다
```

**여기가 백트래킹의 순간이다.** 3행을 볼 필요조차 없다. 1행의 선택(`2열`)이 잘못이었으므로
**1행으로 돌아가** 다음 열을 시도한다.

### 1행을 3열로 바꿔 본다

```
♛ . . .
. . . ♛          col = [0, 3, ?, ?]
```

### 2행 — 1열이 가능하다

```
(2,0):  0행과 같은 열   ✗
(2,1):  안전            ✓

♛ . . .
. . . ♛
. ♛ . .          col = [0, 3, 1, ?]
```

### 3행 — 또 전멸

```
(3,0): 0행과 같은 열   ✗
(3,1): 1행의 대각선    ✗      ← (1,3) 에서 대각선으로 (2,2),(3,1)
(3,2): 2행의 대각선    ✗
(3,3): 0행의 대각선    ✗
```

다시 물러난다. 2행의 남은 열(`2`, `3`)도 전부 막힌다. 그러면 2행도 포기 →
1행으로 물러나는데 1행의 남은 열도 없다 → **0행으로 물러난다.**

> **0행을 0열로 두는 한, 답은 없다.** 이 판정이 나오기까지 25스텝이 걸렸다.
> 그리고 이 한 판정이 `4×4` 의 256가지 중 64가지를 통째로 지운 것이다.

### 0행을 1열로 다시 시작

```
(0,1) 에 놓는다               col = [1, ?, ?, ?]

1행: (1,0) 대각선✗  (1,1) 같은 열✗  (1,2) 대각선✗  (1,3) 안전✓
2행: (2,0) 안전✓
3행: (3,0) 2행과 같은 열✗  (3,1) 0행과 같은 열✗  (3,2) 안전✓
```

```
. ♛ . .
. . . ♛
♛ . . .
. . ♛ .          col = [1, 3, 0, 2]      완성!
```

**시도 8번, 물러남 4번.** 256가지를 다 보지 않고 끝냈다.

### 왜 위쪽 행만 검사하면 되나

`safe(row, c)` 는 `0..row-1` 행만 본다. 아래 행은 아직 비어 있으니 볼 것이 없고,
같은 행에는 애초에 하나만 놓기 때문이다. **한 방향으로만 검사한다.**

대각선 판정은 이 한 줄이다.

```
|col[r] - c| == row - r        ←  행 차이와 열 차이가 같으면 대각선
```

## 아이디어 쌓기

### 1단계 — 제약이 후보를 줄여 준다

"한 행에 하나" 는 문제를 다시 읽어 얻은 것이다. **제약을 먼저 챙기면 탐색 공간이 접힌다.**
`C(16,4)` 에서 `4^4` 로 줄었다.

### 2단계 — 상태를 배열 하나로

각 행의 열만 기억하면 되므로 상태가 `col[0..n-1]` 하나다. 판 전체(`n²` 칸)를 들고 다닐 필요가 없다.

### 3단계 — 부분해가 이미 틀렸으면 즉시 끊는다

```
안전한 칸이 없으면  →  더 내려가지 않고 위로 실패를 알린다
```

이것을 **가지치기(pruning)** 라 한다. 백트래킹이 완전탐색보다 빠른 유일한 이유다.

### 4단계 — 물러남 = 되돌리기

```
col[row] = c;                    // 놓아 본다
if (solve(row + 1)) return true;  // 아래를 맡긴다
col[row] = -1;                    // 실패했으면 원상복구
```

**세 줄이 백트래킹의 전부다.** 놓고 → 맡기고 → 실패하면 거둔다.

`col[row] = -1` 을 빼먹으면 다음 시도에서 유령 퀸이 남아 조용히 틀린다.

### 5단계 — 재귀가 되돌리기를 대신 관리한다

`row` 마다 지역 변수 `c` 가 따로 있으므로, 몇 번째 열까지 시도했는지를 재귀가 기억한다.
**호출 스택이 곧 탐색 경로**다.

## 코드로 옮기기

```cpp
bool solve(int row, int n) {
    if (row == n) return true;              // 모든 행에 놓았다 = 해답
    for (int c = 0; c < n; c++) {
        if (!safe(row, c)) continue;        // ← 3단계: 가지치기
        col[row] = c;                       // ← 4단계: 놓아 본다
        if (solve(row + 1, n)) return true;
        col[row] = -1;                      //    실패했으면 거둔다
    }
    return false;                           // 이 행엔 놓을 자리가 없다
}

bool safe(int row, int c) {                 // 위쪽 행만 확인하면 된다
    for (int r = 0; r < row; r++)
        if (col[r] == c || abs(col[r] - c) == row - r)
            return false;
    return true;
}
```

`row == n` 이 성공 조건이다 — `n` 행까지 다 놓았다는 뜻이다.

## 자주 하는 실수

**`col[row] = -1` 을 빼먹는다.** 4단계의 그 줄. 다음 열을 시도할 때 이전 퀸이 남아 있어
`safe` 가 자기 자신과 비교하게 된다. **조용히 틀리는** 종류다.

**대각선 판정을 한쪽만 한다.** `abs()` 를 빼고 `col[r] - c == row - r` 로만 쓰면
한쪽 대각선만 걸린다. 반드시 절댓값이다.

**아래 행까지 검사한다.** `safe` 를 `0..n-1` 로 돌리면 아직 비어 있는(`-1`) 행과 비교해
엉뚱한 판정이 나온다. `0..row-1` 이다.

**모든 배치를 만든 뒤 검사한다.** 그게 완전탐색이고, 백트래킹의 이득이 사라진다.
**만들면서** 검사해야 한다.

**"한 행에 하나" 를 놓친다.** 판의 아무 칸이나 고르는 완전탐색으로 짜면
`4×4` 에서도 1820가지를 본다.

**모든 해를 찾을 때 `return true` 를 쓴다.** 첫 해에서 멈추려면 `return true`,
전부 세려면 반환하지 않고 카운터만 올리며 계속 돌아야 한다(`4×4` 는 2개, `8×8` 은 92개).

## 스스로 확인하기

1. **스텝 9(2행 전멸)** 를 보자. 4칸이 전부 붉은 테두리로 막히고, 3행은 아예 보지 않는다.
2. **스텝 25** 를 보자. `(0,0)` 의 퀸이 거둬지는 순간이다. 여기까지가 "0행을 0열로 두면 답이 없다" 의 증명이다.
3. **붉은 칸(공격받음)이 퀸을 놓을 때마다 늘어나는 것**을 보자. 후보가 어떻게 줄어드는지가 보인다.
4. **테두리만 있고 붉은 칸**은 "검사했는데 공격받아서 건너뛴 칸" 이다. 왜 건너뛰는지 설명줄과 맞춰 보자.
5. 입력을 `5` 로 바꿔 보자. **물러남이 한 번도 없다** — 17스텝에 바로 찾는다. 운이 좋은 크기다.
6. 입력을 `6` 으로 바꿔 보자. 223스텝, 물러남 25번. 크기가 2 늘었는데 스텝이 6배가 됐다.
7. 입력을 `8` 로 바꿔 보자. 1088스텝이다. **이게 `O(n!)` 의 체감**이다.
8. 입력을 `3` 으로 바꿔 보자. 30스텝을 다 돌고 "해답이 없다" 로 끝난다.
   `n = 2, 3` 은 실제로 해가 없다.

아래 **깊이 보기**에서는 가지치기가 왜 정답을 놓치지 않는지 증명하고,
비트마스크로 `safe` 를 `O(1)` 로 만드는 방법과 해의 개수가 알려진 값들을 다룬다.
