## 어떤 문제인가

배열 `a[1..n]` 이 있고 두 가지를 **자주** 하고 싶다.

```
query(i)         — 접두사 합 a[1] + a[2] + … + a[i]
update(i, delta) — a[i] 를 delta 만큼 바꾼다
```

간단한 두 방법은 각각 한쪽만 빠르다.

- **누적 합 배열**을 미리 만들면 `query` 는 `O(1)` 이지만, `a[i]` 하나만 바뀌어도
  뒤쪽 누적 합을 전부 고쳐야 해 `update` 가 `O(n)`.
- 그냥 배열이면 `update` 는 `O(1)` 이지만 `query` 가 매번 `O(n)`.

값이 계속 바뀌면서 접두사 합도 계속 물어보면 둘 다 곤란하다.
**두 연산을 모두 `O(log n)`** 에 하는 방법이 펜윅 트리다.

## 손으로 해보기

비결은 인덱스의 **최하위 1비트** 하나다.

```
lowbit(i) = i & -i     — i 를 2진수로 봤을 때 가장 아래 켜진 비트
lowbit(6) = lowbit(110₂) = 010₂ = 2
lowbit(8) = lowbit(1000₂) = 1000₂ = 8
```

핵심 약속: **`t[i]` 는 구간 `(i − lowbit(i), i]` 의 합을 담당한다.**

```
i    2진수   담당 구간            t[i] = 합
1    001     (0,1]  → a[1]
2    010     (0,2]  → a[1..2]
3    011     (2,3]  → a[3]
4    100     (0,4]  → a[1..4]
6    110     (4,6]  → a[5..6]
8   1000     (0,8]  → a[1..8]
```

### query(7) — 구간을 이어 붙이며 내려간다

`a[1..7]` 을 담당 구간들로 딱 덮으면 된다. `i` 에서 시작해 `i -= lowbit(i)`.

```
i=7 (111): t[7] = a[7]        더한다.  7 - lowbit(7)=1 → 6
i=6 (110): t[6] = a[5..6]     더한다.  6 - lowbit(6)=2 → 4
i=4 (100): t[4] = a[1..4]     더한다.  4 - lowbit(4)=4 → 0
i=0: 끝

a[7] + a[5..6] + a[1..4] = a[1..7]   ✓ 겹치지 않고 딱 덮었다 — 세 번에!
```

`i` 가 매번 최하위 비트를 하나씩 지운다. 켜진 비트 수만큼만 더하니 `O(log n)`.

### update(3, +5) — 담당 구간들을 타고 오른다

`a[3]` 이 바뀌면, **3을 구간에 포함하는 모든 `t[i]`** 를 고쳐야 한다. `i += lowbit(i)`.

```
i=3 (011): t[3] += 5    3 + lowbit(3)=1 → 4
i=4 (100): t[4] += 5    4 + lowbit(4)=4 → 8
i=8(1000): t[8] += 5    8 + lowbit(8)=8 → 16 > n, 끝
```

`t[3], t[4], t[8]` 셋만 고치면 된다 — 이들이 `a[3]` 을 담당하는 구간 전부다. 역시 `O(log n)`.

### 두 방향이 거울상이다

`query` 는 `i -= lowbit(i)` 로 **내려가며** 구간을 모으고, `update` 는 `i += lowbit(i)` 로
**올라가며** 구간을 고친다. 같은 비트 트릭의 두 방향일 뿐이다.

## 아이디어 쌓기

### 1단계 — 구간을 최하위 비트로 정한다

`t[i]` 가 `(i − lowbit(i), i]` 를 담당한다고 약속한다. 구간 길이가 곧 `lowbit(i)`.

### 2단계 — query: 비트를 지우며 구간을 잇는다

`i -= lowbit(i)` 를 반복하면 `[1..i]` 를 겹치지 않는 구간들로 덮는다. 켜진 비트 수 = `O(log n)` 번.

### 3단계 — update: 비트를 더하며 담당자를 고친다

`i += lowbit(i)` 를 반복하면 `a[i]` 를 담당하는 모든 구간을 방문한다. 역시 `O(log n)` 번.

### 4단계 — 만들기

빈 `t` 에서 각 `a[i]` 를 `update(i, a[i])` 로 넣으면 `O(n log n)`(또는 `O(n)` 트릭)에 완성된다.

## 코드로 옮기기

```cpp
int t[MAXN], n;                       // 펜윅 트리 (1-based)
int lowbit(int i) { return i & -i; }  // 최하위 1비트
void update(int i, int delta) {       // a[i] += delta
    for (; i <= n; i += lowbit(i))    //   담당 구간들을 타고 오른다
        t[i] += delta;
}
int query(int i) {                    // 접두사 합 a[1..i]
    int sum = 0;
    for (; i > 0; i -= lowbit(i))     //   구간을 이어 붙이며 내려간다
        sum += t[i];
    return sum;
}
```

두 함수의 유일한 차이는 `+=` 냐 `-=` 냐다. `i & -i` 가 2의 보수로 최하위 1비트를 뽑는다.

## 자주 하는 실수

**0-based 로 쓴다.** 펜윅 트리는 **1-based** 여야 `lowbit` 트릭이 성립한다. `i=0` 이면
`lowbit(0)=0` 이라 무한 루프거나 아무 일도 안 한다. 인덱스를 1부터 시작하자.

**구간 합을 접두사 차로 안 구한다.** `a[l..r]` 은 `query(r) − query(l−1)` 이다. 따로 구간 합
함수를 만들 필요 없다.

**update 를 "대입" 으로 착각한다.** `update(i, delta)` 는 **더하기** 다. `a[i]` 를 특정 값 `v` 로
**설정**하려면 `update(i, v − a[i])` 처럼 차이를 넣는다.

**담당 구간을 헷갈린다.** `t[i]` 는 `a[i]` 하나가 아니라 구간 `(i−lowbit(i), i]` 의 합이다.
`t[]` 를 원배열처럼 읽으면 안 된다.

## 스스로 확인하기

1. **만들기 단계**에서 각 `a[i]` 가 여러 `t[]` 칸에 더해지는 것을 보자 — 담당 구간들이다.
2. **query 스텝**에서 `i` 가 `7 → 6 → 4 → 0` 으로, 최하위 비트를 하나씩 지우며 내려가는 것을 보자.
3. **세 개의 t 칸**만 더해 `a[1..7]` 을 덮는 것을 보자 — 겹침 없이.
4. **update 스텝**에서 `i` 가 `3 → 4 → 8` 로 올라가며 세 칸만 고치는 것을 보자.
5. **갱신 뒤 query 가 정확히 delta 만큼** 커지는 것을 마지막에서 확인하자.
6. 각 `t[i]` 위에 마우스를 올려 **담당 구간 툴팁**을 확인하자.

아래 **깊이 보기**에서는 두 루프가 왜 접두사 합을 정확히 덮는지 증명하고, 세그먼트 트리와의 비교,
구간 갱신·2차원 BIT 로의 확장을 다룬다.
