## 한눈에

배열의 **접두사 합 질의**와 **한 점 갱신**을 모두 `O(log n)` 에. `t[i]` 가 구간
`(i − lowbit(i), i]` 의 합을 담당하도록 인덱스의 **최하위 1비트** `lowbit(i) = i & −i` 로 쪼갠다.
세그먼트 트리와 같은 일을 하지만 **코드가 짧고 상수가 작으며 메모리가 `n`** 이다.

- **시간** `update`·`query` 각 `O(log n)` · **공간** `Θ(n)`(배열 하나)
- **1-based 필수** — `lowbit` 트릭이 인덱스 1부터 성립
- 구간 합 `a[l..r] = query(r) − query(l−1)` · `update` 는 **더하기**(설정은 차이를 넣음)
- 역연산이 있는 결합 연산(합·XOR 등)에 적합. min/max 는 일반적으로 안 됨(역원 없음)

**언제 쓰나** — 값이 바뀌는 배열에서 접두사/구간 **합**을 자주 물을 때. 반전 수 세기(inversion count),
좌표 압축 + BIT 로 "왼쪽에 나보다 작은 수", 누적 빈도 등.

**언제 안 쓰나** — 구간 최솟값/최댓값(역원이 없어 BIT 로 일반화가 까다롭다) → [세그먼트 트리](#/algo/segment-tree).
구간 전체 갱신 + 구간 질의가 얽히면 세그먼트 트리(지연 전파)가 더 곧다.

## 동작 원리

핵심 약속: **`t[i]` 는 `a[(i − lowbit(i)) + 1 .. i]` 의 합**. 구간 길이가 곧 `lowbit(i)`.

```
query(i): i > 0 인 동안 sum += t[i]; i -= lowbit(i)   // 구간을 이어 붙이며 내려간다
update(i,d): i ≤ n 인 동안 t[i] += d;  i += lowbit(i) // 담당 구간을 타고 오른다
```

### lowbit — 최하위 1비트

2의 보수에서 `−i = ~i + 1` 이라 `i & −i` 는 가장 아래 켜진 비트만 남긴다.
`lowbit(6)=lowbit(110₂)=2`, `lowbit(12)=lowbit(1100₂)=4`. 이 값이 `t[i]` 담당 구간의 길이다.

### 두 방향

- **query** 는 `i` 에서 최하위 비트를 하나씩 **지우며** `[1..i]` 를 덮는 구간들을 모은다.
- **update** 는 `i` 에서 최하위 비트를 하나씩 **더하며** `a[i]` 를 포함하는 구간들을 방문한다.
같은 트릭의 거울상이고, 각 방향의 반복 횟수는 `i` 의 비트 수 → `O(log n)`.

## 정확성

> **담당 구간 불변식.** 모든 `i` 에 대해 `t[i] = Σ_{j=i-lowbit(i)+1}^{i} a[j]`.

`update(i,d)` 가 이를 유지함을 보이자. `a[k]` 가 `d` 만큼 바뀌면, `t[i]` 는 `k ∈ (i−lowbit(i), i]` 인
정확히 그 `i` 들만 `d` 만큼 바뀌어야 한다. `update` 의 경로 `k, k+lowbit(k), …` 가 바로 그 집합임을
아래에서 보인다.

> **query 정확성.** `query(p)` 가 방문하는 인덱스열 `p = i₀ > i₁ > … > 0` (`i_{t+1}=i_t − lowbit(i_t)`)의
> 담당 구간들은 **서로소이고 합집합이 `[1..p]`** 이다. 따라서 `Σ t[i_t] = Σ_{j=1}^{p} a[j]`.

*증명.* `i_t` 의 담당 구간은 `(i_t − lowbit(i_t), i_t] = (i_{t+1}, i_t]`. 연속한 두 구간이
`(i_{t+1}, i_t]` 와 `(i_{t+2}, i_{t+1}]` 로 경계를 공유하며 이어지고, 마지막이 `(0, i_{last}]` 에서 끝난다.
따라서 이들은 겹치지 않고 `(0, p] = [1..p]` 를 정확히 분할한다. ∎

> **update 완전성.** 인덱스 `k` 를 담당하는 모든 `i`(즉 `k ∈ (i−lowbit(i), i]`)는 정확히
> `k, k+lowbit(k), k+lowbit(k)+lowbit(...), …` 로 열거된다.

*스케치.* `k ∈ (i−lowbit(i), i]` 는 "`i ≥ k` 이고 `i` 에서 `lowbit(i)` 를 빼면 `k` 미만" 이라는 조건이다.
최소 그런 `i` 는 `k` 자신이고, 다음은 `k` 의 최하위 0비트를 채운 `k + lowbit(k)` 임을 비트로 확인할 수 있다.
이를 반복하면 `update` 의 경로와 일치한다. ∎

두 정리로 `query`·`update` 가 담당 구간 불변식을 유지하며 정확한 접두사 합을 준다.

## 복잡도

| 연산 | 시간 | 공간 |
|---|---|---|
| `update` | `O(log n)` | — |
| `query` (접두사) | `O(log n)` | — |
| 만들기 | `O(n log n)` 또는 `O(n)` | `Θ(n)` |

반복 횟수는 `i` 의 이진 표현에서 비트를 하나씩 지우거나 더하는 횟수 ≤ `⌊log₂ n⌋ + 1`.

### `O(n)` 만들기

`update` 를 `n` 번 부르면 `O(n log n)`. 대신 `t[i] += a[i]` 로 채운 뒤,
각 `i` 에 대해 `j = i + lowbit(i) ≤ n` 이면 `t[j] += t[i]` 를 한 번씩 하면 `O(n)` 에 만든다
(부모에게 자식 구간 합을 올려 준다).

### 세그먼트 트리와의 비교

| | 펜윅 트리 | [세그먼트 트리](#/algo/segment-tree) |
|---|---|---|
| 코드 길이 | 매우 짧음 | 김 |
| 메모리 | `n` | `2n~4n` |
| 상수 | 작음 | 큼 |
| 연산 종류 | 합·XOR 등 **역원 있는** 것 | 임의의 결합 연산(min/max/gcd…) |
| 구간 갱신 | 트릭 필요(차분 BIT) | 지연 전파로 자연스럽게 |

"접두사 **합**" 계열이면 펜윅이 거의 항상 낫고, min/max 나 복잡한 구간 갱신은 세그먼트 트리다.

## 구현 노트

**1-based** — `t[0]` 은 쓰지 않는다. `lowbit(0)=0` 이라 0에서 시작하면 루프가 진행/종료를 못 한다.

**구간 합** — `sum(l, r) = query(r) − query(l−1)`. 별도 함수 불필요.

**값 설정** — `set(i, v)`: 현재 값 `cur` 을 알고 있으면 `update(i, v − cur)`. 원배열을 따로 들고 있으면 편하다.

**오버플로** — 합이 커지면 64비트(`long long`). BIT 는 값을 여러 번 더하므로 특히 주의.

**좌표 압축** — 값의 범위가 크면 등장 값만 정렬·압축해 `1..m` 인덱스로 매핑한 뒤 BIT 를 얹는다
(반전 수 세기의 표준 수법).

## 변형과 확장

### 구간 갱신 + 한 점 질의 — 차분 BIT

원배열 대신 **차분** `d[i]=a[i]−a[i−1]` 에 BIT 를 얹으면, 구간 `[l,r]` 에 `+v` 는
`update(l,+v); update(r+1,−v)` 두 번, 한 점 질의는 `query(i)`. `O(log n)`.

### 구간 갱신 + 구간 질의 — BIT 두 개

차분 BIT 두 개(`B1`, `B2`)를 조합하면 구간 갱신 + 구간 합을 모두 `O(log n)` 에 한다.
세그먼트 트리 지연 전파와 같은 능력을 더 가벼운 코드로.

### 2차원 BIT

`t[i][j]` 로 확장하면 2차원 접두사 합·한 점 갱신을 `O(log n · log m)` 에.
동적 2D 부분합(격자 위 점 추가 + 직사각 합)에 쓴다.

### 반전 수 세기 (inversion count)

값을 좌표 압축해 오른쪽에서 왼쪽으로(또는 왼→오) 훑으며 "이미 본 것 중 나보다 작은 수" 를
BIT 접두사 합으로 세면, 배열의 반전 수를 `O(n log n)` 에 — 병합 정렬 대안.
