## 어떤 문제인가

[BFS](#/algo/bfs)는 "몇 정거장인가"를 알려 준다. 하지만 현실은 구간마다 걸리는 시간이 다르다.

```
0 ──4── 1        0 → 1 직행은 4분
 \             0 → 2 → 1 은 1 + 2 = 3분  ← 이쪽이 빠르다!
  1─ 2 ──2── 1
```

간선마다 **비용(가중치)** 이 있을 때, 시작점에서 각 정점까지 **가장 싼 길**을 찾고 싶다.

BFS 를 그대로 쓸 수는 없다. BFS 는 "간선 개수"를 최소화하지 "비용 합"을 최소화하지 않는다.
위 그림에서 BFS 는 간선 1개짜리 직행(4분)을 최단이라 답한다.

## 손으로 해보기

기본 그래프를 보자. 0번에서 출발한다.

```
        4
   0 ─────── 1 ──1── 3
   |         |        |
   1         2        3
   |         |        |
   2 ────────┘        |
   └───3──── 4 ──1──── 5
```

간선: `0-1(4)`, `0-2(1)`, `1-3(1)`, `2-1(2)`, `2-4(3)`, `3-5(3)`, `4-5(1)`

각 정점에 **"지금까지 알아낸 가장 싼 값"** 을 적어 둔다. 아직 모르면 `∞`.

```
시작:  0:0   1:∞   2:∞   3:∞   4:∞   5:∞
```

### 규칙

> **아직 확정 안 된 것 중 값이 가장 작은 정점**을 고른다. 그 값은 이제 확정이다.
> 그 정점의 이웃들을 "나를 거쳐 가면 더 싸지나?" 하고 갱신한다.

이 갱신을 **완화(relaxation)** 라고 부른다.

### 따라가 보기

```
① 가장 작은 것: 0 (값 0) → 확정
   0→1: 0+4=4 < ∞ → 1을 4로
   0→2: 0+1=1 < ∞ → 2를 1로
   상태:  0:[0]  1:4  2:1  3:∞  4:∞  5:∞

② 가장 작은 것: 2 (값 1) → 확정
   2→1: 1+2=3 < 4  → 1을 3으로 줄인다!  ★
   2→4: 1+3=4 < ∞  → 4를 4로
   상태:  0:[0]  1:3  2:[1]  3:∞  4:4  5:∞

③ 가장 작은 것: 1 (값 3) → 확정
   1→3: 3+1=4 < ∞ → 3을 4로
   상태:  0:[0]  1:[3]  2:[1]  3:4  4:4  5:∞

④ 가장 작은 것: 3 (값 4) → 확정
   3→5: 4+3=7 < ∞ → 5를 7로
   상태:  ... 3:[4]  4:4  5:7

⑤ 가장 작은 것: 4 (값 4) → 확정
   4→5: 4+1=5 < 7 → 5를 5로 줄인다!  ★
   상태:  ... 4:[4]  5:5

⑥ 가장 작은 것: 5 (값 5) → 확정. 끝.

최종:  0:0  1:3  2:1  3:4  4:4  5:5
```

②에서 `1` 의 값이 4에서 3으로 **줄어든 것**을 보자. 처음 알아낸 값이 최선이 아니었다.
이래서 "일단 알아낸 값"과 "확정된 값"을 구분해야 한다.

## 아이디어 쌓기

### 1단계 — 왜 "가장 작은 것"이 확정인가

이게 이 알고리즘의 심장이다.

지금 확정 안 된 것 중 값이 가장 작은 정점을 `u`, 그 값을 `d` 라 하자.
`u` 로 가는 더 싼 길이 있다면, 그 길은 아직 확정 안 된 다른 정점 `y` 를 반드시 지나야 한다.
그런데 `y` 의 값은 `d` 이상이다(`u` 가 최소였으니까). 그리고 `y` 에서 `u` 까지 가는 데
**추가 비용이 붙는다.**

```
더 싼 길의 비용 = (y까지 비용) + (y→u 비용) ≥ d + 0 = d
```

즉 더 싸질 수가 없다. **단, 마지막 줄에서 "추가 비용 ≥ 0"을 썼다.**

### 2단계 — 그래서 음수 간선이 있으면 안 된다

간선 비용이 음수면 "돌아가면 오히려 싸지는" 일이 생겨 위 논리가 무너진다.
음수 간선이 있으면 [벨만-포드](#/algo/bellman-ford)를 써야 한다.

### 3단계 — "가장 작은 것"을 빨리 찾기

매번 전부 훑어 최솟값을 찾으면 O(V) 다. 정점이 많으면 느리다.
**우선순위 큐(최소 힙)** 를 쓰면 `O(log V)` 에 꺼낼 수 있다.

### 4단계 — 값이 줄면 어떻게 하나

②에서 `1` 의 값이 4→3 으로 줄었다. 우선순위 큐 안의 값을 고치는 건 번거롭다.
그래서 실전에서는 **그냥 새 항목을 하나 더 넣는다.**

그러면 큐에 `(4,1)` 과 `(3,1)` 이 둘 다 있게 된다. `(3,1)` 이 먼저 나오고,
나중에 `(4,1)` 이 나올 때는 이렇게 걸러 낸다.

```cpp
if (d > dist[u]) continue;   // 이미 더 좋은 값으로 확정됨 → 이건 낡은 항목
```

시각화에서 이 "낡은 항목 버리기"가 실제로 일어난다 — 스텝을 넘기며 찾아보자.

## 코드로 옮기기

```cpp
void dijkstra(vector<vector<pair<int,int>>>& adj, int s) {
    vector<int> dist(adj.size(), INF);       // ← 아직 모르는 값은 ∞
    priority_queue<pair<int,int>, vector<pair<int,int>>,
                   greater<>> pq;            // ← 3단계: (거리, 정점) 최소 힙
    dist[s] = 0;
    pq.push({0, s});
    while (!pq.empty()) {
        auto [d, u] = pq.top(); pq.pop();    // ← 1단계: 가장 작은 것을 꺼낸다
        if (d > dist[u]) continue;           // ← 4단계: 낡은 항목은 버린다
        for (auto [v, w] : adj[u]) {
            if (dist[u] + w < dist[v]) {     // ← 완화: 나를 거치면 싸지나?
                dist[v] = dist[u] + w;
                pq.push({dist[v], v});       // ← 4단계: 고치지 말고 새로 넣는다
            }
        }
    }
}
```

| 줄 | 손으로 한 것 |
|---|---|
| `dist(n, INF)` | 아직 모르는 값은 ∞ |
| `pq.top()` | "가장 작은 것"을 고르기 |
| `if (d > dist[u]) continue` | 낡은 항목 걸러 내기 |
| `dist[u] + w < dist[v]` | "나를 거치면 더 싸지나?" |

`greater<>` 는 최소 힙을 만든다. C++ 의 `priority_queue` 는 기본이 **최대** 힙이라
이걸 빼먹으면 가장 먼 것부터 꺼내게 된다.

## 자주 하는 실수

**`greater<>` 를 빼먹는다.** 최대 힙이 되어 완전히 엉뚱한 답이 나온다.

**낡은 항목을 안 거른다.** `if (d > dist[u]) continue;` 가 없으면 같은 정점을
여러 번 처리해 느려진다(답은 맞는 경우가 많아 더 찾기 어렵다).

**`INF` 를 `INT_MAX` 로 둔다.** `dist[u] + w` 에서 오버플로가 난다.
`0x3f3f3f3f`(약 10억)처럼 **두 배 해도 int 범위 안인 값**을 쓰자.

**음수 간선에 쓴다.** 1단계 증명이 깨진다. [벨만-포드](#/algo/bellman-ford)로 가야 한다.

**BFS 로 충분한데 다익스트라를 쓴다.** 모든 간선의 비용이 같다면 [BFS](#/algo/bfs)가 더 빠르고 간단하다.

## 스스로 확인하기

1. **`PQ` 표시를 계속 보자.** 항상 가장 작은 값이 앞에 있다.
2. **정점 아래 숫자(거리)가 줄어드는 순간**을 찾아보자. 기본 그래프에서 정점 1이
   4 → 3 으로, 정점 5가 7 → 5 로 줄어든다.
3. **"낡은 항목"이라는 설명이 나오는 스텝**을 찾아보자. 4단계에서 설명한 그 상황이다.
4. 편집기에서 **⚖ 가중치 모드**로 간선을 클릭해 값을 바꿔 보자.
   `0-2` 를 9로 올리면 최단 경로가 어떻게 달라지는가?
5. 초록으로 남는 간선들이 **최단 경로 트리**다. 시작점에서 각 정점까지 실제로 가는 길이다.

아래 **깊이 보기**에서는 1단계의 논증을 엄밀하게 증명하고,
음수 간선이 왜 정확히 그 한 줄을 깨뜨리는지 반례로 확인한다.
