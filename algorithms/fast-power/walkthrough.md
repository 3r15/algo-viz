## 어떤 문제인가

`3^13` 을 계산하고 싶다. 그런데 결과가 커서 `997` 로 나눈 나머지만 필요하다고 하자
(암호에서 늘 이런 형태다).

가장 단순한 방법은 **13번 곱하는 것**이다.

```
3 → 9 → 27 → 81 → 243 → 729 → …   (13번)
```

`13` 이면 괜찮다. 그런데 지수가 `10억` 이면 10억 번이다. RSA 에서는 지수가 **2048비트**,
즉 `2^2048` 쯤 되는 수다. 우주가 끝날 때까지도 안 끝난다.

> 곱셈 횟수를 **지수의 자릿수**에 비례하게 줄일 수 없을까?

## 손으로 해보기

기본 입력 `3 13 997` — `3^13 mod 997` 이다.

### 지수를 2진수로 쪼갠다

```
13 = 8 + 4 + 1 = 1101₂
```

지수의 덧셈은 거듭제곱의 곱셈이 된다.

```
3^13 = 3^(8+4+1) = 3^8 · 3^4 · 3^1
```

**세 개만 곱하면 된다.** 문제는 `3^8` 과 `3^4` 를 어떻게 싸게 얻느냐다.

### 제곱해 올린다

```
3^1 = 3
3^2 = (3^1)²  = 3² = 9
3^4 = (3^2)²  = 9² = 81
3^8 = (3^4)²  = 81²
```

**제곱 한 번에 지수가 두 배**가 된다. 그래서 `3^1 → 3^2 → 3^4 → 3^8` 이 제곱 3번이다.
`3^(2^k)` 를 다 만드는 데 `⌊log₂ n⌋` 번이면 충분하다.

> [희소 배열](#/algo/sparse-table)과 [이진 상승](#/algo/binary-lifting)의 **배가(doubling)** 와
> 완전히 같은 발상이다. 대상이 구간·조상이 아니라 지수라는 점만 다르다.

### 표를 채워 가며

`997` 로 나눈 나머지를 매번 취한다(수가 커지지 않게).

`13` 의 비트를 **낮은 자리부터** 본다: `1, 0, 1, 1`

**k = 0 (2⁰ = 1 자리)** — 비트가 `1`

```
result = 1 × 3 = 3            (3^1 을 곱했다)
다음을 위해 제곱:  3² = 9      → 이것이 3^2
```

**k = 1 (2¹ = 2 자리)** — 비트가 `0`

```
result 는 3 그대로              (3^2 는 쓰지 않는다)
제곱:  9² = 81                 → 이것이 3^4
```

**k = 2 (2² = 4 자리)** — 비트가 `1`

```
result = 3 × 81 = 243          (3^1 · 3^4 = 3^5)
제곱:  81² = 6561 = 997×6 + 579  →  579   ← 이것이 3^8 mod 997
```

**k = 3 (2³ = 8 자리)** — 비트가 `1`

```
result = 243 × 579 = 140697 = 997×141 + 120  →  120
                                (3^5 · 3^8 = 3^13)
지수의 비트가 끝났으므로 제곱은 하지 않는다
```

### 답

**`3^13 mod 997 = 120`**

검산: `3^13 = 1594323`. `1594323 = 997 × 1599 + 120`. ✓

곱셈은 **6번**이다 — 곱하기 3번(비트가 1인 자리) + 제곱 3번. `13` 번 곱하는 방법의 절반 이하다.
지수가 커지면 격차가 폭발한다.

### 얼마나 줄어드나

```
지수 n        순진한 방법     빠른 거듭제곱
13            12번           6번
1000          999번          약 15번
10^9          10억 번        약 44번
2^2048        불가능         약 4000번
```

**지수가 1000배 커져도 곱셈은 10번 늘 뿐이다.** 이것이 RSA·디피–헬만이 실제로 동작하는 이유다.

### 왜 `mod` 를 매번 취하나

`3^13 = 1594323` 은 작지만 `3^100` 은 51자리다. `mod` 를 마지막에 한 번만 취하면
중간값이 폭발해 `long long` 도 넘친다.

**나머지는 곱셈과 잘 어울린다.**

```
(a × b) mod m = ((a mod m) × (b mod m)) mod m
```

그래서 매 곱셈마다 줄여도 답이 같다. 중간값이 `m²` 을 넘지 않으므로 `m ≤ 10⁹` 까지
`long long` 으로 안전하다.

## 아이디어 쌓기

### 1단계 — 지수를 쪼갠다

모든 자연수는 2의 거듭제곱의 합으로 **유일하게** 쓰인다(= 2진수 표현).
`n` 을 쪼개면 `a^n` 이 `a^(2^k)` 들의 곱이 된다.

### 2단계 — 필요한 재료를 배가로 만든다

`a^(2^k)` 는 `a^(2^(k-1))` 을 **제곱**하면 나온다. 새 재료가 필요 없다.
`⌊log₂ n⌋` 번의 제곱으로 전부 만든다.

### 3단계 — 비트가 1인 것만 곱한다

`n` 의 `k` 번째 비트가 `1` 인지 보는 것은 `n & 1` 과 `n >>= 1` 로 한 자리씩 확인하면 된다.
비트가 `1` 인 개수만큼만 곱셈이 추가된다.

### 4단계 — 두 일을 한 루프에서

제곱해 올리기와 곱하기를 따로 하지 않는다. `k` 를 올리며 **동시에** 처리한다.

```
while (n > 0):
    if (n 의 마지막 비트가 1)  result *= a
    a *= a                     ← 다음 자리 준비
    n >>= 1                    ← 다음 자리로
```

`n` 을 오른쪽으로 밀면 "마지막 비트" 가 곧 `k` 번째 비트가 된다. 변수 하나가 줄어든다.

### 5단계 — 나머지는 매 곱셈마다

`(a×b) mod m = ((a mod m)(b mod m)) mod m` 이므로 중간에 줄여도 안전하다.
줄이지 않으면 오버플로한다.

## 코드로 옮기기

```cpp
long long power(long long a, long long n, long long m) {
    long long result = 1;
    a %= m;                                   // ← 5단계: 미리 줄여 둔다
    while (n > 0) {                           // ← 4단계: 한 루프에서
        if (n & 1) result = result * a % m;    // ← 3단계: 비트가 1이면 곱한다
        a = a * a % m;                        // ← 2단계: 제곱해 올린다
        n >>= 1;                              // ← 1단계: 다음 자리로
    }
    return result;
}
```

**아홉 줄이다.** `result` 를 `1` 로 시작하는 것이 `a^0 = 1` 을 담고, 그래서 `n = 0` 도 자동으로 맞는다.

재귀로도 같은 일을 한다.

```cpp
long long power(long long a, long long n, long long m) {
    if (n == 0) return 1;
    long long half = power(a, n / 2, m);
    long long sq = half * half % m;
    return (n % 2) ? sq * a % m : sq;
}
```

`a^n = (a^(n/2))²` (`n` 짝수) 또는 `(a^(n/2))² · a` (`n` 홀수). **분할 정복**의 모양이 더 뚜렷하다.
다만 `power(a, n/2)` 를 **한 번만** 호출해 변수에 담아야 한다 — 두 번 쓰면 `O(n)` 으로 되돌아간다.

## 자주 하는 실수

**`power(a, n/2) * power(a, n/2)` 로 쓴다.** 같은 값을 두 번 계산해 재귀가 두 갈래로 갈라진다.
호출 횟수가 `2^log n = n` 이 되어 **순진한 방법과 같아진다.** 반드시 변수에 담아 재사용한다.

**오버플로.** `result * a` 가 `m²` 까지 커진다. `m ≤ 10⁹` 이면 `m² ≈ 10¹⁸` 로 `long long`
(약 `9.2 × 10¹⁸`)에 겨우 들어간다. `m` 이 더 크면 `__int128` 이나 몽고메리 곱셈이 필요하다.

**`int` 로 쓴다.** `m` 이 `10⁵` 만 되어도 `m² = 10¹⁰` 이 `int` 를 넘긴다.

**`m = 1` 을 놓친다.** 답은 항상 `0` 인데 `result = 1` 로 시작하므로 `a %= m` 과
`result` 초기화를 조심해야 한다. `power(a, 0, 1)` 이 `1` 을 반환하면 틀리다.

**지수가 음수.** 정수 거듭제곱에는 정의되지 않는다. 모듈러에서는 `a^(-1)` 이 **모듈러 역원**이고,
[유클리드 호제법](#/algo/euclidean-gcd)의 확장판이나 `a^(m-2) mod m`(`m` 이 소수일 때)으로 구한다.

**`n & 1` 대신 `n % 2` 를 쓴다.** 동작은 같지만 음수 `n` 에서 갈린다. 어차피 음수는 배제해야 한다.

## 스스로 확인하기

1. **`n 의 비트` 열**을 보자. 위에서 아래로 `1, 0, 1, 1` — `13 = 1101₂` 을 **거꾸로** 읽은 것이다.
   낮은 자리부터 처리하기 때문이다.
2. **`a^(2^k)` 열**을 보자. `3 → 9 → 81 → 579` 로 매번 **제곱**된다.
   `579` 는 `81² = 6561` 을 `997` 로 나눈 나머지다.
3. **비트가 0 인 스텝**(k = 1)을 찾아보자. `result` 가 그대로다. 제곱은 그래도 한다 —
   다음 자리를 위해 재료를 준비해야 하기 때문이다.
4. **마지막 스텝**의 "곱셈 6번" 을 확인하자. 비트가 1인 자리 3개 + 제곱 3번이다.
5. 입력을 `2 64 997` 로 바꿔 보자. `64 = 1000000₂` 이라 **비트가 1인 자리가 하나뿐**이다.
   곱하기는 1번, 나머지는 전부 제곱이다.
6. 입력을 `2 63 997` 로 바꿔 보자. `63 = 111111₂` — **모든 비트가 1** 이라 최악이다.
   그래도 곱셈이 11번뿐이다.
7. 입력을 `3 13 0` 으로 바꿔 보자(`m` 을 `0` 으로). 나머지 없이 계산해서
   `3^13 = 1594323` 을 그대로 보여 준다.
8. 입력을 `7 0 13` 으로 바꿔 보자. 지수가 `0` 이라 답이 `1` 이고 스텝이 하나다.

아래 **깊이 보기**에서는 이진 표현으로부터 정확성을 귀납으로 증명하고,
곱셈 횟수의 정확한 값과 하한, 그리고 행렬 거듭제곱으로 피보나치를 `O(log n)` 에 구하는
확장을 다룬다.
