## 한눈에

지수를 2진수로 쪼개고 밑을 제곱해 올려, `a^n` 을 `n` 번이 아니라 `Θ(log n)` 번의 곱셈으로 구한다.

- **시간** `Θ(log n)` 곱셈 — 정확히는 `⌊log₂ n⌋ + (n 의 1비트 개수) − 1` 번
- **공간** `O(1)` (반복문) / `O(log n)` (재귀 스택)
- **모노이드면 무엇이든** 된다 — 정수·행렬·다항식·순열·문자열 연결. 결합법칙만 필요하다
- 이것 없이는 RSA·디피–헬만·타원곡선 암호가 성립하지 않는다

**언제 쓰나** — 모듈러 거듭제곱(암호, 페르마 소정리로 역원 구하기, 밀러–라빈 소수 판정),
**행렬 거듭제곱**으로 선형 점화식을 `O(log n)` 에 계산(피보나치, DP 가속),
그래프의 `k`-경로 개수(인접행렬의 `k` 제곱).

**언제 안 쓰나** — `n` 이 아주 작으면(≤ 4 정도) 그냥 곱하는 편이 분기 없이 빠르다.
실수 거듭제곱은 `std::pow` 가 로그·지수 함수로 처리한다(정수 알고리즘이 아니다).
**최소 곱셈 횟수**가 목적이면 이 방법이 최적이 아니다(아래 참고).

## 동작 원리

두 사실을 결합한다.

**① 지수는 2의 거듭제곱 합으로 유일하게 쪼개진다** (= 2진수 표현).

```
13 = 8 + 4 + 1 = 1101₂      →   a^13 = a^8 · a^4 · a^1
```

**② 그 재료는 제곱만으로 만들어진다.**

```
a^1 → a^2 → a^4 → a^8 → …        제곱 한 번에 지수가 두 배
```

`⌊log₂ n⌋` 번의 제곱으로 `a^(2^k)` 를 전부 얻고, 비트가 `1` 인 자리의 것만 곱한다.
[희소 배열](#/algo/sparse-table)·[이진 상승](#/algo/binary-lifting)의 **배가(doubling)** 와
같은 발상이며, 대상이 구간·조상 대신 지수라는 점만 다르다.

```
result = 1
while n > 0:
    if n & 1:  result *= a       // 이 자리의 재료를 쓴다
    a *= a                       // 다음 자리 재료를 만든다
    n >>= 1
```

`n` 을 오른쪽으로 밀면 "마지막 비트" 가 곧 `k` 번째 비트라, 카운터 하나가 필요 없다.

### 실행 예 — `3^13 mod 997`

```
k   n 의 비트   a^(2^k)              result
0      1        3                    1×3   = 3
1      0        3²=9                 3     (건너뜀)
2      1        9²=81                3×81  = 243
3      1        81²=6561 → 579       243×579 = 140697 → 120
```

`3^13 = 1594323 = 997 × 1599 + 120` ✓
곱셈 6번(곱하기 3 + 제곱 3)이다. 순진한 방법은 12번이다.

### 나머지를 매번 취해도 되는 이유

`ℤ/mℤ` 에서 곱셈이 잘 정의되므로

```
(a × b) mod m = ((a mod m) × (b mod m)) mod m
```

중간에 줄여도 최종 결과가 같다. 줄이지 않으면 `a^n` 이 지수적으로 커져 어떤 정수형도 못 담는다.
**모듈러가 없으면 이 알고리즘의 실용성이 사라진다** — 곱셈 횟수는 `log n` 이어도
숫자 자체가 `n · log a` 비트로 커지기 때문이다.

## 정확성

> **불변식.** 루프 반복 시작 시점에, 원래 구하려는 값이 `result × a^n` 이다.
> (여기서 `result`, `a`, `n` 은 현재 변수 값이고, 모듈러가 있으면 모두 `mod m` 에서 본다.)

`a₀`, `n₀` 를 초기 입력이라 하자. 목표는 `a₀^{n₀}` 다.

**기저** — 첫 반복 전 `result = 1`, `a = a₀`, `n = n₀` 이므로
`result × a^n = 1 × a₀^{n₀} = a₀^{n₀}`. ✓

**유지** — 한 번의 반복이 `(result, a, n)` 을 `(result', a', n')` 으로 보낸다.
`n` 의 홀짝으로 나눈다.

*`n` 이 짝수* — `result' = result`, `a' = a²`, `n' = n/2`. 그러면

```
result' × a'^{n'} = result × (a²)^{n/2} = result × a^n     ✓
```

*`n` 이 홀수* — `result' = result × a`, `a' = a²`, `n' = (n−1)/2`. 그러면

```
result' × a'^{n'} = (result × a) × (a²)^{(n−1)/2}
                  = result × a × a^{n−1}
                  = result × a^n                            ✓
```

두 경우 모두 불변식이 보존된다. 여기서 `n >>= 1` 이 정수 나눗셈 `⌊n/2⌋` 와 같고,
`n` 이 홀수일 때 `⌊n/2⌋ = (n−1)/2` 임을 썼다.

**종료 시** — `n = 0` 이므로 `result × a^0 = result` 다. 불변식에 의해 이 값이 `a₀^{n₀}` 다. ∎

**종료성** — `n` 은 음이 아닌 정수이고 매 반복 `⌊n/2⌋` 로 엄격히 감소한다(`n ≥ 1` 일 때).
따라서 `⌊log₂ n₀⌋ + 1` 번 안에 `0` 이 된다.

**`n = 0` 인 경우** — 루프에 들어가지 않고 `result = 1` 을 반환한다.
`a^0 = 1` 이므로 옳다(`0^0` 은 관례적으로 1로 둔다).

### 왜 결합법칙만 있으면 되나

증명에서 쓴 것은 `a^{i+j} = a^i · a^j` 와 `(a^i)^j = a^{ij}` 뿐이고, 이들은
연산이 **결합적**이기만 하면 성립한다. 교환법칙도, 역원도, 심지어 항등원도
(`result` 를 첫 `1`비트에서 초기화하면) 필요 없다.

따라서 **모노이드 위의 거듭제곱**에 그대로 적용된다 — 행렬, 다항식 곱, 순열 합성,
`min`-`plus` 대수(최단경로), 문자열 연결까지.

## 복잡도

| | 곱셈 횟수 | 공간 |
|---|---|---|
| 최선 | `⌊log₂ n⌋` (`n` 이 2의 거듭제곱) | `O(1)` |
| 평균 | `≈ 1.5 log₂ n` | `O(1)` |
| 최악 | `2 log₂ n` (`n` 이 전부 1비트) | `O(1)` |

### 정확한 횟수

루프는 `⌊log₂ n⌋ + 1` 번 돈다. 각 반복에서

- 비트가 `1` 이면 곱하기 1번
- 마지막 반복을 제외하고 제곱 1번

`s(n)` 을 `n` 의 1비트 개수라 하면

```
곱셈 = s(n) + ⌊log₂ n⌋            (마지막 제곱을 생략하면 −1)
```

```
n = 64  = 1000000₂   s=1, ⌊log₂⌋=6  →  1 + 6 = 7번
n = 63  = 111111₂    s=6, ⌊log₂⌋=5  →  6 + 5 = 11번
n = 13  = 1101₂      s=3, ⌊log₂⌋=3  →  3 + 3 = 6번
```

이 페이지의 마지막 스텝이 세는 값이 정확히 이것이다.
**최악(`2^k − 1` 꼴)이 최선(`2^k` 꼴)의 약 2배**인데, 둘 다 `Θ(log n)` 이다.

### 비트 연산으로 세면

곱셈 자체가 공짜가 아니다. `m` 이 `b` 비트면 곱셈 한 번이 `O(b²)`(단순) 또는
`O(b log b)`(FFT 계열)다. 따라서 모듈러 거듭제곱 전체는

```
O(log n · b²)      단순 곱셈,  b = log m
```

RSA-2048 에서 `b = 2048`, `log n ≈ 2048` 이므로 약 `2048 × 2048² ≈ 8.6 × 10⁹` 비트 연산 —
현대 CPU 로 수 밀리초다. **이 다항 시간이 암호를 실용적으로 만든다.**
반대로 인수분해는 이만큼 싼 방법이 알려지지 않았고, 그 비대칭이 RSA 의 안전성이다.

### 이것이 최적인가 — 아니다

**최소 곱셈 횟수**를 묻는 문제(가법 사슬, addition chain)에서는 이 방법이 최적이 아니다.

```
n = 15:  이진법  → 1111₂,  s=4, ⌊log₂⌋=3  →  6번
         최적    → a²  a³ = a²·a,  a⁶ = (a³)²,  a¹² = (a⁶)²,  a¹⁵ = a¹²·a³  →  5번
```

최소 가법 사슬을 구하는 것은 일반적으로 어려운 문제다(NP-난해로 알려져 있다).
실전에서는 **`k`-ary 방법**이나 **슬라이딩 윈도우**로 상수를 줄인다 — 비트를 `k` 개씩 묶어
`a^1 .. a^(2^k −1)` 를 미리 표로 만들면 곱하기 횟수가 `log n / k` 로 줄어든다.
암호 라이브러리는 대부분 이 형태를 쓴다.

## 구현 노트

**오버플로가 첫 번째 함정.** `result * a` 가 최대 `(m−1)²` 이다.

```
m ≤ 10⁹        →  m² ≈ 10¹⁸  <  9.2×10¹⁸ (long long)  ✓
m ≤ 4.3×10⁹    →  __int128 필요
```

`__int128` 을 쓰거나, `m` 이 크면 **몽고메리 곱셈**·**Barrett 축약**으로 나눗셈을 없앤다.

**`m = 1` 을 조심.** 답은 항상 `0` 인데 `result = 1` 로 시작하므로 `n = 0` 에서 `1` 을 반환한다.
`a %= m` 을 먼저 하고 `m == 1` 이면 `0` 을 반환하는 분기를 두는 편이 안전하다.

**음수 지수** — 정수 거듭제곱에는 정의되지 않는다. 모듈러에서는 역원이며,
`m` 이 소수이고 `a ≢ 0` 이면 페르마 소정리로

```cpp
inverse = power(a, m - 2, m);      // a^(m−1) ≡ 1 이므로 a^(m−2) ≡ a^(−1)
```

`m` 이 소수가 아니면 [확장 유클리드 호제법](#/algo/euclidean-gcd)을 써야 한다
(`gcd(a, m) = 1` 이기만 하면 된다).

**재귀 버전의 함정** — `power(a, n/2)` 를 **반드시 변수에 담아** 한 번만 호출한다.
두 번 쓰면 호출 트리가 갈라져 `O(n)` 으로 되돌아간다.

**`n & 1` vs `n % 2`** — 음수 `n` 에서 갈린다. 애초에 `n ≥ 0` 을 보장하자.

**타이밍 공격** — 비트가 `1` 인지에 따라 실행 시간이 달라지므로, 실행 시간을 측정하면
비밀 지수를 유추할 수 있다. 암호 구현은 **몬고메리 사다리**처럼 비트값과 무관하게
같은 연산을 하는 형태를 쓴다. 이 페이지의 코드는 교육용이므로 그런 방어가 없다.

## 변형과 확장

### 행렬 거듭제곱 — 선형 점화식을 `O(log n)` 에

`F(n) = F(n−1) + F(n−2)` 를 행렬로 쓰면

```
[F(n+1)]   [1 1]^n   [F(1)]
[F(n)  ] = [1 0]   · [F(0)]
```

`2×2` 행렬의 `n` 제곱을 빠른 거듭제곱으로 구하면 **피보나치 `n`번째 항을 `O(log n)` 에** 얻는다
(모듈러 안에서). 일반적으로 `k`항 선형 점화식은 `k×k` 행렬로 `O(k³ log n)` 이다.

이 기법은 DP 가속에도 쓴다 — 상태 전이가 선형이면 전이 행렬의 거듭제곱으로 `n` 단계를 뛴다.

### 그래프의 `k`-경로 개수

인접행렬 `A` 의 `k` 제곱에서 `(A^k)[u][v]` 가 `u → v` 의 길이 `k` 경로 개수다.
`min`-`plus` 대수로 바꾸면 **정확히 `k` 개 간선을 쓰는 최단경로**가 되고,
[플로이드-워셜](#/algo/floyd-warshall)과 이어진다.

### 밀러–라빈 소수 판정

`a^(n−1) mod n` 을 여러 밑 `a` 에 대해 계산해 페르마 소정리를 검사한다.
빠른 거듭제곱 없이는 성립하지 않는 알고리즘이며, `n < 3.3 × 10²⁴` 까지는
정해진 밑들로 **결정적**이다.

### 빠른 곱셈 (mulmod)

`m` 이 `long long` 범위를 꽉 채우면 `a * b % m` 자체가 넘친다. 그럴 때는
곱셈에도 같은 발상을 적용한다 — `b` 를 2진 분해해 **덧셈으로** 곱한다(`O(log b)`).
또는 `__int128`, 또는 부동소수 트릭을 쓴다.

### `k`-ary / 슬라이딩 윈도우

비트를 `k` 개씩 묶어 `a^1 .. a^(2^k − 1)` 를 미리 만들면 곱하기가 `log n / k` 번으로 준다.
`k = 4` 정도가 실전에서 흔하다. 전처리 비용과 곱하기 절약의 균형점이다.
