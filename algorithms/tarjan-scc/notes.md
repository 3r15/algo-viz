## 한눈에

방향 그래프에서 **서로 오갈 수 있는** 정점들의 최대 묶음이 **강한 연결 요소(SCC)** 다.
`u → v` 경로도 있고 `v → u` 경로도 있으면 둘은 같은 SCC 에 속한다.

타잔은 이걸 **DFS 한 번**으로 전부 찾아낸다. 정점마다 두 숫자만 들고 다니면 된다.

```
tin[u]   u 를 처음 방문한 시각
low[u]   u 의 서브트리에서 "아직 스택에 있는" 정점까지 갈 수 있는 최소 tin
```

`low[u] == tin[u]` 이면 `u` 가 자기 SCC 의 뿌리이고, 스택에서 `u` 까지 뽑아내면 한 덩이다.

- 시간 O(V+E) · 공간 O(V) · DFS 한 번
- 코사라주(DFS 두 번)보다 빠르고, SCC 를 **위상 역순**으로 내놓는 보너스가 있다

## 동작 원리

```
dfs(u):
    tin[u] = low[u] = timer++
    스택에 u 를 넣는다
    for v in adj[u]:
        v 를 처음 봄       → dfs(v) 후  low[u] = min(low[u], low[v])
        v 가 스택 위에 있음 → low[u] = min(low[u], tin[v])
        v 가 이미 확정됨    → 무시
    low[u] == tin[u] 이면 → 스택에서 u 까지 뽑아 SCC 하나 확정
```

시각화의 정점 라벨이 `tin/low` 이고, SCC 가 확정되면 `C0`, `C1` 로 바뀐다.
`low` 가 내려가는 순간이 "위로 돌아가는 길을 찾았다"는 뜻이다.

### 세 가지 간선을 구분하는 이유

- **트리 간선**(처음 보는 정점): 내려갔다 돌아와서 `low[v]` 를 받아 온다.
  자손이 더 위로 갈 수 있으면 나도 갈 수 있다.
- **스택 위 정점으로 가는 간선**: 지금 탐색 중인 조상이거나 같은 SCC 후보다.
  `low[v]` 가 아니라 **`tin[v]`** 를 쓴다(아래 참고).
- **이미 확정된 SCC 로 가는 간선**: 그 SCC 는 이미 닫혔고 되돌아올 수 없다. **무시해야 한다.**
  이걸 무시하지 않으면 서로 다른 SCC 가 하나로 합쳐져 버린다.

> **왜 `low[v]` 가 아니라 `tin[v]` 인가?** 스택 위 정점으로 가는 간선에서 `low[v]` 를 쓰면
> `v` 의 다른 가지가 알아낸 정보까지 끌어오게 되어, `u` 가 실제로는 갈 수 없는 곳까지
> 갈 수 있다고 착각한다. 그래도 SCC 자체는 맞게 나오는 경우가 많아 버그를 알아채기 어렵다.
> 안전한 정의를 지키려면 `tin[v]` 를 쓴다.

## 정확성

### SCC 는 정점 집합을 분할한다

"서로 오갈 수 있다"는 관계는 **동치 관계**다. 반사적(자기 자신), 대칭적(정의상),
추이적(경로를 이어 붙이면 됨). 따라서 정점 집합이 SCC 들로 깔끔하게 나뉜다.

### DFS 트리 안에서 SCC 는 이어져 있다

> **주장**: 한 SCC 의 정점들은 DFS 트리에서 **하나의 부분 트리 안에 모여** 있고,
> 그중 `tin` 이 가장 작은 정점(= 가장 먼저 방문된 정점)이 나머지 전부의 조상이다.

같은 SCC 의 두 정점 `u`, `v` 를 보자. `u` 가 먼저 방문됐다고 하면, `u → v` 경로가 있고
그 경로 위 정점들도 전부 같은 SCC 다. `dfs(u)` 를 시작하는 시점에 그 경로가 모두 미방문이므로
**흰 경로 정리**([DFS 문서](#/algo/dfs) 참고)에 의해 `v` 는 `u` 의 자손이 된다. ∎

이 가장 이른 정점을 SCC 의 **뿌리**라 부른다.

### `low[u] == tin[u]` ⟺ `u` 가 뿌리다

**(⇐)** `u` 가 뿌리라고 하자. `low[u] < tin[u]` 라면 `u` 의 서브트리에서 `tin` 이 더 작은
스택 위 정점 `w` 로 가는 길이 있다는 뜻이다. `w` 는 스택에 있으므로 아직 SCC 가 확정되지 않았고,
`w` 는 `u` 보다 먼저 방문됐으니 `u` 의 조상이다. 그러면 `u ⇝ w` 도 있고 `w ⇝ u`(트리 경로)도 있으니
둘은 같은 SCC 인데, `tin[w] < tin[u]` 라 `u` 가 뿌리가 아니게 된다 — 모순.

**(⇒)** `low[u] == tin[u]` 인데 `u` 가 뿌리가 아니라고 하자. 그러면 같은 SCC 의 뿌리 `r` 이
`u` 의 진짜 조상이고, `u ⇝ r` 경로가 존재한다. 그 경로의 마지막 간선은 스택 위 정점으로 가는
간선이므로 `low[u] ≤ tin[r] < tin[u]` 가 되어 모순이다. ∎

### 뽑아내는 구간이 정확히 하나의 SCC 다

`u` 가 뿌리로 판정되는 시점에, 스택에서 `u` 위에 쌓인 정점들은 모두 `u` 의 서브트리에서
아직 확정되지 않은 정점들이다. 위 주장에 의해 그것들은 전부 `u` 와 같은 SCC 이고,
다른 SCC 에 속한 정점들은 자기 뿌리에서 이미 뽑혀 나갔다. ∎

### 확정 순서 = 축약 그래프의 위상 역순

SCC 들을 하나의 정점으로 축약한 그래프(**축약 그래프**, condensation)는 항상 DAG 다.
타잔이 SCC 를 확정하는 순서는 이 DAG 의 **위상 역순**이다.
그래서 [위상 정렬](#/algo/topological-sort)을 따로 돌릴 필요 없이 그대로 쓸 수 있다 —
2-SAT 이 타잔으로 풀리는 이유다.

## 복잡도

| | |
|---|---|
| 시간 | **O(V + E)** — DFS 한 번, 각 간선을 한 번씩만 본다 |
| 공간 | O(V) — `tin`, `low`, `onStack`, 스택 + 재귀 깊이 |

각 정점은 스택에 한 번 들어가고 한 번 나온다. `low` 갱신은 간선당 O(1).

### 다른 SCC 알고리즘과 비교

| | DFS 횟수 | 특징 |
|---|---|---|
| **타잔** | 1 | 역방향 그래프 불필요, SCC 를 위상 역순으로 |
| 코사라주 | 2 | 이해하기 쉽지만 **역방향 그래프**를 만들어야 함(메모리 2배) |
| 가보우(Gabow) | 1 | 스택 두 개, `low` 없이. 타잔과 성능 동일 |

## 구현 노트

**재귀 깊이**: DFS 깊이가 `V` 까지 갈 수 있다. 정점이 10만 개를 넘으면 스택 오버플로가
현실적인 위험이다. 명시적 스택으로 바꾸거나 스택 크기를 늘린다.
([DFS 문서의 구현 노트](#/algo/dfs)에 반복 버전 전환 시 주의점이 있다.)

**`onStack` 배열을 빠뜨리지 마라.** "이미 방문했다"와 "아직 스택에 있다"는 다르다.
방문 여부만 보고 `low` 를 갱신하면 이미 확정된 다른 SCC 를 끌어들여 전부 하나로 합쳐진다.
**가장 흔한 버그다.**

**`comp` 번호 매기기**: 이 페이지는 확정 순서대로 `C0, C1, …` 을 붙인다.
축약 그래프에서 위상 순서로 쓰려면 이 번호를 **뒤집어야** 한다는 점에 주의.

**모든 정점에서 시작**: 도달 못 하는 부분이 남지 않도록 미방문 정점마다 DFS 를 다시 시작한다.

## 변형과 확장

### 어디에 쓰이나

- **2-SAT**: 절 `(a ∨ b)` 를 함의 간선 `¬a → b`, `¬b → a` 로 옮기면,
  `x` 와 `¬x` 가 같은 SCC 에 있을 때만 해가 없다. 있으면 SCC 위상 역순으로 값을 정하면 된다.
- **축약 그래프 위의 DP**: 사이클이 있는 그래프를 DAG 로 바꿔 놓고 최장 경로 등을 푼다.
- **의존성 순환 탐지**: 모듈·패키지 그래프에서 순환 참조 덩어리를 찾는다.

### 사촌 알고리즘

`low-link` 라는 도구는 SCC 전용이 아니다. 같은 DFS 한 번으로 다음도 구한다.

- **단절점(articulation point)**: 무방향 그래프에서 지우면 연결이 끊어지는 정점.
  `low[v] >= tin[u]` 인 자식 `v` 가 있으면 `u` 가 단절점.
- **다리(bridge)**: `low[v] > tin[u]` 인 간선 `(u,v)`.
- **이중 연결 요소(BCC)**: 간선 스택을 함께 관리한다.
