## 어떤 문제인가

방향 그래프에서 이런 질문을 해 보자.

> **서로 오갈 수 있는 정점들**은 어떻게 묶이는가?

`u` 에서 `v` 로 가는 길도 있고 `v` 에서 `u` 로 오는 길도 있으면, 둘은 한 덩어리다.
이런 최대 덩어리를 **강한 연결 요소(SCC, Strongly Connected Component)** 라고 한다.

```
0 ──▶ 1 ──▶ 2 ──▶ 3 ──▶ 4 ──▶ 5
▲           │     ▲     │
└───────────┘     └─────┘

{0,1,2} 는 서로 오갈 수 있다  →  SCC
{3,4}   도 서로 오갈 수 있다  →  SCC
{5}     혼자                →  SCC
```

무식하게 하면 정점 쌍마다 도달 가능한지 확인해야 해서 `O(V·(V+E))` 다.
**타잔은 DFS 딱 한 번**으로 전부 찾는다.

## 손으로 해보기

### 준비물: 두 개의 숫자

각 정점에 숫자 두 개를 붙인다.

```
tin[u]   u 를 처음 방문한 시각 (0, 1, 2, … 순서대로)
low[u]   u 에서 출발해 "아직 처리 중인" 정점까지 갈 수 있는 최소 tin
```

`low` 를 말로 풀면 **"내가 얼마나 위쪽까지 되돌아갈 수 있는가"** 다.

### 왜 이게 SCC 를 알려 주나

`low[u] < tin[u]` 라면 → 나보다 먼저 방문된 조상까지 돌아갈 길이 있다
→ **나는 그 조상과 한 덩어리다** → 아직 덩어리의 대표가 아니다.

`low[u] == tin[u]` 라면 → 나보다 위로는 못 간다 → **내가 이 덩어리의 뿌리다.**

### 따라가 보기

기본 그래프에서 0부터 DFS 를 시작한다.

```
0 방문:  tin=0, low=0   스택 [0]
 └ 0→1: 처음 봄 → 내려간다
   1 방문:  tin=1, low=1   스택 [0,1]
    └ 1→2: 처음 봄 → 내려간다
      2 방문:  tin=2, low=2   스택 [0,1,2]
       ├ 2→0: 0 이 스택에 있다! → low[2] = min(2, tin[0]=0) = 0   ★
       │      "0 까지 돌아갈 수 있다"
       └ 2→3: 처음 봄 → 내려간다
         3 방문:  tin=3, low=3   스택 [0,1,2,3]
          └ 3→4: 처음 봄 → 내려간다
            4 방문:  tin=4, low=4   스택 [0,1,2,3,4]
             ├ 4→3: 3 이 스택에 있다 → low[4] = min(4, tin[3]=3) = 3
             └ 4→5: 처음 봄 → 내려간다
               5 방문:  tin=5, low=5   스택 [0,1,2,3,4,5]
                (나갈 곳 없음)
               low[5]=5 == tin[5]=5  →  5 가 뿌리!
               스택에서 5 까지 뽑는다 → SCC {5} 확정   스택 [0,1,2,3,4]
            4 로 복귀: low[4]=3 != tin[4]=4 → 아직 뿌리 아님
         3 으로 복귀: low[3] = min(3, low[4]=3) = 3
            low[3]=3 == tin[3]=3  →  3 이 뿌리!
            스택에서 3 까지 뽑는다 → SCC {4, 3} 확정   스택 [0,1,2]
      2 로 복귀: low[2] = min(0, low[3]=3) = 0
         low[2]=0 != tin[2]=2 → 아직 뿌리 아님
   1 로 복귀: low[1] = min(1, low[2]=0) = 0 → 뿌리 아님
0 으로 복귀: low[0] = min(0, low[1]=0) = 0
   low[0]=0 == tin[0]=0  →  0 이 뿌리!
   스택에서 0 까지 뽑는다 → SCC {2, 1, 0} 확정
```

**결과: `{0,1,2}`, `{3,4}`, `{5}`** — 처음에 눈으로 본 것과 일치한다.

## 아이디어 쌓기

### 1단계 — SCC 는 DFS 트리 안에서 뭉쳐 있다

같은 SCC 의 정점들은 DFS 트리에서 흩어지지 않는다. 가장 먼저 방문된 정점(=뿌리)의
자손으로 전부 모인다.

이유는 [DFS](#/algo/dfs)의 성질 때문이다. 뿌리 `r` 을 방문하는 시점에 같은 SCC 의
나머지는 전부 미방문이고, `r` 에서 그들로 가는 길이 있으므로 DFS 가 반드시 그리로 내려간다.

### 2단계 — 스택으로 "아직 안 끝난 것"을 관리한다

정점을 방문하면 스택에 올린다. SCC 가 확정되면 그 멤버들을 한꺼번에 뽑아낸다.

**스택에 남아 있다 = 아직 어느 SCC 에도 속하지 않았다 = 나와 한 덩어리일 수 있다.**

### 3단계 — 세 종류의 간선을 구분한다

`u → v` 를 볼 때 세 경우가 있다.

| `v` 의 상태 | 뜻 | 하는 일 |
|---|---|---|
| 처음 봄 | 트리 간선 | `dfs(v)` 후 `low[u] = min(low[u], low[v])` |
| 스택에 있음 | 조상 또는 같은 덩어리 후보 | `low[u] = min(low[u], tin[v])` |
| 이미 확정됨 | 다른 SCC | **무시한다** ★ |

세 번째를 무시하지 않으면 **서로 다른 SCC 가 하나로 합쳐진다.** 가장 흔한 버그다.
이미 닫힌 SCC 로는 되돌아올 수 없으니 나와 한 덩어리일 수 없다.

> **왜 두 번째에서 `low[v]` 가 아니라 `tin[v]` 인가?**
> `low[v]` 를 쓰면 `v` 의 다른 가지가 알아낸 정보까지 끌어와서, `u` 가 실제로는 못 가는 곳까지
> 갈 수 있다고 착각한다. 답이 우연히 맞는 경우가 많아 더 위험하다.

### 4단계 — 뿌리에서 뽑아낸다

`low[u] == tin[u]` 인 순간, 스택에서 `u` 가 나올 때까지 뽑는다. 그게 하나의 SCC 다.

## 코드로 옮기기

```cpp
int tin[MAXN], low[MAXN], comp[MAXN], timer = 0;
bool onStack[MAXN];
stack<int> st;

void dfs(int u) {
    tin[u] = low[u] = timer++;          // ← 방문 시각. 처음엔 low = tin
    st.push(u); onStack[u] = true;      // ← 2단계: 스택에 올린다
    for (int v : adj[u]) {
        if (tin[v] == -1) {             // ← 3단계 ①: 처음 보는 정점
            dfs(v);
            low[u] = min(low[u], low[v]);   //   자손이 갈 수 있는 곳은 나도 갈 수 있다
        } else if (onStack[v]) {        // ← 3단계 ②: 스택 위 = 같은 덩어리 후보
            low[u] = min(low[u], tin[v]);   //   tin! (low 아님)
        }
        // 3단계 ③: 이미 확정된 SCC → 아무것도 안 한다
    }
    if (low[u] == tin[u]) {             // ← 4단계: 내가 뿌리다
        while (true) {
            int v = st.top(); st.pop();
            onStack[v] = false;
            comp[v] = u;                //   같은 SCC 로 표시
            if (v == u) break;          //   나까지 뽑으면 끝
        }
    }
}
```

`else if (onStack[v])` 에서 **`else`** 가 중요하다. 처음 보는 정점이면 재귀로 내려가고,
그렇지 않을 때만 스택 여부를 본다.

## 자주 하는 실수

**`onStack` 을 안 쓴다.** "방문했다"와 "아직 스택에 있다"는 다르다.
`visited` 만 보고 `low` 를 갱신하면 이미 확정된 다른 SCC 를 끌어들여 **전부 하나로 합쳐진다.**

**`tin[v]` 대신 `low[v]` 를 쓴다.** 3단계의 주의 사항. 답이 맞는 경우가 많아 더 찾기 어렵다.

**미방문 정점에서 다시 시작하지 않는다.** 시작점에서 도달 못 하는 정점이 있을 수 있다.
모든 정점을 훑으며 `tin[v] == -1` 이면 `dfs(v)` 를 새로 시작해야 한다.

**재귀가 너무 깊어진다.** 정점 10만 개짜리 사슬에서는 스택 오버플로가 난다.

## 스스로 확인하기

1. **정점 라벨을 보자.** `tin/low` 형태로 표시되다가, SCC 가 확정되면 `C0`, `C1` 로 바뀐다.
2. **`low` 가 내려가는 순간**을 찾아보자. `2→0` 을 볼 때 `low[2]` 가 2에서 0으로 떨어진다.
   "0까지 돌아갈 수 있다"를 발견한 순간이다.
3. **`stack` 표시**를 보자. 정점이 쌓였다가 SCC 단위로 한꺼번에 빠져나간다.
4. **SCC 가 확정되는 순서**를 보자. `{5}` → `{3,4}` → `{0,1,2}` 다.
   덩어리들을 하나의 점으로 축약하면 `{0,1,2} → {3,4} → {5}` 라는 사이클 없는 그래프가 되는데,
   확정 순서는 그 **역순**이다. 이 성질이 [위상 정렬](#/algo/topological-sort)과 만나 2-SAT 을 푼다.
5. 편집기에서 `5→0` 간선을 추가해 보자. 전부가 하나의 거대한 SCC 가 된다.

아래 **깊이 보기**에서는 "`low[u] == tin[u]` ⟺ `u` 가 뿌리"를 양방향으로 증명하고,
같은 `low-link` 기법으로 단절점·다리를 찾는 방법을 다룬다.
