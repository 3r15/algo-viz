## 어떤 문제인가

**이분 그래프** — 정점이 두 집합(왼쪽·오른쪽)으로 나뉘고, 간선은 항상 왼쪽과 오른쪽을 잇는다.
"지원자–직무", "학생–프로젝트" 처럼 짝을 짓는 상황이다.

> 한 사람은 한 직무만, 한 직무는 한 사람만 맡을 수 있을 때, **최대한 많은 짝**을 지으려면?

이걸 **최대 매칭**(서로 정점을 공유하지 않는 간선의 최대 집합)이라 한다.

## 손으로 해보기

기본 그래프: 왼쪽 `L0,L1,L2`, 오른쪽 `R0,R1,R2`.
간선 `L0–R0, L0–R1, L1–R0, L1–R2, L2–R1, L2–R2`.

### 탐욕만으로는 막힌다

왼쪽부터 아무 빈 오른쪽에 짝지으면 종종 막힌다. 그래서 **증가 경로(augmenting path)** 로
**이미 지은 짝을 밀어내며** 늘린다.

### 쿤 알고리즘 — 왼쪽을 하나씩

```
L0 짝짓기: R0 비었다 → L0–R0                     매칭 {L0-R0}
L1 짝짓기: R0 은 L0 차지 → L0 를 다른 데로 밀어 본다
           L0 는 R1 도 가능, R1 비었다 → L0–R1
           그럼 R0 이 비니 → L1–R0                매칭 {L0-R1, L1-R0}
L2 짝짓기: R1 은 L0 차지 → L0 를 밀어 본다
           L0 의 다른 이웃 R0 은 L1 차지 → L1 을 밀어 본다
           L1 의 다른 이웃 R2 비었다 → L1–R2, 연쇄로 자리 이동
           결국 L2–R1                            매칭 {L2-R1, L0-R0, L1-R2}
최대 매칭 크기 = 3
```

한 왼쪽 정점을 넣으려고 **짝의 짝의 짝…** 을 연쇄로 밀어내는 것이 증가 경로다.

### 증가 경로란

현재 매칭에서 **매칭 안 된 간선 → 매칭된 간선 → 안 된 간선 → …** 을 번갈아 밟아,
양 끝이 모두 미매칭인 경로. 이 경로의 간선을 **뒤집으면**(매칭↔비매칭) 매칭이 정확히 하나 는다.

### 비용

```
왼쪽 정점 L개, 각자 증가 경로 DFS 한 번 O(E)
합계 O(V·E)
```

## 아이디어 쌓기

### 1단계 — 짝을 밀어낼 수 있다

빈 오른쪽이 없어도, 그 오른쪽의 현재 짝을 **다른 곳으로 옮길 수 있으면** 자리가 난다.

### 2단계 — 증가 경로를 DFS 로

한 왼쪽 정점에서 시작해 "밀어내기" 를 재귀로 시도한다.

### 3단계 — 방문 표시로 무한루프 방지

한 번의 시도에서 각 오른쪽 정점을 한 번만 방문한다.

### 4단계 — 왼쪽을 하나씩 편입

각 왼쪽 정점마다 증가 경로가 있으면 매칭이 하나 는다.

## 코드로 옮기기

```cpp
bool tryKuhn(int u) {                     // 왼쪽 u 의 증가 경로 찾기
    for (int v : adj[u]) {                // u 의 오른쪽 이웃들
        if (!visited[v]) {
            visited[v] = true;
            if (matchR[v] == -1 || tryKuhn(matchR[v])) {
                matchR[v] = u;            // v 를 u 와 짝짓는다
                return true;
            }
        }
    }
    return false;                         // 증가 경로 없음
}
int maxMatching(int L) {
    int cnt = 0;
    for (int u = 0; u < L; u++) {
        fill(visited, visited+R, false);
        if (tryKuhn(u)) cnt++;            // u 를 매칭에 편입
    }
    return cnt;
}
```

`matchR[v] == -1`(빈 오른쪽) **또는** `tryKuhn(matchR[v])`(짝을 밀어냄) 이 증가 경로의 핵심.

## 자주 하는 실수

**매 왼쪽 정점마다 visited 초기화를 빼먹는다.** `tryKuhn` 한 번당 `visited` 를 새로 비운다.

**밀어내기(재귀)를 안 한다.** 빈 오른쪽만 찾으면 탐욕이라 최대가 아니다. 짝을 옮기는 재귀가 핵심.

**이분이 아닌 그래프에 쓴다.** 쿤은 이분 그래프 전용. 일반 그래프 매칭은 블로섬 알고리즘.

**방향을 헷갈린다.** 왼쪽→오른쪽 인접만 본다(오른쪽→왼쪽은 `matchR` 로 추적).

## 스스로 확인하기

1. **L0–R0** 이 먼저 매칭되는 것을 보자.
2. **L1 이 L0 를 R1 로 밀어내는** 증가 경로를 보자(간선 강조).
3. **매칭 간선이 초록**으로 유지되는 것을 보자.
4. **L2 를 넣기 위한 연쇄 밀어내기**를 관찰하자.
5. **최대 매칭 크기 3** 을 확인하자.
6. 그래프 편집기로 간선을 지워 매칭이 줄어드는 것을 보자.
