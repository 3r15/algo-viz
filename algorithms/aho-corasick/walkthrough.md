## 어떤 문제인가

패턴이 **여러 개** 다. 텍스트 하나에서 `{he, she, his}` 를 **전부** 찾고 싶다.

패턴마다 [KMP](#/algo/kmp)를 돌리면 `O(패턴수 × n)`. 패턴이 많으면 느리다.

> 패턴들이 **앞부분을 공유**한다(`he`, `hers` 는 `he…`, `she` 는 `he` 를 접미사로 품는다).
> 텍스트를 **한 번만** 훑어 모든 패턴을 동시에 찾을 수 없을까?

## 손으로 해보기

두 재료를 합친다: **[트라이](#/algo/trie)**(패턴들의 접두사 트리) + **실패 링크**(KMP 실패 함수의 트라이 버전).

기본 입력 텍스트 `ahishers`, 패턴 `his he she`.

### ① 패턴을 트라이에

```
루트─h─┬─i─s(●his)
       └─e(●he)
루트─s─h─e(●she)
```

`●` 는 그 노드에서 **패턴이 끝난다**는 표시.

### ② 실패 링크 — 막혔을 때 어디로 미끄러지나

`fail[u]` = "루트→u 문자열의 **가장 긴 진접미사**" 에 해당하는 트라이 노드. 텍스트를 훑다 다음 글자로
못 가면, **텍스트는 그대로 두고** fail 링크를 따라 미끄러진다(KMP 와 똑같은 발상, 트라이 위에서).

예: `she` 의 `sh` 노드에서 다음이 막히면, `h`(루트의 h 자식)로 미끄러진다 — `sh` 의 접미사 `h` 가
다른 패턴(`he`)의 접두사이기 때문이다.

### ③ 텍스트 훑기

```
a  h  i  s  h  e  r  s
      └his@1┘
            └───┐
         she@3 ─┘ he@4
```

`ahishers` 를 왼→오로 한 번 지나가며 트라이 위를 이동한다:
- `...his` 에서 노드 `his(●)` 도달 → **his@1** 발견
- `...she` 에서 `she(●)` 도달 → **she@3**, 그 접미사 `he` 도 → **he@4**

한 번 훑기로 세 패턴을 다 찾았다.

### 출력 링크 — 접미사로 끝나는 패턴도

`she` 를 찾은 위치는 `he` 로도 끝난다. 그래서 각 노드의 "끝나는 패턴 목록" 에 **fail 링크로 이어지는
패턴** 도 상속한다(`out[v] |= out[fail[v]]`). 겹치는 매칭을 놓치지 않는다.

### 비용

```
트라이 만들기: Σ(패턴 길이)
실패 링크 BFS: Σ(패턴 길이)
텍스트 훑기: n + (매칭 개수 z)
합계: O(n + Σ패턴길이 + z)
```

## 아이디어 쌓기

### 1단계 — 패턴을 트라이로

공통 접두사를 공유해 한 그루에 담는다.

### 2단계 — 실패 링크(KMP 의 일반화)

막히면 "가장 긴 접미사=접두사" 노드로 미끄러진다. 텍스트는 안 되돌린다.

### 3단계 — 출력 링크로 겹침까지

한 노드에서 끝나는 패턴 + fail 사슬로 끝나는 패턴을 모두 보고한다.

### 4단계 — 한 번 훑기

텍스트를 한 번 지나가며 전이 + 보고. 선형 + 매칭 수.

## 코드로 옮기기

```cpp
void build() {                         // 실패 링크 계산(BFS)
    queue<int> q;
    for (int c = 0; c < 26; c++)
        if (go[0][c]) fail[go[0][c]] = 0, q.push(go[0][c]);
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int c = 0; c < 26; c++) if (int v = go[u][c]) {
            int f = fail[u];
            while (f && !go[f][c]) f = fail[f];
            fail[v] = go[f][c];        // 부모 fail 을 따라
            out[v] |= out[fail[v]];    // 접미사로 끝나는 패턴 상속
            q.push(v);
        }
    }
}
void search(string t) {
    int u = 0;
    for (char ch : t) {
        int c = ch - 'a';
        while (u && !go[u][c]) u = fail[u];  // 막히면 fail 로
        u = go[u][c];                  // 전이(없으면 0)
        report(out[u]);                // u 에서 끝나는 모든 패턴
    }
}
```

`build` 의 BFS 가 KMP 실패 함수를 트라이로 일반화한다 — 부모의 fail 을 따라가 자식의 fail 을 정한다.

## 자주 하는 실수

**출력(접미사) 상속을 빼먹는다.** `out[v] |= out[fail[v]]` 가 없으면 `she` 안의 `he` 같은 겹침을 놓친다.

**실패 링크 계산에 BFS 대신 DFS.** fail[v] 는 fail[부모] 를 써야 하므로 **레벨 순(BFS)** 으로 계산.

**루트 처리.** 루트의 fail 은 자기 자신(또는 0). 막혀서 루트까지 오면 거기서 멈춘다.

**텍스트 되돌리기.** KMP 처럼 텍스트 포인터는 앞으로만. 되돌리면 선형이 깨진다.

## 스스로 확인하기

1. **트라이**에 `his`, `he`, `she` 가 접두사 공유하며 놓인 것을 보자(끝 노드 ●).
2. 각 노드의 **fail 정보**(툴팁)를 확인하자 — 막혔을 때 갈 곳.
3. **텍스트 훑기**에서 현재 노드가 이동하는 것을 보자.
4. **his@1, she@3, he@4** 가 각각 발견되는 순간을 보자.
5. **she 를 찾을 때 he 도 함께**(출력 상속) 보고되는지 확인하자.
6. 입력을 `bananas ana ban nan` 으로 바꿔 보자 — 겹치는 매칭들이 한 번 훑기에 나온다.

아래 **깊이 보기**에서는 실패 링크의 정확성(트라이 위 KMP), 자동자 형태(전이 접기)와 복잡도,
사전 필터·바이러스 스캔 응용을 다룬다.
