## 한눈에

배열을 절반으로 나눠 각각 정렬한 뒤, **정렬된 두 배열을 하나로 병합(merge)** 한다.
병합은 양쪽 맨 앞만 비교해 작은 쪽을 꺼내면 되므로 선형 시간이다.

**입력에 관계없이 항상 Θ(n log n)** 이고 **안정(stable)** 하다. 대신 O(n) 추가 공간이 필요하다.

- 비교 기반 · 안정 · 제자리 아님
- [퀵 정렬](#/algo/quick-sort)과 반대로 **"나눌 때는 아무 일도 안 하고 합칠 때 일을 한다"**

## 동작 원리

```
mergeSort(a, lo, hi):
    if lo >= hi: return              // 원소 0~1개는 이미 정렬됨
    mid = (lo + hi) / 2
    mergeSort(a, lo, mid)            // 왼쪽 절반 정렬
    mergeSort(a, mid+1, hi)          // 오른쪽 절반 정렬
    merge(a, lo, mid, hi)            // 두 정렬 구간을 합침
```

병합은 두 손가락을 각 구간의 맨 앞에 두고, **작은 쪽을 꺼내 결과에 붙이고 그 손가락만 한 칸
전진**시키는 것을 반복한다. 한쪽이 먼저 바닥나면 나머지는 그대로 이어 붙인다.

```
왼쪽  [2 5 9]   오른쪽 [1 5 6]
          ↑              ↑
2 vs 1 → 1 채택 → [1]
2 vs 5 → 2 채택 → [1 2]
5 vs 5 → 왼쪽 우선(<=) → [1 2 5]      ← 안정성의 핵심
9 vs 5 → 5 채택 → [1 2 5 5]
9 vs 6 → 6 채택 → [1 2 5 5 6]
오른쪽 소진 → 9 이어 붙임 → [1 2 5 5 6 9]
```

## 정확성

### 병합 보조정리

> `a[lo..mid]` 와 `a[mid+1..hi]` 가 각각 정렬돼 있으면, 위 절차는 두 구간의 원소 전체를
> 정렬된 순서로 `tmp` 에 담는다.

**불변식**: `tmp` 는 항상 정렬돼 있고, `tmp` 의 모든 원소는 아직 남아 있는 `a[i..mid]`,
`a[j..hi]` 의 모든 원소보다 작거나 같다.

처음엔 `tmp` 가 비어 있어 자명하다. 각 단계에서 꺼내는 값은 `min(a[i], a[j])` 이고,
두 구간이 각각 정렬돼 있으므로 이 값은 **남아 있는 모든 원소 중 최솟값**이다.
따라서 `tmp` 뒤에 붙여도 정렬이 유지되고 불변식도 유지된다. 루프가 끝나면 한쪽만 남는데,
그쪽은 이미 정렬돼 있고 불변식에 의해 `tmp` 의 모든 원소 이상이므로 그대로 붙이면 된다. ∎

### 전체 정렬 — 구간 길이에 대한 강귀납법

길이 1 이하 구간은 정렬돼 있다(기저). 길이 `m > 1` 구간에서 두 부분 구간의 길이는
`⌈m/2⌉`, `⌊m/2⌋` 로 모두 `m` 미만이다. 귀납 가정에 의해 두 재귀 호출이 각각을 정렬하고,
병합 보조정리에 의해 합친 결과가 정렬된다. ∎

### 안정성

비교가 `a[i] <= a[j]` 이다. **값이 같으면 왼쪽(=원래 앞쪽) 구간에서 먼저 꺼낸다.**
그래서 같은 값의 상대 순서가 보존된다. 이 부등호를 `<` 로 바꾸는 순간 안정성이 깨진다.
병합 정렬을 쓰는 이유의 절반이 안정성이므로, 이 한 글자가 생각보다 중요하다.

## 복잡도

```
T(n) = 2 T(n/2) + Θ(n),   T(1) = Θ(1)
```

마스터 정리에서 `a = 2, b = 2, f(n) = Θ(n)` 이고 `n^(log_b a) = n` 이므로 **case 2**,
따라서 `T(n) = Θ(n log n)` 이다.

재귀 트리로 봐도 같다. 깊이는 `log₂ n` 이고, 각 깊이에서 병합에 쓰는 총 시간은 구간들의
길이 합인 `Θ(n)` 이다. 곱하면 `Θ(n log n)`.

| | 시간 | 비고 |
|---|---|---|
| 최선 | Θ(n log n) | 입력에 무관하게 항상 같은 분할·병합 |
| 평균 | Θ(n log n) | |
| 최악 | Θ(n log n) | **퀵 정렬과 달리 최악이 없다** |
| 공간 | Θ(n) | `tmp` 배열 + 재귀 스택 O(log n) |

비교 횟수는 정확히 `n log₂ n − n + 1` 근처이며, 아래 하한과 상수까지 맞닿아 있다.

### 왜 이보다 빠를 수 없나 — 비교 정렬의 하한

비교만으로 정렬하는 알고리즘은 **결정 트리(decision tree)** 로 모델링할 수 있다.
비교 한 번이 노드 하나, 가능한 출력 순열 하나가 잎 하나다.

- `n`개 원소의 순열은 `n!` 가지이므로 잎이 최소 `n!` 개 필요하다.
- 높이 `h`인 이진 트리의 잎은 최대 `2^h` 개다.

따라서 `2^h ≥ n!`, 즉

```
h ≥ log₂(n!) = Θ(n log n)      (스털링 근사)
```

**어떤 비교 기반 정렬도 최악에 Ω(n log n) 비교가 필요하다.** 병합 정렬은 이 하한을 달성하므로
비교 횟수 면에서 **점근적으로 최적**이다. (계수 정렬·기수 정렬이 더 빠른 이유는
비교를 쓰지 않아 이 모델 밖에 있기 때문이다.)

## 구현 노트

**`tmp` 를 매 병합마다 새로 만들지 마라.** 이 페이지 코드처럼 `vector<int> tmp;` 를 함수 안에
두면 재귀 호출마다 할당이 일어나 상수가 크게 나빠진다. 크기 `n`짜리 버퍼를 **한 번만 잡아
바깥에서 넘겨 쓰는 것**이 표준이다.

**`mid = (lo + hi) / 2` 의 오버플로**: `lo + hi` 가 `int` 범위를 넘을 수 있다면
`lo + (hi - lo) / 2` 로 쓴다. 이 사이트의 입력 크기에서는 문제가 없지만 습관을 들여 두면 좋다.

**하향식 vs 상향식**: 재귀 없이 길이 1, 2, 4, 8… 짜리 구간을 아래에서부터 병합해 올라가는
**bottom-up merge sort** 도 있다. 재귀 스택이 없고 캐시 지역성이 좋다.

**작은 구간은 삽입 정렬로**: 길이가 16 이하인 구간에서는 [삽입 정렬](#/algo/insertion-sort)이
상수 면에서 유리하다. 실전 구현은 대부분 이 컷오프를 둔다.

## 변형과 확장

- **자연 병합 정렬(natural merge sort)**: 이미 정렬된 구간(run)을 찾아 그것부터 병합한다.
  거의 정렬된 입력에서 O(n)까지 떨어진다. **팀소트(Timsort)** 가 이 아이디어를 정교하게 발전시킨 것으로,
  파이썬과 자바의 객체 정렬이 쓴다.
- **외부 정렬(external sort)**: 메모리에 안 들어가는 데이터를 조각내 정렬한 뒤
  `k`-way 병합으로 합친다. 병합 정렬이 디스크·분산 환경의 표준인 이유다.
- **역전 수 세기**: 병합 중 오른쪽 원소를 꺼낼 때 `mid - i + 1` 을 더하면
  배열의 역전(inversion) 개수를 O(n log n)에 셀 수 있다.
- **in-place merge**: 추가 공간 없이 병합하는 방법도 있지만 상수가 커서 실용성이 낮다.
