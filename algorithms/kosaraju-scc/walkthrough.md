## 어떤 문제인가

방향 그래프에서 **강한 연결 요소(SCC)** 를 찾는다. SCC 란 그 안의 어떤 두 정점 `u, v` 든
`u→…→v` 로도, `v→…→u` 로도 갈 수 있는 최대 덩어리다 — 즉 **서로 오갈 수 있는 정점들의 모임**.

```
0 → 1 → 2 → 0     {0,1,2} 는 서로 오간다 → 한 SCC
        ↓
        3 ⇄ 4     {3,4} 도 서로 오간다 → 또 한 SCC
            ↓
            5      5 는 혼자 → SCC
```

[타잔 알고리즘](#/algo/tarjan-scc)은 이걸 **한 번의 DFS** 로 푼다(low-link 로).
코사라주는 같은 문제를 훨씬 **직관적인 두 번의 DFS** 로 푼다.

> 그래프를 DFS 해서 **끝나는 순서**를 적어 두고, **간선을 전부 뒤집은** 그래프를
> 그 순서의 역순으로 DFS 하면, 한 번의 탐색이 SCC 하나씩을 정확히 집어낸다.

왜 이게 되는지가 핵심인데, 먼저 손으로 해 보자.

## 손으로 해보기

기본 그래프(타잔과 같다)로 가 보자. 간선: `0→1, 1→2, 2→0, 2→3, 3→4, 4→3, 4→5`.

### ① 원래 그래프를 DFS — 끝나는 순서를 스택에 쌓는다

DFS 하다가 한 정점의 **모든 이웃을 다 본 뒤(= 완료)** 그 정점을 스택에 쌓는다.

```
0 방문 → 1 → 2 → (2의 이웃 0은 방문됨, 3으로) → 3 → 4 → 5
5 완료 → 쌓기         스택: [5]
4 완료 → 쌓기         스택: [5,4]
3 완료 → 쌓기         스택: [5,4,3]
2 완료 → 쌓기         스택: [5,4,3,2]
1 완료 → 쌓기         스택: [5,4,3,2,1]
0 완료 → 쌓기         스택: [5,4,3,2,1,0]
```

스택 맨 위(가장 늦게 완료)는 `0`. **완료가 늦은 정점일수록 위상적으로 "앞선" SCC 에 있다.**

### ② 간선을 뒤집고, 스택 위에서부터 DFS

모든 간선의 방향을 뒤집는다: `1→0, 2→1, 0→2, 3→2, 4→3, 3→4, 5→4`.
스택 맨 위(`0`)부터 꺼내며, 아직 SCC 가 없는 정점에서 DFS 를 시작한다. **한 번의 DFS 로 닿는 정점 = SCC 하나.**

```
스택 위 0 꺼냄 → 뒤집은 그래프에서 DFS
  0 → 2 → 1 (→ 0은 이미)   닿은 곳: {0,1,2}   → SCC C0

다음 위 1,2 는 이미 C0. 건너뜀.
스택 위 3 꺼냄 → DFS
  3 → 4 (→ 3은 이미)       닿은 곳: {3,4}     → SCC C1

스택 위 5 꺼냄 → DFS
  5 (뒤집으면 5→4, 4는 이미)  닿은 곳: {5}     → SCC C2
```

**끝.** SCC 세 덩이 `{0,1,2}, {3,4}, {5}` — 타잔과 같은 답이다.

### 왜 뒤집은 그래프에서 딱 그 덩어리만 닿나

`0` 에서 뒤집은 그래프로 DFS 하면, 원래 그래프에서 **`0` 으로 올 수 있던** 정점들에 닿는다.
그런데 `0` 은 완료가 가장 늦었으니 원래 그래프에서 `0` 은 **다른 SCC 로 나가기만** 했다(들어오진 않음).
그래서 뒤집으면 `0` 의 SCC 밖으로는 **못 나간다** — 딱 `0` 이 속한 덩어리만 닿는다.
이게 두 번째 DFS 가 SCC 를 하나씩 정확히 잘라내는 이유다.

## 아이디어 쌓기

### 1단계 — SCC 를 "서로 오갈 수 있는 최대 덩어리" 로 본다

SCC 끼리 묶으면 그래프는 사이클 없는 DAG(축약 그래프)가 된다.

### 2단계 — 완료 순서가 위상 정보를 담는다

DFS 완료 시각이 늦은 정점은 축약 DAG 에서 "앞선"(위상적으로 먼저인) SCC 에 있다.

### 3단계 — 간선을 뒤집으면 SCC 는 그대로, 방향만 반대

뒤집어도 "서로 오갈 수 있음" 은 대칭이라 SCC 는 변하지 않는다. 하지만 SCC **사이** 의 방향은 반대가 된다.

### 4단계 — 늦게 끝난 정점부터 뒤집은 그래프 DFS

완료 역순으로 시작하면, 각 DFS 가 자기 SCC 밖으로 못 나가 덩어리를 하나씩 집어낸다.

## 코드로 옮기기

```cpp
vector<int> order;                         // 완료 순서 스택
void dfs1(int u) {                         // ① 원래 그래프
    visited[u] = true;
    for (int v : adj[u])
        if (!visited[v]) dfs1(v);
    order.push_back(u);                     //    끝나면 쌓는다
}
void dfs2(int u, int c) {                   // ② 뒤집은 그래프
    comp[u] = c;                            //    같은 SCC 번호
    for (int v : radj[u])                   //    거꾸로 간선
        if (comp[v] < 0) dfs2(v, c);
}
int kosaraju(int n) {                       // ① 전부 DFS → order
    for (int u = 0; u < n; u++)
        if (!visited[u]) dfs1(u);
    int c = 0;                              // ② order 위에서부터
    for (int i = n - 1; i >= 0; i--) {
        int u = order[i];
        if (comp[u] < 0) dfs2(u, c++);      //    새 DFS = 새 SCC
    }
    return c;                               // SCC 개수
}
```

`adj` 는 원래 간선, `radj` 는 **뒤집은** 간선. `dfs1` 은 완료 순서를 `order` 에,
`dfs2` 는 그 역순으로 돌며 SCC 번호를 매긴다.

## 자주 하는 실수

**완료 순서가 아니라 방문 순서로 쌓는다.** SCC 를 결정하는 건 **완료(post-order)** 시각이다.
방문(발견) 순서로 하면 틀린다.

**두 번째 DFS 를 원래 그래프에서 한다.** 반드시 **뒤집은** 그래프여야 한다. 안 뒤집으면 SCC 하나에서
다른 SCC 로 새어 나가 여러 덩어리가 뭉쳐 버린다.

**스택 아래(먼저 완료)부터 꺼낸다.** 반드시 **위(늦게 완료)부터** 꺼내야 각 DFS 가 SCC 에 갇힌다.

**뒤집은 그래프를 따로 안 만든다.** `radj` 를 미리 구성하거나, 간선을 `(v,u)` 로 넣어야 한다.

## 스스로 확인하기

1. **① 단계**에서 정점이 완료될 때마다 오른쪽 **스택**에 쌓이는 것을 보자. 스택 맨 위가 `0` 이 된다.
2. **① → ② 전환 설명**에서 완료 순서 `[5,4,3,2,1,0]` 을 확인하자.
3. **② 단계**에서 스택 맨 위(`0`)부터 꺼내 뒤집은 간선을 따라가는 것을 보자.
4. **각 DFS 가 한 SCC 만 칠하고 멈추는 것**을 보자 — `C0={0,1,2}`, `C1={3,4}`, `C2={5}`.
5. 정점 색이 SCC 별로 갈리는 것을 확인하자(라벨 `C0/C1/C2`).
6. 그래프 편집기로 사이클을 하나 끊어 보자(예: `2→0` 삭제). SCC 가 어떻게 쪼개지는지 관찰하자.
7. [타잔 SCC](#/algo/tarjan-scc)와 **같은 그래프** 다. 두 알고리즘이 같은 답을 다르게 구하는 것을 비교하자.

아래 **깊이 보기**에서는 "완료 역순 + 전치 그래프" 가 왜 SCC 를 정확히 잘라내는지 증명하고,
타잔과의 비교, 축약 DAG 로의 응용을 다룬다.
