## 어떤 문제인가

평면에 점이 여럿 있다. 그중 **가장 가까운 두 점**은?

가장 단순한 방법은 **모든 쌍**의 거리를 재는 것 — `n`개면 `n(n−1)/2` 쌍, `O(n²)`. 점이 많으면 느리다.

> 정렬과 분할 정복으로 `O(n log n)` 에 할 수 없을까?

## 손으로 해보기

기본 입력 `(1,3) (2,8) (4,5) (6,7) (7,2) (8,6)` 여섯 점으로 가 보자.

### ① x 로 나눈다

점을 x 좌표로 정렬하고, 가운데 **세로 분할선**으로 왼쪽·오른쪽 절반으로 나눈다.

```
왼쪽: (1,3) (2,8) (4,5)   |   오른쪽: (6,7) (7,2) (8,6)
                       분할선
```

### ② 각 절반의 최근접을 재귀로

절반이 작으면(≤3점) 전수 비교. 왼쪽에서 가장 가까운 쌍의 거리 `dL`, 오른쪽에서 `dR` 을 구한다.
`d = min(dL, dR)`.

### ③ 분할선을 가로지르는 쌍 — 띠(strip)만

가장 가까운 쌍이 **분할선을 사이에 두고** 갈라져 있을 수도 있다. 하지만 그런 쌍은 분할선에서
**좌우 `d` 안**에 있어야 한다(더 멀면 `d` 보다 가까울 수 없다). 이 좁은 **띠** 안의 점만 검사한다.

```
분할선 좌우로 폭 2d 인 띠 안의 점만 모은다 → y 로 정렬
각 점은 y 방향으로 가까운 몇 개(상수 개)만 비교하면 된다
```

### 왜 띠 안에서 상수 개만?

띠 안에서 한 점 주위 `d × d` 칸을 보면, "서로 `d` 이상 떨어져야 한다"는 성질(각 절반은 이미 `d`
간격) 때문에 그런 상자 안에 점이 **많아야 상수 개(≈ 8)** 밖에 없다. 그래서 y 정렬 후 이웃 몇 개만 본다.

### 답

이 예에서 최근접은 거리² = 5 인 쌍이다(예: `(6,7)`–`(8,6)`). 분할선을 넘는 쌍까지 확인해 확정한다.

### 비용

```
정렬: O(n log n)  (한 번)
재귀: T(n) = 2T(n/2) + O(n)   (띠 검사가 O(n))  →  O(n log n)
```

## 아이디어 쌓기

### 1단계 — 모든 쌍은 낭비

`O(n²)` 은 멀리 떨어진 쌍까지 다 본다. 공간을 나누면 대부분 걸러진다.

### 2단계 — x 로 나눠 재귀

분할선으로 반씩, 각 절반의 최근접을 따로 구한다(분할 정복).

### 3단계 — 경계의 띠만 병합

분할선을 넘는 후보는 폭 `2d` 띠 안에만. 그 밖은 볼 필요 없다.

### 4단계 — 띠 안 상수 개 비교

y 로 정렬하면 각 점당 상수 개만 비교 → 병합이 `O(n)`.

## 코드로 옮기기

```cpp
long long closest(vector<P>& px) {
    int n = px.size();
    if (n <= 3) return brute(px);            // 작으면 전수 비교
    int mid = n / 2;
    long long midX = px[mid].x;              // 세로 분할선
    long long dl = closest(left half);       // 왼쪽 재귀
    long long dr = closest(right half);      // 오른쪽 재귀
    long long d = min(dl, dr);
    vector<P> strip = { |x - midX|² < d 인 점 };
    sort(strip by y);
    for (i : strip)
        for (j : 다음 몇 개, y차²<d)
            d = min(d, dist²(strip[i], strip[j]));
    return d;
}
```

거리는 **제곱**으로 비교해 제곱근·부동소수점을 피한다(정수 좌표면 전 과정 정수).

## 자주 하는 실수

**띠 폭을 잘못 잡는다.** 분할선 좌우 `d`(총 `2d`) 안의 점만. 이보다 넓으면 낭비, 좁으면 답을 놓친다.

**띠를 y 로 정렬 안 한다.** y 정렬 없이 띠 안 모든 쌍을 보면 최악 `O(n²)`. y 정렬 + 이웃 상수 개가 핵심.

**제곱근을 남발한다.** 거리 비교는 제곱으로 충분. 정수 좌표면 오차도 없다.

**병합 정렬처럼 y 정렬을 매번 새로.** 재귀에서 y 정렬 결과를 병합해 올리면 로그 인자를 아낀다
(구현 최적화).

## 스스로 확인하기

1. **세로 분할선**이 점들을 좌우로 나누는 것을 보자.
2. **각 절반의 전수 비교**(기저)에서 후보 거리가 갱신되는 것을 보자.
3. **현재 최근접 쌍이 선으로** 그려지는 것을 보자(거리가 줄면 갱신).
4. **띠 검사**에서 분할선 근처 점만 강조되어 비교되는 것을 보자.
5. **분할선을 넘는 쌍**이 최종 답이 되는 경우가 있는지 관찰하자.
6. 점을 바꿔 보자 — 답이 항상 전수 비교 결과와 같다.

아래 **깊이 보기**에서는 띠 안 상수 개 비교의 증명, `T(n)=2T(n/2)+O(n)` 점화식,
스위프라인 대안과 3차원 확장을 다룬다.
