## 한눈에

정렬된 배열에서 후보 구간의 가운데를 보고 절반을 버린다. 비교 `⌊log₂ n⌋ + 1` 번 안에 끝난다.

- **시간** `Θ(log n)` (운 좋으면 `O(1)`) · **공간** `O(1)` — 반복문이면 재귀 스택도 없다
- **전제**: 배열이 정렬돼 있어야 한다. 이 전제가 깨지면 **조용히 틀린다**
- **중복이 있으면 아무 위치**나 준다. 첫/마지막이 필요하면 `lower_bound`/`upper_bound` 꼴로
- 실무에서 더 자주 쓰는 것은 "찾기" 가 아니라 **삽입 위치**(`lower_bound`)다

**언제 쓰나** — 정렬된 정적 배열에 질의가 많을 때. 그리고 훨씬 넓게, **"판정이 단조로운
답 공간"** 을 탐색할 때(매개 변수 탐색). "최소 용량", "최대 최소값" 류 문제의 표준 도구다.

**언제 안 쓰나** — 삽입·삭제가 잦으면 정렬을 유지하는 비용이 더 크다(균형 이진 탐색 트리로).
정확 일치만 필요하고 순서가 필요 없다면 해시 테이블이 기대 `O(1)` 로 더 빠르다.
`n` 이 아주 작으면(수십 이하) 선형 탐색이 캐시 지역성 덕에 실측으로 더 빠를 수 있다.

## 동작 원리

핵심은 **정렬이 비교 한 번을 여러 칸에 대한 판정으로 바꿔 준다**는 것이다.
`a[mid] < target` 을 알면 `a[0..mid]` 전체가 `target` 보다 작음까지 따라온다.

상태는 후보 구간 `[lo, hi]` 두 정수뿐이다.

```
mid = lo + (hi - lo)/2
a[mid] == target  →  답은 mid
a[mid] <  target  →  lo = mid + 1
a[mid] >  target  →  hi = mid - 1
lo > hi           →  없다 (그리고 lo 가 삽입 위치)
```

### 실행 예

`a = [1, 2, 3, 5, 5, 6, 8, 9]`, `target = 6`

```
lo=0 hi=7  mid=3  a[3]=5 < 6  →  [0..3] 4칸 버림,  lo=4
lo=4 hi=7  mid=5  a[5]=6      →  찾았다 (인덱스 5)

후보 칸 수:  8 → 4 → 찾음        비교 2번
```

없는 값(`target = 7`)이면

```
lo=0 hi=7  mid=3  5 < 7  →  lo=4
lo=4 hi=7  mid=5  6 < 7  →  lo=6
lo=6 hi=7  mid=6  8 > 7  →  hi=5
lo=6 > hi=5  →  없다.  lo=6 이 7 의 삽입 위치
```

## 정확성

> **불변식.** 반복 시작 시점에, `target` 이 `a` 에 존재한다면 그 위치는 `[lo, hi]` 안에 있다.

**기저** — `lo = 0`, `hi = n-1` 이므로 후보 구간이 배열 전체다. 자명하다. ✓

**유지** — `mid ∈ [lo, hi]` 이다(아래 종료성 논증에서 확인). 세 경우를 본다.

- `a[mid] == target` — 즉시 반환하므로 반복이 이어지지 않는다.
- `a[mid] < target` — `a` 가 비내림차순이므로 모든 `k ≤ mid` 에 대해 `a[k] ≤ a[mid] < target`.
  따라서 `[lo, mid]` 에는 `target` 이 없다. 남은 후보는 `[mid+1, hi]` 이고, 새 `lo = mid+1` 이
  정확히 그것이다. 불변식이 유지된다.
- `a[mid] > target` — 대칭으로 모든 `k ≥ mid` 에 대해 `a[k] ≥ a[mid] > target`.
  `[mid, hi]` 에 없으므로 `hi = mid-1` 로 좁혀도 답을 잃지 않는다.

**종료** — 루프는 `lo > hi` 로 빠져나온다. 그 시점의 후보 구간은 공집합이고, 불변식에 의해
`target` 이 존재한다면 그 안에 있어야 한다. 공집합에는 아무것도 없으므로 **`target` 은 없다**. ∎

### 종료성 — 후보가 반드시 줄어든다

`len = hi - lo + 1 ≥ 1` 이라 하자. `mid = lo + ⌊(len-1)/2⌋` 이므로 `lo ≤ mid ≤ hi` 다.

- `lo = mid + 1` 로 가면 새 길이는 `hi - mid = len - 1 - ⌊(len-1)/2⌋ = ⌈(len-1)/2⌉ < len`
- `hi = mid - 1` 로 가면 새 길이는 `mid - lo = ⌊(len-1)/2⌋ < len`

두 경우 모두 길이가 **엄격히 감소**하고 음수가 될 수 없으므로 유한 번에 `lo > hi` 가 된다.
`mid` 를 후보에서 제외하는 `±1` 이 이 엄격 감소의 근거다 —
`lo = mid` 로 쓰면 `len = 2` 에서 `mid = lo` 라 길이가 줄지 않고 **무한 루프**가 된다.

### 삽입 위치의 정당성

> 루프가 끝난 시점의 `lo` 는 `a` 의 정렬을 유지하며 `target` 을 끼워 넣을 수 있는 위치다.

`lo` 는 `a[mid] < target` 인 `mid` 에 대해서만 `mid+1` 로 갱신되므로, 종료 시
`a[k] < target` 인 모든 `k` 는 `k < lo` 를 만족한다. 대칭으로 `hi` 는 `a[mid] > target` 일 때만
줄어들므로 `a[k] > target` 인 모든 `k` 는 `k > hi = lo - 1`, 즉 `k ≥ lo` 다.
따라서 `lo` 앞은 모두 `target` 미만, `lo` 부터는 모두 `target` 초과다. ∎

## 복잡도

| | 시간 | 공간 |
|---|---|---|
| 최선 | `Θ(1)` (첫 `mid` 가 답) | `O(1)` |
| 평균 | `Θ(log n)` | `O(1)` |
| 최악 | `Θ(log n)` | `O(1)` |

**시간** — 후보 길이가 `len` 에서 최대 `⌈(len-1)/2⌉` 로 줄므로, `t` 번 반복 후 길이는

```
len_t ≤ n / 2^t
```

`len_t < 1` 이 되는 최소 `t` 는 `t = ⌈log₂ n⌉` 이고, 비교 횟수는 `⌊log₂ n⌋ + 1` 을 넘지 않는다.

```
n = 8      →  4번
n = 10^6   →  20번
n = 10^9   →  30번
```

**공간** — 반복문 구현은 변수 세 개뿐이다. 재귀로 쓰면 꼬리 재귀라 컴파일러가 보통 펴 주지만,
보장이 필요하면 반복문으로 쓰는 편이 안전하다.

### 하한 — 이보다 빠를 수 없다

비교 기반 모델에서 정렬된 `n` 개 중 하나를 찾는(또는 없음을 확인하는) 문제의 하한은
`Ω(log n)` 이다. **결정 트리 논증**으로 본다.

한 번의 비교는 `<`, `==`, `>` 세 갈래를 낳지만, 구별해야 하는 결과는
"각 위치에 있음" `n` 가지 + "없음(삽입 위치)" `n+1` 가지 = `2n+1` 가지다.
깊이 `d` 인 삼분 결정 트리의 잎은 최대 `3^d` 개이므로

```
3^d ≥ 2n + 1   →   d ≥ log₃(2n+1) = Ω(log n)
```

즉 이분 탐색은 상수 배 안에서 최적이다. 이보다 빠르려면 비교가 아닌 정보를 써야 하고,
그것이 보간 탐색(값의 분포)과 해시(계산)다.

## 구현 노트

**오버플로** — `mid = (lo + hi) / 2` 는 `lo + hi > INT_MAX` 에서 깨진다.
`mid = lo + (hi - lo) / 2` 를 쓴다. 자바 `Arrays.binarySearch` 에 9년간 남아 있던 버그다.

**반열린 구간 관례** — `[lo, hi)` 로 쓰면 조건이 `lo < hi`, 갱신이 `hi = mid` 가 된다.
어느 쪽이든 좋지만 **한 코드 안에서 섞지 마라.** 이 페이지는 닫힌 구간 `[lo, hi]` 를 쓴다.

**중복** — 이 구현은 임의의 일치 위치를 준다. `[5,5,5,5]` 에서 인덱스 1을 반환한다.

**표준 라이브러리** — 직접 쓸 일은 사실 드물다.

```cpp
lower_bound(a.begin(), a.end(), x);   // x 이상이 처음 나오는 위치
upper_bound(a.begin(), a.end(), x);   // x 초과가 처음 나오는 위치
binary_search(a.begin(), a.end(), x); // 존재 여부(bool)
equal_range(a.begin(), a.end(), x);   // 두 경계를 한 번에
```

`upper_bound(x) - lower_bound(x)` 가 `x` 의 개수다.

## 변형과 확장

### lower_bound — 경계를 찾는 형태

"찾았으면 즉시 반환" 을 없애고 **끝까지 좁힌다.** 실무에서 더 유용한 쪽이다.

```cpp
int lowerBound(vector<int>& a, int x) {   // x 이상이 처음 나오는 위치
    int lo = 0, hi = a.size();            // 반열린 [lo, hi)
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] < x) lo = mid + 1;     // mid 는 답이 아니다
        else            hi = mid;         // mid 가 답일 수 있다 → 남긴다
    }
    return lo;
}
```

`==` 분기가 사라져 코드가 짧아지고, 중복이 있어도 **항상 첫 위치**를 준다.
`else hi = mid` 에서 `mid` 를 버리지 않는 것이 "답일 수 있는 후보를 남긴다" 는 뜻이다.

### 매개 변수 탐색 — 답 자체를 이분한다

배열이 아니라 **답의 범위**를 이분한다. 조건이 **단조**롭기만 하면 된다.

```
어떤 값 x 에 대해 판정 P(x) 가
  x 가 작을 때 거짓, 어떤 지점부터 계속 참    (단조)
이면, 그 경계를 이분 탐색으로 찾을 수 있다.
```

```cpp
int lo = 0, hi = UPPER;
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (feasible(mid)) hi = mid;    // 되면 더 줄여 본다
    else               lo = mid + 1;
}
// lo = 가능한 최솟값
```

"랜선 자르기", "나무 자르기", "K개로 나눌 때 최대 구간합 최소화" 가 모두 이 꼴이다.
**핵심은 `feasible` 이 단조인지 확인하는 것**이고, 그게 정렬 전제를 대신한다.

### 실수 범위 이분 탐색

정수가 아니면 "후보가 빈다" 는 조건이 없으므로 **횟수로 끊는다.**

```cpp
for (int iter = 0; iter < 100; iter++) {       // 2^-100 배까지 좁혀진다
    double mid = (lo + hi) / 2;
    if (feasible(mid)) hi = mid; else lo = mid;
}
```

`while (hi - lo > EPS)` 는 EPS 를 잘못 잡으면 무한 루프가 되므로 고정 횟수가 안전하다.

### 회전된 정렬 배열

`[4,5,6,7,0,1,2]` 처럼 한 번 회전된 배열에서도 `O(log n)` 이 가능하다.
`a[mid]` 와 `a[lo]` 를 비교해 **어느 쪽 절반이 정렬돼 있는지**를 먼저 판정하면,
그 절반 안에 target 이 있는지를 상수 시간에 결정할 수 있다.

### 보간 탐색 — 하한을 넘는 방법

값이 균등 분포라면 `mid` 를 가운데가 아니라 **값에서 추정한 위치**로 잡는다.
기대 `O(log log n)` 이다. 비교 외의 정보(값의 크기)를 쓰기 때문에 위의 하한에 걸리지 않는다.
다만 분포가 치우치면 최악 `O(n)` 이라 실무에서는 드물다.
