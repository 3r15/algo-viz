## 어떤 문제인가

정수 배열을 정렬한다. 그런데 지금까지의 정렬(버블·퀵·병합·힙)은 전부 **값을 비교**했다.

```
a[i] < a[j] 인가?   ← 비교
```

비교로 정렬하면 아무리 잘해도 `O(n log n)` 이 벽이다(정보 이론적 하한).
그런데 조건이 하나 붙으면 이 벽을 넘을 수 있다.

> **값의 범위가 좁다면** — 예컨대 0..9 나 시험 점수 0..100 —
> 비교하지 말고 **각 값이 몇 번 나오는지 세기만** 하면 되지 않을까?

## 손으로 해보기

기본 입력 `[4, 2, 2, 6, 3, 3, 1, 5]` 로 끝까지 가 보자. 값이 1..6 뿐이다.

### ① 개수를 센다

값마다 **칸(버킷)** 을 하나씩 두고, 배열을 훑으며 해당 칸을 올린다.

```
        1  2  3  4  5  6
count:  0  0  0  0  0  0     ← 처음

a=4 → count[4]++
a=2 → count[2]++
a=2 → count[2]++
...

        1  2  3  4  5  6
count:  1  2  2  1  1  1     ← 다 센 뒤
```

`2` 가 두 번, `3` 이 두 번 나왔다는 게 칸에 담겼다. **비교는 한 번도 안 했다.**

### ② 작은 값부터 다시 늘어놓는다

칸을 `1` 부터 순서대로 보며, 센 횟수만큼 값을 배열에 채운다.

```
count[1]=1  →  1 을 한 번:        1
count[2]=2  →  2 를 두 번:        1 2 2
count[3]=2  →  3 을 두 번:        1 2 2 3 3
count[4]=1  →  4 를 한 번:        1 2 2 3 3 4
count[5]=1  →  5 를 한 번:        1 2 2 3 3 4 5
count[6]=1  →  6 을 한 번:        1 2 2 3 3 4 5 6
```

**끝. 정렬됐다.** 작은 값부터 꺼냈으니 저절로 오름차순이다.

### 비용을 세어 보자

```
① 세기:      배열을 한 번 훑는다        n번
② 늘어놓기:  칸을 훑으며 원소를 놓는다   n + (칸 수)번
합계:  O(n + k)         k = 값의 범위
```

`n = 100만` 이고 값이 0..100 이면 약 **100만 번**이다.
비교 정렬의 `n log n ≈ 2천만` 과 비교해 보자.

### 왜 비교의 벽을 넘나

비교 정렬은 "어느 게 큰가?" 만 물어 정보를 조금씩 모은다. 그래서 `log(n!) ≈ n log n` 번이 필요하다.
계수 정렬은 **값을 곧바로 위치(칸 번호)로 쓴다** — 비교로 정보를 캐지 않고 값 자체를 이용한다.
"값이 곧 자리" 라는 이 도약이 하한을 우회하는 비결이다.

### 공짜가 아니다

칸을 값마다 하나씩 둬야 한다. 값이 `1..10억` 이면 칸이 10억 개 — 메모리가 터진다.
**값의 범위 `k` 가 작을 때만** 쓸모 있다. `k` 가 `n` 보다 훨씬 크면 오히려 손해다.

## 아이디어 쌓기

### 1단계 — 비교 대신 값을 이용한다

값의 범위가 좁으면 "값 = 칸 번호" 로 삼을 수 있다. 비교가 사라진다.

### 2단계 — 세기

각 값의 개수를 칸에 담는다. 배열 한 번 훑기, `O(n)`.

### 3단계 — 작은 값부터 펼치기

칸을 오름차순으로 보며 센 만큼 늘어놓으면 정렬 순서가 저절로 나온다.

### 4단계 — 범위를 확인한다

`k`(값 범위)가 `n` 규모를 넘지 않아야 이득이다. 넘으면 다른 정렬을 쓴다.

## 코드로 옮기기

```cpp
void countingSort(vector<int>& a, int lo, int hi) {
    vector<int> count(hi - lo + 1, 0);
    for (int x : a) count[x - lo]++;        // ① 세기
    int pos = 0;
    for (int v = 0; v <= hi - lo; v++)       // ② 작은 값부터
        while (count[v]-- > 0)               //    센 횟수만큼
            a[pos++] = v + lo;               //    늘어놓는다
}
```

`x - lo` 로 **값을 0부터 시작하는 칸 번호로** 옮긴다(음수나 큰 시작값도 다루려는 오프셋).

## 자주 하는 실수

**범위가 넓은 데 쓴다.** 값이 `0..10억` 이면 칸이 10억 개다. `k ≲ n` 일 때만 쓴다.

**오프셋을 빼먹는다.** 값이 `50..100` 이면 칸을 51개만 두고 `x - 50` 으로 접근해야 한다.
`count[x]` 로 바로 쓰면 배열 밖을 읽는다.

**안정성을 신경 안 쓴다.** 위 단순 버전은 값만 다시 만들어 내므로, 원소에 딸린 부가 정보(키-값 쌍)가
있으면 순서가 보존되지 않는다. **안정** 계수 정렬은 누적 합(prefix sum)으로 원소를 제자리에 놓는다 —
[기수 정렬](#/algo/radix-sort)이 바로 이 안정 버전을 쓴다.

**실수(소수)에 쓴다.** 칸 번호는 정수여야 한다. 소수는 값을 칸으로 쓸 수 없다.

## 스스로 확인하기

1. **① 세기 단계**에서 버킷이 하나씩 올라가는 것을 보자. 배열 원소를 강조하고 그 값의 칸을 올린다.
2. **`2` 와 `3` 의 칸이 2가 되는 것**을 보자. 중복이 개수로 담긴다.
3. **② 늘어놓기 단계**에서 배열이 왼쪽부터 초록으로 채워지는 것을 보자. 버킷은 줄어든다.
4. **비교 횟수 0** 을 마지막 설명에서 확인하자.
5. 입력을 `9 8 7 6 5` 로 바꿔 보자. 역순인데도 비교 없이 정렬된다.
6. 입력을 `3 3 3 3` 로 바꿔 보자. 한 칸만 4가 되고 그 칸만 비운다.
7. 입력을 `5 2 9 1 5 6` 로 바꿔 보자. 값 범위가 1..9 로 넓어져 빈 칸(0)이 생긴다 —
   빈 칸은 그냥 건너뛴다.

아래 **깊이 보기**에서는 비교 정렬의 `Ω(n log n)` 하한을 왜 우회할 수 있는지 정리하고,
안정 버전(누적 합)과 기수 정렬로의 확장을 다룬다.
