## 한눈에

값을 비교하지 않는다. 각 값의 출현 횟수를 세어 작은 값부터 다시 늘어놓는다.
값의 범위 `k` 가 좁을 때 **비교 정렬의 `Ω(n log n)` 하한을 우회**해 `Θ(n + k)` 에 정렬한다.

- **시간** `Θ(n + k)` — 입력과 무관하게 일정 · **공간** `Θ(n + k)`
- **안정 정렬로 만들 수 있다**(누적 합 버전) — 그래서 [기수 정렬](#/algo/radix-sort)의 부품이 된다
- **범위가 좁아야** 쓸모 있다. `k ≫ n` 이면 손해
- 정수(또는 정수 키로 사상 가능한 값)만 대상

**언제 쓰나** — 값 범위가 작은 정수(점수 0~100, 나이, 소문자 a~z, 픽셀 0~255).
기수 정렬의 자릿수 정렬, 버킷 정렬의 버킷 내 정렬로도 쓰인다.
`k = O(n)` 이면 선형 시간 정렬이 된다.

**언제 안 쓰나** — 값 범위가 크거나(`k ≫ n`) 미리 모를 때, 실수·문자열·일반 비교 키일 때.
그럴 땐 [퀵 정렬](#/algo/quick-sort)·[병합 정렬](#/algo/merge-sort) 같은 비교 정렬을 쓴다.

## 동작 원리

핵심은 **값을 배열 인덱스로 직접 쓰는 것**이다. 비교로 정보를 캐내지 않고, 값 자체가 위치를 정한다.

```
① for x in a:  count[x − lo]++            각 값의 개수
② pos = 0
   for v in lo..hi:
       count[v−lo] 번 만큼  a[pos++] = v   작은 값부터 펼치기
```

### 실행 예

`a = [4, 2, 2, 6, 3, 3, 1, 5]`, 범위 1..6

```
count:  [1](1) [2](2) [2](3) [1](4) [1](5) [1](6)
펼치기: 1 · 2 2 · 3 3 · 4 · 5 · 6   →  [1,2,2,3,3,4,5,6]
```

### 안정 버전 — 누적 합

단순 버전은 값을 새로 만들어 내므로 원소에 딸린 데이터를 보존하지 못한다.
**누적 합(prefix sum)** 으로 각 값의 시작 위치를 구하고, 입력을 **뒤에서부터** 출력에 놓으면
같은 값끼리 원래 순서가 유지된다(안정).

```cpp
for (int v = 1; v <= k; v++) count[v] += count[v-1];   // 누적 합
for (int i = n - 1; i >= 0; i--)                        // 뒤에서(안정성)
    out[--count[a[i] - lo]] = a[i];
```

이 안정성이 기수 정렬을 가능하게 한다.

## 정확성

> **불변식.** ① 단계가 끝난 뒤, 모든 `v` 에 대해 `count[v−lo]` 는 `a` 에서 값 `v` 의 출현 횟수와 같다.

각 원소가 정확히 한 번 자기 값의 칸을 1 올리므로 자명하다.

> **정리.** ② 단계가 끝나면 `a` 는 원래 원소들의 오름차순 정렬(다중집합으로 동일)이다.

**다중집합 보존** — ② 는 값 `v` 를 정확히 `count[v−lo]` 번 쓴다. 불변식에 의해 이는 원래 `v` 의
개수와 같으므로, 출력의 값 다중집합이 입력과 같다.

**순서** — 바깥 루프가 `v` 를 오름차순으로 돌고, 같은 `v` 는 연속해서 놓인다. 따라서 `pos` 가
증가하며 놓이는 값은 비감소다. 즉 `a[0] ≤ a[1] ≤ … ≤ a[n-1]`. ∎

**종료성** — ① 은 `n` 번, ② 는 각 `count` 를 0까지 내리므로 총 `n` 번 + 칸 순회 `k` 번. 유한.

### 안정성 (누적 합 버전)

> `a[i]` 와 `a[j]` 가 같은 값이고 `i < j` 이면, 출력에서도 `a[i]` 가 `a[j]` 보다 앞이다.

**증명.** 입력을 `i = n-1 … 0` 으로 훑으며 `out[--count[v]]` 에 놓는다. `count[v]` 는 매번 1 줄므로,
**나중에 처리되는(= 인덱스가 작은)** 원소가 **더 앞(작은 인덱스)** 자리를 받는다.
`i < j` 이면 `i` 가 나중에 처리되어 더 앞에 놓인다. ∎

## 복잡도

| | 시간 | 공간 |
|---|---|---|
| 최선/평균/최악 | `Θ(n + k)` | `Θ(n + k)` |

`k = O(n)` 이면 `Θ(n)` — **선형 정렬**이다. 조기 종료가 없어 세 경우가 모두 같다.

### 왜 비교 하한을 넘나

비교 정렬은 각 비교가 `<`/`=`/`>` 세 결과를 낳는 **결정 트리**로 모형화된다.
`n` 개의 순열 `n!` 가지를 구별하려면 잎이 `n!` 개 이상이어야 하므로 깊이(=최악 비교 횟수)가

```
d ≥ log₂(n!) = Θ(n log n)          (스털링 근사)
```

즉 **비교만으로는 `Ω(n log n)` 이 하한**이다. 계수 정렬은 이 모형 **밖**에 있다 —
값을 비교하지 않고 **인덱스로 사용**하므로 결정 트리 논증이 적용되지 않는다.
대가로 "값이 작은 정수" 라는 가정을 쓴다. 하한을 깨는 게 아니라 **다른 게임을 하는 것**이다.

### 공간이 진짜 제약

`k` 가 크면 `count` 배열이 메모리를 삼킨다. `k = 10⁹` 이면 40억 바이트다.
시간이 `Θ(n+k)` 라도 공간 때문에 못 쓴다. 이 벽을 우회하는 것이 **기수 정렬**(자리별로 `k=10`)과
**버킷 정렬**(구간으로 나눔)이다.

## 구현 노트

**오프셋** — 값이 `[lo, hi]` 면 칸 크기는 `hi − lo + 1`, 접근은 `count[x − lo]`.

**음수** — 오프셋으로 자연히 처리된다(`lo` 가 음수여도 됨).

**안정성이 필요하면** 누적 합 버전을 쓴다. 기수 정렬·"값+데이터" 정렬에서 필수다.

**최댓값을 모를 때** 한 번 훑어 `min`/`max` 를 구한다(`O(n)`). 다만 그 범위가 크면
계수 정렬 자체가 부적합하다는 신호다.

**제자리(in-place) 아님** — 출력 배열 또는 카운트 배열이 별도로 필요하다.

## 변형과 확장

### 기수 정렬 — 큰 범위를 자리로 쪼갠다

`k` 가 커서 못 쓸 때, 값을 자릿수로 나눠 **자리마다 계수 정렬**(`k = 진법`)을 반복한다.
안정 계수 정렬이 핵심 부품이다. → [기수 정렬](#/algo/radix-sort).

### 버킷 정렬 — 구간으로 나눈다

값을 `n` 개의 구간(버킷)에 분배하고 각 버킷을 정렬한 뒤 이어 붙인다.
값이 균등 분포면 기대 `O(n)`. 각 버킷 내부를 계수 정렬로 처리하기도 한다.

### 히스토그램·빈도 분석

정렬이 목적이 아니라 `count[]` 자체가 답인 경우가 많다 — 최빈값, 중앙값(누적 합으로),
"k번째로 작은 값" 등을 `count` 로 `O(n + k)` 에 구한다.

### 카운팅 정렬 기반 안정 부분 정렬

`k` 가 작은 키(예: 카드의 무늬)로 안정 정렬하면, 여러 키를 낮은 자리부터 순서대로 적용해
다중 키 정렬(사전식)을 만들 수 있다. 기수 정렬이 이 원리다.
