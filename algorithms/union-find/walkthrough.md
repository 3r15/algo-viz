## 어떤 문제인가

원소가 여럿 있고, 이들이 여러 **그룹(집합)** 으로 나뉜다. 두 가지를 빠르게 하고 싶다.

```
unite(a, b)  — a 가 속한 그룹과 b 가 속한 그룹을 하나로 합친다
same(a, b)   — a 와 b 가 지금 같은 그룹인가?
```

예를 들어 친구 관계를 합쳐 가며 "이 둘은 (직접이든 건너서든) 이어져 있나?" 를 묻는 것이다.
[크루스칼](#/algo/kruskal)이 간선을 더할 때 "사이클이 생기나?" 를 판정하는 것도 정확히 이 문제다.

순진하게 각 그룹을 리스트로 들고 다니면, 합칠 때마다 한쪽을 전부 복사해 `O(n)` 이 든다.
**거의 상수 시간**에 이 둘을 하려면 어떻게 저장해야 할까?

## 손으로 해보기

핵심 아이디어: 각 그룹을 **뿌리를 가진 나무**로 표현한다. 그룹의 "이름" 은 그 나무의 **뿌리** 다.
`parent[x]` 는 x 의 부모를 가리키고, 뿌리는 `parent[x] == x`.

기본 입력 `0 1 · 2 3 · 4 5 · 1 2 · 0 3 · 5 6` (쌍마다 unite)로 가 보자.

### 처음 — 모두 홀로

```
parent: 0 1 2 3 4 5 6      (각자 자기 자신이 뿌리)
숲:     0  1  2  3  4  5  6   (일곱 그루의 홀로 선 나무)
```

### unite(0,1), unite(2,3), unite(4,5)

각 쌍의 뿌리를 찾아, 하나를 다른 하나 **아래에 매단다**.

```
parent[1]=0, parent[3]=2, parent[5]=4
숲:   0     2     4      6
      |     |     |
      1     3     5
```

### unite(1,2) — 서로 다른 나무를 합친다

`find(1)` → 뿌리 0. `find(2)` → 뿌리 2. 다르니 합친다. 크기가 같으니 2를 0 아래로.

```
      0            4      6
     / \           |
    1   2          5
        |
        3
```

### unite(0,3) — 이미 한 그룹

`find(0)` → 0. `find(3)` → 3의 부모는 2, 2의 부모는 0 → 뿌리 0. **두 뿌리가 같다!**
이미 한 그룹이므로 아무것도 하지 않는다. (`same(0,3)` 이 참이라는 뜻)

### 경로 압축 — find 하는 김에 지름길을 낸다

`find(3)` 이 `3 → 2 → 0` 을 거쳐 뿌리 0을 찾았다. 그렇다면 **3을 아예 0에 직접 매달아** 두자.
다음에 `find(3)` 은 한 걸음이면 된다.

```
      0                      0
     /|\        압축 후      /|\
    1 2 3   ←──────────    1 2 3   (3이 2 밑이 아니라 0 바로 밑으로)
      |
      3
```

이 **경로 압축**이 유니온 파인드를 거의 상수 시간으로 만드는 첫 번째 비결이다.

## 아이디어 쌓기

### 1단계 — 그룹을 뿌리로 대표한다

각 그룹을 나무로, 그룹의 이름을 뿌리로 삼는다. `same(a,b)` = `find(a) == find(b)`.

### 2단계 — find: 부모를 따라 뿌리까지

`parent[x]` 를 계속 따라 올라가 `parent[x] == x` 인 뿌리를 만난다.

### 3단계 — 경로 압축으로 나무를 납작하게

find 하며 지나온 노드를 뿌리에 직접 매단다. 나무가 납작해져 다음 find 가 빨라진다.

### 4단계 — 크기로 합친다(union by size)

합칠 때 **작은 나무를 큰 나무 아래**에 붙인다. 나무 높이가 천천히 자라 find 가 짧게 유지된다.

## 코드로 옮기기

```cpp
int parent[MAXN], sz[MAXN];
void init(int n) {
    for (int i = 0; i < n; i++) parent[i] = i, sz[i] = 1;   // 각자 자기 집합
}
int find(int x) {
    if (parent[x] == x) return x;             // 뿌리를 찾았다
    return parent[x] = find(parent[x]);       // 경로 압축: 뿌리에 직접 매단다
}
void unite(int a, int b) {
    a = find(a); b = find(b);                 // 각자의 뿌리
    if (a == b) return;                       // 이미 같은 집합
    if (sz[a] < sz[b]) swap(a, b);            // 큰 나무에 붙인다(랭크)
    parent[b] = a;                            // b 의 뿌리를 a 아래로
    sz[a] += sz[b];                           // 크기 합치기
}
```

`find` 의 `parent[x] = find(...)` 한 줄이 경로 압축이다 — 재귀가 뿌리를 들고 돌아오며
지나온 모든 노드의 부모를 뿌리로 바꾼다.

## 자주 하는 실수

**뿌리를 안 찾고 원소끼리 바로 잇는다.** `parent[b] = a` 가 아니라 `parent[find(b)] = find(a)`
여야 한다. 뿌리가 아닌 노드를 이으면 두 나무가 제대로 안 합쳐진다.

**크기(또는 랭크)로 안 합친다.** 항상 b를 a 밑에 붙이면 한 줄로 길게 자라(사슬), find 가 `O(n)` 이 된다.
작은 쪽을 큰 쪽에 붙여야 높이가 눌린다.

**경로 압축을 빼먹는다.** 압축이 없으면 최악에 `O(log n)`, 있으면 거의 `O(1)`. 한 줄이면 되니 꼭 넣자.

**같은 그룹인데 또 합치려 한다.** `find(a) == find(b)` 면 즉시 멈춰야 한다 — 크루스칼에서
이 검사가 곧 "사이클 판정" 이다.

## 스스로 확인하기

1. **unite 마다 두 번의 find** 가 먼저 일어나는 것을 보자. 뿌리를 찾아야 합칠 수 있다.
2. **unite(0,3) 에서 "이미 한 집합"** 이 뜨는 것을 보자 — 두 뿌리가 0으로 같다.
3. **경로 압축 스텝**에서 노드가 뿌리에 직접 매달리며 나무가 납작해지는 것을 보자.
4. **크기 비교 스텝**에서 큰 나무가 뿌리가 되는 것을 보자(sz 행 강조).
5. matrix 의 **parent 행·sz 행**이 나무 그림과 어떻게 대응하는지 확인하자.
6. 입력을 `0 1 1 2 2 3 3 4` 로 바꿔 보자 — 사슬처럼 이어 붙지만 압축이 곧 납작하게 만든다.

아래 **깊이 보기**에서는 두 최적화가 왜 상각 `O(α(n))` 을 주는지(역아커만 함수), 그리고
[크루스칼](#/algo/kruskal)·연결 요소·오프라인 질의로의 확장을 다룬다.
