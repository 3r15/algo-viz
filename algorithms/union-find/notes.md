## 한눈에

서로소 집합(disjoint set)들을 **뿌리 있는 나무의 숲**으로 관리한다. 두 연산 `find`(대표 찾기)와
`unite`(합치기)를, **경로 압축**과 **크기(랭크)로 합치기** 두 최적화로 상각 `O(α(n))` 에 처리한다.
`α` 는 역아커만 함수 — `n` 이 우주의 원자 수여도 4 이하라, 사실상 상수다.

- **시간** 상각 `O(α(n))` / 단일 최악 `O(log n)` · **공간** `O(n)`
- 두 최적화를 **함께** 써야 `O(α(n))` — 하나만 쓰면 `O(log n)`
- `same(a,b)` = `find(a) == find(b)` · 삭제·분리는 지원 안 함(합치기 전용)
- [크루스칼](#/algo/kruskal)의 사이클 판정, 연결 요소, 오프라인 질의의 핵심 부품

**언제 쓰나** — 원소들이 점점 **합쳐지기만** 하는 상황에서 "같은 그룹인가"·"그룹 수"·"그룹 크기" 를
빠르게. MST(크루스칼), 그래프 연결성, 같은 집합 판정, 오프라인 쿼리(역순 처리) 등.

**언제 안 쓰나** — 그룹을 **쪼개야** 할 때(유니온 파인드는 분리를 못 한다), 원소 목록 자체를
자주 열거해야 할 때. 동적 분리는 링크-컷 트리나 다른 구조가 필요하다.

## 동작 원리

각 집합은 하나의 나무이고, 집합의 **대표(canonical id)** 는 그 뿌리다. `parent[x]` 가 부모,
뿌리는 `parent[x] == x`.

```
find(x)     : parent 를 따라 뿌리까지 올라간다. 올라가며 경로 압축.
unite(a, b) : ra=find(a), rb=find(b). 다르면 작은 나무를 큰 나무 밑에.
```

### 두 최적화

- **경로 압축(path compression)** — `find` 가 뿌리를 찾은 뒤, 경로 위 모든 노드를 뿌리에 직접 매단다.
  나무가 납작해져 이후 `find` 가 짧아진다. `parent[x] = find(parent[x])` 한 줄.
- **크기로 합치기(union by size)** 또는 **랭크로 합치기(union by rank)** — 합칠 때 항상
  작은(낮은) 나무를 큰(높은) 나무 밑에 붙인다. 나무 높이가 `O(log n)` 이하로 유지된다.

### 실행 예

`unite(0,1),(2,3),(4,5),(1,2),(0,3),(5,6)` → 두 집합 `{0,1,2,3}, {4,5,6}`.
`unite(0,3)` 은 두 뿌리가 이미 0으로 같아 아무 일도 하지 않는다(= `same(0,3)` 참).

## 정확성

> **불변식 1 (숲).** 매 순간 `parent[]` 는 사이클 없는 숲을 이룬다. 각 나무의 노드 집합이 정확히
> 하나의 서로소 집합이고, 그 나무의 뿌리가 대표다.

*유지.* `unite` 는 한 뿌리 `b` 의 부모를 다른 뿌리 `a` 로 바꾼다(`parent[b]=a`). `a, b` 가 서로 다른
나무의 뿌리이므로 사이클이 생기지 않고, 두 나무의 노드 집합이 하나로 합쳐진다.
경로 압축은 노드의 부모를 **같은 나무의 뿌리**로 바꿀 뿐이라 집합 구성원을 바꾸지 않는다. ∎

> **정리.** `find(a) == find(b)` ⟺ `a` 와 `b` 가 지금까지의 `unite` 로 같은 집합에 속한다.

불변식 1에서 두 원소가 같은 나무(=같은 집합)에 있음과 같은 뿌리를 가짐이 동치이므로 성립. ∎

### 높이 한계 (union by rank/size)

> **보조정리.** 크기로 합치면, 크기 `s` 인 나무의 높이는 `⌊log₂ s⌋` 이하.

*증명.* 귀납. 홀로 있는 노드는 크기 1, 높이 0. 크기 `s₁ ≤ s₂` 인 두 나무를 합쳐 `s₁` 을 `s₂` 밑에
붙이면, 새 높이는 `max(h₂, h₁+1)`. 귀납 가정 `h₁ ≤ log₂ s₁`, `h₂ ≤ log₂ s₂` 와
`s₁ ≤ (s₁+s₂)/2` 에서 `h₁+1 ≤ log₂ s₁ + 1 = log₂(2s₁) ≤ log₂(s₁+s₂)`. 따라서
새 높이 `≤ log₂(s₁+s₂)`. ∎ → 압축이 없어도 `find` 는 `O(log n)`.

## 복잡도

| 연산 | 압축만 | 랭크만 | 압축 + 랭크 |
|---|---|---|---|
| `find` / `unite` (상각) | `O(log n)` | `O(log n)` | `O(α(n))` |
| 최악 단일 연산 | `O(log n)` | `O(log n)` | `O(log n)` |

공간 `O(n)`(`parent`, `sz`).

### 왜 상각 `O(α(n))` 인가

타잔의 고전 결과: **경로 압축 + 랭크로 합치기**를 함께 쓰면 `m` 번 연산의 총비용이
`O(m · α(n))` 이다. `α` 는 아커만 함수의 역함수로, 실용 범위 `n` 에서 `α(n) ≤ 4`.
증명은 노드에 "레벨" 을 매기고 압축이 부모의 랭크를 급격히 키운다는 **회계(accounting)** 논증으로,
각 노드가 부담하는 총비용을 `α(n)` 으로 묶는다.

- **압축만** 또는 **랭크만** 쓰면 상각 `Θ(log n)` 으로 떨어진다(둘의 시너지가 핵심).
- 정보 이론적으로 `Ω(α(n))` 하한도 알려져 있어, 이 자료구조로는 더 못 줄인다.

## 구현 노트

**경로 압축의 두 형태** — 재귀형 `parent[x]=find(parent[x])`(완전 압축)과, 반복형
**경로 이등분(path halving)** `parent[x]=parent[parent[x]]`. 후자는 스택 없이 같은 상각을 준다.

**랭크 vs 크기** — 랭크(대략 높이)로 합치나 크기로 합치나 둘 다 `O(α(n))`. 크기가 부가 정보
(그룹 크기 질의)로 유용해 실전에서 자주 쓰인다.

**0-based vs 1-based** — `parent[i]=i` 초기화만 맞으면 무관.

**뿌리에만 부가 데이터** — 그룹 크기·합·최댓값 등은 **뿌리에만** 저장하고 `unite` 에서 병합한다.
비-뿌리에 저장하면 압축이 정보를 흩뜨린다.

**분리는 불가** — 한 번 합치면 못 가른다. "간선 삭제" 문제는 **역순 오프라인**(삭제를 뒤에서부터
합치기로)으로 우회한다.

## 변형과 확장

### 크루스칼 MST — 사이클 판정

[크루스칼](#/algo/kruskal)은 간선을 가중치 순으로 보며 `find(u) != find(v)` 일 때만 채택하고
`unite` 한다. 유니온 파인드가 "이 간선이 사이클을 만드나" 를 거의 상수에 답한다.

### 연결 요소·같은 집합 질의

간선을 모두 `unite` 한 뒤 서로 다른 뿌리의 수 = 연결 요소 수. 온라인으로 "지금 같은 그룹?" 도 즉답.

### 가중치 유니온 파인드 (weighted / potential DSU)

각 노드에 뿌리까지의 **상대값(퍼텐셜)** 을 함께 저장하면, "a 와 b 의 차이" 같은 관계를
유지·질의할 수 있다(예: 홀짝 관계, 화폐 환율). 압축 시 퍼텐셜도 함께 갱신한다.

### 오프라인 동적 연결성

간선 추가·삭제가 섞인 질의를, 시간 구간으로 나눠 **롤백 가능한 유니온 파인드**(압축 대신 랭크만 +
스택으로 되돌리기)로 처리한다. 압축을 포기해 `O(log n)` 이 되지만 되돌리기가 가능해진다.
