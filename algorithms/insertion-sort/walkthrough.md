## 어떤 문제인가

배열을 작은 순서대로 정렬하는 같은 문제다. 다만 이번에는 **카드 게임을 떠올려 보자.**

손에 카드를 정렬해서 들고 있는데, 새 카드를 한 장 받았다. 어떻게 하는가?

> 새 카드를 오른쪽 끝에 대 보고, **자기보다 큰 카드가 있으면 왼쪽으로 밀어 넣는다.**
> 자기보다 작거나 같은 카드를 만나면 거기가 제자리다.

사람이 실제로 하는 이 동작을 그대로 코드로 옮긴 것이 **삽입 정렬**이다.

## 손으로 해보기

`[5, 2, 9, 1, 5, 6]` 을 정렬해 보자. `|` 왼쪽이 **이미 정렬해 둔 부분**(=손에 든 카드)이고,
오른쪽이 아직 안 본 부분이다.

처음엔 카드가 한 장뿐이라고 치자. 한 장은 그 자체로 정렬돼 있다.

```
5 | 2 9 1 5 6
```

**2를 받았다.** 왼쪽의 5보다 작으니 넘어간다.

```
5 (2)          5 > 2 → 자리 바꿈
(2) 5          왼쪽 끝 도달 → 여기가 제자리
2 5 | 9 1 5 6
```

**9를 받았다.** 왼쪽의 5보다 크다. 바로 제자리다.

```
2 5 (9)        5 < 9 → 멈춤
2 5 9 | 1 5 6
```

**1을 받았다.** 왼쪽 끝까지 계속 밀린다.

```
2 5 (9 1)      9 > 1 → 바꿈
2 (5 1) 9      5 > 1 → 바꿈
(2 1) 5 9      2 > 1 → 바꿈
1 2 5 9 | 5 6  왼쪽 끝 도달
```

**5를 받았다.** 9보다는 작지만 5를 만나면 멈춘다.

```
1 2 5 (9 5)    9 > 5 → 바꿈
1 2 (5 5) 9    5 = 5 → 멈춤! (같으면 안 바꾼다)
1 2 5 5 9 | 6
```

**6을 받았다.**

```
1 2 5 5 (9 6)  9 > 6 → 바꿈
1 2 5 (5 6) 9  5 < 6 → 멈춤
1 2 5 5 6 9    ← 완성
```

`|` 왼쪽 구간이 **왼쪽에서 오른쪽으로** 자라는 것을 보자.
[버블 정렬](#/algo/bubble-sort)은 반대로 오른쪽에서 왼쪽으로 자란다.

## 아이디어 쌓기

### 1단계 — 지킬 약속 하나를 정한다

이 알고리즘의 전부는 다음 한 문장이다.

> **`a[0 .. i-1]` 은 항상 정렬돼 있다.**

이런 "항상 참인 약속"을 **불변식**이라고 부른다. 처음엔 `a[0..0]`, 즉 한 칸뿐이라 자동으로 참이다.

### 2단계 — 약속을 지키며 한 칸 넓힌다

`a[i]` 를 정렬된 구간에 편입시키면 약속이 `a[0..i]` 로 넓어진다.
편입 방법은 위에서 손으로 한 그대로다.

```
j = i 에서 시작해서
왼쪽 이웃 a[j-1] 이 나(a[j])보다 크면 → 자리를 바꾸고 j 를 하나 줄인다
아니면 → 제자리를 찾았으니 멈춘다
```

### 3단계 — 멈추는 두 가지 경우

밀고 가다 보면 반드시 둘 중 하나로 끝난다.

| 멈추는 이유 | 뜻 |
|---|---|
| `j == 0` | 왼쪽 끝에 도달. 구간에서 가장 작은 값이었다 |
| `a[j-1] <= a[j]` | 왼쪽 이웃이 나보다 작거나 같다. 여기가 제자리 |

두 경우 모두 **왼쪽은 다 나보다 작거나 같고, 오른쪽은 다 나보다 크거나 같다.**
그래서 약속이 유지된다.

### 4단계 — `i` 를 1부터 n-1까지

```
for (int i = 1; i < n; i++)   ← i = 0 은 이미 정렬된 것으로 보므로 1부터
```

`i` 가 `n` 에 도달하면 약속은 "`a[0..n-1]` 이 정렬돼 있다" 가 되고, 그게 곧 답이다.

## 코드로 옮기기

```cpp
void insertionSort(vector<int>& a) {
    int n = a.size();
    for (int i = 1; i < n; i++) {                 // ← 4단계: 편입할 원소
        int j = i;
        while (j > 0 && a[j - 1] > a[j]) {        // ← 3단계: 멈춤 조건 두 개
            swap(a[j - 1], a[j]);                 // ← 2단계: 왼쪽으로 한 칸
            j--;
        }
    }
}
```

`while` 의 조건 두 개가 각각 3단계 표의 한 줄씩이다.

- `j > 0` — 왼쪽 끝에 닿으면 멈춘다
- `a[j-1] > a[j]` — 왼쪽 이웃이 더 크지 않으면 멈춘다

`&&` 이므로 **`j > 0` 을 먼저 검사**한다는 점이 중요하다. 순서를 바꾸면 `j = 0` 일 때
`a[-1]` 을 읽어 버린다.

### 왜 이게 빠를 수 있나

**정렬된 배열을 넣으면** `a[j-1] > a[j]` 가 첫 비교에서 바로 거짓이 된다.
`while` 이 한 번도 안 돌고, `i` 마다 비교 한 번으로 끝난다 — 전체 `n-1`번.

즉 **이미 정렬돼 있거나 거의 정렬된 데이터에서는 사실상 선형**이다.
버블 정렬은 (조기 종료 장치가 없으면) 그런 경우에도 비교를 다 하므로 이 점이 다르다.

## 자주 하는 실수

**`while` 조건 순서를 바꾼다.** `a[j-1] > a[j] && j > 0` 으로 쓰면 배열 밖을 읽는다.
C++ 의 `&&` 는 왼쪽이 거짓이면 오른쪽을 아예 평가하지 않는다는 성질에 기대고 있다.

**`i` 를 0부터 시작한다.** `i = 0` 이면 `j = 0` 이라 `while` 이 바로 끝나 해롭진 않지만,
"한 칸은 이미 정렬돼 있다"는 출발점을 흐린다.

**`>` 를 `>=` 로 바꾼다.** 같은 값을 만나도 계속 밀고 가게 되어,
뒤에서 온 원소가 같은 값의 앞으로 넘어간다. 안정성이 깨진다.

**`swap` 이 느리다는 것을 모른다.** `swap` 은 대입 3번이다. 실전에서는 값을 하나 빼 두고
한 칸씩 밀다가 마지막에 한 번만 넣는 방식이 3배쯤 빠르다.

```cpp
int key = a[i], j = i - 1;
while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; }  // 밀기만
a[j + 1] = key;                                          // 마지막에 한 번
```

## 스스로 확인하기

1. **`1 2 3 4 5` 를 넣어 보자.** 스텝 수가 확 줄어드는 것을 볼 수 있다.
   같은 입력을 [버블 정렬](#/algo/bubble-sort)에도 넣어 스텝 수를 비교해 보자.
2. **`5 4 3 2 1` 을 넣어 보자.** 매번 왼쪽 끝까지 밀린다. 가장 나쁜 경우다.
3. 초록 구간이 **왼쪽에서 오른쪽으로** 자란다. 버블 정렬과 방향이 반대다.
4. 값이 같은 입력(`3 1 3`)에서 두 개의 `3` 이 서로 넘어가지 않는지 확인해 보자.

아래 **깊이 보기**에서는 이 "약속"이 왜 항상 지켜지는지 귀납으로 증명하고,
이동 횟수가 정확히 **역전(inversion) 개수**와 같다는 사실을 다룬다.
