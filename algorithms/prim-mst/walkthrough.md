## 어떤 문제인가

정점 몇 개를 **모두 잇는** 도로망을 놓되, 도로 건설 비용의 합을 최소로 하고 싶다.
사이클(빙 도는 길)은 낭비다 — 정점 `n` 개를 잇는 데는 간선 `n-1` 개면 충분하다.

이렇게 "모든 정점을 잇는, 사이클 없는, 가중치 합 최소인 부분 그래프" 를
**최소 신장 트리(MST)** 라 한다.

기본 그래프(정점 6개)를 보자. 모든 간선을 다 놓으면 비용이 크고 사이클도 생긴다.
**꼭 필요한 5개**만 골라야 한다.

> 어떤 간선을 골라야 할까? 그리고 **탐욕적으로** 골라도 최적이 나올까?

## 손으로 해보기

기본 그래프로 끝까지 가 보자. 시작 정점은 `0` 이다.

### 트리를 한 정점씩 키운다

프림의 발상은 **트리를 눈덩이처럼 키우는** 것이다. 정점 하나에서 시작해,
매 단계 **트리와 바깥을 잇는 간선(경계 간선) 중 가장 싼 것**을 골라 그 반대편 정점을 트리에 넣는다.

각 바깥 정점 `v` 에 대해 `key[v]` = "트리와 `v` 를 잇는 간선 중 최소 가중치" 를 기억한다.

### 시작 — 정점 0

```
트리 = {0}
0 의 이웃:  0—1 (2),  0—2 (4)
key[1] = 2,  key[2] = 4
```

### 1번째 — 가장 싼 경계 간선

경계 간선 중 최소는 `0—1` (가중치 2). 정점 `1` 을 트리에 넣는다.

```
트리 = {0, 1}         MST 간선: 0—1
```

`1` 을 넣었으니 `1` 의 이웃을 보며 key 를 갱신한다.

```
1—2 (3) < key[2]=4  →  key[2] = 3   (0—2 보다 1—2 가 싸다)
1—3 (3)             →  key[3] = 3
```

### 2번째

경계: `key[2]=3`, `key[3]=3`. 동점이면 번호가 작은 `2` 를 고른다(간선 `1—2`).

```
트리 = {0, 1, 2}      MST 간선: 1—2
2 의 이웃:  2—4 (6)  →  key[4] = 6
```

### 3번째

경계: `key[3]=3`, `key[4]=6`. `3` 을 고른다(간선 `1—3`).

```
트리 = {0, 1, 2, 3}   MST 간선: 1—3
3 의 이웃:  3—4 (5) < 6  →  key[4] = 5
           3—5 (1)      →  key[5] = 1
```

### 4번째

경계: `key[5]=1`, `key[4]=5`. `5` 를 고른다(간선 `3—5`, 가중치 1).

```
트리 = {0, 1, 2, 3, 5}  MST 간선: 3—5
5 의 이웃:  4—5 (4) < 5  →  key[4] = 4
```

### 5번째

경계: `key[4]=4`. 마지막 정점 `4` 를 고른다(간선 `4—5`).

```
트리 = 전부           MST 간선: 4—5
```

### 완성

```
MST 간선:  0—1 (2),  1—2 (3),  1—3 (3),  3—5 (1),  4—5 (4)
가중치 합:  2 + 3 + 3 + 1 + 4 = 13
간선 5개 (정점 6개 - 1)
```

[크루스칼](#/algo/kruskal)로 같은 그래프를 풀어도 **똑같이 13** 이다. 방법이 다른데 답이 같다 —
MST 의 가중치 합은 유일하기 때문이다(간선 조합은 다를 수 있다).

### 왜 탐욕이 통하나 — 절단 성질

핵심은 이것이다.

> **절단 성질.** 그래프를 두 덩어리로 가르는 어떤 방법(절단)에서든,
> 그 경계를 넘는 간선 중 **가장 싼 것**은 반드시 어떤 MST 에 들어간다.

프림의 매 단계는 "트리 안" vs "트리 밖" 이라는 절단을 만들고, 그 경계에서 가장 싼 간선을 고른다.
절단 성질에 의해 그 선택은 **항상 안전**하다 — 최적을 망치지 않는다.

## 아이디어 쌓기

### 1단계 — 사이클은 낭비다

정점 `n` 개를 잇는 데 간선 `n-1` 개면 된다. 그보다 많으면 사이클이 생기고, 사이클의 어떤 간선을
빼도 여전히 연결된다. 그러니 **트리** 를 찾는 문제다.

### 2단계 — 트리를 키운다

이미 이은 정점들(트리)과 아직 안 이은 정점들 사이의 **경계**에서 간선을 고른다.
트리에 하나씩 더하면 사이클이 절대 안 생긴다(새 정점은 트리에 없던 것이니까).

### 3단계 — 경계에서 가장 싼 것

절단 성질이 "경계 최소 간선은 안전" 을 보장한다. 그래서 **탐욕**이 통한다.

### 4단계 — key 로 경계를 관리한다

바깥 정점마다 `key[v]` = 트리까지의 최소 간선 가중치. 정점을 트리에 넣을 때마다
그 이웃들의 `key` 를 낮춘다. **가장 작은 `key` 를 빠르게 꺼내려면** 우선순위 큐(최소 힙)를 쓴다.

이 구조는 [다익스트라](#/algo/dijkstra)와 거의 같다 — 다르는 것은 갱신 식뿐이다.

```
다익스트라:  key[v] = min(key[v], dist[u] + w)   ← 시작점까지 누적 거리
프림      :  key[v] = min(key[v], w)             ← 트리까지 간선 하나
```

## 코드로 옮기기

```cpp
int prim(vector<vector<pair<int,int>>>& adj, int n) {
    vector<int> key(n, INF);
    vector<bool> inMST(n, false);
    priority_queue<pair<int,int>, vector<pair<int,int>>,
                   greater<>> pq;                // ← 4단계: (key, 정점) 최소 힙
    key[0] = 0; pq.push({0, 0});
    int total = 0;
    while (!pq.empty()) {
        auto [k, u] = pq.top(); pq.pop();
        if (inMST[u]) continue;                  // 낡은 항목
        inMST[u] = true; total += k;             // ← 2단계: u 를 트리에
        for (auto [v, w] : adj[u])
            if (!inMST[v] && w < key[v]) {        // ← 3단계: 더 싼 경계 간선
                key[v] = w;
                pq.push({w, v});
            }
    }
    return total;
}
```

`greater<>` 가 **최소** 힙을 만든다. 이걸 빼먹으면 가장 비싼 간선을 골라 정반대가 된다.

**`if (inMST[u]) continue;`** 가 필요하다. 같은 정점이 더 싼 key 로 PQ 에 여러 번 들어갈 수 있어,
이미 트리에 든 것을 다시 꺼내면 건너뛴다("낡은 항목"). 다익스트라와 같은 처리다.

## 자주 하는 실수

**최대 힙을 쓴다.** `greater<>` 를 빼먹는 실수. 가장 비싼 간선을 골라 최대 신장 트리가 된다.

**낡은 항목을 안 거른다.** `inMST[u]` 검사를 빼면 한 정점을 두 번 처리해 비용이 부풀려진다.

**시작점까지의 거리로 갱신한다.** 프림은 `key[v] = w`(간선 하나)지 `dist[u] + w`(누적)가 아니다.
그렇게 쓰면 다익스트라가 되어 **최단 경로 트리**를 만든다 — MST 와 다르다.

**연결 그래프라고 가정한다.** 그래프가 끊겨 있으면 신장 트리가 없다. PQ 가 비었는데
트리에 안 든 정점이 남으면 그 경우다.

**MST 가 유일하다고 생각한다.** 같은 가중치가 있으면 **간선 조합이 여럿**일 수 있다.
다만 **가중치 합은 항상 같다**(크루스칼과 13으로 일치하는 이유).

## 스스로 확인하기

1. **트리가 한 정점씩 커지는 것**을 보자. 매 단계 정점 하나와 간선 하나가 확정(초록)된다.
2. **key 라벨**(정점 아래 숫자)을 보자. 정점이 트리에 들어갈 때마다 이웃의 key 가 낮아진다.
3. **`0—2` 대신 `1—2` 가 선택되는 순간**을 보자. `1` 을 넣은 뒤 `key[2]` 가 4에서 3으로 낮아진다.
4. **PQ 목록**(아래)이 가중치 순인 것을 보자. 맨 앞이 다음에 꺼낼 것이다.
5. **"낡은 항목" 스텝**을 찾아보자. 이미 트리에 든 정점을 PQ 에서 꺼내 건너뛴다.
6. 시작 정점을 바꿔 편집기에서 다시 그려 보자. 트리가 자라는 **순서는 달라져도** 총합은 13 그대로다.
7. [크루스칼](#/algo/kruskal)로 같은 그래프를 풀어 보자. 간선을 고르는 순서가 전혀 다른데 답이 같다.

아래 **깊이 보기**에서는 절단 성질을 교환 논법으로 증명하고, 프림과 크루스칼이
같은 정리의 두 얼굴임을, 그리고 힙 선택에 따른 복잡도 차이를 다룬다.
