## 한눈에

세그먼트 트리에 **지연 전파(lazy propagation)** 를 더해, **구간 전체 갱신**([l,r)에 +v)과 구간 질의를
모두 `O(log n)` 에 한다. 구간에 완전히 덮이는 노드엔 자식까지 내려가지 않고 "나중에 내릴 값(lazy)"
만 걸고, 그 자식이 필요해질 때 비로소 한 단계 내린다(push down).

- **시간** 구간 갱신·구간 질의 각 `O(log n)` · **공간** `O(n)`
- 세 연산 — **apply**(노드에 즉시 반영 + lazy 적립), **push**(자식으로 한 단계 내림), **pull**(자식 합 되올림)
- 연산에 맞춰 apply 를 바꾸면 구간 합·최댓값·구간 대입 등으로 일반화
- 일반 세그먼트 트리의 한 점 갱신 한계를 구간 갱신으로 확장

**언제 쓰나** — 구간 갱신 + 구간 질의가 얽힌 문제(구간 덧셈/대입 후 구간 합·최댓값), 스케줄·구간 반영,
좌표 압축 위의 구간 연산.

**언제 안 쓰나** — 한 점 갱신 + 접두사 합만이면 [펜윅 트리](#/algo/fenwick-tree)가 더 가볍다.
정적 배열의 반복 최소/최대 질의는 [희소 배열](#/algo/sparse-table).

## 동작 원리

```
apply(i,l,r,v): t[i] += v*(r-l);  lazy[i] += v         # 노드에 즉시 반영, 자식은 지연
push(i,l,r):    lazy[i] 를 두 자식에 apply, lazy[i]=0   # 한 단계만 내림
update(i,l,r,ql,qr,v):
    겹침 없음 → return
    완전 포함 → apply(i,...); return                    # 자식으로 안 내려감
    부분 겹침 → push; 두 자식 재귀; t[i]=자식 합(pull)
query 도 같은 골격(부분 겹침이면 push 후 재귀)
```

### 지연값의 의미

`lazy[i]` 는 "노드 `i` 의 **자식들**에게 아직 안 내린 갱신" 이다. `t[i]`(노드 합)에는 이미 반영돼 있고,
자식에는 나중에 push 될 때 반영된다. 그래서 `t[i]` 는 항상 자기 구간의 정확한 합을 유지한다.

## 정확성

> **노드 값 불변식.** 임의의 시점에 `t[i]` 는 노드 `i` 구간의 정확한 합이다(자기 노드에 걸린 lazy 는
> 이미 `t[i]` 에 반영, 자식으로 향한 lazy 는 push 될 때 반영).

*apply 유지.* `apply(i,l,r,v)` 는 `t[i] += v·(r−l)` 로 구간 합을 정확히 갱신하고, `lazy[i] += v` 로
"자식에게 나중에" 를 적립한다. `t[i]` 는 여전히 정확. ∎

*push 유지.* `push(i)` 는 `lazy[i]` 를 두 자식에 apply → 자식 `t` 가 정확해지고, `lazy[i]=0`.
부모 `t[i]` 는 안 바뀐다(이미 반영돼 있었으므로). ∎

*update/query 유지.* 부분 겹침에서 **먼저 push** 해 자식을 최신화한 뒤 재귀하므로, 자식은 항상
자기 몫의 지연을 반영한 상태에서 다뤄진다. 재귀 후 `t[i]=t[2i]+t[2i+1]`(pull)로 부모를 되올린다. ∎

> **정확성.** `query(ql,qr)` 는 `[ql,qr)` 의 정확한 합을 반환한다.

완전 포함 노드의 `t` 를 더하고, 부분 겹침은 push 후 재귀하므로, 불변식에 의해 각 조각이 정확하다. ∎

## 복잡도

| 연산 | 시간 | 공간 |
|---|---|---|
| 구간 갱신 | `O(log n)` | — |
| 구간 질의 | `O(log n)` | `O(n)` |

### 왜 `O(log n)` 인가

각 트리 레벨에서 질의/갱신 구간의 경계는 **최대 2개 노드**에만 부분적으로 걸치고, 나머지는
완전 포함(멈춤)이거나 무관(무시)이다. 완전 포함 노드는 자식으로 안 내려가므로, 방문·push 하는 노드
수가 레벨당 `O(1)` → 전체 `O(log n)`. 지연이 없으면 구간을 리프까지 펼쳐 `O(구간 크기)` 가 된다.

## 구현 노트

**연산별 apply** — 구간 합이면 `t[i]+=v·(r−l)`. 구간 **대입**(=v)이면 `t[i]=v·(r−l)`, lazy 를 "대입값"
으로(적립이 아니라 덮어쓰기). 구간 최댓값+구간 덧셈이면 `t[i]+=v`, lazy 도 `+=v`.

**push 순서** — 부분 겹침에서 **재귀 전에** push. 자식을 읽기 전 반드시 최신화.

**대입과 덧셈 혼합** — 두 종류 갱신이 섞이면 lazy 를 (대입, 덧셈) 쌍으로 관리하고 합성 규칙을 정의한다.

**메모리** — 재귀 세그먼트 트리는 `4n` 노드 배열이 안전(2의 거듭제곱으로 올려도 됨).

**오버플로** — 구간 합 × 갱신 누적이 커지면 64비트.

## 변형과 확장

### 구간 대입 (assign)

lazy 를 "이 구간을 v 로 덮어써라" 로. apply 는 `t[i]=v·(r−l)`, lazy 합성은 나중 값이 이긴다.

### 구간 최댓값/최솟값 + 구간 덧셈

apply: `t[i]+=v`(최댓값은 크기 안 곱함), lazy `+=v`. push 동일. 다양한 (질의, 갱신) 조합이 가능.

### 좌표 압축 · 구간 위의 스위프

구간을 값 압축한 인덱스로 매핑해, 이벤트를 스위프하며 구간 갱신/질의(예: 직사각형 넓이 합집합).

### 펜윅 두 개로 구간 갱신+구간 합

[펜윅 트리](#/algo/fenwick-tree)의 차분 트릭 두 개로도 구간 갱신+구간 합을 `O(log n)` 에 —
코드가 더 짧지만 min/max 등 일반 연산엔 세그먼트 트리 지연 전파가 필요하다.
