## 어떤 문제인가

배열에 두 가지를 **자주** 하고 싶다.

```
update(l, r, v)  — 구간 [l, r) 의 모든 원소에 v 를 더한다   (구간 전체 갱신)
query(l, r)      — 구간 [l, r) 의 합
```

보통 [세그먼트 트리](#/algo/segment-tree)는 **한 점** 갱신만 `O(log n)`. 구간 전체에 더하려면
그 구간의 리프를 전부 고쳐야 해 `O(구간 크기)` — 최악 `O(n)`.

> 구간 `[2, 6)` 에 +3 하는데, 그 구간을 통째로 덮는 노드가 있다면 **자식까지 안 내려가고**
> 그 노드에만 "나중에 +3" 이라고 적어 둘 수 없을까?

## 손으로 해보기

핵심은 **지연값(lazy)** 이다. 노드에 "이 구간 전체에 나중에 더할 값" 을 걸어 두고,
그 자식이 **실제로 필요해질 때** 비로소 한 단계 내린다(push down).

기본 입력 `a = [3,1,4,1,5,9,2,6]`, 구간 갱신 `[2,6) += 3`, 질의 `[1,7)` 로 가 보자.

### 두 규칙

```
apply(노드, +v):  노드 합 += v × (구간 크기);  노드 lazy += v   (자식엔 나중에)
push(노드):       노드 lazy 를 두 자식에 apply 하고 노드 lazy = 0  (한 단계만 내린다)
```

### 구간 갱신 [2, 6) += 3

루트에서 내려가며, **구간에 완전히 덮이는 노드**를 만나면 거기서 멈추고 지연만 건다.

```
[2,6) 은 노드 [0,4) 와 [4,8) 에 걸친다 → 각각 재귀
  [0,4) 안: [2,4) 는 그 노드에 완전 포함 → apply(+3), 멈춤 (자식 안 내려감!)
  [4,8) 안: [4,6) 는 그 노드에 완전 포함 → apply(+3), 멈춤
```

리프까지 안 내려가고 **두 노드에만** +3 지연을 걸었다. 그 위 노드들의 합은 되올림(pull up)으로 갱신.

### 구간 질의 [1, 7)

질의도 내려가다 부분만 겹치는 노드에선 **먼저 push** 로 지연을 한 단계 내린 뒤 재귀한다.
완전히 덮이는 노드를 만나면 그 합을 채택한다. 걸어 둔 지연이 이때 정확히 반영된다.

```
[1,7) 의 합 = (원래 합) + (덮인 [2,6) 에 더한 3씩)
            = 34
```

### 왜 O(log n) 인가

구간 갱신도 질의도, 트리의 각 레벨에서 **완전히 덮이는 노드 O(1)개 + 경계 노드 O(1)개**만 건드린다.
지연 덕에 완전히 덮이면 자식으로 안 내려가므로, 방문 노드가 `O(log n)` 으로 유지된다.

## 아이디어 쌓기

### 1단계 — 완전히 덮이면 멈춘다

구간이 노드를 통째로 덮으면 자식까지 갈 필요가 없다. 그 노드 하나만 갱신.

### 2단계 — 지연값을 걸어 둔다

자식에 즉시 반영하지 않고 "나중에 내릴 값" 을 노드에 저장한다.

### 3단계 — 필요할 때 내린다(push down)

부분만 겹쳐 자식으로 내려가야 할 때, 먼저 지연을 한 단계 내려 자식을 최신화한다.

### 4단계 — 되올린다(pull up)

재귀에서 돌아올 때 노드 합 = 두 자식 합으로 갱신한다.

## 코드로 옮기기

```cpp
void apply(int i, int l, int r, long long v) {
    t[i] += v * (r - l);                   // 구간 전체에 +v
    lazy[i] += v;                          // 자식엔 나중에(지연)
}
void push(int i, int l, int r) {           // 지연값을 자식으로 내린다
    if (!lazy[i]) return;
    int m = (l + r) / 2;
    apply(2*i, l, m, lazy[i]);
    apply(2*i+1, m, r, lazy[i]);
    lazy[i] = 0;
}
void update(int i,int l,int r,int ql,int qr,long long v) {
    if (qr <= l || r <= ql) return;        // 겹침 없음
    if (ql <= l && r <= qr) { apply(i,l,r,v); return; } // 완전 포함 → 지연
    push(i, l, r);                          // 부분 → 내리고 재귀
    int m = (l + r) / 2;
    update(2*i, l, m, ql, qr, v);
    update(2*i+1, m, r, ql, qr, v);
    t[i] = t[2*i] + t[2*i+1];
}
```

`query` 도 같은 골격 — 부분 겹침이면 `push` 후 재귀, 완전 포함이면 그 합을 반환한다.

## 자주 하는 실수

**질의 전에 push 를 안 한다.** 부분 겹치는 노드로 내려갈 땐 반드시 먼저 `push`. 안 하면 걸어 둔
지연이 자식에 안 반영돼 틀린다.

**apply 에서 구간 크기를 안 곱한다.** 구간 합이면 `v × (r−l)`. 최솟값/최댓값이면 그냥 `v` 를 더한다
(연산에 맞춰 apply 를 바꾼다).

**pull up 을 빼먹는다.** 자식이 바뀌면 부모 합도 자식 합으로 되올려야 한다.

**되올림 시점에 자식의 지연을 무시.** `t[2*i]` 는 그 자식의 지연이 이미 반영된 합이어야 한다
(apply 가 노드 합에 즉시 반영하므로 OK).

## 스스로 확인하기

1. **구간 갱신 [2,6)+3** 에서 완전히 덮이는 노드에 **+3 배지(지연)** 가 걸리고 멈추는 것을 보자.
2. **리프까지 안 내려가는 것**을 보자 — 지연이 자식으로 안 퍼진다.
3. **질의 중 push** 로 배지가 자식으로 내려가는 순간을 보자.
4. **되올림(pull)** 으로 부모 합이 갱신되는 것을 보자.
5. **최종 구간 합 34** 를 확인하자.
6. 입력 배열을 바꿔 보자 — 갱신·질의가 항상 O(log n)개 노드만 건드린다.

최댓값)·펜윅과의 비교를 다룬다.
