## 어떤 문제인가

`ABRACADABRA` 를 0과 1로 저장하려 한다. 글자가 5종류(`A B C D R`)니
**한 글자에 3비트**를 주면 된다.

```
A=000  B=001  C=010  D=011  R=100
11글자 × 3비트 = 33비트
```

그런데 글자가 나오는 횟수가 전혀 다르다.

```
A: 5번    B: 2번    R: 2번    C: 1번    D: 1번
```

`A` 가 5번이나 나오는데 `D`(1번)와 똑같이 3비트를 쓰는 건 아깝다.

> **자주 나오는 글자에 짧은 부호**를 주면 전체가 줄어들지 않을까?

### 그런데 길이가 다르면 못 읽는다

`A=0`, `B=1`, `C=01` 로 정하고 `01` 을 받으면 — `AB` 인가 `C` 인가? **알 수 없다.**

문제는 `A` 의 부호 `0` 이 `C` 의 부호 `01` 의 **앞부분**이라는 것이다.

> **접두사 조건**: 어떤 부호도 다른 부호의 앞부분이 되면 안 된다.

이걸 지키면 왼쪽부터 읽어 나가다 부호가 완성되는 순간 확정할 수 있다 — 구분자가 필요 없다.

## 손으로 해보기

기본 입력 `ABRACADABRA` 로 끝까지 가 보자.

### 트리로 생각하면 접두사 조건이 공짜다

부호를 **이진 트리의 잎**에 두자. 왼쪽으로 내려가면 `0`, 오른쪽이면 `1`.
글자는 **잎에만** 놓는다.

```
        ●
       0 1
      /   \
     A     ●
          0 1
         /   \
        B     C

A=0,  B=10,  C=11
```

잎은 다른 잎의 조상이 될 수 없으니, **접두사 조건이 자동으로 지켜진다.**
이제 문제는 "어떤 트리 모양이 가장 짧은가" 하나로 바뀐다.

### 그리디: 가장 드문 둘을 가장 깊이 보낸다

깊은 잎일수록 부호가 길다. 그러니 **가장 드문 글자를 가장 깊게** 두면 좋겠다.
그런데 트리를 위에서부터 만들면 어디가 깊어질지 알 수 없다.

**아래에서부터 만든다.**

> 가장 드문 두 노드를 골라 **형제로 묶고**, 빈도를 합친 새 노드로 되돌린다.
> 하나가 남을 때까지 반복한다.

형제로 묶인 둘은 앞으로 어떻게 되든 **항상 함께 한 층씩 깊어진다.**
가장 드문 둘을 먼저 묶으면 그 둘이 가장 많이 깊어진다.

### 1번 합치기 — C(1) 과 D(1)

후보를 빈도순으로 늘어놓는다.

```
C:1   D:1   B:2   R:2   A:5
 ↑     ↑  가장 드문 둘
```

둘을 묶어 빈도 `1+1=2` 인 노드를 만들고 되돌린다.

```
     ●2
    /  \
   C1   D1

후보:  ●2   B:2   R:2   A:5
```

**빈도가 같은 것이 여럿일 때 누굴 고르든 총 비트 수는 같다** (증명은 깊이 보기에).
이 페이지는 순서를 완전히 정해 두려고 "빈도 → 만들어진 순서" 로 줄을 세운다.

### 2번 합치기 — B(2) 와 R(2)

```
후보:  B:2   R:2   ●2   A:5
        ↑     ↑

     ●4
    /  \
   B2   R2

후보:  ●2   ●4   A:5
```

### 3번 합치기 — ●2 와 ●4

```
후보:  ●2   ●4   A:5
        ↑    ↑

         ●6
        /   \
      ●2     ●4
     /  \   /  \
    C1  D1 B2  R2

후보:  A:5   ●6
```

### 4번 합치기 — A(5) 와 ●6

```
            ●11
           /   \
         A5     ●6
               /   \
             ●2     ●4
            /  \   /  \
           C1  D1 B2  R2

후보:  ●11        →  하나 남았다. 이게 루트다
```

### 부호 읽어 내기

루트에서 잎까지 내려가며 왼쪽=`0`, 오른쪽=`1` 을 적는다.

```
A  :  0            (1비트)   빈도 5
C  :  1 0 0        (3비트)   빈도 1
D  :  1 0 1        (3비트)   빈도 1
B  :  1 1 0        (3비트)   빈도 2
R  :  1 1 1        (3비트)   빈도 2
```

**`A` 가 1비트다.** 5번 나오는 글자를 1비트로 줄인 것이 이득의 대부분이다.

### 얼마나 줄었나

```
5×1 + 1×3 + 1×3 + 2×3 + 2×3 = 5 + 3 + 3 + 6 + 6 = 23비트
같은 길이(3비트)로는                                33비트
                                          10비트 절약 (30%)
```

`ABRACADABRA` 를 실제로 써 보면

```
A  B   R   A  C   A  D   A  B   R   A
0  110 111 0  100 0  101 0  110 111 0     ← 23비트
```

구분자가 없는데도 왼쪽부터 유일하게 읽힌다. `0` 을 보면 바로 `A` 고,
`1` 로 시작하면 3비트를 다 읽어야 결정된다.

## 아이디어 쌓기

### 1단계 — 접두사 조건을 트리로 옮긴다

"부호가 서로 앞부분이 되지 않게" 를 직접 관리하기는 어렵다.
**글자를 잎에만 두면** 구조가 그 조건을 대신 지켜 준다. 문제가 "트리 모양 고르기" 로 바뀐다.

### 2단계 — 비용을 식으로 쓴다

```
전체 비트 수 = Σ (글자 빈도) × (그 잎의 깊이)
```

이걸 최소화하는 트리를 찾는 문제다. **깊이가 곧 부호 길이**다.

### 3단계 — 아래에서부터 묶는다

위에서 내려가며 트리를 만들면 어느 잎이 깊어질지 미리 알 수 없다.
반대로, **두 노드를 형제로 묶으면 그 둘은 앞으로 항상 같이 깊어진다.**
그러니 "많이 깊어져도 괜찮은 것" = 가장 드문 둘을 먼저 묶는다.

### 4단계 — 합친 것을 다시 후보로

묶은 결과를 빈도 `f₁+f₂` 인 **하나의 노드**로 취급해 후보에 되돌린다.
그러면 문제 크기가 `n` 에서 `n-1` 로 줄고, 형태는 똑같은 문제가 된다.
`n-1` 번 반복하면 하나가 남는다.

### 5단계 — 최솟값 둘을 계속 꺼내야 한다

매번 "가장 작은 둘" 이 필요하고, 중간에 새 값이 계속 들어온다.
이건 정확히 **우선순위 큐(최소 힙)** 가 하는 일이다.

```
꺼내기 2번 + 넣기 1번,  각 O(log n),  총 n-1 회  →  O(n log n)
```

## 코드로 옮기기

```cpp
Node* huffman(map<char,int>& freq) {
    priority_queue<pair<int,Node*>, vector<pair<int,Node*>>,
                   greater<>> pq;                    // ← 5단계: 최소 힙
    for (auto [ch, f] : freq)
        pq.push({f, new Node(ch)});                  // ← 1단계: 글자는 잎에만
    while (pq.size() > 1) {
        auto [f1, left]  = pq.top(); pq.pop();       // ← 3단계: 가장 드문 둘
        auto [f2, right] = pq.top(); pq.pop();
        pq.push({f1 + f2, new Node(f1 + f2, left, right)});   // ← 4단계: 되돌린다
    }
    return pq.top().second;                          // 남은 하나가 루트
}

void assign(Node* v, string path) {
    if (v->isLeaf()) { codeOf[v->ch] = path; return; }
    assign(v->left,  path + "0");
    assign(v->right, path + "1");
}
```

`greater<>` 가 **최소** 힙을 만든다(C++ 의 `priority_queue` 는 기본이 최대 힙이다).
이 한 글자를 빼먹으면 가장 흔한 글자를 묶게 되어 정반대 결과가 나온다.

## 자주 하는 실수

**최대 힙을 쓴다.** `greater<>` 를 빼먹는 실수다. 자주 나오는 글자가 깊어져
같은 길이 부호보다 **더 나빠진다.**

**내부 노드에 글자를 둔다.** 접두사 조건이 깨진다. 글자는 **잎에만**.

**빈도가 같을 때 순서에 따라 답이 달라진다고 생각한다.** 트리 **모양**은 달라지지만
**총 비트 수는 항상 같다.** 다만 프로그램의 출력이 실행마다 바뀌면 곤란하니
tie-breaking 을 정해 두는 게 좋다(이 페이지는 그렇게 한다).

**글자가 한 종류일 때를 놓친다.** `AAAA` 면 트리에 잎이 하나뿐이라 깊이가 0 —
부호 길이가 0이 되어 아무것도 저장하지 못한다. 관례적으로 1비트(`0`)를 준다.
**경계 조건을 반드시 따로 처리해야 한다.**

**부호표를 함께 저장하지 않는다.** 받는 쪽이 트리를 모르면 복호화할 수 없다.
실제 압축 파일에는 부호표(또는 트리 모양)가 헤더로 들어가고, **그 크기도 비용이다.**
짧은 입력에서는 부호표가 절약분보다 커서 오히려 손해일 수 있다.

## 스스로 확인하기

1. **PQ(아래 목록)가 항상 빈도 오름차순**인지 확인하자. 초록으로 강조된 앞의 둘이 다음에 묶일 쌍이다.
2. **트리가 여러 개(숲)로 흩어져 있는 중간 상태**를 보자. 3번째 합치기 전에는
   `A5` / `●2` / `●4` 세 그루가 따로 서 있다. 마지막 합치기에서 하나가 된다.
3. **묶는 순간**을 보자. 부모의 값이 두 자식의 합이다.
4. **부호 붙이기 단계**에서 루트→잎 경로가 회색으로 강조된다. 잎 위에 붙는 배지가 부호다.
5. `A` 의 부호가 **1비트**인 것을 확인하자. 그리고 `A` 가 루트의 **직접 자식**이라는 것도.
6. 입력을 `AAAABBBCCD` 로 바꿔 보자. 빈도가 `4,3,2,1` 로 고르게 흩어져
   트리가 한쪽으로 기운 모양(부호 길이 `1,2,3,3`)이 된다.
7. 입력을 `ABCDEFGH` 로 바꿔 보자. 8글자가 전부 1번씩이라 **완전 균형 트리**가 되고
   부호가 모두 3비트다 — 이때는 같은 길이 부호와 비트 수가 **똑같다**(24비트).
   빈도가 고르면 허프만이 이득을 못 낸다.
8. 입력을 `MISSISSIPPI` 로 바꿔 보자. `S`(4) `I`(4) `P`(2) `M`(1) 로 21비트다.

아래 **깊이 보기**에서는 "가장 드문 둘을 묶어도 최적을 잃지 않는다" 를 교환 논법으로
증명하고, 엔트로피 하한과 산술 부호화가 그 하한을 어떻게 넘는지 다룬다.
