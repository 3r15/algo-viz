## 한눈에

글자마다 길이가 다른 **접두사 부호**를 만들어 전체 비트 수를 최소화한다.
가장 드문 두 노드를 계속 형제로 묶는 그리디인데, **최적임이 증명된다.**

- **시간** `Θ(n log n)` (`n` = 글자 종류). 빈도가 이미 정렬돼 있으면 큐 두 개로 `Θ(n)`
- **공간** `Θ(n)` — 노드 `2n-1` 개
- **최적** — 모든 접두사 부호 중 기대 길이가 최소다. 그리디가 최적인 드문 경우
- **한 글자당 정수 비트**라는 제약이 있어 엔트로피 하한에 최대 1비트 못 미친다

**언제 쓰나** — 기호 빈도가 크게 치우칠 때. DEFLATE(gzip·PNG·ZIP), JPEG, MP3 의
마지막 엔트로피 코딩 단계가 허프만이다. 실무에서는 트리를 매번 만들지 않고
**표준 부호표**를 쓰거나(JPEG), 길이만 저장하는 **정규 허프만**을 쓴다.

**언제 안 쓰나** — 빈도가 고르면 이득이 없다(균등 8종이면 정확히 3비트씩 = 고정 길이와 동일).
입력이 짧으면 **부호표 헤더가 절약분보다 크다.** 엔트로피 하한에 더 붙어야 하면
산술 부호화나 ANS 를 쓴다. 문자열 반복이 주된 중복이면 LZ 계열이 먼저다.

## 동작 원리

두 번의 발상 전환이 전부다.

**① 접두사 조건을 트리로 옮긴다.** 부호를 이진 트리의 잎에 두고, 왼쪽 간선을 `0`,
오른쪽을 `1` 로 읽는다. 잎은 다른 잎의 조상이 될 수 없으므로 접두사 조건이 **구조적으로** 지켜진다.
문제가 "트리 모양 고르기" 로 환원된다.

**② 아래에서부터 묶는다.** 최소화할 비용은

```
cost(T) = Σ_{글자 c} freq(c) × depth_T(c)
```

이고, `depth` 는 곧 부호 길이다. 두 노드를 형제로 묶으면 그 둘은 이후 **항상 함께**
한 층씩 깊어진다. 그러니 많이 깊어져도 손해가 적은 것 — **가장 드문 둘**을 먼저 묶는다.

### 절차

```
1. 글자마다 잎을 만들어 최소 힙에 넣는다 (키 = 빈도)
2. 힙에 둘 이상 있는 동안:
     가장 작은 둘 x, y 를 꺼낸다
     빈도 w(x)+w(y) 인 새 내부 노드를 만들어 x, y 를 자식으로 붙인다
     새 노드를 힙에 넣는다
3. 남은 하나가 루트. 루트에서 내려가며 0/1 을 붙인다
```

`n` 개의 잎에서 시작해 매 반복이 후보를 하나 줄이므로 정확히 `n-1` 번 합친다.
결과 트리의 노드 수는 `2n-1` 이고, **모든 내부 노드가 자식 둘을 가진다**(full binary tree).

### 실행 예

`ABRACADABRA` — `A:5 B:2 R:2 C:1 D:1`

```
후보  C1 D1 B2 R2 A5
① C1+D1 → ●2        후보  ●2 B2 R2 A5
② B2+R2 → ●4        후보  ●2 ●4 A5
③ ●2+●4 → ●6        후보  A5 ●6
④ A5+●6 → ●11       후보  ●11   → 루트

            ●11
           /   \
         A5     ●6
               /   \
             ●2     ●4
            /  \   /  \
           C1  D1 B2  R2

A=0(1비트) · C=100 · D=101 · B=110 · R=111
비용 = 5·1 + 1·3 + 1·3 + 2·3 + 2·3 = 23비트   (고정 3비트: 33비트)
```

### 크래프트 등식

완성된 트리는 full binary tree 이므로 부호 길이 `ℓᵢ` 가 **등호**를 만족한다.

```
Σ 2^{-ℓᵢ} = 1
```

위 예: `2⁻¹ + 4·2⁻³ = 0.5 + 0.5 = 1` ✓
부등식 `Σ 2^{-ℓᵢ} ≤ 1` 은 접두사 부호가 존재하기 위한 필요충분조건(크래프트 부등식)이고,
**등호는 "낭비된 자리가 없다"** 는 뜻이다. `< 1` 이면 더 짧게 만들 여지가 남아 있다.

## 정확성

두 단계로 증명한다. 먼저 최적 트리가 가진 성질을 밝히고(보조정리), 그다음 귀납한다.

### 보조정리 — 가장 드문 둘은 형제로 둘 수 있다

> `x`, `y` 를 빈도가 가장 작은 두 글자라 하자(`freq(x) ≤ freq(y) ≤ 다른 모든 빈도`).
> 그러면 `x` 와 `y` 가 **최대 깊이에서 형제인** 최적 트리가 존재한다.

**증명(교환 논법).** 최적 트리 `T` 를 하나 잡는다.

먼저 `T` 의 모든 내부 노드는 자식이 둘이다. 자식이 하나뿐인 내부 노드가 있다면
그 노드를 자식으로 대체해 모든 하위 잎의 깊이를 1 줄일 수 있고, 이는 `T` 가 최적이라는 데
모순이다. 따라서 **최대 깊이에는 형제인 잎 두 개가 존재한다.** 그것을 `b`, `c` 라 하자.

`x` 와 `b` 를 맞바꾼 트리를 `T'` 라 하면, 깊이 차 `d = depth(b) - depth(x) ≥ 0` 이고

```
cost(T') - cost(T) = (freq(x) - freq(b)) · d
```

`x` 가 최소 빈도이므로 `freq(x) ≤ freq(b)`, 그리고 `d ≥ 0` 이므로 이 값은 `≤ 0` 이다.
`T` 가 최적이므로 `< 0` 은 불가능하고, 따라서 **`= 0`** — `T'` 도 최적이다.
같은 방식으로 `y` 와 `c` 를 맞바꾸면 여전히 최적이면서 `x`, `y` 가 최대 깊이에서 형제다. ∎

교환해도 비용이 늘지 않는다는 이 부등식이 그리디를 정당화하는 핵심이다.

### 정리 — 알고리즘이 최적 트리를 만든다

> 빈도 집합 `F` 에 대해 허프만 알고리즘이 만드는 트리는 `cost` 를 최소화한다.

`n = |F|` 에 대한 귀납법.

**기저** — `n = 2`. 접두사 부호는 두 글자에 각각 1비트를 주는 것뿐이고,
알고리즘도 그 트리를 만든다. ✓

**귀납 단계** — `n ≥ 3` 이고 크기 `n-1` 에서 정리가 성립한다고 하자.
`x`, `y` 를 최소 빈도 둘이라 하고, 이들을 하나의 기호 `z`(빈도 `freq(x)+freq(y)`)로 합친
빈도 집합을 `F'` 라 하자(`|F'| = n-1`).

`F'` 의 임의의 트리 `T'` 와, 그 `z` 잎을 `x`, `y` 두 자식으로 펼친 `F` 의 트리 `T` 사이에는

```
cost(T) = cost(T') + freq(x) + freq(y)
```

가 성립한다. `x`, `y` 는 `z` 보다 한 층 깊어지므로 각각 빈도만큼 비용이 늘고,
나머지 잎의 깊이는 그대로이기 때문이다. **이 차이는 `T'` 와 무관한 상수다.**

이제 알고리즘의 출력을 `H`, 합친 문제에서의 출력을 `H'` 라 하자.
알고리즘은 첫 단계에서 정확히 `x`, `y` 를 묶으므로 `H` 는 `H'` 의 `z` 를 펼친 것이다.
귀납 가정에 의해 `H'` 는 `F'` 에서 최적이다.

`F` 의 최적 트리를 `T*` 라 하자. 보조정리에 의해 `x`, `y` 가 형제인 최적 트리를 고를 수 있고,
그것의 `x`, `y` 를 하나로 접으면 `F'` 의 트리 `T*'` 가 되어

```
cost(T*)  = cost(T*') + freq(x) + freq(y)
          ≥ cost(H')  + freq(x) + freq(y)      (귀납 가정: H' 가 F' 에서 최적)
          = cost(H)
```

`T*` 가 최적이므로 `cost(T*) ≤ cost(H)` 이기도 하다. 따라서 `cost(H) = cost(T*)` — 최적이다. ∎

**종료성** — 매 반복이 힙 크기를 정확히 1 줄이므로 `n-1` 번 후 종료한다.

### 동점일 때 답이 여러 개인 이유

빈도가 같은 후보가 여럿이면 **트리 모양은 달라지지만 총 비용은 같다.**
위 증명의 교환 논법에서 `freq(x) = freq(b)` 이면 `cost` 차이가 `0` 이므로,
어느 쪽을 골라도 최적 집합 안에 머문다. 따라서 최적해는 일반적으로 유일하지 않다.

프로그램의 출력이 실행마다 바뀌면 곤란하므로 tie-breaking 을 고정해야 한다.
이 페이지의 생성기는 `(빈도, 노드 번호)` 순으로 줄을 세워 결정적으로 만든다 —
`generate` 가 순수 함수라는 계약을 지키기 위해서다.

## 복잡도

| | 시간 | 공간 |
|---|---|---|
| 최선 | `Θ(n log n)` (정렬 입력이면 `Θ(n)`) | `Θ(n)` |
| 평균 | `Θ(n log n)` | `Θ(n)` |
| 최악 | `Θ(n log n)` | `Θ(n)` |

`n` 은 **글자 종류 수**다(텍스트 길이가 아니다). 아스키면 `n ≤ 256` 이라 사실상 상수다.

**시간** — 힙에 `n` 번 넣고(초기화), `n-1` 번의 반복이 각각 꺼내기 2회·넣기 1회다.

```
초기화  n × O(log n)  (또는 heapify 로 O(n))
반복    (n-1) × 3 × O(log n)
합계    Θ(n log n)
```

빈도를 세는 비용 `Θ(텍스트 길이)` 가 따로 붙지만 보통 이쪽이 지배적이다.

**정렬돼 있으면 `Θ(n)`** — 힙 없이 **큐 두 개**로 된다. 잎을 빈도순으로 넣은 큐 하나와
새로 만든 내부 노드를 넣는 큐 하나를 두면, 내부 노드의 빈도는 **비내림차순으로 생성**되므로
각 큐의 앞만 보면 최솟값을 `O(1)` 에 얻는다. 두 큐의 front 4개 중 작은 둘을 고른다.

**공간** — 노드가 `2n-1` 개, 힙이 최대 `n` 개.

### 최적성의 한계 — 엔트로피 하한

기호 확률이 `pᵢ` 일 때, 어떤 부호도 기대 길이가 섀넌 엔트로피 미만일 수 없다.

```
H(p) = -Σ pᵢ log₂ pᵢ  ≤  기대 길이  <  H(p) + 1
```

허프만은 **접두사 부호 중에서는 최적**이지만, 한 기호에 **정수 비트**를 배정해야 하므로
하한에 최대 1비트 못 미친다. 확률이 `2` 의 거듭제곱들일 때만 정확히 `H(p)` 를 달성한다.

이 1비트 격차가 심각해지는 경우가 있다. `p = (0.99, 0.01)` 이면 `H ≈ 0.08` 비트인데
허프만은 어쩔 수 없이 1비트씩 준다 — **12배 낭비**다. 산술 부호화는 기호당 정수 비트라는
제약이 없어 이 격차를 없앤다.

## 구현 노트

**최소 힙이어야 한다.** C++ `priority_queue` 는 기본이 최대 힙이므로 `greater<>` 를 명시한다.
빠뜨리면 흔한 글자가 깊어져 고정 길이보다 나빠진다.

**tie-breaking 을 고정하라.** 빈도가 같을 때 힙의 내부 순서에 답이 좌우되면
같은 입력에 다른 출력이 나온다. `(빈도, 생성 순서)` 같은 2차 키를 두자.

**글자가 한 종류인 경계** — 잎이 하나면 깊이 0, 즉 부호 길이 0이 되어 아무것도 저장하지 못한다.
관례적으로 1비트를 준다. 반드시 별도 분기가 필요하다.

**부호표도 비용이다.** 복호화에는 트리가 필요하므로 헤더에 실어야 한다.
짧은 입력에서는 이 헤더가 절약분을 넘어 **압축이 되레 커진다.**

**정규 허프만(canonical Huffman)** — 트리 모양 전체를 저장하지 않고 **각 기호의 부호 길이만**
저장한다. 길이가 같으면 사전 순으로 부호를 배정하는 규칙을 양쪽이 공유하면 트리를 복원할 수 있다.
DEFLATE 가 이 방식이고, 헤더가 훨씬 작아진다.

**복호화 속도** — 트리를 비트마다 따라가면 느리다. 실무에서는 상위 `k` 비트를 인덱스로 하는
**룩업 테이블**을 만들어 한 번에 여러 비트를 처리한다.

**깊이 제한** — 빈도가 피보나치 수열처럼 치우치면 트리 깊이가 `n-1` 까지 간다.
룩업 테이블 크기 때문에 실무 포맷은 최대 길이를 제한하고(DEFLATE 는 15비트),
**길이 제한 허프만**(package-merge 알고리즘, `O(n·L)`)으로 최적해를 구한다.

## 변형과 확장

### 큐 두 개로 `Θ(n)`

빈도가 정렬돼 있을 때. 내부 노드의 빈도가 비내림차순으로 생성된다는 성질을 쓴다.

```
Q1: 잎 (빈도 오름차순, 미리 정렬)
Q2: 새로 만든 내부 노드 (자동으로 오름차순)
매번 두 큐의 front 중 작은 것을 두 번 꺼낸다
```

힙 연산이 사라져 `log` 가 빠진다.

### 산술 부호화 · ANS

기호당 정수 비트 제약을 버려 엔트로피 하한에 임의로 가까워진다.
확률이 극단적으로 치우칠 때(`0.99` / `0.01`) 허프만보다 압도적으로 유리하다.
현대 압축기(Zstandard, Brotli)는 FSE/tANS 를 쓴다.

### 적응형 허프만

빈도를 미리 모르고 스트리밍으로 처리해야 할 때. 읽어 가며 트리를 갱신한다(FGK·Vitter 알고리즘).
부호표를 따로 보낼 필요가 없어지는 것이 이득이다.

### 길이 제한 허프만

부호 길이 상한 `L` 을 두고 비용을 최소화한다. 단순 허프만은 상한을 보장하지 못한다.
package-merge 알고리즘이 `O(n·L)` 에 최적해를 준다.

### 병합 비용 최소화 — 같은 골격의 다른 문제

"파일 `n` 개를 두 개씩 합치는데 비용이 크기의 합일 때 총비용 최소화" 는
**허프만과 완전히 같은 알고리즘**이다. 합치는 순서를 트리로 보면 비용이 `Σ freq × depth` 이기 때문이다.
"돌 합치기", "카드 묶기" 로 불리는 문제들이 이 정체다.

### 왜 그리디가 여기서는 통하나

[0/1 배낭](#/algo/knapsack)에서는 그리디가 실패했다. 차이는 **교환 논법이 성립하는지**다.
허프만에서는 "최소 빈도 잎을 최대 깊이로 옮겨도 비용이 늘지 않는다" 는 부등식이 성립하고,
배낭에서는 "비율 좋은 물건을 먼저 담아도 손해가 없다" 는 명제가 **거짓**이다
(남는 공간을 부분 활용할 수 없어서). 그리디를 쓸 수 있는지는 이 교환 부등식이 결정한다.
