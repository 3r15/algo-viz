## 어떤 문제인가

[다익스트라](#/algo/dijkstra)는 빠르지만 **간선 비용이 음수면 틀린다.**

왜 그런지 가장 작은 예로 보자.

```
s ──1──▶ a ──(-5)──▶ b
 └────────2─────────▶ b
```

다익스트라는 `b` 를 값 2로 확정해 버린다. 확정한 뒤에는 다시 안 보므로,
나중에 `a` 를 처리하며 `1 + (-5) = -4` 라는 더 싼 길을 발견해도 이미 늦었다.

음수가 왜 생기냐고? **환전 차익, 할인 쿠폰, 게임의 회복 아이템** 같은 것들이 전부 음수 비용이다.

> 그러니 "확정"이라는 개념을 아예 버리자.
> 대신 **모든 간선을 몇 번이고 반복해서 완화**하면 어떨까?

## 손으로 해보기

기본 그래프(방향 그래프)를 보자.

```
간선:  0→1(6)   0→2(9)   1→3(5)   2→1(2)   3→2(-4)   1→4(4)   3→4(2)
```

`3→2` 가 **-4** 다. 시작점은 0.

```
초기:  0:0   1:∞   2:∞   3:∞   4:∞
```

### 라운드 1 — 간선을 위 순서대로 전부 훑는다

```
0→1(6):  0+6=6  < ∞ → 1 = 6
0→2(9):  0+9=9  < ∞ → 2 = 9
1→3(5):  6+5=11 < ∞ → 3 = 11
2→1(2):  9+2=11 > 6 → 그대로
3→2(-4): 11-4=7 < 9 → 2 = 7    ★ 음수 간선이 값을 줄였다!
1→4(4):  6+4=10 < ∞ → 4 = 10
3→4(2):  11+2=13 > 10 → 그대로

라운드 1 후:  0:0  1:6  2:7  3:11  4:10
```

`2` 가 9 였다가 **7로 줄어든 것**이 핵심이다. 직행 `0→2 = 9` 보다
돌아가는 `0→1→3→2 = 6+5-4 = 7` 이 더 싸다.

다익스트라라면 `2` 를 9로 확정한 뒤에 `3` 을 처리하므로 이 개선을 놓친다.

### 라운드 2 — 한 번 더 전부 훑는다

```
0→1(6):  6 → 그대로
0→2(9):  9 > 7 → 그대로
1→3(5):  11 → 그대로
2→1(2):  7+2=9 > 6 → 그대로
3→2(-4): 7 → 그대로
1→4(4):  10 → 그대로
3→4(2):  13 > 10 → 그대로

아무것도 안 바뀌었다 → 이미 수렴했다. 끝!
```

## 아이디어 쌓기

### 1단계 — 완화만 반복한다

완화는 다익스트라와 똑같다.

```
dist[u] + w < dist[v] 이면  dist[v] = dist[u] + w
```

다른 점은 **누구를 먼저 볼지 고르지 않는다**는 것. 그냥 모든 간선을 순서대로 다 훑는다.
고르지 않으니 잘못 고를 일도 없다.

### 2단계 — 라운드 하나가 무엇을 보장하나

라운드를 한 번 돌 때마다 이런 일이 일어난다.

> **`r` 번째 라운드가 끝나면, 간선을 `r`개 이하로 쓰는 최단 경로는 전부 반영돼 있다.**

왜 그런가? 간선 `r`개짜리 경로 `s ⇝ u → v` 를 보자. 앞부분 `s ⇝ u` 는 간선 `r-1`개짜리라
`r-1` 라운드에 이미 반영됐다. `r` 번째 라운드는 **모든 간선**을 훑으므로 `u → v` 도 반드시 본다.

**라운드 하나 = 경로 길이 한 칸 허용.**

### 3단계 — 몇 라운드면 충분한가

음수 사이클이 없다면 **최단 경로는 같은 정점을 두 번 지나지 않는다**
(지나면 그 구간을 잘라내는 편이 더 싸거나 같으니까).

정점이 `V`개면 경로의 간선 수는 최대 `V-1` 개다. 그러니 **`V-1` 라운드**면 충분하다.

기본 그래프는 정점 5개라 4 라운드가 상한이지만, 실제로는 2 라운드에서 수렴했다.
**아무것도 안 바뀌면 바로 멈추는 것**이 실전 요령이다.

### 4단계 — 음수 사이클을 잡아내기

사이클을 한 바퀴 돌 때 비용 합이 음수라면? 계속 돌수록 싸지므로 **최단 경로가 존재하지 않는다.**

이걸 어떻게 알아채나? 간단하다.

> `V-1` 라운드를 다 돌고 **한 번 더** 훑어 봤을 때 **여전히 줄어드는 간선이 있으면**
> 음수 사이클이 있는 것이다.

음수 사이클이 없다면 이미 수렴했으니 더 줄어들 리가 없기 때문이다.

## 코드로 옮기기

```cpp
bool bellmanFord(vector<Edge>& edges, int n, int s) {
    vector<int> dist(n, INF);
    dist[s] = 0;
    for (int round = 0; round < n - 1; round++) {   // ← 3단계: V-1 라운드
        bool changed = false;
        for (auto [u, v, w] : edges)                // ← 1단계: 모든 간선
            if (dist[u] != INF && dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;              //    완화
                changed = true;
            }
        if (!changed) break;                        // ← 조기 종료
    }
    for (auto [u, v, w] : edges)                    // ← 4단계: 검사 라운드
        if (dist[u] != INF && dist[u] + w < dist[v])
            return false;                           //    아직 줄어든다 = 음수 사이클
    return true;
}
```

다익스트라와 비교하면 **놀랄 만큼 단순하다.** 우선순위 큐도, "낡은 항목" 처리도 없다.
인접 리스트조차 필요 없고 **간선 목록만** 있으면 된다.

| | 다익스트라 | 벨만-포드 |
|---|---|---|
| 자료구조 | 우선순위 큐 | 없음 |
| 순서 고르기 | 가장 작은 것 | 안 고름 |
| 음수 간선 | ✗ | ○ |
| 시간 | O((V+E) log V) | O(VE) |

**단순함의 대가가 속도다.**

## 자주 하는 실수

**`dist[u] != INF` 검사를 빠뜨린다.** ★ 이게 가장 치명적이다.

```
INF + (-5) = INF - 5  →  INF 보다 작다!
```

도달할 수도 없는 정점의 거리가 이상하게 줄어든다. **음수 간선이 있을 때만 터지는 버그**라
평소엔 멀쩡하다가 갑자기 틀린다.

**라운드 수를 `V` 나 `V-2` 로 쓴다.** `V-1` 이 정확한 값이다.
`V-2` 면 긴 경로를 놓치고, `V` 면 음수 사이클 검사와 섞여 버린다.

**무방향 그래프에 음수 간선을 넣는다.** 무방향 간선 하나가 곧 왕복 가능한 사이클이므로,
음수면 그 자체로 음수 사이클이다.

**음수 사이클이 있는데 거리 값을 그대로 쓴다.** 사이클이 탐지되면 그 영향을 받는 정점들의
거리는 아무 의미가 없다. `-∞` 로 봐야 한다.

## 스스로 확인하기

1. **라운드 경계 스텝**을 찾아보자. "라운드 1 종료 — 현재 거리: …" 가 나온다.
   라운드마다 거리 배열이 한 단계씩 좋아진다.
2. **`3→2(-4)` 간선이 값을 줄이는 순간**을 찾아보자. 정점 2가 9에서 7로 바뀐다.
3. 같은 그래프를 [다익스트라](#/algo/dijkstra)에 넣어 보자.
   (참고: 이 사이트의 다익스트라는 "확정 후 재완화 금지"를 하지 않는 게으른 구현이라
   이 그래프에서는 우연히 맞는 답을 낸다. 교과서 다익스트라라면 `2` 를 9로 답한다.)
4. **조기 종료**를 확인해 보자. 4 라운드가 상한인데 2 라운드에서 멈춘다.
5. 편집기에서 `2→3` 간선을 만들고 가중치를 1로 두면 `2→3→2` 사이클의 합이
   `1 + (-4) = -3` 으로 음수가 된다. 실행해서 음수 사이클 탐지를 확인해 보자.

아래 **깊이 보기**에서는 "라운드 = 간선 한 칸"을 귀납으로 증명하고,
음수 사이클 탐지가 왜 정확한지(양방향 모두) 다룬다.
