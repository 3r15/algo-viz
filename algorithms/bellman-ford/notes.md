## 한눈에

[다익스트라](#/algo/dijkstra)가 못 하는 일을 한다 — **음수 간선이 있어도 최단 거리를 구하고,
음수 사이클이 있으면 그 사실을 알려 준다.**

전략은 그리디가 아니라 무식함에 가깝다.

> 모든 간선을 한 번씩 완화하는 라운드를 `V-1`번 반복한다.

"확정"이라는 개념이 없어서 언제든 값을 되돌릴 수 있고, 그래서 음수 간선에도 안전하다.
대신 O(VE) 로 느리다.

- 시간 O(VE) · 공간 O(V) · 자료구조 없음(간선 목록만)
- **음수 사이클 탐지**는 이 알고리즘의 고유 능력이다

## 동작 원리

```
dist[s] = 0, 나머지 ∞
V-1 번 반복:
    모든 간선 (u, v, w) 에 대해:
        dist[u] + w < dist[v] 이면  dist[v] = dist[u] + w
```

간선을 훑는 순서는 상관없다. 라운드를 충분히 돌면 어차피 수렴한다.

### 라운드의 의미

`r`번째 라운드가 끝나면 다음이 보장된다.

> `dist[v] ≤` (간선을 `r`개 **이하** 쓰는 s→v 경로 중 최단 비용)

즉 라운드 하나가 "경로 길이를 한 칸 더 허용"하는 것과 같다. 시각화에서 라운드 경계마다
거리 배열이 한 번에 좋아지는 것을 볼 수 있다.

### 왜 하필 V-1 번인가

음수 사이클이 없다면 **최단 경로는 같은 정점을 두 번 지나지 않는다.** 정점이 `V`개니까
최단 경로의 간선 수는 최대 `V-1`개다. 라운드 하나가 간선 하나를 감당하므로 `V-1`번이면 충분하다.

### 조기 종료

한 라운드에서 아무 값도 바뀌지 않으면 이미 수렴한 것이므로 남은 라운드를 돌 필요가 없다.
기본 그래프는 라운드 2회 만에 끝난다 — 이론상 4회지만 실제로는 훨씬 빨리 수렴하는 것이 보통이다.

## 정확성

### 라운드 불변식

> **주장**: `r`번째 라운드가 끝난 뒤, 간선 `r`개 이하를 쓰는 최단 경로가 존재하는 모든 `v` 에 대해
> `dist[v]` 는 그 값 이하다.

`r`에 대한 귀납이다.

**기저** `r = 0`: 간선 0개 경로는 `s` 자신뿐이고 `dist[s] = 0` 이다.

**귀납 단계**: 간선 `r`개짜리 최단 경로 `s ⇝ u → v` 를 보자. 앞부분 `s ⇝ u` 는 간선 `r-1`개
경로이므로, 귀납 가정에 의해 `r-1`라운드가 끝난 시점에 `dist[u] ≤ (그 비용)` 이다.
`r`번째 라운드는 **모든 간선**을 훑으므로 간선 `(u,v)` 도 반드시 완화한다. 따라서

```
dist[v] ≤ dist[u] + w(u,v) ≤ (s⇝u 비용) + w(u,v) = (경로 전체 비용)
```

음수 사이클이 없으면 최단 경로의 간선 수는 `V-1` 이하이므로,
`V-1`라운드 후 모든 `v` 에서 `dist[v]` 가 최단 거리다. ∎

> 완화는 항상 "실제로 존재하는 어떤 경로의 비용"만 대입하므로 `dist[v]` 가 최단 거리보다
> 작아지는 일은 없다. 위 부등식과 합치면 등호가 된다.

### 음수 사이클 탐지

`V-1`라운드가 끝난 뒤 한 번 더 훑어서 **여전히 줄어드는 간선이 있으면 음수 사이클이 있다.**

**(⇐)** 음수 사이클이 있다면: 사이클 위 정점들의 `dist` 합을 보자. 모든 간선이 더 이상
완화되지 않는다면 사이클의 각 간선에서 `dist[v] ≤ dist[u] + w` 이고, 사이클을 한 바퀴 돌며
전부 더하면 `Σdist ≤ Σdist + (사이클 가중치 합)`, 즉 `0 ≤ (사이클 가중치 합)` 이다.
음수 사이클이면 모순이므로, 반드시 아직 완화되는 간선이 남는다.

**(⇒)** 음수 사이클이 없다면 위 정확성 증명에 의해 `V-1`라운드로 이미 수렴했고,
수렴한 값은 더 줄어들지 않는다. ∎

### 다익스트라와 갈라지는 지점

기본 그래프에는 `3→2` 가중치 `-4` 인 간선이 있어서
`0→1→3→2 = 6+5-4 = 7` 이 직행 `0→2 = 9` 보다 짧다.

| | dist[2] |
|---|---|
| 교과서 다익스트라(확정한 정점은 다시 안 봄) | **9** ← 오답 |
| 벨만-포드 | **7** ← 정답 |

다익스트라는 `2` 를 9 로 확정한 **뒤에** `3` 을 꺼내므로, `3→2` 를 봐도 이미 늦었다.

> 참고: 이 사이트의 다익스트라 구현은 "닫힌 집합"을 두지 않고 완화될 때마다 큐에 다시 넣는
> 게으른(lazy) 방식이라, 이 그래프에서는 **우연히** 7 을 찾아낸다. 하지만 그건 보장이 아니다.
> 음수 간선에서 게으른 다익스트라는 지수 시간으로 폭발할 수도 있다.

## 복잡도

| | |
|---|---|
| 시간 | **O(VE)** — 라운드 `V-1`회 × 간선 `E`개 |
| 시간(실제) | 조기 종료 덕에 보통 훨씬 빠르다. 최선은 O(E) |
| 공간 | **O(V)** — `dist` 배열뿐. 간선 목록만 있으면 되고 인접 리스트도 필요 없다 |

`V = 1000, E = 10000` 이면 1천만 연산 — 감당 가능하다.
그보다 커지면 SPFA(큐 기반 개선)나 존슨 알고리즘을 고려한다.

### 언제 무엇을 쓰나

| 상황 | 선택 |
|---|---|
| 가중치가 모두 음이 아님 | [다익스트라](#/algo/dijkstra) O((V+E) log V) |
| 음수 간선 있음, 시작점 하나 | **벨만-포드** O(VE) |
| 음수 간선 있음, 모든 쌍 | [플로이드-워셜](#/algo/floyd-warshall) O(V³) |
| 가중치가 전부 1 | [BFS](#/algo/bfs) O(V+E) |

## 구현 노트

**`dist[u] == INF` 검사를 빠뜨리지 마라.** `INF + (-4)` 가 `INF` 보다 작아져서,
도달할 수도 없는 정점의 거리가 이상하게 줄어든다. 음수 간선이 있을 때만 터지는 버그라
찾기 어렵다.

```cpp
if (dist[u] != INF && dist[u] + w < dist[v]) dist[v] = dist[u] + w;
```

**간선 목록이면 충분하다.** 인접 리스트를 만들 필요가 없어서 구현이 짧다.
무방향 그래프라면 각 간선을 양방향 두 개로 펼쳐 넣는다.
다만 **무방향 그래프에 음수 간선이 있으면** 그 간선 하나가 곧 음수 사이클이다(왔다 갔다 하면 된다).

**경로 복원**: `parent[v] = u` 를 함께 기록한다. 음수 사이클을 실제로 출력하려면
탐지된 정점에서 `parent` 를 `V`번 거슬러 올라가 사이클 위로 확실히 들어간 뒤,
거기서부터 한 바퀴 돌면 된다.

**음수 사이클의 영향 범위**: 사이클이 있으면 그 사이클에서 **도달 가능한** 모든 정점의
거리가 `-∞` 다. 탐지된 정점들에서 BFS/DFS 를 한 번 더 돌려 표시한다.

## 변형과 확장

- **SPFA(Shortest Path Faster Algorithm)**: "값이 바뀐 정점의 이웃만" 다시 보도록 큐를 쓴다.
  평균은 훨씬 빠르지만 최악은 여전히 O(VE) 이고, 일부러 만든 입력에서는 오히려 느리다.
- **존슨 알고리즘**: 벨만-포드로 정점마다 퍼텐셜 `h(v)` 를 구해
  `w'(u,v) = w(u,v) + h(u) - h(v) ≥ 0` 으로 재조정한 뒤 각 정점에서 다익스트라를 돌린다.
  희소 그래프의 모든 쌍 최단 경로에서 [플로이드-워셜](#/algo/floyd-warshall)보다 빠르다.
- **차분 제약 시스템(difference constraints)**: `x_j - x_i ≤ c` 꼴 부등식 묶음은
  간선 `i→j` 가중치 `c` 인 그래프의 최단 경로 문제와 같다. 해가 없는 경우 = 음수 사이클.
- **최소 평균 사이클**: 라운드별 `dist` 를 모두 보관하면 카프(Karp)의 공식으로 구할 수 있다.
