## 어떤 문제인가

텍스트에서 패턴이 나오는 위치를 찾는다. 순진한 방법은 텍스트의 모든 위치에 패턴을 대고 **글자마다 비교**한다 — 최악 `O(n·m)`.

```
텍스트: x a b c x a b c
패턴:   a b c              ← 위치마다 최대 m글자 비교
```

각 위치에서 m글자를 다시 보는 게 낭비다.

> 한 창(window)을 **숫자 하나(해시)** 로 요약해 두면, 그 숫자만 비교해서
> "여기는 아예 다르다" 를 즉시 걸러낼 수 있지 않을까?

## 손으로 해보기

기본 입력 텍스트 `xabcxabc`, 패턴 `abc` 로 가 보자. 글자를 숫자로 본다(`a=1, b=2, …`),
밑 `B`, 법 `M` 으로 해시를 만든다(전시용 `B=31, M=1009`).

### 해시 = 글자들의 다항식 값

```
hash("abc") = (1·B² + 2·B + 3) mod M
```

패턴 `abc` 의 해시 `hp` 와, 텍스트 첫 3글자 `xab` 의 해시를 구해 비교한다.

### 롤링 — 창을 옮길 때 O(1)

`xab` → `abc` 로 한 칸 옮길 때, **앞 글자 `x` 를 빼고 뒤 글자 `c` 를 더한다.**

```
새 해시 = ((옛 해시 − x·B²)·B + c) mod M
```

전체를 다시 계산(`O(m)`)하지 않고 **상수 시간**에 갱신한다 — 이게 "롤링" 이다.

### 해시가 같을 때만 진짜 비교

```
i=0: 창 "xab" 해시 ≠ hp → 건너뜀 (문자 비교 0회)
i=1: 창 "abc" 해시 = hp → 실제 "abc"==="abc" 확인 → 위치 1 발견
i=2: 창 "bcx" 해시 ≠ hp → 건너뜀
…
i=5: 창 "abc" 해시 = hp → 확인 → 위치 5 발견
```

대부분의 위치는 해시가 달라 **문자 비교 없이** 지나간다. 해시가 같을 때만 진짜로 확인한다.

### 왜 진짜 비교가 필요한가 — 충돌

서로 다른 문자열이 **우연히 같은 해시**를 가질 수 있다(충돌). 그래서 "해시 같음" 은 후보일 뿐,
반드시 문자로 확인해야 한다. 법 `M` 이 크면 충돌 확률이 아주 낮다.

### 비용

```
해시 비교: 위치마다 O(1)          → 총 O(n)
실제 비교: 해시 같은 곳만 O(m)     → 충돌이 드물면 거의 안 함
합계: 기대 O(n + m)
```

## 아이디어 쌓기

### 1단계 — 창을 숫자로 요약

문자열 창을 다항식 해시 하나로 만든다.

### 2단계 — 롤링으로 O(1) 갱신

창을 옮길 때 앞을 빼고 뒤를 더해 해시를 상수 시간에 갱신한다.

### 3단계 — 해시로 거른다

패턴 해시와 다르면 즉시 건너뛴다(문자 비교 없음).

### 4단계 — 같으면 확인

해시 충돌 가능성 때문에, 같을 때만 실제 문자를 비교한다.

## 코드로 옮기기

```cpp
int rabinKarp(string t, string p) {          // 밑 B, 소수 법 M
    int n = t.size(), m = p.size();
    long long hp = 0, ht = 0, pw = 1;
    for (int i = 0; i < m; i++) {             // 패턴·첫 창 해시
        hp = (hp*B + p[i]) % M;
        ht = (ht*B + t[i]) % M;
        if (i) pw = pw*B % M;                 // pw = B^(m-1)
    }
    for (int i = 0; i + m <= n; i++) {
        if (ht == hp && t.substr(i,m) == p)   // 해시 같으면 실제 비교
            return i;                         // 찾았다
        if (i + m < n)                        // 창을 한 칸 굴린다
            ht = ((ht - t[i]*pw%M + M)*B + t[i+m]) % M;
    }
    return -1;
}
```

`pw = B^(m-1)` 이 "맨 앞 글자의 자릿값". 롤링에서 `− t[i]·pw` 로 앞 글자를 뺀다.

## 자주 하는 실수

**해시만 믿고 문자 비교를 생략한다.** 충돌 때문에 틀린다. 해시 같음 → **반드시** 실제 비교
(생략하면 몬테카를로 버전 — 낮은 확률로 오답).

**음수 mod.** `ht − t[i]·pw` 가 음수일 수 있다. `((… % M) + M) % M` 로 양수화.

**법 M 이 작다.** 충돌이 잦아지면 최악 `O(n·m)` 로 퇴화. 큰 소수(또는 두 개의 해시)를 쓴다.

**밑 B 가 예측 가능하다.** 적대적 입력이 충돌을 유도할 수 있다. **무작위 B** 로 이를 막는다(랜덤화).

## 스스로 확인하기

1. **해시가 다른 위치**가 "건너뜀"(문자 비교 없이) 처리되는 것을 보자.
2. **해시가 같은 위치**에서만 실제 문자 비교가 일어나는 것을 보자.
3. **창이 한 칸씩 굴러가며** 앞을 빼고 뒤를 더하는 롤링을 관찰하자.
4. **두 번의 일치(위치 1, 5)** 를 모두 찾는 것을 확인하자.
5. 입력을 `abracadabra abra` 로 바꿔 보자 — 위치 0과 7에서 찾는다.
6. 입력을 `aaabaaab aab` 로 바꿔 보자 — 반복 문자에서 롤링이 어떻게 도는지 보자.

아래 **깊이 보기**에서는 다항식 해시·충돌 확률·이중 해시, 그리고 랜덤화(무작위 밑)와
2차원·다중 패턴 확장을 다룬다.
