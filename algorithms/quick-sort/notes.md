## 한눈에

**피벗(pivot)** 하나를 골라 "피벗보다 작은 것 / 큰 것"으로 배열을 두 덩이로 가른다.
이때 피벗은 **최종 위치에 확정**된다. 그다음 양쪽 덩이를 재귀적으로 같은 방법으로 정렬한다.

평균 O(n log n)이면서 상수가 매우 작고 제자리에서 동작해, 실제 범용 정렬의 기본 골격으로 쓰인다.

- 비교 기반 · 제자리(in-place) · **불안정(unstable)**
- 분할정복이지만 [병합 정렬](#/algo/merge-sort)과 반대로 **"나눌 때 일을 하고 합칠 때는 아무것도 안 한다"**

## 동작 원리

이 페이지는 **로무토(Lomuto) 분할**을 쓴다. 맨 뒤 원소를 피벗으로 삼고, 변수 `i`를
"피벗보다 작은 값들이 놓일 다음 자리"로 유지한다.

```
pivot = a[hi]
i = lo
for j in [lo, hi):
    if a[j] < pivot:  swap(a[i], a[j]);  i++
swap(a[i], a[hi])        // 피벗을 경계로 옮긴다 → a[i] 확정
```

`j`가 훑고 지나가면서 피벗보다 작은 값을 발견할 때마다 그 값을 경계 `i`로 끌어온다.
루프가 끝나면 `a[lo..i-1]`은 전부 피벗 미만, `a[i..hi-1]`은 전부 피벗 이상이다.
마지막 교환으로 피벗이 정확히 그 사이인 `i`번 칸에 들어간다.

### 분할 후에 왜 피벗을 재귀에서 빼는가

`quickSort(a, lo, i-1)` 과 `quickSort(a, i+1, hi)` 로 **`i`를 제외하고** 재귀한다.
`a[i]`는 이미 최종 위치이므로 다시 건드릴 필요가 없다. 이 덕분에 각 재귀 단계에서
문제 크기가 최소 1씩은 줄어들어 종료가 보장된다.

## 정확성

### 분할 루프 불변식

`j`번째 반복을 시작하는 시점에 다음이 성립한다.

> 1. `a[lo .. i-1]` 의 모든 원소 `< pivot`
> 2. `a[i .. j-1]` 의 모든 원소 `>= pivot`
> 3. `a[hi] == pivot`

시작 시점(`i = j = lo`)에는 두 구간이 모두 비어 있어 자명하다.

- `a[j] >= pivot` 이면 아무것도 하지 않고 `j`만 증가한다. 구간 2가 하나 늘어나며 불변식 유지.
- `a[j] < pivot` 이면 `a[i]`와 `a[j]`를 교환한다. 불변식 2에 의해 `a[i] >= pivot` 이었으므로
  교환 후 `a[j]`(구간 2의 끝)에는 피벗 이상인 값이, `a[i]`에는 피벗 미만인 값이 놓인다.
  `i`와 `j`를 모두 증가시키면 구간 1과 2가 각각 하나씩 늘어난 채로 불변식이 유지된다.

`j == hi` 로 루프가 끝나면 `a[lo..i-1] < pivot <= a[i..hi-1]` 이다. 여기서 `a[i]`와 `a[hi]`를
교환하면 `a[i] == pivot` 이고 좌우 조건이 그대로 유지된다. 즉 **피벗은 최종 위치에 있다.**

### 전체 정렬 — 구간 길이에 대한 강귀납법

길이가 0 또는 1인 구간은 이미 정렬돼 있다(`lo >= hi` 에서 즉시 반환).

길이 `m > 1`인 구간을 보자. 분할 결과 두 부분 구간의 길이는 각각 `i - lo` 와 `hi - i` 이고,
둘 다 `m`보다 **엄밀히 작다**(피벗이 빠졌으므로). 귀납 가정에 의해 두 재귀 호출은 각각을
정렬한다. 분할 불변식에 의해 왼쪽 ≤ 피벗 ≤ 오른쪽이므로, 세 조각을 이어 붙인 전체가 정렬된다. ∎

### 왜 불안정한가

`swap(a[i], a[j])` 는 멀리 떨어진 두 원소를 맞바꾼다. 이때 사이에 있던 같은 값의 상대 순서가
깨질 수 있다. 예를 들어 `[2a, 2b, 1]` 에서 피벗 `1`로 분할하면 `2a`와 `2b`의 순서가 뒤집힌다.
안정성이 필요하면 [병합 정렬](#/algo/merge-sort)을 쓴다.

## 복잡도

분할 자체는 구간을 한 번 훑으므로 `Θ(m)`이다. 점화식은 피벗이 만든 두 조각의 크기에 달려 있다.

```
T(n) = T(k) + T(n-1-k) + Θ(n)
```

| 상황 | 점화식 | 시간 |
|---|---|---|
| 최선(정확히 반씩) | T(n) = 2T(n/2) + Θ(n) | Θ(n log n) |
| 평균(무작위 피벗) | — | Θ(n log n) |
| 최악(매번 한쪽이 비는 분할) | T(n) = T(n-1) + Θ(n) | **Θ(n²)** |

**최악은 우연이 아니다.** 이 구현은 맨 뒤 원소를 피벗으로 쓰므로, 입력이 **이미 정렬돼 있거나
역순이면** 매번 `k = n-1` 또는 `k = 0` 인 최악 분할이 나온다. 하필 실무에서 가장 흔한 입력이다.

### 평균이 O(n log n)인 이유

무작위 피벗을 가정하면, 두 원소 `a_i < a_j` 가 비교되는 사건은 "둘 사이 값들 중 `a_i`나 `a_j`가
가장 먼저 피벗으로 뽑힌" 경우뿐이고, 그 확률은 `2 / (j - i + 1)` 이다. 기대 비교 횟수는

```
Σ_{i<j} 2/(j-i+1) = 2n·H(n) + O(n) ≈ 1.39 n log₂ n
```

즉 평균적으로 최적(`n log₂ n`)보다 39%만 더 비교한다.

### 공간

추가 배열은 없지만 **재귀 스택**을 쓴다. 균형 잡히면 `O(log n)`, 최악에는 `O(n)`이다.
아래의 꼬리 재귀 제거로 최악에도 `O(log n)`을 보장할 수 있다.

## 구현 노트

**피벗 선택이 전부다.** 최악을 피하는 표준 대처는 세 가지다.

1. **무작위 피벗** — `swap(a[hi], a[lo + rand() % (hi-lo+1)])` 를 분할 전에 한 줄 넣는다.
   어떤 고정 입력에도 기대 시간이 O(n log n)이 된다.
2. **median-of-three** — `a[lo]`, `a[mid]`, `a[hi]` 의 중앙값을 피벗으로. 정렬된 입력에서
   정확히 반씩 갈라진다.
3. **introsort** — 재귀 깊이가 `2 log n` 을 넘으면 힙 정렬로 전환해 **최악도 O(n log n)** 을 보장한다.
   `std::sort` 가 쓰는 방법이다.

> 이 페이지의 생성기는 `generate(input)` 이 **순수 함수**여야 하므로(같은 입력 → 같은 트레이스)
> 무작위 피벗을 쓰지 않는다. 그래서 정렬된 배열을 넣으면 최악 동작이 그대로 보인다 —
> 직접 `1 2 3 4 5 6` 을 넣어 스텝 수를 비교해 보자.

**중복이 많은 입력**에서 로무토 분할은 특히 취약하다. 모든 값이 같으면 `a[j] < pivot` 이 한 번도
참이 되지 않아 매번 최악 분할이 난다. 이때는 **3-way 분할(네덜란드 국기 문제)** 로
`< pivot`, `== pivot`, `> pivot` 세 덩이를 만들면 같은 값 구간을 통째로 확정할 수 있다.

**꼬리 재귀 제거**: 짧은 쪽만 재귀하고 긴 쪽은 루프로 처리하면 스택 깊이가 항상 `O(log n)`이다.

```cpp
while (lo < hi) {
    int p = partition(a, lo, hi);
    if (p - lo < hi - p) { quickSort(a, lo, p-1); lo = p+1; }
    else                 { quickSort(a, p+1, hi); hi = p-1; }
}
```

## 변형과 확장

- **호어(Hoare) 분할**: 양쪽에서 포인터를 좁혀 온다. 로무토보다 교환 횟수가 평균 3배 적어
  실전에서는 이쪽이 표준이다. 단 피벗이 최종 위치에 놓이지 않아 재귀 범위가 달라진다.
- **퀵 셀렉트(quickselect)**: 분할 후 **한쪽만** 재귀하면 `k`번째 원소를 평균 O(n)에 찾는다.
  `std::nth_element` 가 이것이다.
- **3-way quicksort**: 중복이 많은 데이터에서 O(n log n)을 유지한다.
