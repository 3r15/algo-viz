## 한눈에

`gcd(a, b) = gcd(b, a mod b)` 를 `b = 0` 이 될 때까지 반복한다. 나머지로 갈아치우면
두 수는 작아지지만 **공약수 집합이 보존**되므로 답이 바뀌지 않는다.

- **시간** `O(log min(a, b))` 번의 나눗셈. 최악은 **피보나치 연속항**
- **공간** `O(1)` — 정수 두 개. 재귀로 써도 꼬리 재귀다
- 기원전 300년경 유클리드의 『원론』에 실려 있다. **현존하는 가장 오래된 비자명 알고리즘**
- 확장하면 `ax + by = gcd(a, b)` 의 정수해까지 준다 → 모듈러 역원, 중국인의 나머지 정리의 토대

**언제 쓰나** — 사실상 언제나. 분수 약분, 최소공배수, 모듈러 역원(확장판), RSA 키 생성,
유리수 산술. 다항식·가우스 정수 같은 **유클리드 정역**에서도 같은 알고리즘이 그대로 작동한다.

**언제 안 쓰나** — 나눗셈이 비싼 하드웨어에서는 나눗셈을 뺄셈과 시프트로 대체한
**이진 GCD(Stein 알고리즘)** 가 빠르다. 아주 큰 수(수만 비트)에서는 준선형
`O(M(n) log n)` 알고리즘이 쓰인다.

## 동작 원리

핵심은 **답을 보존하는 축소 변환**이 딱 하나 있다는 것이다.

```
(a, b)  →  (b, a mod b)          b = 0 이 되면 답은 a
```

나머지는 나누는 수보다 작으므로 두 수가 매번 작아지는데, 아래 보조정리에 의해
**공약수 집합이 그대로**여서 답은 바뀌지 않는다. 뺄셈으로도 같은 일을 할 수 있지만
(`gcd(a, b) = gcd(a − b, b)`), 나눗셈은 그 뺄셈을 **한 번에 몰아서** 하는 것이라
`O(a)` 가 `O(log a)` 로 줄어든다.

### 실행 예

`gcd(966, 630)`

```
966 = 630 × 1 + 336      gcd(966, 630) = gcd(630, 336)
630 = 336 × 1 + 294      gcd(630, 336) = gcd(336, 294)
336 = 294 × 1 +  42      gcd(336, 294) = gcd(294,  42)
294 =  42 × 7 +   0      gcd(294,  42) = gcd( 42,   0) = 42
```

`966 = 42 × 23`, `630 = 42 × 15` 이고 `gcd(23, 15) = 1` 이다. ✓

## 정확성

### 보존 보조정리

> **보조정리.** `b ≠ 0` 이면 `a` 와 `b` 의 공약수 집합은 `b` 와 `a mod b` 의 공약수 집합과 **같다**.

**증명.** `r = a mod b` 라 하고 `q = ⌊a/b⌋` 라 하면 `a = bq + r` 이다.

*(⊆)* `d | a` 이고 `d | b` 라 하자. `r = a − bq` 이고 우변의 두 항이 모두 `d` 의 배수이므로 `d | r`.
따라서 `d` 는 `b` 와 `r` 의 공약수다.

*(⊇)* `d | b` 이고 `d | r` 라 하자. `a = bq + r` 의 우변이 모두 `d` 의 배수이므로 `d | a`.
따라서 `d` 는 `a` 와 `b` 의 공약수다.

두 포함관계가 성립하므로 집합이 같고, 따라서 **최댓값도 같다** — `gcd(a, b) = gcd(b, r)`. ∎

### 불변식과 귀납

> **불변식.** 반복 시작 시점에 `gcd(a, b)` 는 처음 입력 `gcd(a₀, b₀)` 와 같다.

**기저** — 첫 반복 전에는 `(a, b) = (a₀, b₀)` 이므로 자명하다. ✓

**유지** — 한 번의 반복은 `(a, b)` 를 `(b, a mod b)` 로 바꾼다. 보조정리에 의해
`gcd(a, b) = gcd(b, a mod b)` 이므로 불변식이 유지된다. ✓

**종료 시** — `b = 0` 이다. `0` 은 모든 정수의 배수이므로 `a` 와 `0` 의 공약수는 `a` 의 약수 전체이고,
그중 최대는 `a` 자신이다(`a > 0`). 따라서 `gcd(a, 0) = a` 이고, 불변식에 의해
반환값 `a` 가 `gcd(a₀, b₀)` 다. ∎

**종료성** — `b > 0` 인 동안 `a mod b < b` 이므로 두 번째 인자가 **엄격히 감소**하는 음이 아닌 정수열이다.
무한히 감소할 수 없으므로 유한 번에 `0` 이 된다. ∎

## 복잡도

| | 나눗셈 횟수 | 공간 |
|---|---|---|
| 최선 | `1` (한쪽이 다른 쪽의 배수) | `O(1)` |
| 평균 | `≈ (12 ln 2 / π²) ln N ≈ 0.843 ln N` | `O(1)` |
| 최악 | `O(log min(a, b))` — 피보나치 | `O(1)` |

### 왜 로그인가 — 두 번에 절반

> **주장.** 두 번의 반복이 지나면 첫 인자가 절반 이하가 된다.

`(a, b)` 에서 시작해 두 경우로 나눈다.

- `b ≤ a/2` 이면 다음 첫 인자가 `b ≤ a/2` 다.
- `b > a/2` 이면 `⌊a/b⌋ = 1` 이므로 `a mod b = a − b < a − a/2 = a/2`. 두 번째 반복의 첫 인자가
  이 값이므로 `< a/2` 다.

따라서 두 번마다 크기가 절반 이하로 줄어 반복 횟수는 `2 log₂ a + O(1)` 이하다. ∎

### 최악은 피보나치 — 라메 정리

> **라메(Lamé) 정리.** 유클리드 호제법이 `k` 번의 나눗셈을 요구하는 가장 작은 입력은
> `(F_{k+2}, F_{k+1})` 이다. 즉 `min(a, b) < F_{k+1}` 이면 나눗셈이 `k` 번 미만이다.

직관은 이렇다. 나머지를 **가장 느리게** 줄이려면 매 단계의 몫이 최소인 `1` 이어야 하고,
`a = b·1 + r` 즉 `a = b + r` 이 되는 수열이 정확히 피보나치다.

```
gcd(987, 610):  987 = 610 + 377 → 610 = 377 + 233 → … → 나눗셈 14번
gcd(999, 998):  999 = 998 + 1   → 998 = 1 × 998   → 나눗셈 2번
```

두 입력의 크기가 거의 같은데 횟수가 7배 차이 난다. **크기가 아니라 몫의 패턴이 최악을 만든다.**
`F_{k} ≈ φ^k / √5` 이므로 최악 횟수는 `log_φ(√5 · min(a,b)) ≈ 4.785 log₁₀ min(a,b) + 1.672` 다.

### 평균은 최악보다 훨씬 좋다

몫의 분포가 가우스–쿠즈민 분포를 따르므로 평균 나눗셈 횟수는
`(12 ln 2 / π²) ln N ≈ 0.843 ln N` 이다(하이브레히츠·디시터 결과).
최악의 `2 log₂ N ≈ 1.386 ln N` 보다 작다.

**비트 연산으로 세면** 큰 수에서는 나눗셈 자체가 `O(log² N)` 이므로 전체가 `O(log² N)` 비트 연산이다.

## 구현 노트

**`b == 0` 검사를 먼저.** `a % 0` 은 C++ 에서 정의되지 않은 동작이다.

**음수** — C++ 의 `%` 는 피제수의 부호를 따르므로(`-7 % 3 == -1`) 결과가 음수가 될 수 있다.
`std::gcd` 는 절댓값을 취해 항상 음이 아닌 값을 준다. 직접 쓸 때도 `abs` 를 씌우자.

**최소공배수의 오버플로** — 반드시 먼저 나눈다.

```cpp
long long lcm(long long a, long long b) {
    return a / std::gcd(a, b) * b;      // a * b / gcd 는 중간값이 넘친다
}
```

`a` 가 `gcd` 로 나눠지는 것이 보장되므로 정확하다.

**표준 라이브러리** — C++17 이후 `<numeric>` 의 `std::gcd`, `std::lcm`.
직접 구현할 이유는 학습 목적이나 확장판이 필요할 때뿐이다.

**세 수 이상** — `gcd(a, b, c) = gcd(gcd(a, b), c)`. 결합법칙이 성립하므로 접어 나가면 된다.

## 변형과 확장

### 확장 유클리드 호제법 — `ax + by = gcd(a, b)`

`gcd` 만이 아니라 그것을 만드는 **계수**까지 구한다(베주 항등식).

```cpp
// 반환값 = gcd(a, b), 그리고 a*x + b*y = gcd 를 만족하는 x, y 를 채운다
int extGcd(int a, int b, int& x, int& y) {
    if (b == 0) { x = 1; y = 0; return a; }      // a·1 + 0·0 = a
    int x1, y1;
    int g = extGcd(b, a % b, x1, y1);            // b·x1 + (a mod b)·y1 = g
    x = y1;                                       // a mod b = a − b⌊a/b⌋ 를 대입해 정리하면
    y = x1 - (a / b) * y1;                        //   a·y1 + b·(x1 − ⌊a/b⌋·y1) = g
    return g;
}
```

**모듈러 역원**이 여기서 나온다. `gcd(a, m) = 1` 이면 `ax + my = 1` 이므로
`ax ≡ 1 (mod m)` — `x` 가 `a` 의 역원이다. RSA 의 비밀키 계산이 정확히 이 단계다.
[빠른 거듭제곱](#/algo/fast-power)의 페르마 소정리 방식(`a^(m-2) mod m`)은 `m` 이 소수일 때만
쓸 수 있지만, 이쪽은 `gcd(a, m) = 1` 이기만 하면 된다.

### 이진 GCD (Stein 알고리즘)

나눗셈을 쓰지 않는다. 짝수/홀수 판정과 시프트만으로 같은 일을 한다.

```
gcd(2a, 2b) = 2·gcd(a, b)
gcd(2a, b)  = gcd(a, b)        (b 가 홀수)
gcd(a, b)   = gcd(|a−b|/2, min(a,b))   (둘 다 홀수)
```

나눗셈이 비싼 환경(임베디드, 다정밀도 산술)에서 실측이 더 빠르다. 복잡도는 같은 `O(log)` 다.

### 유클리드 정역으로의 일반화

"나머지가 있는 나눗셈" 이 정의되는 구조라면 어디서든 그대로 작동한다.

- **다항식** — `gcd(x²−1, x−1) = x−1`. 유리함수 약분, 부분분수 분해에 쓰인다
- **가우스 정수** `ℤ[i]` — 복소 정수의 gcd
- 여기서 "가장 큰" 은 크기가 아니라 **나눗셈 관계**로 정의된다

### 연분수와의 관계

호제법의 **몫 수열**이 곧 `a/b` 의 연분수 전개다.

```
966/630 = 1 + 1/(1 + 1/(1 + 1/7))       몫 1, 1, 1, 7
```

최악이 피보나치인 이유가 여기서도 보인다 — 몫이 전부 `1` 인 수열이 황금비의 연분수 전개
`[1; 1, 1, 1, …]` 이고, 그것이 가장 느린 수렴이다.
