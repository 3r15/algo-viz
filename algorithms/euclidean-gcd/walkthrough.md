## 어떤 문제인가

`966` 과 `630` 의 **최대공약수**를 구하고 싶다. 두 수를 모두 나누는 가장 큰 수다.

가장 단순한 방법은 **다 나눠 보는 것**이다.

```
1? 나눠진다.  2? 나눠진다.  3? 나눠진다.  4? 안 된다.  …
630 까지 전부 시도하고 그중 가장 큰 것
```

`630` 번 나눠 봐야 한다. 두 수가 10억쯤이면 10억 번이다.

소인수분해도 방법이지만, 큰 수를 소인수분해하는 것 자체가 어렵다(그 어려움이 RSA 암호의 근거다).

> 두 수를 **작게 만들면서** 최대공약수는 그대로 두는 방법이 있을까?

## 손으로 해보기

기본 입력 `966 630` 으로 끝까지 가 보자.

### 핵심 관찰 — 공약수는 나머지에도 남는다

`966` 을 `630` 으로 나눠 본다.

```
966 = 630 × 1 + 336
```

여기서 `d` 가 `966` 과 `630` 을 **둘 다** 나눈다고 하자. 그러면

```
336 = 966 − 630 × 1
      ↑     ↑     ↑
      d로 나눠짐  d로 나눠짐
```

`d` 로 나눠지는 수끼리 빼도 여전히 `d` 로 나눠진다. 그러니 **`d` 는 `336` 도 나눈다.**

반대 방향도 성립한다. `d` 가 `630` 과 `336` 을 나누면 `966 = 630 + 336` 도 나눈다.

> `(966, 630)` 의 공약수 집합 = `(630, 336)` 의 공약수 집합
> **완전히 같다.** 그러니 최대공약수도 같다.

이게 전부다. 큰 쪽을 **나머지로 갈아치우면** 수는 작아지는데 답은 안 바뀐다.

### 끝까지 굴려 보기

```
1회:  966 = 630 × 1 + 336        (a, b) ← (630, 336)
2회:  630 = 336 × 1 + 294        (a, b) ← (336, 294)
3회:  336 = 294 × 1 +  42        (a, b) ← (294,  42)
4회:  294 =  42 × 7 +   0        (a, b) ← ( 42,   0)
                        ↑ 나머지가 0
```

`b` 가 `0` 이 되었다. `gcd(42, 0) = 42` 다 — `0` 은 모든 수로 나눠지므로, `42` 와 `0` 의 공약수는
`42` 의 약수 전부이고 그중 최대는 `42` 자신이다.

**`gcd(966, 630) = 42`.** 나눗셈 **4번**이다. 다 나눠 보는 방법의 `630` 번과 비교해 보자.

검산: `966 = 42 × 23`, `630 = 42 × 15`. `23` 과 `15` 는 서로소다. ✓

### 왜 이렇게 빨리 줄어드나

나머지는 나누는 수보다 **반드시 작다.** `a mod b < b` 다. 그래서 매번 두 수가 작아진다.

더 세게 말할 수 있다. 두 번 반복하면 **큰 수가 절반 이하**가 된다.

```
b ≤ a/2 이면      →  새 a = b ≤ a/2         (한 번에 절반)
b > a/2 이면      →  a mod b = a − b < a/2   (나머지가 절반 미만)
```

어느 쪽이든 두 번 안에 절반이 되므로 반복 횟수가 `O(log)` 다.

### 순서는 신경 쓸 필요 없다

`630 966` 을 넣어도 같은 답이 나온다.

```
630 = 966 × 0 + 630   →  (966, 630)
```

첫 반복이 **알아서 자리를 바꿔 준다.** `a < b` 면 `a mod b = a` 이므로 `(b, a)` 가 되는 것이다.

## 아이디어 쌓기

### 1단계 — 답을 보존하는 변환을 찾는다

"작게 만들되 답은 그대로" 인 변환 하나만 찾으면, 그걸 반복해 문제를 녹여 버릴 수 있다.
그 변환이 `(a, b) → (b, a mod b)` 다.

### 2단계 — 뺄셈에서 나눗셈으로

`d | a`, `d | b` 면 `d | (a − b)` 다. 그래서 원래는 **큰 수에서 작은 수를 빼는** 방법도 된다.

```
966, 630 → 336, 630 → 336, 294 → 42, 294 → 42, 252 → 42, 210 → …
```

옳긴 한데 `(1000000, 1)` 이면 백만 번 빼야 한다. **뺄셈을 한꺼번에 하는 것이 나눗셈**이고,
`a mod b` 가 "가능한 만큼 다 뺀 결과" 다. 이 한 번의 교체가 `O(a)` 를 `O(log a)` 로 만든다.

### 3단계 — 멈추는 자리를 정한다

`b = 0` 일 때 `gcd(a, 0) = a`. `0` 은 모든 수의 배수이므로 자연스럽다.
이 기저가 있어야 재귀가 끝난다.

### 4단계 — 상태는 두 정수뿐

추가 배열이 없다. 공간 `O(1)` 이다.

## 코드로 옮기기

```cpp
int gcd(int a, int b) {
    while (b != 0) {                // ← 3단계: b 가 0 이면 끝
        int r = a % b;              // ← 2단계: 나눗셈으로 한꺼번에
        a = b;                      // ← 1단계: (a, b) ← (b, a mod b)
        b = r;
    }
    return a;
}
```

재귀로 쓰면 정의가 그대로 코드가 된다.

```cpp
int gcd(int a, int b) { return b == 0 ? a : gcd(b, a % b); }
```

**꼬리 재귀**라 컴파일러가 보통 반복문으로 펴 준다. C++ 표준 라이브러리에도 있다 — `std::gcd(a, b)`.

## 자주 하는 실수

**`b` 가 0 인지 검사하지 않고 나눈다.** `a % 0` 은 **0으로 나누기**라 정의되지 않는다
(C++ 에서는 정의되지 않은 동작). 반드시 `while (b != 0)` 을 먼저 본다.

**음수를 그대로 넣는다.** C++ 의 `%` 는 음수에서 나머지가 음수일 수 있어(`-7 % 3 == -1`)
결과가 음수로 나온다. 보통 `abs` 를 먼저 씌운다.

**최소공배수를 `a * b / gcd` 로 계산하다 오버플로.** `a * b` 가 먼저 계산되어 넘친다.

```cpp
long long lcm = a / gcd(a, b) * b;   // 먼저 나눈다
```

`a` 는 `gcd` 로 반드시 나눠지므로 정확하고, 중간값이 작아 안전하다.

**`gcd(0, 0)` 을 기대한다.** 정의되지 않는다(모든 수가 공약수라 최대가 없다).
이 페이지는 그 경우를 따로 안내한다.

## 스스로 확인하기

1. **표의 `a mod b` 열**을 보자. `336 → 294 → 42 → 0` 으로 줄어든다. 나머지가 항상 나누는 수보다 작다.
2. **각 스텝의 설명줄**이 `gcd(966, 630) = gcd(630, 336)` 처럼 **등식**으로 쓰여 있다.
   값이 바뀌는데 답은 그대로라는 것이 알고리즘의 심장이다.
3. **막대 두 개**가 급격히 줄어드는 것을 보자. 4스텝에 `966` 이 `42` 가 된다.
4. 입력을 `630 966` 으로 **순서를 바꿔** 보자. 첫 반복이 자리를 맞바꾸므로 나눗셈이 한 번 늘어 5번이 되고(4번 → 5번), 이후 과정과 답은 똑같다.
5. 입력을 `999 998` 로 바꿔 보자. **나눗셈 2번**에 끝난다(답은 1). 연속한 두 수는 항상 서로소다.
6. 입력을 `12 60` 로 바꿔 보자. 한쪽이 다른 쪽의 배수라 **2번**에 끝난다 — 자리를 맞추는 한 번, 나머지가 0 이 되는 한 번.
7. 입력을 `987 610` 으로 바꿔 보자. 피보나치 연속항이라 **최악의 경우**다 —
   `999 998` 이 2번인데 이쪽은 **14번**이다. 두 수의 크기가 비슷한 것과 최악은 별개다.

아래 **깊이 보기**에서는 `gcd` 보존을 정식으로 증명하고, 최악이 피보나치라는 라메 정리와
확장 유클리드 호제법(`ax + by = gcd`)을 다룬다.
