## 어떤 문제인가

수열이 하나 있다. 여기서 원소 몇 개를 **순서를 바꾸지 않고** 골라, 골라낸 것들이
**계속 커지기만 하도록** 만들고 싶다. 가장 길게 고르면 몇 개일까?

```
3  4  1  5  8  2  6  9
```

"연속"일 필요는 없다. 띄엄띄엄 골라도 되고, **왼쪽에서 오른쪽 순서만 지키면 된다.**

```
3  4     5  8        9      ← 길이 5. 3 < 4 < 5 < 8 < 9
   4  1                     ← 안 됨. 4 다음에 1 은 작아진다
```

가장 단순한 방법은 **모든 부분 수열을 다 만들어 보는 것**이다. 원소가 `n` 개면
고르거나 안 고르거나 이므로 `2^n` 가지. `n = 40` 이면 1조 개가 넘는다.

> 다 만들어 보지 않고, **앞에서부터 한 칸씩 쌓아 올릴 수는 없을까?**

## 손으로 해보기

기본 입력 `[3, 4, 1, 5, 8, 2, 6, 9]` 로 끝까지 가 보자.

### 상태를 어떻게 잡을까

"길이가 가장 긴 증가 수열"을 통째로 구하려 하면 손을 댈 데가 없다. 대신 질문을 **좁힌다.**

> `dp[i]` = **`a[i]` 로 끝나는** 증가 부분 수열 중 가장 긴 것의 길이

"로 끝나는" 이 결정적이다. 끝점을 못 박아 두면 **그 뒤에 뭘 이어 붙일 수 있는지** 판단할 수 있다.
끝점을 모르면 이어 붙일 수가 없다.

### 왼쪽부터 채운다

`dp[i]` 를 구할 땐 **앞의 모든 `j`** 를 후보로 본다. `a[j] < a[i]` 라면
"`j` 로 끝나는 수열" 뒤에 `a[i]` 를 붙일 수 있다.

```
dp[i] = max( dp[j] + 1 )     단, j < i 이고 a[j] < a[i]
        아무도 없으면 1      (자기 혼자)
```

**i = 0 (a=3)** — 앞이 없다. `dp[0] = 1`.

**i = 1 (a=4)** — `j=0`: `3 < 4` ✓ → `dp[0]+1 = 2`.

```
dp[1] = 2      수열: 3 4
```

**i = 2 (a=1)** — `j=0`: `3 < 1`? ✗ / `j=1`: `4 < 1`? ✗

```
dp[2] = 1      아무 뒤에도 못 붙는다. 1 은 가장 작으니 당연하다
```

**i = 3 (a=5)**

```
j=0:  3 < 5 ✓   dp[0]+1 = 2   →  dp[3] = 2
j=1:  4 < 5 ✓   dp[1]+1 = 3   →  dp[3] = 3   (더 길다! 갱신)
j=2:  1 < 5 ✓   dp[2]+1 = 2   →  3 을 못 넘는다. 그대로
dp[3] = 3      수열: 3 4 5
```

`j=2` 를 보자. `1 < 5` 라 **이어 붙일 수는 있다.** 그런데 `1` 로 끝나는 수열은 길이가 1뿐이라
붙여 봐야 2다. 이미 3을 얻었으니 소용없다. **조건이 두 개**인 이유가 이것이다 —
붙일 수 있느냐(`a[j] < a[i]`)와 붙여서 이득이냐(`dp[j]+1 > dp[i]`).

**i = 4 (a=8)** — `j=3` 에서 `dp[3]+1 = 4` 로 갱신된다.

```
dp[4] = 4      수열: 3 4 5 8
```

**i = 5 (a=2)** — `2` 보다 작은 건 앞의 `1` 뿐이다.

```
j=2:  1 < 2 ✓   dp[2]+1 = 2
dp[5] = 2      수열: 1 2
```

여기서 갈래가 하나 더 생겼다. 지금은 짧지만 **버리면 안 된다** — 뒤에서 이 갈래가 자랄 수도 있다.

**i = 6 (a=6)**

```
j=0: 3<6 → 2      j=1: 4<6 → 3      j=3: 5<6 → 4  ← 최대
j=4: 8<6 ✗        j=5: 2<6 → dp[5]+1 = 3, 4 를 못 넘음
dp[6] = 4      수열: 3 4 5 6
```

**i = 7 (a=9)** — 모두가 `9` 보다 작다. 그중 `dp` 가 가장 큰 `j=4` (`dp=4`) 를 고른다.

```
dp[7] = 5      수열: 3 4 5 8 9
```

### 표 전체

```
i:       0   1   2   3   4   5   6   7
a[i]:    3   4   1   5   8   2   6   9
dp[i]:   1   2   1   3   4   2   4   5
prev[i]: ·   0   ·   1   3   2   3   4
```

**답은 dp 의 최댓값 5** 이고, 그 자리는 `i = 7` 이다.

### 수열 자체를 되찾기

길이만으로는 아쉽다. 갱신할 때마다 **"누구 뒤에 붙였는지"** 를 `prev` 에 적어 두면 거슬러 갈 수 있다.

```
7 → prev[7]=4 → prev[4]=3 → prev[3]=1 → prev[1]=0 → prev[0]=·

인덱스:  0  1  3  4  7
값:      3  4  5  8  9      ✓ 길이 5
```

## 아이디어 쌓기

### 1단계 — 완전탐색은 왜 안 되나

각 원소를 고르거나 말거나 → `2^n`. 그런데 이 `2^n` 개 중 **대부분은 서로 겹친다.**
`3 4 5` 로 시작하는 수열을 몇 번이고 다시 만들고 있다. 겹치는 계산을 한 번만 하면 된다.

### 2단계 — 끝점으로 상태를 좁힌다

"가장 긴 것" 을 바로 묻지 말고 **"`i` 로 끝나는 것 중 가장 긴 것"** 을 묻는다.
끝점이 정해지면 확장 가능 여부(`a[j] < a[i]`)를 즉시 판단할 수 있다.

이렇게 좁힌 상태가 `n` 개뿐이므로, 답은 그중 **최댓값**이다.

### 3단계 — 작은 것부터 채운다

`dp[i]` 는 `dp[0..i-1]` 만 쓴다. 그러니 **왼쪽부터 채우면** 필요한 값이 항상 준비돼 있다.
이게 [동적 계획법](#/paradigm/dynamic-programming)의 기본 골격이다.

```
dp[0] → dp[1] → dp[2] → …      각 칸은 왼쪽 칸들만 참조
```

### 4단계 — 발자국을 남긴다

`dp[i]` 를 갱신할 때 `prev[i] = j` 를 함께 적는다. 길이는 `dp` 가, **수열은 `prev` 가** 알려 준다.
공간이 `O(n)` 더 들 뿐이다.

### 5단계 — 답은 어디 있나

`dp[n-1]` 이 아니다! 마지막 원소로 끝나는 게 가장 길다는 보장이 없다.
`[1, 2, 3, 0]` 이면 답은 `dp[2] = 3` 이고 `dp[3] = 1` 이다.
**`dp` 전체의 최댓값**을 찾아야 한다.

## 코드로 옮기기

```cpp
int lis(vector<int>& a) {
    int n = a.size(), best = 0;
    vector<int> dp(n, 1), prev(n, -1);      // ← 2단계: 전부 1(자기 혼자)
    for (int i = 1; i < n; i++) {           // ← 3단계: 왼쪽부터
        for (int j = 0; j < i; j++) {       //    앞의 모든 후보
            if (a[j] < a[i] && dp[j] + 1 > dp[i]) {
                //  └ 붙일 수 있나   └ 붙여서 이득인가
                dp[i] = dp[j] + 1;
                prev[i] = j;                // ← 4단계: 발자국
            }
        }
        if (dp[i] > dp[best]) best = i;     // ← 5단계: 최댓값 자리 추적
    }
    return dp[best];
}
```

`dp` 를 **1 로 초기화**하는 것이 "자기 혼자로도 길이 1" 을 담는다. 그래서 별도의 예외 처리가 없다.

이중 반복문이 그대로 `O(n²)` 다. `n = 5000` 정도까지는 넉넉하고,
그보다 크면 **이분 탐색으로 `O(n log n)`** 짜리 다른 방법이 있다(깊이 보기에서 다룬다).

## 자주 하는 실수

**`dp[n-1]` 을 답으로 낸다.** 5단계의 그 문제. 마지막 원소가 답의 끝점이라는 보장이 없다.

**조건을 `a[j] <= a[i]` 로 쓴다.** 그러면 같은 값도 이어 붙여 **비내림차순**을 세게 된다.
"증가"가 강한 뜻(`<`)인지 약한 뜻(`≤`)인지는 문제마다 다르니 꼭 확인하자.
기본 입력에는 중복이 없어 이 실수가 드러나지 않는다 — `7 7 7 7` 을 넣어 보면 바로 보인다.

**`dp` 를 0 으로 초기화한다.** 아무 후보도 없는 원소의 `dp` 가 0 이 되어 길이가 1씩 모자란다.

**갱신 조건에서 `dp[i]` 비교를 뺀다.** `if (a[j] < a[i]) dp[i] = dp[j] + 1;` 로 쓰면
**나중 `j` 가 앞의 좋은 결과를 덮어쓴다.** `i=3` 에서 `j=2` 가 `dp[3]` 을 3에서 2로 떨어뜨린다.

**`prev` 를 `dp` 와 따로 갱신한다.** 둘은 반드시 **같은 `if` 안에서 함께** 바뀌어야 한다.
따로 두면 길이와 발자국이 어긋나 복원이 엉킨다.

## 스스로 확인하기

1. **`i = 3` 의 `j = 2` 스텝**을 찾아보자. `1 < 5` 라 붙일 수는 있는데 갱신은 안 된다.
   설명줄이 "이어 붙여도 길이 2 로, 지금의 dp[3]=3 을 넘지 못한다" 라고 말한다.
2. **`i = 5` (`a=2`)** 를 보자. `dp` 가 2에 그친다. 이 짧은 갈래를 왜 버리지 않는지 생각해 보자.
3. **마지막 스텝**에서 `a[i]` 줄과 `dp[i]` 줄에 초록으로 표시되는 칸들이 복원된 수열이다.
   인덱스가 `0, 1, 3, 4, 7` 로 **띄엄띄엄**한 것을 확인하자.
4. 입력을 `1 2 3 4 5` 로 바꿔 보자. `dp` 가 계단처럼 오르고 갱신이 매번 일어난다.
5. 입력을 `5 4 3 2 1` 로 바꿔 보자. `dp` 가 전부 1 이고, 갱신 스텝이 **하나도 없다.**
6. 입력을 `7 7 7 7` 로 넣어 보자. 답이 1 이다 — `<` 가 강한 부등호이기 때문이다.

아래 **깊이 보기**에서는 이 DP 가 왜 최적해를 놓치지 않는지 귀납으로 증명하고,
`O(n log n)` 으로 줄이는 이분 탐색 방법을 다룬다.
