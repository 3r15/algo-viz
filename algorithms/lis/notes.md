## 한눈에

수열에서 **순서를 지키며 고른 증가 부분 수열** 중 가장 긴 것의 길이를 구한다.
상태를 "`i` 로 끝나는 것 중 최장" 으로 좁혀, 앞의 모든 원소를 후보로 훑는 `O(n²)` DP 다.

- **시간** `Θ(n²)` — 입력과 무관하게 항상 같다(조기 종료가 없다)
- **공간** `Θ(n)` — `dp` 와 `prev` 각각 배열 하나
- **복원 가능** — `prev` 만 있으면 길이뿐 아니라 수열 자체를 얻는다
- **부분 수열이지 부분 배열이 아니다** — 연속일 필요가 없다

**언제 쓰나** — `n` 이 수천 이하이고, 구현이 단순한 쪽이 나을 때. 무엇보다
**"증가" 대신 다른 조건**(2차원 좌표의 지배 관계, 가중치 합 최대 등)으로 바꾸기 쉽다.
`dp[j] + 1` 을 `dp[j] + w[i]` 로 바꾸면 곧바로 최대 가중치 증가 수열이 된다.

**언제 안 쓰나** — `n` 이 10만 이상이면 `Θ(n²)` 는 감당이 안 된다.
순수한 LIS 길이만 필요하다면 아래 **변형과 확장**의 `O(n log n)` 방법을 쓴다.

## 동작 원리

핵심은 **상태를 끝점으로 못 박는 것**이다.

> `dp[i]` = `a[i]` 를 마지막 원소로 하는 증가 부분 수열의 최대 길이

이렇게 두면 확장 조건이 국소적으로 판정된다. `a[i]` 를 `a[j]` 뒤에 붙일 수 있는지는
`a[j] < a[i]` 하나로 결정되고, 그 앞이 어떻게 생겼는지는 볼 필요가 없다.

### 점화식

```
dp[i] = 1 + max{ dp[j] : j < i, a[j] < a[i] }        (그런 j 가 있으면)
      = 1                                             (없으면)

답 = max{ dp[i] : 0 ≤ i < n }
```

두 번째 줄이 중요하다. 답은 `dp[n-1]` 이 아니라 **`dp` 전체의 최댓값**이다.
`a = [1, 2, 3, 0]` 에서 `dp = [1, 2, 3, 1]` 이고 답은 3이다.

### 실행 예

`a = [3, 4, 1, 5, 8, 2, 6, 9]`

```
i:       0   1   2   3   4   5   6   7
a[i]:    3   4   1   5   8   2   6   9
dp[i]:   1   2   1   3   4   2   4   5
prev[i]: ·   0   ·   1   3   2   3   4
                                     ↑ 최댓값

복원:  7 → 4 → 3 → 1 → 0
값:    3  4  5  8  9        길이 5
```

`i = 5` (값 2) 에서 `dp = 2` 로 짧게 끝난 갈래를 주목하자. 이 갈래는 끝까지 자라지 못했지만,
**버릴 수 없다.** 뒤에 3, 4, 5 가 이어졌다면 이쪽이 답이 됐을 것이다. 모든 끝점을 남겨 두는
이유가 여기 있다.

## 정확성

`dp[i]` 의 정의를 그대로 만족시킴을 `i` 에 대한 강귀납법으로 보인다.

> **불변식.** `i` 번째 반복이 끝난 시점에 `dp[i]` 는 `a[i]` 로 끝나는 증가 부분 수열의
> 최대 길이와 같고, `prev[i]` 는 그 최적 수열에서 `a[i]` 의 바로 앞 원소의 인덱스다
> (그런 원소가 없으면 `-1`).

**기저** — `i = 0`. `a[0]` 으로 끝나는 증가 부분 수열은 `[a[0]]` 뿐이므로 최대 길이는 1이다.
코드는 `dp` 를 1로 초기화하고 `prev[0] = -1` 로 두므로 성립한다.

**귀납 단계** — `dp[0..i-1]` 이 불변식을 만족한다고 하자. `dp[i]` 를 양쪽에서 조인다.

*(≥) 코드가 구한 값은 실현 가능하다.* 코드가 `dp[i] = dp[j] + 1` 로 쓴 순간, 그 `j` 는
`j < i` 이고 `a[j] < a[i]` 를 통과했다. 귀납 가정에 의해 `a[j]` 로 끝나는 길이 `dp[j]` 짜리
증가 수열 `S` 가 실제로 존재한다. `a[j] < a[i]` 이고 `j < i` 이므로 `S` 뒤에 `a[i]` 를 붙인
것도 증가 부분 수열이며 길이는 `dp[j] + 1` 이다. 초기값 1 도 `[a[i]]` 로 실현된다.

*(≤) 최적해를 넘지 않는다.* `a[i]` 로 끝나는 최적 증가 수열을 `T` 라 하고 `|T| = L` 이라 하자.

- `L = 1` 이면 `dp[i] ≥ 1` 이므로 볼 것이 없다.
- `L ≥ 2` 이면 `T` 에서 `a[i]` 바로 앞 원소를 `a[k]` 라 하자. `T` 의 정의상 `k < i` 이고
  `a[k] < a[i]` 다. `T` 에서 마지막 `a[i]` 를 떼면 `a[k]` 로 끝나는 길이 `L-1` 짜리
  증가 수열이므로, 귀납 가정에 의해 `dp[k] ≥ L - 1`.
  코드는 `j = k` 를 반드시 검사하고(내부 루프가 `0..i-1` 전체를 돈다), 그때 조건
  `a[k] < a[i]` 는 참이므로 `dp[i] ≥ dp[k] + 1 ≥ L` 이 된다.

두 방향을 합치면 `dp[i] = L`. `prev[i]` 는 마지막으로 `dp[i]` 를 갱신한 `j` 이고,
그 `j` 가 위 (≥) 논증의 실현을 주므로 복원이 실제 최적 수열을 만든다. ∎

**종료성** — 두 반복문 모두 유한 범위의 단조 증가 카운터이므로 항상 종료한다.

**답의 정당성** — 임의의 증가 부분 수열은 어떤 원소로 끝나고, 그 끝점이 `i` 라면
길이는 `dp[i]` 이하다. 따라서 `max dp[i]` 가 전체 최댓값이고, 그 이상은 존재하지 않는다.

### 왜 조건이 두 개인가

```cpp
if (a[j] < a[i] && dp[j] + 1 > dp[i])
```

앞 조건은 **실현 가능성**(증가 조건), 뒤 조건은 **최대성**(더 나은 후보만 채택)이다.
뒤 조건을 빼면 나중 `j` 가 앞의 더 좋은 결과를 덮어써서 (≤) 방향이 깨진다.
위 예에서 `i = 3`, `j = 2` 가 정확히 그 경우다 — `1 < 5` 는 통과하지만 `dp` 는 2로 떨어진다.

## 복잡도

| | 시간 | 공간 |
|---|---|---|
| 최선 | `Θ(n²)` | `Θ(n)` |
| 평균 | `Θ(n²)` | `Θ(n)` |
| 최악 | `Θ(n²)` | `Θ(n)` |

**시간** — 내부 루프가 `i` 번 도므로 총 비교 횟수는

```
Σ_{i=0}^{n-1} i = n(n-1)/2 = Θ(n²)
```

조기 종료 조건이 없어 **최선과 최악이 같다.** 이미 정렬된 입력이든 역순 입력이든
비교 횟수는 동일하고, 갱신이 일어나는 횟수만 달라진다(역순이면 0회).

**공간** — `dp`, `prev` 각각 `n` 칸. 복원이 필요 없으면 `prev` 를 버려 절반으로 줄일 수 있지만,
어차피 `Θ(n)` 이다.

**하한은 아니다** — `Θ(n²)` 는 이 알고리즘의 비용이지 문제의 하한이 아니다.
비교 기반 모델에서 LIS 의 하한은 `Ω(n log n)` 이고, 아래 방법이 그 하한을 달성한다.

## 구현 노트

**엄격 증가 vs 비내림차순** — `a[j] < a[i]` 는 **엄격 증가**다. 같은 값을 허용하려면
`a[j] <= a[i]` 로 바꾼다. 문제 설명의 "증가"가 어느 쪽인지 반드시 확인하자.
중복 없는 입력에서는 두 구현이 같은 답을 내므로 테스트를 통과하고도 틀릴 수 있다.

**최댓값 추적** — 루프 안에서 `best` 를 갱신하는 대신 끝나고 `max_element` 를 써도 된다.
다만 복원까지 하려면 값이 아니라 **인덱스**가 필요하다.

**오버플로 없음** — 값이 아니라 길이를 더하므로 `dp[i] ≤ n` 이다. `int` 로 충분하다.

**빈 입력** — `n = 0` 이면 답은 0 이다. `dp[best]` 를 그대로 반환하면 접근 위반이 되니
분기해서 막아야 한다.

## 변형과 확장

### `O(n log n)` — 이분 탐색

길이별로 **가능한 최소 끝값**만 기억한다. `tail[k]` = 길이 `k+1` 짜리 증가 수열의 끝값 중 최소.

```cpp
vector<int> tail;
for (int x : a) {
    auto it = lower_bound(tail.begin(), tail.end(), x);   // 엄격 증가
    if (it == tail.end()) tail.push_back(x);              // 길이가 늘었다
    else *it = x;                                          // 끝값을 더 작게 교체
}
return tail.size();
```

`tail` 은 항상 **오름차순**이라 이분 탐색이 성립한다. 원소마다 `O(log n)` 이므로 전체 `O(n log n)`.

> **주의: `tail` 은 답이 아니다.** `tail` 의 내용물은 실제 LIS 가 아닐 수 있다
> (끝값만 교체하며 섞이기 때문). **길이는 맞고 수열은 틀리다.**
> 수열까지 복원하려면 각 원소가 놓인 위치를 별도 배열에 기록하고 역추적해야 한다.
> 비내림차순이면 `lower_bound` 를 `upper_bound` 로 바꾼다.

### 최대 가중치 증가 수열

`dp[j] + 1` 을 `dp[j] + w[i]` 로 바꾸면 "개수"가 아니라 "가중치 합"의 최대가 된다.
`O(n²)` 골격이 그대로 살아 있어 변형이 쉽다는 것이 이 방법의 실질적 장점이다.

### 최장 감소 / 양방향

부등호를 뒤집으면 최장 감소 부분 수열이다. 앞에서 온 LIS 와 뒤에서 온 LIS 를 합치면
"산 모양(증가 후 감소)" 부분 수열의 최댓값도 `O(n²)` 에 구한다.

### 딜워스 정리

수열을 **비증가 부분 수열들로 덮는 최소 개수**는 LIS 의 길이와 같다.
겉보기에 다른 최소 덮개 문제가 LIS 로 환원되는 고전적인 예다.
