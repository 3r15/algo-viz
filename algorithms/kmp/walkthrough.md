## 어떤 문제인가

긴 텍스트에서 짧은 패턴이 **처음 나오는 위치**를 찾는다. 예: `"ababcababa"` 에서 `"ababa"` 는 어디?

가장 순진한 방법은 텍스트의 모든 위치에 패턴을 대 보는 것이다.

```
텍스트: a b a b c a b a b a
패턴:   a b a b a           ← 0번부터 대 봄
        a b a b ✗           ← 4번째에서 어긋남
          a b a b a         ← 1칸 밀어 다시
          ✗                 ← 바로 어긋남
```

어긋날 때마다 패턴을 1칸 밀고 **텍스트 포인터도 되돌린다.** 최악이면 `O(n·m)` — 텍스트를 몇 번씩 다시 읽는다.

> 어긋났을 때, 이미 맞춰 본 부분에서 **뭔가 배운 게 없을까?**
> 텍스트를 되돌리지 않고 패턴만 똑똑하게 밀 수는 없을까?

## 손으로 해보기

기본 입력 텍스트 `ababcababa`, 패턴 `ababa` 로 가 보자.

### ① 패턴의 "실패 함수" 를 먼저 만든다

패턴이 **자기 자신과 얼마나 겹치는지** 를 미리 계산한다.

```
fail[i] = pattern[0..i] 에서 "접두사이면서 접미사" 인 가장 긴 조각의 길이
```

패턴 `ababa` 를 보자.

```
i=0  "a"      접두사=접미사 없음        fail[0]=0
i=1  "ab"     없음                     fail[1]=0
i=2  "aba"    "a" 가 앞에도 뒤에도      fail[2]=1
i=3  "abab"   "ab" 가 앞뒤로           fail[3]=2
i=4  "ababa"  "aba" 가 앞뒤로          fail[4]=3
```

`fail = [0, 0, 1, 2, 3]`. 이게 KMP 의 지도다.

### ② 텍스트를 훑는다 — 텍스트는 절대 되돌리지 않는다

```
텍스트: a b a b c a b a b a
패턴:   a b a b a
        ✓ ✓ ✓ ✓ ✗       ← i=4 에서 c≠a 어긋남
```

여기서 순진한 방법은 패턴을 1칸 밀고 텍스트를 되돌렸다. KMP 는 다르다.
지금까지 `abab` 4글자가 맞았고, `fail[3] = 2` 다. 즉 **이미 맞은 부분의 끝 2글자 `ab` 가
패턴 앞 2글자 `ab` 와 같다.** 그러니 패턴을 그만큼 밀어 앞 2글자는 맞은 셈 치고,
**텍스트는 그대로 `i=4` 에서** 이어 본다.

```
텍스트: a b a b c a b a b a
패턴:       a b a b a         ← 패턴만 2칸 밀림, 텍스트 i 는 그대로
                ✗            ← c≠a, 또 어긋남 → fail 로 또 미끄러짐
```

이렇게 텍스트 포인터 `i` 는 **한 번도 뒤로 안 간다.** 계속 나아가며 `abababa` 뒤쪽에서 `ababa` 를 찾아낸다.

### 비용을 세어 보자

```
① 실패 함수:  패턴 길이만큼          O(m)
② 텍스트 훑기: 텍스트 포인터가 안 되돌아감  O(n)
합계:  O(n + m)
```

순진한 `O(n·m)` 이 `O(n+m)` 이 됐다. 텍스트가 100만 글자여도 딱 한 번만 훑는다.

## 아이디어 쌓기

### 1단계 — 어긋남에서 정보를 캔다

이미 맞은 부분은 텍스트와 패턴이 **같다는 것을 안다.** 이 정보를 버리지 말자.

### 2단계 — 패턴의 자기 겹침을 미리 계산

패턴의 접두사=접미사 길이(`fail`)를 알면, 어긋났을 때 몇 글자는 다시 안 맞춰도 된다.

### 3단계 — 텍스트는 고정, 패턴만 미끄러뜨린다

어긋나면 `k = fail[k-1]` 로 패턴 포인터만 줄인다. 텍스트 포인터 `i` 는 전진만 한다.

### 4단계 — 실패 함수도 같은 원리로 만든다

`fail` 자체를 계산할 때도, 패턴을 패턴에 맞춰 보며 같은 미끄러뜨림을 쓴다(자기 자신에 대한 KMP).

## 코드로 옮기기

```cpp
// fail[i] = pattern[0..i] 의 최장 "접두사=접미사" 길이
vector<int> buildFail(string p) {
    vector<int> fail(p.size(), 0);
    for (int i = 1, k = 0; i < p.size(); i++) {
        while (k > 0 && p[i] != p[k]) k = fail[k-1];
        if (p[i] == p[k]) k++;
        fail[i] = k;
    }
    return fail;
}
int kmp(string t, string p) {
    vector<int> fail = buildFail(p);
    for (int i = 0, k = 0; i < t.size(); i++) {
        while (k > 0 && t[i] != p[k]) k = fail[k-1];  // 패턴만 미끄러뜨린다
        if (t[i] == p[k]) k++;
        if (k == p.size()) return i - k + 1;          // 찾았다
    }
    return -1;
}
```

두 루프의 모양이 **똑같다** — `while (k>0 && 안 맞으면) k = fail[k-1];` 이 KMP 의 심장이다.
`i` 는 두 루프 모두 뒤로 가지 않는다.

## 자주 하는 실수

**텍스트 포인터를 되돌린다.** 그러면 순진한 `O(n·m)` 으로 돌아간다. KMP 의 요점은 `i` 가 전진만 하는 것이다.

**`fail` 을 잘못 정의한다.** "접두사이면서 접미사" 는 **자기 자신 전체는 제외**한 진접두사·진접미사여야
쓸모 있다. 전체를 포함하면 `fail[i]=i+1` 이 돼 미끄러뜨림이 멈춘다.

**`while` 을 `if` 로 쓴다.** 한 번 미끄러뜨려도 여전히 어긋날 수 있다. `fail` 을 따라 **여러 번** 줄여야 한다.

**한 번 찾고 멈춰야 하는데 안 멈춘다(또는 그 반대).** 모든 등장을 찾으려면 `k = fail[k-1]` 로 이어서 탐색한다.
여기 구현은 **처음 한 번**만 찾고 반환한다.

## 스스로 확인하기

1. **① 실패 함수 단계**에서 `fail` 표가 채워지는 것을 보자 — `ababa → [0,0,1,2,3]`.
2. **② 텍스트 훑기**에서 패턴이 어긋날 때 **패턴만 오른쪽으로 미끄러지고 텍스트 열은 그대로**인 것을 보자.
3. **패턴 포인터 `k` 가 `fail` 로 줄어드는 순간**을 설명에서 확인하자.
4. 패턴을 `aab` 로 바꿔 보자 — `fail = [0,1,0]`. 반복 문자에서 겹침이 어떻게 잡히는지 보자.
5. 텍스트에 패턴이 없게 바꿔 보자(`abcabc xyz`). 끝까지 훑고 "못 찾음" 이 나온다.
6. `aaaaab aab` 를 넣어 보자. `aa` 가 계속 맞다가 `b` 에서 미끄러지는 전형적인 예다.

아래 **깊이 보기**에서는 실패 함수의 정의와 두 루프가 왜 `O(n+m)` 인지(전위 인자 논증)를 증명하고,
Z-함수·아호-코라식으로의 확장을 다룬다.
