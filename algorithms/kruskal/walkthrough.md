## 어떤 문제인가

여러 마을을 도로로 연결하려고 한다. 마을 쌍마다 공사비가 다르다.

> **모든 마을이 서로 오갈 수 있게** 하면서 **공사비 합을 최소로** 하려면 어떤 도로를 놓아야 할까?

몇 개를 놓아야 할까? 마을이 `n`개면 **`n-1`개**면 충분하다.
그보다 적으면 끊긴 곳이 생기고, 많으면 **순환로**가 생겨 하나는 낭비다.

간선 `n-1`개로 모두 연결된 그래프를 **트리**라고 하고,
원래 그래프의 모든 정점을 덮으므로 **신장 트리(spanning tree)**,
그중 비용이 최소인 것이 **최소 신장 트리(MST)** 다.

## 손으로 해보기

기본 그래프다.

```
간선:  0-1(2)  0-2(4)  1-2(3)  1-3(3)  2-4(6)  3-4(5)  3-5(1)  4-5(4)
```

### 규칙

> **싼 간선부터** 차례로 본다. **순환로를 만들지 않으면** 채택, 만들면 버린다.

정말 이게 다다. 놀랍도록 단순하다.

### 따라가 보기

먼저 가중치 순으로 줄을 세운다.

```
3-5(1)  0-1(2)  1-2(3)  1-3(3)  0-2(4)  4-5(4)  3-4(5)  2-4(6)
```

각 정점은 처음엔 **혼자만 있는 집합**이다. `{0} {1} {2} {3} {4} {5}`

```
① 3-5(1):  3과 5는 다른 집합 → 채택!   집합: {0}{1}{2}{3,5}{4}
           총 1

② 0-1(2):  0과 1은 다른 집합 → 채택!   집합: {0,1}{2}{3,5}{4}
           총 3

③ 1-2(3):  1은 {0,1}, 2는 {2} → 다르다 → 채택!
           집합: {0,1,2}{3,5}{4}      총 6

④ 1-3(3):  1은 {0,1,2}, 3은 {3,5} → 다르다 → 채택!
           집합: {0,1,2,3,5}{4}       총 9

⑤ 0-2(4):  0과 2가 둘 다 {0,1,2,3,5} → 같다! → 버린다 ✗
           이미 0에서 2로 가는 길이 있다(0-1-2). 여기에 도로를 더 놓으면 순환로다.

⑥ 4-5(4):  4는 {4}, 5는 {0,1,2,3,5} → 다르다 → 채택!
           집합: {0,1,2,3,4,5}        총 13

간선 5개(= 6-1) 를 모았다 → 완성! 나머지는 볼 필요 없다.
```

**최소 신장 트리: `3-5, 0-1, 1-2, 1-3, 4-5`, 총 비용 13**

⑤에서 버린 것이 핵심 장면이다. `0-2` 는 가중치 4로 나쁘지 않지만,
**이미 연결된 두 정점을 또 잇는 것**이라 아무 이득이 없다.

## 아이디어 쌓기

### 1단계 — 왜 싼 것부터 골라도 되나

"눈앞의 최선을 고른다"는 전략을 **그리디**라고 한다. 대부분의 문제에서 그리디는 틀리는데,
이 문제에서는 맞는다. 직관적인 이유는 이렇다.

지금 보고 있는 간선 `e` 가 두 덩어리 `A` 와 `B` 를 잇는 가장 싼 간선이라 하자.
`A` 와 `B` 는 언젠가 반드시 연결돼야 하고, 그러려면 둘 사이를 잇는 간선이 최소 하나는 필요하다.
그런데 `e` 가 그중 제일 싸다. **`e` 를 안 쓰고 다른 걸 쓰면 손해거나 같다.**

(이걸 엄밀하게 만든 것이 **컷 성질**이고, 아래 깊이 보기에서 증명한다.)

### 2단계 — "순환로를 만드나?"를 어떻게 빨리 아나

간선 `(u,v)` 를 넣으면 순환로가 생긴다 ⟺ **`u` 와 `v` 가 이미 이어져 있다.**

매번 탐색으로 확인하면 느리다. 대신 **"지금 누가 누구와 한 덩어리인가"** 를 관리하자.

### 3단계 — 유니온 파인드

각 덩어리를 대표 하나로 나타낸다.

```
find(x)     x 가 속한 덩어리의 대표를 알려 준다
union(a,b)  두 덩어리를 하나로 합친다
```

그러면 판정이 한 줄이 된다.

```
find(u) == find(v)  →  이미 같은 덩어리 → 순환로 → 버린다
find(u) != find(v)  →  다른 덩어리 → 채택하고 union(u,v)
```

시각화의 정점 아래 숫자가 바로 이 **대표**다. 간선을 채택할 때마다 두 대표가 하나로 합쳐지는 걸 볼 수 있다.

### 4단계 — 경로 압축

대표를 찾으려면 부모를 타고 위로 올라간다. 그런데 **올라가면서 지나온 노드들의 부모를
대표로 바로 바꿔 두면** 다음 번엔 한 칸 만에 끝난다.

```cpp
int find(int x) {
    return parent[x] == x ? x : parent[x] = find(parent[x]);
                               ↑ 여기서 부모를 대표로 갈아 끼운다
}
```

이 한 줄이 유니온 파인드를 사실상 O(1) 로 만든다.

## 코드로 옮기기

```cpp
int parent[MAXN];

int find(int x) {                            // ← 3·4단계
    return parent[x] == x ? x : parent[x] = find(parent[x]);
}
bool unite(int a, int b) {
    a = find(a); b = find(b);
    if (a == b) return false;                // ← 같은 덩어리 = 순환로
    parent[b] = a;
    return true;
}

int kruskal(vector<Edge>& edges, int n) {
    sort(edges.begin(), edges.end());        // ← 싼 것부터
    for (int v = 0; v < n; v++) parent[v] = v;  // ← 각자 혼자
    int total = 0, picked = 0;
    for (auto [w, u, v] : edges) {
        if (unite(u, v)) {                   // ← 순환로가 아니면 채택
            total += w;
            if (++picked == n - 1) break;    // ← n-1 개 모으면 끝
        }
    }
    return total;
}
```

`unite` 가 `bool` 을 돌려주는 게 요령이다. "합쳤다"(=채택했다)와 "이미 같았다"(=버렸다)를
한 번의 호출로 판정하고 처리한다.

## 자주 하는 실수

**정렬을 빠뜨린다.** 싼 것부터 보는 게 전부인데 정렬을 안 하면 아무 의미가 없다.

**`find` 없이 `parent` 를 직접 비교한다.**

```cpp
if (parent[u] == parent[v]) ...   // ✗ 틀렸다
if (find(u) == find(v)) ...       // ○ 대표까지 올라가야 한다
```

`parent` 는 바로 위 노드일 뿐, 덩어리의 대표가 아니다.

**경로 압축을 빼먹는다.** 동작은 하지만 덩어리가 한 줄로 길어지면 `find` 가 느려진다.

**`n-1` 개를 못 채웠는데 그냥 끝낸다.** 그래프가 연결돼 있지 않으면 신장 트리가 없다.
결과는 각 덩어리의 MST 를 모은 **최소 신장 숲**이 되고, 그 사실을 알려 줘야 한다.

## 스스로 확인하기

1. **정점 아래 숫자(대표)를 보자.** 간선을 채택할 때마다 두 그룹의 대표가 하나로 합쳐진다.
2. **버려지는 간선을 찾아보자.** "대표가 같다 → 순환로" 라는 설명이 나온다. 기본 그래프에선 `0-2(4)` 다.
3. **간선 5개를 모으면 즉시 멈춘다.** 남은 간선 `3-4(5)`, `2-4(6)` 은 아예 보지 않는다.
4. 편집기에서 **⚖ 가중치 모드**로 `0-2` 를 1로 낮춰 보자. 이제 이 간선이 가장 먼저 검토되고,
   대신 다른 간선이 버려진다. 총 비용이 어떻게 달라지는가?
5. 정점 하나를 **간선 없이** 떼어 놓고 실행해 보자. "연결되어 있지 않다"는 결과가 나온다.

아래 **깊이 보기**에서는 1단계의 직관을 **컷 성질**로 엄밀하게 증명하고
(교환 논법이 나온다), 유니온 파인드의 `α(n)` 복잡도를 다룬다.
