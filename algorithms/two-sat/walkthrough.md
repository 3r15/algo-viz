## 어떤 문제인가

각 조건이 **둘 중 하나는 참** 인 형태의 논리 퍼즐이 있다.

```
(x1 ∨ x2) ∧ (¬x1 ∨ x3) ∧ (¬x2 ∨ ¬x3) ∧ (x1 ∨ x3)
```

각 괄호(절)는 "이 둘 중 적어도 하나는 참" 이라는 뜻이다. **모든 절을 동시에 참**으로 만드는
변수 배정(각 xᵢ 를 참/거짓으로)이 있을까? 있다면 무엇일까?

일반 SAT(절에 리터럴이 셋 이상)은 NP-완전이라 어렵지만, **절마다 리터럴이 딱 둘(2-SAT)** 이면
그래프로 **선형 시간**에 풀린다.

## 손으로 해보기

핵심 착상: **절 (a∨b) 는 두 개의 함의(→)와 같다.**

```
(a ∨ b)  ≡  (¬a → b)  그리고  (¬b → a)
```

"둘 중 하나는 참" = "하나가 거짓이면 **반드시** 다른 하나가 참". 이걸 **함의 그래프**로 그린다.

### 함의 그래프 만들기

리터럴 `x1, ¬x1, x2, ¬x2, …` 를 **정점**으로 두고, 절마다 두 함의를 **방향 간선**으로 넣는다.

```
(x1 ∨ x2):   ¬x1 → x2,   ¬x2 → x1
(¬x1 ∨ x3):   x1 → x3,   ¬x3 → ¬x1
(¬x2 ∨ ¬x3):  x2 → ¬x3,   x3 → ¬x2
(x1 ∨ x3):   ¬x1 → x3,   ¬x3 → x1
```

### 강한 연결 요소(SCC)로 판정

함의 그래프에서 `A → B` 는 "A 가 참이면 B 도 참" 이다. 그러니 **서로 오갈 수 있는**(SCC) 리터럴들은
**전부 같은 값**이어야 한다(하나가 참이면 연쇄로 다 참).

> **핵심 정리.** 어떤 변수 `x` 에 대해 `x` 와 `¬x` 가 **같은 SCC** 에 있으면 모순 → **충족 불가**.
> 그런 변수가 없으면 → **충족 가능**.

`x` 와 `¬x` 가 같은 SCC 면 "x 가 참이면 ¬x 도 참" 이 되어 버려 불가능하기 때문이다.

### 배정하기

충족 가능하면, 각 변수는 **위상적으로 더 뒤에 오는**(SCC 순서가 더 나중인) 리터럴을 **참**으로 둔다.
그러면 모든 함의 `A → B` 에서 "A 참인데 B 거짓" 인 경우가 생기지 않는다.

이 예에서는 SCC 를 구하면 `x1=참, x2=거짓, x3=참` 이 나오고, 네 절을 모두 만족한다.

### 비용

```
정점 2n개(리터럴), 간선 2m개(절마다 둘)
SCC 계산: O(V + E) = O(n + m)
변수별 검사: O(n)
합계 O(n + m) — 선형!
```

## 아이디어 쌓기

### 1단계 — 절을 함의로

`(a∨b)` = `¬a→b` ∧ `¬b→a`. "둘 중 하나는 참" 을 함의 두 개로.

### 2단계 — 함의 그래프

리터럴이 정점, 함의가 방향 간선. `A→B` = "A 참이면 B 참".

### 3단계 — SCC 는 같은 값

서로 오갈 수 있는 리터럴은 값이 같아야 한다. `x` 와 `¬x` 가 한 SCC → 모순.

### 4단계 — 위상 순서로 배정

충족 가능하면, 더 뒤 SCC 의 리터럴을 참으로. 모든 함의가 만족된다.

## 코드로 옮기기

```cpp
void addClause(int a, int b) {
    g.add_edge(neg(a), b);              // a 가 거짓이면 b 는 참
    g.add_edge(neg(b), a);              // b 가 거짓이면 a 는 참
}
bool twoSat(int n) {
    auto comp = scc(g);                 // 강한 연결 요소
    for (int v = 0; v < n; v++)
        if (comp[node(v,true)] == comp[node(v,false)])
            return false;               // x 와 ¬x 가 한 SCC → 모순
    for (int v = 0; v < n; v++)          // 값 배정
        x[v] = comp[node(v,true)] > comp[node(v,false)];
    return true;
}
```

`scc` 는 [코사라주](#/algo/kosaraju-scc)나 [타잔](#/algo/tarjan-scc)을 그대로 쓴다.
`node(v,true)` = 변수 v 의 "참" 리터럴 정점, `neg` 는 리터럴의 부정.

## 자주 하는 실수

**함의를 한 방향만 넣는다.** `(a∨b)` 는 `¬a→b` **와** `¬b→a` **둘 다**. 하나만 넣으면 틀린다.

**배정 방향을 뒤집는다.** "위상적으로 뒤(더 큰 SCC 번호)를 참" — SCC 번호 규약(코사라주는 역위상 순서)
에 맞춰 부등호 방향을 정한다. 헷갈리면 배정을 만든 뒤 모든 절을 검사해 확인.

**리터럴 정점 번호를 헷갈린다.** 변수 v 의 참 정점 `2v`, 거짓 정점 `2v+1`, `neg` 는 최하위 비트 뒤집기.

**SCC 를 잘못 구한다.** 함의 그래프의 SCC 가 답의 전부다 — SCC 알고리즘이 정확해야 한다.

## 스스로 확인하기

1. **절마다 두 함의 간선**이 그래프에 추가되는 것을 보자(초록 강조).
2. **리터럴 정점**(x1, ¬x1, …)이 좌우로 배치된 것을 보자.
3. **SCC 라벨(C0, C1…)** 이 정점에 붙는 것을 보자 — 같은 라벨 = 같은 값.
4. **변수별 검사**에서 x 와 ¬x 가 다른 SCC 인지 확인하는 것을 보자.
5. **최종 배정**에서 참으로 정해진 리터럴이 초록이 되는 것을 보자.
6. 입력을 `1 2 -1 -2 1 -2 -1 2` 로 바꿔 보자 — x1 과 ¬x1 이 한 SCC 가 되어 **충족 불가(UNSAT)**.
