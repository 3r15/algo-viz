## 어떤 문제인가

배열을 오름차순으로 정렬하고 싶다. 가장 단순한 생각은 **선택 정렬**이다.

```
남은 것 중 최댓값을 찾아 맨 뒤로 보낸다. 그걸 반복한다.
```

옳긴 한데 느리다. **최댓값을 찾을 때마다 전부 훑기** 때문이다.

```
7개 중 최댓값 찾기 → 6번 비교
6개 중 최댓값 찾기 → 5번 비교
...                  합계 n²/2 번
```

문제는 매번 **처음부터 다시 찾는다**는 것이다. 방금 훑으면서 알아낸 정보를 전부 버린다.

> 최댓값을 **꺼낸 뒤에도 남는** 구조로 원소를 담아 둘 수는 없을까?

그 구조가 **힙(heap)** 이다. 힙에서는 최댓값을 꺼내는 데 `O(log n)` 밖에 안 든다.
`n` 번 꺼내면 `O(n log n)`. 이게 힙 정렬의 전부다.

## 손으로 해보기

기본 입력 `[4, 10, 3, 5, 1, 8, 7]` 로 끝까지 가 보자.

### 배열이 곧 트리다

힙의 첫 번째 마법은 **포인터가 필요 없다**는 것이다. 배열 인덱스를 그대로 트리로 읽는다.

```
인덱스:  0   1   2   3   4   5   6
값:      4  10   3   5   1   8   7

                 4  (0)
               /      \
          10 (1)        3  (2)
          /    \       /    \
       5 (3)  1 (4)  8 (5)  7 (6)
```

규칙은 딱 하나다.

```
부모 i  →  왼쪽 자식 2i+1,  오른쪽 자식 2i+2
자식 c  →  부모 (c-1)/2
```

**최대 힙 조건**은 "모든 부모가 자기 자식보다 작지 않다" 이다. 지금은 아니다 —
`4` 가 자식 `10` 보다 작다.

### ① 힙 만들기 — 아래에서 위로

잎(자식이 없는 노드)은 **이미 크기 1짜리 힙**이다. 고칠 필요가 없다.
그러니 **마지막 부모부터** 거꾸로 올라가며 고친다.

원소가 7개면 마지막 부모는 `⌊7/2⌋ - 1 = 2` 번이다.

**i = 2 (값 3)**

```
자식 5(값 8) 과 6(값 7) 중 큰 쪽은 8
부모 3 < 8  →  교환

→  [4, 10, 8, 5, 1, 3, 7]
```

**i = 1 (값 10)**

```
자식 3(값 5) 과 4(값 1) 중 큰 쪽은 5
부모 10 ≥ 5  →  그대로 둔다
```

**i = 0 (값 4)** — 여기가 재미있다. 한 번 바꾸고 **끝이 아니다.**

```
자식 1(값 10) 과 2(값 8) 중 큰 쪽은 10
부모 4 < 10  →  교환.  →  [10, 4, 8, 5, 1, 3, 7]
                            내려간 4 는 이제 1번 자리에 있다

1번에서 다시: 자식 3(값 5) 과 4(값 1) 중 큰 쪽은 5
부모 4 < 5  →  교환.  →  [10, 5, 8, 4, 1, 3, 7]

3번에는 자식이 없다  →  끝
```

`4` 가 제자리를 찾을 때까지 **계속 내려간다.** 이 동작이 `siftDown` 이다.

```
최대 힙 완성:  [10, 5, 8, 4, 1, 3, 7]

                10 (0)
               /     \
           5 (1)      8 (2)
           /   \      /   \
        4 (3) 1 (4) 3 (5) 7 (6)
```

**루트가 전체 최댓값**이다. 이게 힙의 유일한 약속이다 —
형제끼리는 아무 순서도 없다(`5` 가 `8` 보다 작지만 왼쪽에 있다).

### ② 하나씩 빼내기

최댓값이 루트에 있다. **맨 뒤 자리와 바꾸면** 그 자리는 영원히 확정이다.

```
루트 10 ↔ 마지막 7      →  [7, 5, 8, 4, 1, 3 | 10]
                                              ↑ 확정. 힙 크기 6
```

이제 루트에 `7` 이 앉아 힙 조건이 깨졌다. **그런데 깨진 곳은 루트 하나뿐이다.**
아래는 여전히 멀쩡한 힙이다. 그러니 `siftDown` 한 번이면 복구된다.

```
자식 1(5) 과 2(8) 중 큰 쪽은 8.  7 < 8  →  교환
→  [8, 5, 7, 4, 1, 3 | 10]
2번에서 다시: 자식 5(3).  7 ≥ 3  →  멈춘다
```

이걸 반복한다.

```
[8, 5, 7, 4, 1, 3 | 10]   루트 8 ↔ 마지막 3
[3, 5, 7, 4, 1 | 8, 10]   siftDown  →  [7, 5, 3, 4, 1 | 8, 10]
[1, 5, 3, 4 | 7, 8, 10]   siftDown  →  [5, 4, 3, 1 | 7, 8, 10]
[1, 4, 3 | 5, 7, 8, 10]   siftDown  →  [4, 1, 3 | 5, 7, 8, 10]
[3, 1 | 4, 5, 7, 8, 10]   siftDown  →  [3, 1 | 4, 5, 7, 8, 10]
[1 | 3, 4, 5, 7, 8, 10]   힙 크기 1 → 끝
```

**`[1, 3, 4, 5, 7, 8, 10]`** ✓

정렬 구역이 **뒤에서부터 자란다.** 추가 배열이 전혀 없다 — 배열 하나 안에서
왼쪽은 힙, 오른쪽은 정렬 완료로 나뉠 뿐이다.

## 아이디어 쌓기

### 1단계 — 선택 정렬의 낭비를 없앤다

"최댓값을 뒤로" 라는 뼈대는 선택 정렬과 **똑같다.** 다른 건 최댓값을 찾는 방법뿐이다.

```
선택 정렬:  매번 전부 훑는다        O(n)   →  전체 O(n²)
힙 정렬  :  힙에서 꺼낸다           O(log n) →  전체 O(n log n)
```

### 2단계 — 트리를 배열에 담는다

완전 이진 트리(빈틈 없이 왼쪽부터 채운 트리)는 **레벨 순서로 배열에 눕히면**
포인터 없이도 부모·자식을 계산으로 찾을 수 있다. 메모리도 딱 `n` 칸이다.

### 3단계 — siftDown 하나면 된다

힙이 깨지는 방식은 항상 같다 — **어떤 노드 하나가 자기 자식보다 작다.**
그 노드를 제자리까지 내려보내면 복구된다. 높이가 `⌊log₂ n⌋` 이므로 `O(log n)`.

### 4단계 — 힙 만들기는 아래에서 위로

```
for (int i = n/2 - 1; i >= 0; i--) siftDown(a, i, n);
```

`i` 를 **거꾸로** 도는 게 핵심이다. `siftDown(i)` 가 성립하려면 `i` 의 **두 자식이 이미 힙**이어야 하는데,
자식은 `i` 보다 큰 인덱스라 이미 처리됐다.

잎(`n/2` 이상)은 건드리지 않는다 — 자식이 없어 이미 힙이다.

> 위에서 아래로(`i = 0 → n-1`) 돌면 **틀린다.** 아래가 아직 힙이 아니라
> siftDown 의 전제가 무너진다.

### 5단계 — 정렬은 힙을 줄이는 것

루트를 뒤와 바꾸고 **힙 크기만 1 줄인다.** 원소를 실제로 옮기거나 지우지 않는다.
`size` 라는 숫자 하나가 "여기까지가 힙" 이라는 경계선이다.

## 코드로 옮기기

```cpp
void siftDown(vector<int>& a, int i, int size) {
    while (2*i + 1 < size) {                    // ← 3단계: 자식이 있는 동안
        int child = 2*i + 1;
        if (child + 1 < size && a[child+1] > a[child])
            child++;                            //    큰 자식 쪽으로만 내려간다
        if (a[i] >= a[child]) break;            //    제자리를 찾았다
        swap(a[i], a[child]);
        i = child;
    }
}

void heapSort(vector<int>& a) {
    int n = a.size();
    for (int i = n/2 - 1; i >= 0; i--)          // ← 4단계: 아래에서 위로
        siftDown(a, i, n);
    for (int size = n; size > 1; size--) {      // ← 5단계: 힙을 줄여 간다
        swap(a[0], a[size-1]);
        siftDown(a, 0, size - 1);
    }
}
```

**왜 큰 자식과만 비교하나?** 작은 자식과 바꾸면 그 자식이 자기 형제보다 작아져
**힙 조건이 또 깨진다.** 큰 쪽을 올려야 한 번에 정리된다.

**`size` 를 인자로 받는 이유**가 5단계다. 배열은 그대로 두고 "여기까지만 힙" 이라고 알려 준다.

## 자주 하는 실수

**힙 만들기를 위에서 아래로 돈다.** 4단계의 그 문제. `i = 0` 부터 돌면 조용히 틀린 힙이 나온다.
게다가 `O(n log n)` 이 되어 느리기까지 하다(아래에서 위로 하면 `O(n)` 이다).

**작은 자식과 바꾼다.** 한 번의 교환으로 힙 조건이 두 군데 깨진다.

**`size` 대신 `n` 을 넘긴다.** 정렬 단계에서 `siftDown(a, 0, n)` 을 부르면
**이미 확정한 뒷부분을 다시 힙에 끌어들인다.** 정렬이 무너진다.

**오른쪽 자식 존재 검사를 뺀다.** `child + 1 < size` 를 빼면 배열 밖을 읽는다.
완전 이진 트리라도 **마지막 부모는 자식이 하나뿐일 수 있다.**

**`n/2` 대신 `n/2 - 1` 을 안 쓴다.** 0-based 에서 마지막 부모는 `⌊n/2⌋ - 1` 이다.
`n/2` 부터 시작하면 잎 하나를 헛돈다(틀리진 않지만 군더더기).

**안정 정렬이라고 생각한다.** 힙 정렬은 **불안정**하다. 멀리 있는 원소끼리 교환하기 때문에
값이 같은 원소의 앞뒤 순서가 뒤집힐 수 있다.

## 스스로 확인하기

1. **`i = 0` 의 siftDown**(스텝 8~13)을 보자. `4` 가 **두 층**을 내려간다.
   한 번 바꾸고 끝이 아니라는 걸 눈으로 확인하자.
2. **`i = 1` 스텝**(6~7)을 보자. 비교만 하고 교환이 없다. `10 ≥ 5` 라 이미 제자리다.
3. **힙 완성 스텝**(14)에서 트리를 보자. `5`(1번)가 `8`(2번)보다 작은데도 왼쪽에 있다.
   **형제끼리는 순서가 없다** — 부모-자식 관계만 지켜지면 힙이다.
4. **트리에서 노드가 사라지는 순간**(15, 19, 23…)을 보자. 힙 크기가 줄면서
   맨 뒤 노드가 트리에서 빠지고, 아래 배열 줄에서는 **초록(정렬 완료)** 으로 바뀐다.
5. 입력을 `1 2 3 4 5 6 7` 로 바꿔 보자. 이미 오름차순인데도 **비용이 전혀 줄지 않는다.**
   힙 정렬에 "운 좋은 입력" 은 없다.
6. 입력을 `7 6 5 4 3 2 1` 로 바꿔 보자. 내림차순은 이미 최대 힙이라
   **① 단계에서 교환이 한 번도 없다.**
7. 입력을 `5 5 5 5` 로 바꿔 보자. 전부 같아도 교환이 일어난다 — 불안정성의 씨앗이다.

아래 **깊이 보기**에서는 "아래에서 위로 힙 만들기가 왜 `O(n)` 인가" 를 급수로 증명하고,
`n log n` 이 비교 정렬의 하한이라는 사실과 실전에서 퀵 정렬에 밀리는 이유를 다룬다.
