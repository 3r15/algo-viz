## 한눈에

배열을 최대 힙으로 만든 뒤 루트(최댓값)를 배열 뒤쪽으로 하나씩 빼내며 정렬한다.
**추가 메모리 없이 최악에도 `O(n log n)` 을 보장**하는 유일한 고전 정렬이다.

- **시간** `Θ(n log n)` — 최선·평균·최악이 모두 같다. 조기 종료가 없다
- **공간** `O(1)` — 완전한 제자리 정렬. 재귀도 필요 없다(반복 siftDown)
- **불안정(unstable)** — 멀리 떨어진 원소끼리 교환하므로 동일 값의 순서가 뒤집힌다
- **비교 기반** — 하한 `Ω(n log n)` 을 상수 배 안에서 달성한다

**언제 쓰나** — **최악 시간을 보장해야 할 때**. 실시간 시스템, 적대적 입력이 가능한 서버,
[퀵 정렬](#/algo/quick-sort)의 `O(n²)` 최악을 막는 안전망(introsort 가 정확히 이것을 한다).
메모리가 극도로 제한된 환경에서도 유일한 선택지가 되곤 한다.

**언제 안 쓰나** — **평균 속도가 목적이면 퀵 정렬이 보통 2~3배 빠르다**(아래 참고).
안정성이 필요하면 [병합 정렬](#/algo/merge-sort)로 간다.
"가장 큰 `k` 개"만 필요하면 전체를 정렬하지 말고 힙에서 `k` 번만 꺼내면 `O(n + k log n)` 이다.

## 동작 원리

핵심은 **완전 이진 트리를 배열에 눕히면 포인터가 사라진다**는 것이다.

```
부모 i  →  자식 2i+1, 2i+2          (0-based)
자식 c  →  부모 ⌊(c-1)/2⌋
```

> **최대 힙 조건.** 모든 `i` 에 대해 `a[i] ≥ a[2i+1]` 이고 `a[i] ≥ a[2i+2]` (인덱스가 있는 한).

형제 사이에는 아무 순서도 요구되지 않는다. 이 **느슨함**이 힙을 싸게 유지하는 이유다.
정렬은 전순서를 요구하지만 힙은 부분 순서만 요구한다.

### siftDown — 유일한 기본 연산

노드 하나가 자식보다 작아 힙 조건이 깨졌을 때, 그 노드를 제자리까지 내려보낸다.

```
while (자식이 있다) {
    더 큰 자식을 고른다
    부모 ≥ 그 자식이면 멈춘다
    부모와 큰 자식을 교환하고 한 층 내려간다
}
```

**큰 자식과 교환해야** 한다. 작은 자식과 바꾸면 올라간 값이 자기 형제보다 작아져
힙 조건이 새로 깨진다.

### 두 단계

```
① 힙 만들기   for (i = n/2-1; i >= 0; i--) siftDown(i, n)
② 뽑아내기    for (size = n; size > 1; size--) { swap(a[0], a[size-1]); siftDown(0, size-1); }
```

②에서 힙 크기를 줄이는 것만으로 정렬 구역이 뒤에서부터 자란다. **원소를 옮기지 않는다** —
`size` 라는 경계선 하나가 배열을 힙과 정렬 구역으로 나눈다.

### 실행 예

`[4, 10, 3, 5, 1, 8, 7]`

```
① i=2:  3 ↔ 8        →  [4, 10, 8, 5, 1, 3, 7]
  i=1:  10 ≥ 5, 그대로
  i=0:  4 ↔ 10, 다시 4 ↔ 5  →  [10, 5, 8, 4, 1, 3, 7]     ← 최대 힙

② 10↔7, siftDown  →  [8, 5, 7, 4, 1, 3 | 10]
   8↔3,  siftDown  →  [7, 5, 3, 4, 1 | 8, 10]
   7↔1,  siftDown  →  [5, 4, 3, 1 | 7, 8, 10]
   5↔1,  siftDown  →  [4, 1, 3 | 5, 7, 8, 10]
   4↔3,  siftDown  →  [3, 1 | 4, 5, 7, 8, 10]
   3↔1              →  [1 | 3, 4, 5, 7, 8, 10]
```

`i = 0` 에서 값 `4` 가 **두 층**을 내려간 것에 주목하자. siftDown 은 한 번의 교환이 아니라
제자리를 찾을 때까지의 하강이다.

## 정확성

### siftDown 의 정당성

> **전제.** `i` 의 두 부분 트리는 각각 이미 최대 힙이고, 힙 조건이 깨졌다면 오직 `i` 에서만 깨져 있다.
> **결론.** `siftDown(i, size)` 가 끝나면 `i` 를 뿌리로 하는 부분 트리 전체가 최대 힙이다.

**증명.** 루프 불변식을 잡는다.

> 각 반복의 시작 시점에, `i` 를 뿌리로 하는 부분 트리는 **`i` 자신을 제외하면** 최대 힙 조건을
> 모두 만족한다. 즉 위반이 있다면 `a[i] < max(자식)` 하나뿐이다.

*초기* — 전제가 그대로 불변식이다.

*유지* — 반복 한 번을 보자. `c` 를 `i` 의 자식 중 값이 최대인 것이라 하자.

- `a[i] ≥ a[c]` 이면 `a[i]` 는 두 자식 모두보다 크거나 같으므로 `i` 에서의 위반이 없다.
  나머지는 불변식상 이미 힙이므로 부분 트리 전체가 힙이다. 루프를 빠져나가고 결론이 성립한다.
- `a[i] < a[c]` 이면 교환한다. 교환 후 `i` 자리에는 옛 `a[c]` 가 있는데,
  이 값은 `i` 의 두 자식 중 최대였으므로 **양쪽 자식 모두보다 크거나 같다** → `i` 에서 위반이 없다.
  한편 `c` 자리에는 옛 `a[i]` 가 내려왔고, `c` 의 부분 트리는 불변식상 힙이었으므로
  위반이 생긴다면 오직 `c` 에서만 생긴다. `i ← c` 로 갱신하면 불변식이 그대로 유지된다.

*종료* — 매 반복에서 `i` 의 깊이가 1씩 증가한다. 깊이는 `⌊log₂ size⌋` 를 넘을 수 없으므로
유한 번에 자식이 없어져 루프가 끝난다. 종료 시 불변식과 "위반 없음" 이 함께 성립하므로
부분 트리는 최대 힙이다. ∎

### ① 힙 만들기의 정당성

> **불변식.** 반복이 `i` 를 처리하기 직전에, 인덱스 `i+1, i+2, …, n-1` 을 뿌리로 하는
> 모든 부분 트리는 이미 최대 힙이다.

**기저** — 첫 반복은 `i = ⌊n/2⌋ - 1`. 인덱스 `⌊n/2⌋` 이상은 모두 잎이고
(자식 `2i+1 ≥ n` 이므로), 잎 하나짜리 트리는 자명하게 힙이다. ✓

**유지** — `i` 의 두 자식 `2i+1`, `2i+2` 는 모두 `i` 보다 크므로 불변식에 의해 이미 힙이다.
따라서 siftDown 의 전제가 충족되어, 호출 후 `i` 의 부분 트리가 힙이 된다.
`i+1` 이상의 부분 트리들은 siftDown 이 `i` 의 부분 트리 안에서만 값을 옮기므로 영향받지 않는다.
`i` 를 하나 줄이면 불변식이 유지된다.

**종료** — `i = 0` 을 처리하고 나면 인덱스 0을 뿌리로 하는 트리, 즉 **배열 전체가 최대 힙**이다. ∎

여기서 `i` 를 **내림차순**으로 도는 것이 필수임이 드러난다. 오름차순이면
"자식이 이미 힙" 이라는 전제가 성립하지 않아 유지 단계가 무너진다.

### ② 정렬의 정당성

> **불변식.** `size` 값으로 반복을 시작할 때, (1) `a[0..size-1]` 은 최대 힙이고,
> (2) `a[size..n-1]` 은 오름차순으로 정렬돼 있으며, (3) 그 구간의 모든 원소는
> `a[0..size-1]` 의 모든 원소보다 크거나 같다.

**기저** — `size = n`. ①에 의해 (1)이 성립하고, (2)·(3)은 빈 구간이라 자명하다. ✓

**유지** — `a[0]` 은 힙의 최댓값이므로 `a[0..size-1]` 전체의 최댓값이다.
(3)에 의해 뒤쪽 구간은 모두 그 이상이므로, `a[0]` 을 `a[size-1]` 자리에 놓으면
그 자리는 **정렬된 위치**가 맞다. 교환 후 (2)와 (3)이 크기 `size-1` 기준으로 유지된다.
루트에 올라온 값 때문에 힙 조건은 루트에서만 깨지고, 두 부분 트리는 여전히 힙이므로
`siftDown(0, size-1)` 이 (1)을 복구한다.

**종료** — `size = 1` 이면 `a[1..n-1]` 이 정렬돼 있고 `a[0]` 은 그 모두보다 작거나 같으므로
배열 전체가 오름차순이다. ∎

### 불안정성

> 값이 같은 두 원소의 상대 순서가 보존되지 않는다.

`[5a, 5b, 1]` 을 보자(구분을 위해 첨자를 붙였다). 힙을 만들면 `5a` 가 루트에 남고,
`swap(a[0], a[2])` 로 `5a` 가 맨 뒤로 간다. 결과는 `[1, 5b, 5a]` — **뒤집혔다.**
루트와 맨 뒤를 바꾸는 연산이 거리에 상관없이 원소를 옮기기 때문이며,
이는 알고리즘의 본질적 성질이라 국소적으로 고칠 수 없다.
안정성이 필요하면 각 원소에 원래 인덱스를 붙여 2차 키로 쓰거나, 다른 정렬을 택한다.

## 복잡도

| | 시간 | 공간 |
|---|---|---|
| 최선 | `Θ(n log n)` | `O(1)` |
| 평균 | `Θ(n log n)` | `O(1)` |
| 최악 | `Θ(n log n)` | `O(1)` |

### ① 힙 만들기는 `Θ(n)` 이다

흔한 오해가 "`n` 번의 `O(log n)` 이니 `O(n log n)`" 인데, **더 정확히 세면 선형**이다.
siftDown 의 비용은 `log n` 이 아니라 **그 노드의 높이**에 비례한다.
높이 `h` 인 노드는 최대 `⌈n / 2^{h+1}⌉` 개다.

```
T(n) ≤ Σ_{h=0}^{⌊log₂ n⌋}  ⌈n / 2^{h+1}⌉ · O(h)
     =  O( n · Σ_{h=0}^{∞} h / 2^{h+1} )
```

여기서 급수 `Σ_{h≥0} h / 2^h` 는 수렴한다. `Σ h x^h = x/(1-x)²` 에 `x = 1/2` 를 넣으면 2이므로

```
Σ_{h≥0} h / 2^{h+1} = 1        →  T(n) = O(n)
```

**대부분의 노드가 바닥 근처에 있어 거의 안 내려간다**는 것이 직관이다.
잎 `n/2` 개는 비용 0, 그 위 `n/4` 개는 최대 1층, … 로 기하급수적으로 줄어든다.

### ② 뽑아내기가 `Θ(n log n)` 이다

`i` 번째 추출에서 힙 크기가 `n-i` 이므로 siftDown 비용은 `⌊log₂(n-i)⌋`.

```
Σ_{k=1}^{n} ⌊log₂ k⌋ = Θ(n log n)
```

`n/2` 개 이상의 항이 `log₂(n/2) = log₂ n - 1` 이상이므로 하한도 `Ω(n log n)` 이다.
따라서 **②가 지배적**이고 전체는 `Θ(n log n)` 이다.

### 최선도 `Θ(n log n)`

②는 매 라운드마다 루트에 "가장 작은 축" 의 값을 올려놓고 시작한다.
그 값은 거의 항상 바닥까지 내려가므로, **이미 정렬된 입력이라도 비용이 줄지 않는다.**
[삽입 정렬](#/algo/insertion-sort)의 `Ω(n)` 최선 같은 것이 여기엔 없다.
이 균일함이 최악 보장의 대가다.

### 비교 횟수

정확한 비교 횟수는 약 `2n log₂ n` 이다(각 층에서 형제 비교 1회 + 부모 비교 1회).
병합 정렬의 `n log₂ n` 보다 **두 배**라 상수가 불리하다.
"큰 자식과만 비교" 를 바닥까지 내려간 뒤 되올라오며 자리를 찾는
**Floyd 의 개선**을 쓰면 비교를 `n log₂ n + O(n)` 으로 줄일 수 있다.

## 구현 노트

**반복 siftDown 을 쓰자.** 재귀로 써도 되지만 꼬리 재귀라 반복이 자연스럽고,
`O(1)` 공간이라는 성질이 명확해진다.

**1-based 인덱싱** 을 쓰면 식이 예뻐진다(`2i`, `2i+1`, 부모 `i/2`).
경쟁 프로그래밍에서 흔한 관례이며, 이 코드는 0-based 를 썼다.

**`size` 를 반드시 넘기자.** 정렬 단계에서 `n` 을 넘기면 이미 확정한 뒷부분을 다시
힙으로 끌어들여 정렬이 무너진다.

**오른쪽 자식 존재 검사**(`child + 1 < size`)를 빼면 배열 밖을 읽는다.
`n` 이 짝수일 때 마지막 부모는 자식이 하나뿐이다.

**최소 힙**이 필요하면 부등호만 뒤집는다. 다만 최소 힙으로 같은 방식을 돌리면
**내림차순**으로 정렬된다.

**C++ 표준 라이브러리** 에 그대로 있다.

```cpp
make_heap(a.begin(), a.end());       // ①  O(n)
sort_heap(a.begin(), a.end());       // ②  O(n log n)
// 또는 한 번에
partial_sort(a.begin(), a.begin() + k, a.end());   // 상위 k 개만
```

`priority_queue` 도 내부적으로 이 힙이다.

## 변형과 확장

### 상위 `k` 개만 — 부분 정렬

전체를 정렬할 필요가 없다. 힙을 만들고(`O(n)`) `k` 번만 뽑으면 `O(n + k log n)`.
`k` 가 작으면 `O(n log n)` 보다 훨씬 싸다. 스트리밍이라면 **크기 `k` 의 최소 힙**을
유지하며 훑어 `O(n log k)` 공간 `O(k)` 로 처리한다.

### introsort — 실전의 타협

퀵 정렬은 평균이 빠르지만 최악이 `O(n²)` 다. 재귀 깊이가 `2 log n` 을 넘으면
**힙 정렬로 갈아타** 최악을 `O(n log n)` 으로 묶는다. GCC 의 `std::sort` 가 이 구조다.
힙 정렬은 여기서 "느리지만 절대 무너지지 않는 안전망" 역할을 한다.

### 왜 실전에서 퀵 정렬에 밀리나

복잡도가 같은데도 힙 정렬이 보통 더 느린 이유는 **캐시**다.

- 퀵 정렬은 인접한 메모리를 순차적으로 훑는다 → 캐시 적중률이 높다
- 힙 정렬의 `i → 2i+1` 은 **배열을 껑충껑충 건너뛴다** → 캐시 미스가 잦다
- 게다가 비교 횟수의 상수도 약 2배다

`n` 이 커질수록(캐시에 안 들어갈수록) 격차가 벌어진다.

### d-ary 힙

자식을 `d` 개로 늘리면 높이가 `log_d n` 으로 줄어 siftDown 이 얕아지지만,
매 층에서 자식 `d` 개를 비교해야 한다. 삽입이 잦고 추출이 드문 워크로드
(다익스트라의 우선순위 큐 등)에서 `d = 4` 정도가 유리하다는 실측이 알려져 있다.
