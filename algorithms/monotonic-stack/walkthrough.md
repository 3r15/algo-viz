## 어떤 문제인가

배열의 각 원소에 대해, **오른쪽에서 처음으로 자기보다 큰 원소**(다음 큰 원소, next greater element)를
찾고 싶다.

```
a = [2, 1, 5, 6, 2, 3]
      ↓
     2 의 다음 큰 원소 → 5
     1 → 5,  5 → 6,  6 → 없음,  2 → 3,  3 → 없음
답 = [5, 5, 6, -1, 3, -1]
```

순진하게 각 원소마다 오른쪽을 끝까지 훑으면 `O(n²)`. "온도가 며칠 뒤 오르나(daily temperatures)",
"히스토그램 최대 직사각형" 같은 문제도 이 꼴이다.

> 이미 지나온 원소들의 정보를 **버리지 않고** 쌓아 두면, 한 번 훑기로 안 될까?

## 손으로 해보기

핵심은 **아직 답을 못 찾은 원소들의 인덱스를, 값이 감소하는 순서로 스택에 쌓아 두는 것**이다.
새 원소가 오면, 그보다 작은 스택 원소들은 **바로 지금** 답을 찾은 것이다.

`a = [2, 1, 5, 6, 2, 3]` 로 가 보자. 스택엔 인덱스를 쌓지만 값으로 표시한다.

```
i=0, a=2:  스택 비었다 → push 0.        스택(값): [2]
i=1, a=1:  top 2 ≥ 1 → 그대로 push 1.   스택: [2, 1]
i=2, a=5:  top 1 < 5 → 1의 답=5, pop.
           top 2 < 5 → 2의 답=5, pop.
           스택 비었다 → push 2.          스택: [5]
i=3, a=6:  top 5 < 6 → 5의 답=6, pop.
           push 3.                        스택: [6]
i=4, a=2:  top 6 ≥ 2 → push 4.            스택: [6, 2]
i=5, a=3:  top 2 < 3 → (그 2의)답=3, pop.
           top 6 ≥ 3 → push 5.            스택: [6, 3]
끝. 남은 6, 3 은 다음 큰 원소 없음(-1).
답 = [5, 5, 6, -1, 3, -1]
```

### 왜 스택이 항상 감소하나

값이 **증가하는** 원소가 오면, 스택 위의 작은 것들은 그 자리에서 답을 얻고 빠진다. 그래서 스택엔
**아직 자기보다 큰 것을 못 만난** 원소들만, 자연히 **감소 순서**로 남는다. 이 단조성이 이름의 유래다.

### 왜 O(n) 인가

각 인덱스는 **딱 한 번 push** 되고, pop 되면 다시는 안 본다. 그래서 안쪽 `while` 이 아무리 돌아도
**전체 pop 횟수 ≤ n**. 겉보기엔 이중 루프지만 분할상환으로 `O(n)` — [투 포인터](#/algo/two-pointers)·
괄호 검사와 같은 논증이다.

## 아이디어 쌓기

### 1단계 — 못 푼 원소를 쌓아 둔다

답을 아직 못 찾은 인덱스를 스택에 보관한다.

### 2단계 — 새 원소가 작은 것들을 해결한다

새 `a[i]` 가 스택 top 보다 크면, 그 top 의 답이 바로 `a[i]` 다 → 확정하고 pop.

### 3단계 — 단조성 유지

pop 을 멈추면 스택은 다시 감소 순서. `i` 를 push 한다.

### 4단계 — 남은 것은 없음

끝까지 답을 못 받은 스택 원소는 오른쪽에 더 큰 값이 없다(-1).

## 코드로 옮기기

```cpp
vector<int> nextGreater(vector<int>& a) {
    int n = a.size();
    vector<int> ans(n, -1);              // 기본: 없음
    stack<int> st;                        // 값이 감소하는 인덱스 스택
    for (int i = 0; i < n; i++) {
        while (!st.empty() && a[st.top()] < a[i]) {
            ans[st.top()] = a[i];         // a[i] 가 그 원소의 다음 큰 값
            st.pop();
        }
        st.push(i);                       // i 를 쌓는다
    }
    return ans;                           // 남은 것은 -1(없음)
}
```

스택엔 **인덱스**를 담아 답 배열에 바로 쓴다. `<` 를 `>` 로 바꾸면 "다음 작은 원소" 가 된다.

## 자주 하는 실수

**값 대신 인덱스를 안 담는다.** 답을 `ans[j]` 에 써야 하므로 스택엔 인덱스가 편하다(값만 담으면
어디에 쓸지 잃는다).

**부등호 방향·등호 처리를 헷갈린다.** `<` 는 "엄격히 큰 다음 원소", `<=` 로 하면 "크거나 같은" 이
된다. 중복 값 처리(같으면 미룰지)를 문제에 맞춰 정한다.

**O(n²) 로 착각해 안 쓴다.** 이중 루프처럼 보이지만 총 pop ≤ n 이라 선형이다. 이 분할상환 논증을 믿자.

**방향.** 왼쪽의 다음 큰 원소, 다음 작은 원소 등은 순회 방향·부등호를 바꾸면 된다.

## 스스로 확인하기

1. **i=2(a=5)** 에서 스택의 `1`, `2` 가 연달아 pop 되며 답이 채워지는 것을 보자.
2. **스택이 항상 감소 순서**로 유지되는 것을 보자(위로 갈수록 작다).
3. **답 행**이 pop 되는 순간에 채워지는 것을 보자.
4. **끝에 남은 `6`, `3`** 이 "없음(—)" 이 되는 것을 확인하자.
5. 배열을 `5 4 3 2 1` 로 바꿔 보자 — 아무도 pop 되지 않고 전부 "없음".
6. 배열을 `1 2 3 4 5` 로 바꿔 보자 — 매 스텝 직전 원소가 바로 pop 된다.

아래 **깊이 보기**에서는 분할상환 O(n) 증명, 단조 스택/덱의 여러 변형(히스토그램 최대 직사각형,
슬라이딩 윈도우 최대)을 다룬다.
