## 어떤 문제인가

지하철 노선도를 떠올려 보자. 지금 역에서 출발해 목적지까지 **최소 몇 정거장**인지 알고 싶다.

이런 구조를 **그래프**라고 부른다.

- **정점(vertex)** — 역, 도시, 사람, 격자의 한 칸…
- **간선(edge)** — 정점 사이의 연결

문제는 이렇다.

> 시작점에서 각 정점까지 **최소 몇 개의 간선**을 지나야 도달하는가?

무작정 아무 방향으로 파고들면 안 된다. 멀리 돌아가는 길을 먼저 찾아 버리면
그게 최단인 줄 착각하게 된다. **가까운 곳부터 차례로** 봐야 한다.

## 손으로 해보기

기본 그래프에서 0번에서 출발해 보자.

```
      1 ─── 3
     /        \
    0          5
     \        /
      2 ─── 4
```

### 규칙

> 발견한 순서대로 처리한다. **먼저 발견한 것을 먼저 처리한다.**

이 "먼저 온 사람이 먼저"를 지켜 주는 것이 **큐(queue)** 다. 뒤로 넣고 앞에서 꺼낸다.

### 따라가 보기

```
큐 [0]                  0 을 넣고 시작. 거리 0

0 을 꺼낸다 (거리 0)
  이웃 1 → 처음 봄 → 큐에 넣음 (거리 1)
  이웃 2 → 처음 봄 → 큐에 넣음 (거리 1)
큐 [1, 2]

1 을 꺼낸다 (거리 1)
  이웃 0 → 이미 봤음 → 무시
  이웃 3 → 처음 봄 → 큐에 넣음 (거리 2)
큐 [2, 3]

2 를 꺼낸다 (거리 1)
  이웃 0 → 이미 봤음
  이웃 4 → 처음 봄 → 큐에 넣음 (거리 2)
큐 [3, 4]

3 을 꺼낸다 (거리 2)
  이웃 5 → 처음 봄 → 큐에 넣음 (거리 3)
큐 [4, 5]

4 를 꺼낸다 (거리 2)
  이웃 5 → 이미 봤음 → 무시
큐 [5]

5 를 꺼낸다 (거리 3)
큐 []  → 끝
```

꺼낸 순서를 보자: `0, 1, 2, 3, 4, 5`. 거리로 묶으면

```
거리 0: [0]
거리 1: [1, 2]
거리 2: [3, 4]
거리 3: [5]
```

**거리가 같은 것들끼리 뭉쳐서 차례로 나온다.** 물결이 퍼지듯 층(layer)이 하나씩 넓어진다.
그래서 **너비 우선 탐색(Breadth-First Search)** 이다.

## 아이디어 쌓기

### 1단계 — 같은 것을 두 번 보지 않는다

그래프에는 사이클이 있을 수 있다. `0 → 1 → 0 → 1 → …` 로 영원히 돌지 않으려면
**이미 본 정점을 기억**해야 한다. 그게 `visited` 배열이다.

### 2단계 — 순서를 큐가 관리한다

"가까운 것부터"를 손으로 관리할 필요가 없다. 큐에 넣는 순서가 곧 발견 순서이고,
발견 순서가 곧 거리 순서이기 때문이다.

거리 `d` 인 정점을 처리하면 거리 `d+1` 인 정점만 새로 발견된다.
큐에 이미 있는 것들은 전부 거리 `d` 아니면 `d+1` — 그래서 **큐는 저절로 거리순으로 정렬돼 있다.**

### 3단계 — 표시는 "넣을 때" 한다 ★

여기가 초보자가 가장 많이 틀리는 곳이다. 두 가지 선택지가 있다.

```
(A) 큐에 넣을 때 visited = true       ← 올바름
(B) 큐에서 꺼낼 때 visited = true     ← 문제 발생
```

(B)로 하면 어떻게 되는지 위 예시로 보자. `1` 과 `2` 를 처리할 때 둘 다 `5` 로 가는 길이 있다면,
`5` 가 **큐에 두 번 들어간다.** 정점이 많아지면 큐가 부풀고 같은 정점을 여러 번 처리한다.

(A)로 하면 **각 정점이 정확히 한 번만 큐에 들어간다.**

### 4단계 — 왜 이게 최단 거리인가

직관적으로는 이렇다. 거리 1인 곳을 **전부** 본 다음에야 거리 2를 보고,
거리 2를 전부 본 다음에야 거리 3을 본다. 그러니 어떤 정점을 처음 발견했을 때의
층 번호보다 더 짧은 길은 있을 수 없다 — 있었다면 더 앞 층에서 이미 발견됐을 것이다.

## 코드로 옮기기

```cpp
void bfs(vector<vector<int>>& adj, int s) {
    vector<bool> visited(adj.size(), false);   // ← 1단계: 본 것 기억
    queue<int> q;                              // ← 2단계: 순서 관리
    q.push(s); visited[s] = true;              // ← 시작점을 넣고 표시
    while (!q.empty()) {
        int u = q.front(); q.pop();            // ← 가장 먼저 들어온 것을 꺼낸다
        // u 처리(방문 확정)
        for (int v : adj[u]) {                 // ← u 의 이웃들
            if (!visited[v]) {                 // ← 처음 보는 이웃만
                visited[v] = true;             // ← 3단계: 넣을 때 표시! ★
                q.push(v);
            }
        }
    }
}
```

`adj` 는 **인접 리스트**다. `adj[u]` 가 "u와 이어진 정점들의 목록"이다.
편집기 아래에 인접 리스트/행렬이 표시되니 눌러서 확인해 보자.

### 거리도 같이 구하려면

`visited` 를 `dist` 로 바꾸면 배열 하나로 두 가지를 다 한다.

```cpp
vector<int> dist(n, -1);       // -1 = 아직 안 봄
dist[s] = 0;  q.push(s);
while (!q.empty()) {
    int u = q.front(); q.pop();
    for (int v : adj[u])
        if (dist[v] == -1) { dist[v] = dist[u] + 1; q.push(v); }
}
```

## 자주 하는 실수

**꺼낼 때 표시한다.** 3단계에서 본 그 문제. 답은 맞을 수 있지만 큐가 부풀어 느려진다.

**시작점을 표시하지 않는다.** `q.push(s)` 만 하고 `visited[s] = true` 를 빠뜨리면
`s` 가 자기 이웃을 통해 다시 큐에 들어간다.

**스택을 쓴다.** `queue` 대신 `stack` 을 쓰면 [DFS](#/algo/dfs)가 된다.
동작은 하지만 **최단 경로가 나오지 않는다.** 자료구조 하나가 알고리즘을 바꾼다.

**가중치가 있는데 BFS 를 쓴다.** BFS 가 최소화하는 건 **간선 개수**다.
간선마다 비용이 다르면 [다익스트라](#/algo/dijkstra)로 가야 한다.

## 스스로 확인하기

1. **정점 색이 바뀌는 순서**를 보자. 회색(미방문) → 테두리 강조(큐 대기) →
   밝게 채움(처리 중) → 초록(완료).
2. **큐 표시를 계속 보자.** 큐에 든 정점들의 거리가 항상 두 종류(`d` 와 `d+1`)뿐이다.
3. 편집기에서 **간선을 하나 지우고** 다시 실행해 보자. 방문 순서가 어떻게 달라지는가?
4. 같은 그래프를 [DFS](#/algo/dfs)에도 넣어 보자. 큐 대신 스택을 쓰면 순서가 완전히 달라진다.
5. 정점을 하나 뚝 떼어 놓고(간선 없이) 실행해 보자. 도달할 수 없는 정점은 끝까지 회색이다.

아래 **깊이 보기**에서는 "큐 안의 거리가 항상 두 종류뿐"이라는 성질을 증명하고,
그것으로부터 최단 거리임을 유도한다.
