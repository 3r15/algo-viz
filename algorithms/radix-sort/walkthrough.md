## 어떤 문제인가

정수 배열을 정렬한다. [계수 정렬](#/algo/counting-sort)은 빠르지만 **값의 범위 `k` 가 크면** 칸이
너무 많아 못 쓴다. `0..999` 만 돼도 칸이 1000개, `0..10억` 이면 아예 불가능하다.

> 값이 크더라도 **자릿수는 몇 개 안 된다.** 세 자리 수는 자리가 셋뿐이고, 각 자리는 `0..9` 열 칸이면 된다.
> 그럼 **자리마다 따로** 정렬하면 되지 않을까?

## 손으로 해보기

기본 입력 `[42, 8, 17, 25, 63, 4, 51, 30]` 을 정렬해 보자. 가장 큰 수가 63, 즉 **두 자리**다.

### ① 1의 자리로 정렬한다

각 수의 **1의 자리**만 보고 계수 정렬한다.

```
42  8  17  25  63   4  51  30
 2  8   7   5   3   4   1   0     ← 1의 자리

0 부터 순서대로 모으면:
30 51 42 63  4 25 17  8
```

`30`(0), `51`(1), `42`(2), `63`(3), `4`(4), `25`(5), `17`(7), `8`(8) — 1의 자리 오름차순.

### ② 10의 자리로 정렬한다

이제 **10의 자리**로 다시 계수 정렬한다. **중요**: 같은 10의 자리끼리는 ①의 순서를 **유지**한다(안정).

```
30 51 42 63  4 25 17  8
 3  5  4  6  0  2  1  0     ← 10의 자리

0 부터 순서대로(같은 자리는 순서 유지):
 4  8 17 25 30 42 51 63
```

**끝. 정렬됐다.** `4`(0), `8`(0) 는 10의 자리가 같은데 ①에서 `4` 가 `8` 앞이었으니 여기서도 `4 8`.

### 왜 낮은 자리부터인가

높은 자리부터 하면 낮은 자리를 정렬할 때 앞서 맞춘 순서가 흐트러진다.
**낮은 자리부터** 하고 각 단계가 **안정**이면, 높은 자리를 정렬해도 같은 값 안에서 낮은 자리 순서가 살아남는다.
그래서 마지막(가장 높은) 자리를 마치는 순간 전체가 정렬된다.

### 비용을 세어 보자

```
자리 수 d = 2 (두 자리)
각 자리마다 계수 정렬 = O(n + 10)
합계 = O(d · (n + b))    b = 진법 = 10
```

값이 아무리 커도 **자릿수 `d` 만큼만** 반복한다. `32비트` 정수라도 10진법으로 10자리, `d = 10` 이면 사실상 선형이다.

## 아이디어 쌓기

### 1단계 — 계수 정렬은 범위가 작아야 한다

`0..9` 열 칸이면 계수 정렬은 완벽하다. 문제는 값이 클 때다.

### 2단계 — 값을 자리로 쪼갠다

큰 값도 각 자리는 `0..9`. 자리마다 계수 정렬하면 범위 문제가 사라진다.

### 3단계 — 낮은 자리부터, 안정하게

낮은 자리부터 올라가며 각 단계를 안정 정렬로 하면, 높은 자리 정렬이 낮은 자리 순서를 보존한다.

### 4단계 — 자릿수만큼 반복

가장 큰 수의 자릿수 `d` 만큼 반복하면 끝. `O(d·(n+b))`.

## 코드로 옮기기

```cpp
void radixSort(vector<int>& a) {
    int mx = *max_element(a.begin(), a.end());
    for (int exp = 1; mx / exp > 0; exp *= 10) {   // 1, 10, 100 …
        vector<int> out(a.size()), count(10, 0);
        for (int x : a) count[(x / exp) % 10]++;    // 자릿수 세기
        for (int d = 1; d < 10; d++) count[d] += count[d-1];
        for (int i = a.size() - 1; i >= 0; i--) {   // 뒤에서(안정성)
            int d = (a[i] / exp) % 10;
            out[--count[d]] = a[i];
        }
        a = out;
    }
}
```

`(x / exp) % 10` 으로 `exp` 자리의 숫자를 뽑는다. `exp` 를 10배씩 키우며 자리를 올린다.
**뒤에서부터** 채우는 `for (i = n-1; …)` 가 안정성의 핵심이다.

## 자주 하는 실수

**높은 자리부터 정렬한다.** 그러면 낮은 자리를 뒤에 정렬할 때 앞 순서가 깨진다.
**낮은 자리(LSD)부터** 올라가야 한다.

**안정하지 않은 정렬을 자리 정렬로 쓴다.** 각 자리 정렬이 **안정**이 아니면 이전 자리의 순서가 보존되지 않아 틀린다.
그래서 계수 정렬(누적 합 버전)을 부품으로 쓴다.

**음수·소수에 쓴다.** LSD 기수 정렬은 음이 아닌 정수가 기본이다. 음수는 부호 처리를,
소수는 정수 키로의 사상을 따로 해야 한다.

**자릿수를 잘못 센다.** 가장 큰 수의 자릿수만큼만 돌면 된다. 더 돌면 낭비, 덜 돌면 미완성.

## 스스로 확인하기

1. **① 1의 자리 단계**에서 버킷이 1의 자리별로 채워지는 것을 보자. 배열이 1의 자리 순으로 재배열된다.
2. **② 10의 자리 단계**에서 배열이 최종 정렬되는 것을 보자.
3. **`4` 와 `8`(둘 다 10의 자리 0)** 이 ①의 순서를 유지하는지 보자 — 안정성.
4. **마지막 설명의 "비교 0회"** 를 확인하자.
5. 입력을 `100 10 1 1000` 으로 바꿔 보자. 자릿수가 늘어 네 번 반복한다.
6. 입력을 `5 4 3 2 1` 로 바꿔 보자. 한 자리라 한 번만에 끝난다.

아래 **깊이 보기**에서는 낮은 자리부터 정렬해야 하는 이유를 안정성 불변식으로 증명하고,
자릿수·진법 선택의 트레이드오프와 MSD 변형을 다룬다.
