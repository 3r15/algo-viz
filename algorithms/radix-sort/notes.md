## 한눈에

값을 자릿수로 쪼개 **낮은 자리부터 자리마다 안정 [계수 정렬](#/algo/counting-sort)** 을 반복한다.
값 범위가 커도 각 자리는 `0..b−1`(진법 `b`) 뿐이라, 계수 정렬의 "범위가 넓으면 못 쓴다" 는 벽을 우회한다.

- **시간** `Θ(d·(n + b))` — `d` = 자릿수, `b` = 진법 · **공간** `Θ(n + b)`
- **안정 정렬** — 각 자리 정렬이 안정이어야 전체가 옳다(필수 조건)
- **비교하지 않는다** — 계수 정렬처럼 `Ω(n log n)` 하한 밖
- 음이 아닌 정수(또는 정수 키로 사상 가능한 값)가 기본

**언제 쓰나** — 고정 폭 정수(32비트 값), 문자열(고정 길이 키), 값 범위는 넓지만 자릿수는 적을 때.
`d` 가 상수로 볼 만하면(정수 워드 크기 고정) 사실상 `O(n)` 선형 정렬.

**언제 안 쓰나** — 키가 길고 편차가 클 때(`d` 가 큼), 실수·일반 비교 키일 때, 메모리가 빠듯할 때
(출력 버퍼 `O(n)` 추가). 그럴 땐 [퀵 정렬](#/algo/quick-sort)·[병합 정렬](#/algo/merge-sort).

## 동작 원리

핵심은 **자리별 정렬을 낮은 자리부터 쌓되, 각 단계를 안정하게** 하는 것이다.

```
exp = 1, 10, 100 … (자리를 하나씩 올림)
각 exp 에서:
  ① 각 원소의 (x / exp) % b 로 자릿수를 센다        계수 정렬
  ② 누적 합으로 시작 위치를 구하고
  ③ 뒤에서부터 out 에 놓는다(안정)
```

### 실행 예 (b = 10)

`a = [42, 8, 17, 25, 63, 4, 51, 30]`

```
exp=1  (1의 자리):  30 51 42 63 4 25 17 8
exp=10 (10의 자리):  4 8 17 25 30 42 51 63   ← 정렬 완료
```

`exp=10` 단계에서 `4`·`8` 은 둘 다 10의 자리가 0인데, `exp=1` 단계가 남긴 `… 4 … 8 …` 순서가
안정성 덕에 유지된다.

## 정확성

> **불변식.** `exp` 단계(자리 `p`)가 끝나면, 배열은 **하위 `p+1` 자리로 이루어진 수**를 기준으로
> 안정 정렬되어 있다.

**기저** — `exp=1` 단계 후, 1의 자리(하위 1자리)로 안정 정렬됨. 계수 정렬의 정확성으로 자명.

**귀납** — `exp` 단계 전, 배열이 하위 `p` 자리로 안정 정렬돼 있다고 하자(귀납 가정).
`exp` 단계는 자리 `p`(가중치가 가장 큰 새 자리)를 **안정** 정렬한다. 두 원소 `x, y` 를 보자.

- 자리 `p` 가 **다르면** — 이번 정렬이 `p` 자리 순으로 바르게 놓는다. 하위 `p+1` 자리 순서 = `p` 자리 순서가 결정.
- 자리 `p` 가 **같으면** — 안정성에 의해 이번 정렬은 둘의 **입력 순서를 보존**한다. 그 입력 순서는
  귀납 가정에 의해 하위 `p` 자리로 정렬된 순서다. 따라서 하위 `p+1` 자리로도 정렬됨. ∎

가장 높은 자리 단계까지 마치면 배열은 전체(모든 자리)로 정렬된다.

### 안정성이 없으면 왜 깨지나

자리 `p` 가 같은 두 원소의 하위 순서는 **오직 이전 단계가 만든 순서**로만 유지된다. 자리 정렬이
안정이 아니면 이 순서가 무너져 하위 자리 정보가 사라진다 — 그래서 **안정 계수 정렬이 필수 부품**이다.

## 복잡도

| | 시간 | 공간 |
|---|---|---|
| 최선/평균/최악 | `Θ(d·(n + b))` | `Θ(n + b)` |

`d` = 자릿수, `b` = 진법. 조기 종료가 없어 세 경우가 같다.

### `d` 를 상수로 볼 수 있을 때

고정 폭 정수(예: 32비트)면 `b=2^16` 으로 잡을 때 `d=2`, 즉 `Θ(n)`. 이 관점에서 기수 정렬은
**선형 정렬**이다. 다만 이는 "키 길이가 고정" 이라는 가정에 기댄 것으로, 임의로 긴 키에는 `d` 가 커진다.

### 진법 `b` 의 트레이드오프

`b` 를 키우면 자릿수 `d = log_b(최댓값)` 이 줄지만 각 단계의 `count` 배열이 `b` 로 커진다.
시간은 `d·(n+b) = (n+b)·log_b(K)`. 대략 `b ≈ n` 근처에서 최소가 되므로, 실전에선
`b = 2^8`(바이트 단위)이나 `n` 규모로 잡는다.

### 비교 하한과의 관계

계수 정렬과 같은 이유로 결정 트리 하한 `Ω(n log n)` **밖**에 있다 — 값을 비교하지 않고
자릿수를 **인덱스로** 쓴다. 대가는 "정수 키 + 자릿수 유한" 가정이다.

## 구현 노트

**LSD vs MSD** — 여기 구현은 **LSD**(낮은 자리부터). 구현이 단순하고 각 단계가 전체를 훑는다.
**MSD**(높은 자리부터)는 자리마다 버킷을 재귀 분할 — 가변 길이 문자열·조기 분기에 유리하지만 구현이 복잡.

**음수 처리** — 부호를 분리해 음수·양수를 따로 정렬하거나, 오프셋을 더해 음이 아니게 만든다.
가장 높은 자리(부호 비트)를 뒤집는 트릭도 쓴다.

**안정 계수 정렬** — 반드시 누적 합 + **뒤에서부터** 채우는 버전을 써야 한다. `while(count--)` 로
값을 다시 만들어 내는 단순 버전은 안정성이 없어 기수 정렬에 못 쓴다.

**공간** — 출력 버퍼 `out` 이 `O(n)` 추가로 든다. 제자리(in-place) 기수 정렬(미국 국기 정렬 등)도
있으나 복잡하다.

## 변형과 확장

### MSD 기수 정렬 — 문자열·가변 길이

가장 높은 자리부터 버킷으로 나누고 각 버킷을 재귀. 접두사가 갈리는 순간 분기가 끝나므로,
긴 키를 끝까지 안 봐도 되는 경우가 많다. 문자열 정렬·트라이와 궁합이 좋다.

### 버킷 정렬 — 값 분포로 나눈다

기수 정렬이 "자리" 로 나눈다면 버킷 정렬은 "값 구간" 으로 나눈다. 균등 분포면 기대 `O(n)`.
둘 다 계수 정렬 계열의 분배 정렬(distribution sort)이다.

### 문자열·튜플의 사전식 정렬

각 문자(또는 튜플 성분)를 한 자리로 보고 낮은 자리부터 안정 정렬하면 사전식 순서가 나온다.
접미사 배열(suffix array) 구성의 기초 아이디어이기도 하다.
