## 어떤 문제인가

`kitten` 을 `sitting` 으로 바꾸려면 **최소 몇 번** 고쳐야 할까? 허용되는 편집은 셋이다.

```
삽입   한 글자를 끼워 넣는다
삭제   한 글자를 지운다
교체   한 글자를 다른 글자로 바꾼다
```

`kitten → sitting` 을 손으로 해 보면

```
kitten
sitten   k → s 교체
sittin   e → i 교체
sitting  끝에 g 삽입
```

**3번**이다. 그런데 이게 정말 최소일까? 다른 순서로 하면 더 줄지 않을까?
편집 방법은 무수히 많아서 하나하나 세어 볼 수 없다.

이 거리를 **레벤슈타인 거리**라 한다. 맞춤법 검사기의 오타 교정("did you mean…"), DNA 서열 비교,
`diff` 의 바탕이 전부 이것이다.

> 통째로 비교하지 말고, **앞에서부터 한 글자씩** 최소 편집 수를 쌓아 올릴 수 없을까?

## 손으로 해보기

기본 입력 `kitten sitting` 으로 끝까지 가 보자. [LCS](#/algo/lcs)와 **똑같은 모양의 표**를 쓴다.

### 상태를 어떻게 잡을까

두 문자열의 **앞부분(prefix)끼리** 짝지어 묻는다.

> `dp[i][j]` = `kitten` 의 **앞 `i` 글자**를 `sitting` 의 **앞 `j` 글자**로 바꾸는 최소 편집 수

표는 `(m+1) × (n+1)`. 0행·0열은 "한쪽이 빈 문자열" 인 경우다.

### 경계부터 — 빈 문자열로 바꾸기

한쪽이 비어 있으면 답이 뻔하다.

```
"kit" → ""     k, i, t 를 다 지운다      = 3번
""    → "sit"  s, i, t 를 다 넣는다      = 3번
```

**0행·0열은 그냥 인덱스 그 자체**다. `dp[i][0] = i`, `dp[0][j] = j`.

```
      ∅  s  i  t  t  i  n  g
   ∅  0  1  2  3  4  5  6  7
   k  1
   i  2
   t  3
   t  4
   e  5
   n  6
```

### 마지막 글자만 보면 된다

`dp[i][j]` 를 채울 때 결정할 것은 **A 의 `i`번째와 B 의 `j`번째 글자**뿐이다.

**두 글자가 같으면** — 손댈 것이 없다. 그 글자는 그냥 두고, 남는 문제는
"앞 `i-1` 글자를 앞 `j-1` 글자로" 다.

```
dp[i][j] = dp[i-1][j-1]        ← 대각선 값 그대로 (편집 +0)
```

**두 글자가 다르면** — 세 가지 편집 중 하나를 써야 한다. **세 이웃의 최솟값 + 1**.

```
dp[i][j] = 1 + min(
    dp[i-1][j],      ← 위:   A 의 글자를 삭제
    dp[i][j-1],      ← 왼쪽: B 의 글자를 삽입
    dp[i-1][j-1] )   ← 대각선: 한 글자를 교체
```

### 몇 칸 채워 보기

**`dp[1][1]`** — A의 `k` vs B의 `s`. 다르다.

```
세 이웃: 위 dp[0][1]=1, 왼쪽 dp[1][0]=1, 대각선 dp[0][0]=0
최솟값 0(교체) + 1 = 1        → k 를 s 로 교체
```

**`dp[2][2]`** — A의 `i` vs B의 `i`. **같다!**

```
dp[2][2] = dp[1][1] = 1        ← 대각선 그대로, 편집 없음
```

### 완성된 표

```
      ∅  s  i  t  t  i  n  g
   ∅  0  1  2  3  4  5  6  7
   k  1  1  2  3  4  5  6  7
   i  2  2  1  2  3  4  5  6
   t  3  3  2  1  2  3  4  5
   t  4  4  3  2  1  2  3  4
   e  5  5  4  3  2  2  3  4
   n  6  6  5  4  3  3  2  3
```

**`dp[6][7] = 3`.** 대각선을 따라 `1` 이 죽 이어지는 것을 보자 — `itt` 가 공통이라 편집이 안 든 구간이다.

### 무엇을 편집했나

**오른쪽 아래에서 거슬러 올라간다.** 각 칸에서 값이 어느 이웃에서 왔는지 따라간다.

```
(6,7) g 삽입    ← 위나 왼쪽에서 +1
(6,6) n=n 유지  ← 대각선 (편집 없음)
(5,5) e→i 교체  ← 대각선 +1
(4,4) t=t 유지
(3,3) t=t 유지
(2,2) i=i 유지
(1,1) k→s 교체  ← 대각선 +1
```

거꾸로 뒤집으면 **`k→s` 교체, `itt` 유지, `e→i` 교체, `g` 삽입** — 편집 3회. 손으로 한 것과 같다.

## 아이디어 쌓기

### 1단계 — 접두사 쌍으로 상태를 잡는다

무수히 많은 편집 순서를 `(i, j)` 두 정수로 접는다. LCS 와 완전히 같은 발상이다.

### 2단계 — 경계가 공짜다

한쪽이 비면 나머지를 통째로 넣거나 지운다 = 글자 수. `dp[i][0]=i`, `dp[0][j]=j`.

### 3단계 — 마지막 글자로 경우를 나눈다

같으면 대각선 그대로(+0), 다르면 세 편집(삭제·삽입·교체)의 최솟값 +1.
**세 이웃이 세 편집에 정확히 대응**한다.

```
위        = 삭제 (A 를 한 글자 줄인다)
왼쪽      = 삽입 (B 를 한 글자 맞춘다)
대각선    = 교체 (둘 다 한 글자 줄인다)
```

### 4단계 — 채우는 순서

세 이웃이 모두 **위·왼쪽·대각선**이다. 위에서 아래로, 왼쪽에서 오른쪽으로 채우면 준비돼 있다.

## 코드로 옮기기

```cpp
int editDistance(string A, string B) {
    int m = A.size(), n = B.size();
    vector<vector<int>> dp(m + 1, vector<int>(n + 1));
    for (int i = 0; i <= m; i++) dp[i][0] = i;    // ← 2단계: 경계
    for (int j = 0; j <= n; j++) dp[0][j] = j;
    for (int i = 1; i <= m; i++)                   // ← 4단계: 위에서 아래로
        for (int j = 1; j <= n; j++) {
            if (A[i-1] == B[j-1])
                dp[i][j] = dp[i-1][j-1];           // ← 3단계: 같으면 그대로
            else
                dp[i][j] = 1 + min({ dp[i-1][j],   // 삭제
                                     dp[i][j-1],   // 삽입
                                     dp[i-1][j-1] }); // 교체
        }
    return dp[m][n];
}
```

**`A[i-1]` 의 `-1`** 을 조심하자. 표의 `i` 는 "앞 `i` 글자" 라 1부터, C++ 인덱스는 0부터다 — LCS 와 같은 함정이다.

## 자주 하는 실수

**경계를 0으로 초기화한다.** `dp[i][0]` 은 `0` 이 아니라 `i` 다(글자 `i` 개를 지워야 한다).
경계를 틀리면 표 전체가 어긋난다.

**같을 때 대각선에 +1 한다.** 글자가 같으면 편집이 **0** 이다. `dp[i-1][j-1] + 0` 이지 `+1` 이 아니다.

**세 이웃 중 하나를 빠뜨린다.** 삭제·삽입·교체 셋을 다 봐야 한다. 대각선(교체)을 빼먹는 실수가 흔하다.

**표 크기를 `m × n` 으로 잡는다.** 0행·0열이 필요하므로 `(m+1) × (n+1)` 이다.

**LCS 와 헷갈린다.** LCS 는 **최대**(닮은 만큼), 편집 거리는 **최소**(다른 만큼)다.
점화식의 방향이 반대다.

## 스스로 확인하기

1. **`dp[2][2]` 스텝**을 보자. `i = i` 라 대각선 값이 편집 없이 내려온다.
2. **표의 대각선에 `1`이 이어지는 구간**을 보자. `itt` 가 공통이라 편집이 안 든다.
3. **다른 글자 칸**에서 회색으로 강조되는 **세 이웃**을 보자. 같은 글자면 **대각선 하나**만 본다.
4. **마지막 스텝**의 초록 역추적 경로를 보자. 대각선으로 내려가는 칸이 유지 또는 교체다.
5. 입력을 `abc abc` 로 바꿔 보자. 표의 **대각선이 전부 0** 이고 답이 0이다(똑같은 문자열).
6. 입력을 `abc xyz` 로 바꿔 보자. 공통 글자가 없어 세 번 모두 **교체**, 답이 3이다.
7. 입력을 `cat cut` 으로 바꿔 보자. `a→u` 한 번, 답이 1이다.
8. 입력을 `horse ros` 로 바꿔 보자 — 길이가 달라 삽입·삭제가 섞인다.

아래 **깊이 보기**에서는 세 이웃 점화식이 왜 최적을 놓치지 않는지 증명하고,
공간을 `O(min(m,n))` 으로 줄이는 방법과 LCS·DNA 정렬과의 관계를 다룬다.
