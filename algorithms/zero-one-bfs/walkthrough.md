## 어떤 문제인가

그래프의 최단 경로를 구하는데, **간선 가중치가 0 아니면 1** 뿐이다(예: 어떤 이동은 공짜, 어떤 이동은 비용 1).

- 모든 가중치가 1이면 그냥 [BFS](#/algo/bfs) 로 `O(V+E)`.
- 가중치가 제각각이면 [다익스트라](#/algo/dijkstra) 로 `O(E log V)`(우선순위 큐).

> 가중치가 **0과 1 둘뿐**이라는 특수함을 살려, 우선순위 큐 없이 BFS 만큼 빠르게(`O(V+E)`) 풀 수 없을까?

## 손으로 해보기

핵심 도구는 **덱(deque, 양끝 큐)** 이다. 보통 BFS 는 큐(뒤로만 넣음)를 쓰지만, 0-1 BFS 는
**앞뒤 양쪽**에 넣는다.

> 완화(거리 갱신)에 성공했을 때
> - 가중치가 **0**이면 거리가 안 늘었으니 덱 **앞**으로 (지금 정점과 같은 거리)
> - 가중치가 **1**이면 거리가 1 늘었으니 덱 **뒤**로

이렇게 하면 덱은 항상 "거리 `d` 인 정점들, 그다음 거리 `d+1` 인 정점들" 순서를 유지한다.
앞에서 꺼내면 **거리 오름차순** — 다익스트라의 우선순위 큐를 덱이 대신한다.

### 기본 그래프로

```
0 —1— 1      간선 옆 숫자가 가중치(0 또는 1)
|      |\
0      0 1
|      |  \
2 —1— 3 —1— 4
        \0    \1
         5 —1—
```

`0`에서 시작:

```
dist[0]=0, 덱 [0]
0 꺼냄: 0—1(w1)→dist[1]=1 뒤로;  0—2(w0)→dist[2]=0 앞으로     덱 [2, 1]
2 꺼냄: 2—3(w1)→dist[3]=1 뒤로                                덱 [1, 3]
1 꺼냄: 1—3(w0)→dist[3]=1(그대로);  1—4(w1)→dist[4]=2 뒤로     덱 [3, 4]
3 꺼냄: 3—5(w0)→dist[5]=1 앞으로;  3—4(w1)→2(그대로)           덱 [5, 4]
5 꺼냄: 5—4(w1)→2(그대로)                                     덱 [4]
4 꺼냄: 끝
결과 dist = [0, 1, 0, 1, 2, 1]
```

`2`와 `5`는 0-간선 지름길 덕에 거리가 작다. 앞에서 꺼내는 순서가 정확히 거리 순서였다.

### 왜 덱이 정렬을 지키나

덱 안의 거리는 **최대 1만** 차이 난다(앞쪽 `d`, 뒤쪽 `d+1`). 0-간선은 `d`짜리를 앞에 더하고,
1-간선은 `d+1`짜리를 뒤에 더하니, 이 "많아야 두 층" 구조가 유지된다. 그래서 우선순위 큐 없이도
항상 가장 가까운 것을 앞에서 꺼낸다.

### 비용

```
각 정점 한 번 확정, 각 간선 한 번 완화 → O(V + E)
우선순위 큐의 log 인자가 사라진다
```

## 아이디어 쌓기

### 1단계 — 0/1 가중치의 특수함

거리 차가 최대 1 → 덱의 "두 층" 으로 정렬을 흉내 낼 수 있다.

### 2단계 — 완화 방향에 따라 앞/뒤

0-간선은 앞(같은 거리), 1-간선은 뒤(거리 +1)로 넣는다.

### 3단계 — 앞에서 꺼내 확정

앞에서 꺼내면 거리 오름차순. 처음 꺼낼 때가 최단(그 뒤 재등장은 무시).

### 4단계 — 확정 표시로 중복 처리

한 정점이 여러 번 덱에 들 수 있으니, 처음 확정한 뒤엔 건너뛴다.

## 코드로 옮기기

```cpp
void bfs01(int s) {
    deque<int> dq;
    dist[s] = 0; dq.push_back(s);
    while (!dq.empty()) {
        int u = dq.front(); dq.pop_front();
        if (done[u]) continue;                // 이미 확정
        done[u] = true;
        for (auto [v, w] : adj[u]) {          // w 는 0 또는 1
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                if (w == 0) dq.push_front(v); //  0이면 앞으로
                else        dq.push_back(v);  //  1이면 뒤로
            }
        }
    }
}
```

다익스트라와 거의 같되, **우선순위 큐 → 덱**, `push`의 앞/뒤가 가중치 0/1로 갈린다.

## 자주 하는 실수

**0-간선을 뒤로 넣는다.** 그러면 거리 순서가 깨져 틀린다. 0은 반드시 **앞**.

**확정 검사를 뺀다.** 한 정점이 여러 번 덱에 들 수 있다. `done[u]` 로 처음만 처리(안 그러면 스텝 낭비/오류).

**가중치가 0/1이 아니다.** 2 이상이 섞이면 0-1 BFS 로는 안 된다 — 다익스트라로. (단, 작은 정수
가중치는 간선을 쪼개거나 다이얼(dial) 알고리즘으로 확장 가능.)

**큐로 착각.** 보통 BFS 는 큐지만, 여기선 반드시 **양끝 덱**.

## 스스로 확인하기

1. **0-간선 완화**에서 정점이 덱 **앞**(◀앞 표시)으로 들어가는 것을 보자.
2. **1-간선 완화**에서 정점이 덱 **뒤**로 들어가는 것을 보자.
3. **정점 아래 거리 라벨**이 갱신되는 것을 보자(∞ → 값).
4. **덱에서 앞부터 꺼내는 순서가 거리 오름차순**인지 확인하자.
5. `2`와 `5`가 0-간선 지름길로 거리 0, 1이 되는 것을 보자.
6. 그래프 편집기로 간선 가중치를 바꿔 보자(1로 채우면 일반 BFS처럼 동작).

아래 **깊이 보기**에서는 덱 불변식(거리 차 ≤ 1)의 증명, 다익스트라·BFS 와의 관계,
작은 정수 가중치로의 확장(다이얼)을 다룬다.
