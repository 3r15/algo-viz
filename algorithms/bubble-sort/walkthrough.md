## 어떤 문제인가

숫자가 뒤죽박죽 들어 있는 배열을 **작은 것부터 큰 것 순서로** 다시 배치하고 싶다.

```
[5, 2, 9, 1, 5, 6]   →   [1, 2, 5, 5, 6, 9]
```

컴퓨터는 사람처럼 배열 전체를 한눈에 보지 못한다. **한 번에 두 개씩만** 꺼내서
"어느 쪽이 더 큰가?"를 물어볼 수 있을 뿐이다. 그리고 자리를 바꾸는 것도 두 칸씩만 가능하다.

그래서 질문이 이렇게 바뀐다.

> **두 개씩 비교하고 두 개씩 맞바꾸는 것만으로**, 어떻게 전체를 정렬할 수 있을까?

## 손으로 해보기

가장 단순한 생각부터 해 보자. **바로 옆에 있는 두 개만** 비교해서, 순서가 뒤집혀 있으면 바꾼다.

`[5, 2, 9, 1, 5, 6]` 을 왼쪽부터 오른쪽까지 한 번 훑어 보자.
비교하는 두 칸을 `( )` 로 표시하겠다.

```
(5 2) 9  1  5  6     5 > 2 → 바꾼다
 2 (5 9) 1  5  6     5 < 9 → 그대로
 2  5 (9 1) 5  6     9 > 1 → 바꾼다
 2  5  1 (9 5) 6     9 > 5 → 바꾼다
 2  5  1  5 (9 6)    9 > 6 → 바꾼다
 2  5  1  5  6  9    ← 끝
```

전체가 정렬되지는 않았다. 그런데 **뭔가 하나는 확실하게 일어났다.**

> **9 가 맨 뒤에 도착했다.**

우연이 아니다. `9` 는 만나는 상대마다 이겼기 때문에, 한 번 만난 뒤로는 계속 오른쪽으로
끌려갔다. 가장 큰 값은 **절대 지지 않으므로 반드시 끝까지 밀려난다.**

큰 값이 물속의 거품처럼 위로 떠오른다고 해서 **버블(거품) 정렬**이라는 이름이 붙었다.

### 한 번 더 훑어 보기

이제 맨 뒤 `9` 는 제자리를 찾았으니 건드릴 필요가 없다. 앞의 다섯 칸만 다시 훑어 보자.

```
(2 5) 1  5  6  | 9     그대로
 2 (5 1) 5  6  | 9     바꾼다
 2  1 (5 5) 6  | 9     5 = 5 → 그대로 (같으면 안 바꾼다)
 2  1  5 (5 6) | 9     그대로
 2  1  5  5  6 | 9     ← 이번엔 6 이 확정
```

`|` 오른쪽이 **정렬이 끝난 구간**이다. 한 번 훑을 때마다 이 구간이 하나씩 늘어난다.
시각화에서 초록색으로 칠해지는 부분이 바로 여기다.

이걸 계속 반복하면 언젠가 전부 확정된다.

```
1회차 후:  2 5 1 5 6 | 9
2회차 후:  2 1 5 5 | 6 9
3회차 후:  1 2 5 | 5 6 9
4회차 후:  1 2 | 5 5 6 9
5회차 후:  1 | 2 5 5 6 9      ← 남은 한 칸은 자동으로 제자리
```

## 아이디어 쌓기

방금 한 일을 순서대로 정리해 보자.

### 1단계 — "인접한 두 개 비교"라는 최소 도구

`a[j]` 와 `a[j+1]` 을 비교해서 앞이 더 크면 바꾼다. 이게 우리가 가진 유일한 도구다.

```
if (a[j] > a[j+1]) 두 값을 맞바꾼다
```

### 2단계 — 한 번 훑으면 최댓값이 끝으로 간다

이 도구를 왼쪽 끝부터 오른쪽 끝까지 한 번 적용하는 것을 **패스(pass)** 라고 부르자.
위에서 봤듯이 패스 한 번이면 **그 구간의 최댓값이 맨 오른쪽에 놓인다.**

이유를 조금 더 또박또박 말하면 이렇다. 훑어 가는 동안 우리는 늘
"지금까지 본 것 중 가장 큰 값"을 손에 들고 오른쪽으로 이동하는 셈이다.
더 큰 값을 만나면 그걸로 바꿔 들고, 아니면 원래 것을 계속 들고 간다.
끝에 도착하면 손에 든 것이 곧 구간의 최댓값이다.

### 3단계 — 확정된 뒤쪽은 다시 안 본다

패스가 끝날 때마다 뒤에서부터 한 칸씩 확정된다.
`i` 번째 패스에서는 뒤쪽 `i` 개가 이미 확정돼 있으니 `a[0 .. n-1-i]` 만 보면 된다.

```
for (int j = 0; j < n - 1 - i; j++)
                    ↑
              확정된 만큼 줄여 준다
```

이 `- i` 를 빼먹어도 **답은 맞는다.** 다만 이미 정리된 뒤쪽을 계속 헛되이 훑어서
시간이 두 배로 든다. 시각화에서 초록 구간이 자라지 않는 것으로 바로 드러난다.

### 4단계 — 몇 번 반복해야 하나

패스 한 번에 한 칸씩 확정되고, 마지막 한 칸은 자동으로 제자리다.
그래서 **`n-1` 번**이면 충분하다.

```
for (int i = 0; i < n - 1; i++)   ← 패스 반복
```

이렇게 안쪽 루프(한 번 훑기)와 바깥 루프(패스 반복)가 완성된다.

## 코드로 옮기기

위에서 쌓은 네 조각이 그대로 코드가 된다.

```cpp
void bubbleSort(vector<int>& a) {
    int n = a.size();
    for (int i = 0; i < n - 1; i++) {            // ← 4단계: 패스를 n-1 번
        for (int j = 0; j < n - 1 - i; j++) {    // ← 3단계: 확정된 뒤쪽 제외
            if (a[j] > a[j + 1]) {               // ← 1단계: 인접 비교
                swap(a[j], a[j + 1]);            // ← 1단계: 맞바꾸기
            }
        }
    }
}
```

한 줄씩 다시 읽어 보자.

| 줄 | 하는 일 |
|---|---|
| `int n = a.size();` | 배열 길이. 반복 횟수를 정하는 데 쓴다 |
| `for (int i ...)` | **패스 번호**. `i`번 패스가 끝나면 뒤쪽 `i+1`개가 확정 |
| `for (int j ...)` | 왼쪽부터 오른쪽까지 훑는 **위치** |
| `if (a[j] > a[j+1])` | 순서가 뒤집혀 있는가? |
| `swap(...)` | 뒤집혀 있으면 바로잡는다 |

### `>` 와 `>=` 의 차이

값이 **같을 때** 바꾸지 않는다는 점이 중요하다.

```
5a 5b   →  >  로 비교하면 안 바꾼다  →  5a 5b  (원래 순서 유지)
5a 5b   →  >= 로 비교하면 바꾼다     →  5b 5a  (순서 뒤바뀜)
```

같은 값끼리 원래 순서가 지켜지는 성질을 **안정적(stable)** 이라고 한다.
부등호 하나 차이로 이 성질이 사라진다.

## 자주 하는 실수

**`j + 1` 이 배열 밖으로 나간다.** 안쪽 루프 조건이 `j < n` 이면 마지막에 `a[n]` 을 읽는다.
그래서 `j < n - 1` 이 기본이고, 여기에 확정된 만큼 빼서 `j < n - 1 - i` 가 된다.

**바깥 루프에서 `i` 를 쓰지 않는다.** `i` 는 단순한 반복 횟수가 아니라
"뒤쪽 몇 칸이 확정됐는가"를 나타내는 값이다. 안쪽 루프 범위에 반드시 반영하자.

**"이미 정렬됐으면 멈춰야 하는 거 아닌가?"** 맞다. 다만 **이 페이지의 코드에는 그 장치가 없다.**
매 패스의 진행을 끝까지 보여 주려고 일부러 뺐다. 실제로는 아래처럼 쓴다.

```cpp
bool swapped = false;
// ... 패스 중에 교환이 일어나면 swapped = true
if (!swapped) break;      // 한 번도 안 바꿨다 = 이미 정렬 완료
```

## 스스로 확인하기

위 플레이어에서 직접 눌러 보며 확인해 보자.

1. **`5 4 3 2 1` 을 넣어 보자.** 매번 교환이 일어난다. 이게 가장 나쁜 경우다.
2. **`1 2 3 4 5` 를 넣어 보자.** 교환은 한 번도 없지만 **비교는 그대로 다 한다.**
   조기 종료 장치가 없기 때문이다.
3. **`3 3 3` 을 넣어 보자.** 값이 같으면 교환하지 않는다는 걸 확인할 수 있다.
4. 초록 구간이 **오른쪽에서 왼쪽으로** 자라는 것을 보자.
   [삽입 정렬](#/algo/insertion-sort)은 반대 방향으로 자란다 — 나란히 비교해 보면 재미있다.

교환 횟수가 정확히 무엇과 같은지 확인해 보자.
