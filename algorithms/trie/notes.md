## 한눈에

문자열 집합을 **글자 단위 트리**로 저장하는 자료구조다. 뿌리에서 내려가는 한 경로가 한 접두사이고,
공통 접두사를 **한 경로로 공유**한다. 삽입·검색·접두사 질의를 모두 문자열 길이 `O(L)` 에 한다
(집합 크기와 무관).

- **시간** `insert`·`search` 각 `O(L)`(L = 문자열 길이) · **공간** `O(총 글자 수 · Σ)`(Σ = 알파벳 크기)
- 노드마다 **단어 끝(end) 표시** — "접두사가 존재" 와 "단어가 존재" 를 구별
- 접두사 질의(자동완성)가 자연스럽다 — 해시로는 못 하는 것
- 정렬·비교가 필요 없다(글자 인덱싱)

**언제 쓰나** — 사전·자동완성·맞춤법, 접두사로 묶는 질의, 여러 패턴 동시 검색(아호-코라식의 뼈대),
비트 트라이(최대 XOR). "접두사" 가 열쇠말이면 트라이를 떠올려라.

**언제 안 쓰나** — 정확 일치만 필요하고 접두사가 필요 없으면 해시 집합이 더 가볍다.
알파벳이 크고 데이터가 희소하면 26칸 배열이 메모리를 낭비(맵·축약 트라이로 완화).

## 동작 원리

```
insert(s): cur=루트. 각 글자마다 자식이 없으면 만들고 내려간다. 끝 노드에 end=true.
search(s): cur=루트. 각 글자마다 자식이 없으면 false. 끝까지 가면 end 여부 반환.
```

### 접두사 = 경로

노드 `v` 는 "뿌리에서 `v` 까지의 글자들" 이라는 하나의 접두사에 대응한다. 두 문자열이 접두사를
공유하면 그 접두사 구간에서 **같은 경로**를 지난다 — 이 공유가 트라이의 절약이자 접두사 질의의 근거.

### end 플래그가 필요한 이유

`do` 와 `dog` 처럼 한 단어가 다른 단어의 접두사일 수 있다. 노드의 존재만으로는 "여기가 단어" 인지
알 수 없어, `end` 로 명시한다. 검색은 "끝까지 도달(접두사 존재) ∧ `end`(단어 존재)".

## 정확성

> **경로 대응 불변식.** 삽입이 끝난 뒤, 문자열 `s` 가 집합에 있다 ⟺ 뿌리에서 `s` 의 글자들을 따라간
> 노드가 존재하고 그 노드의 `end` 가 참이다.

*삽입.* `insert(s)` 는 `s` 의 각 글자에 대해 자식이 없으면 만들고 내려가므로, 끝나면 `s` 경로가
반드시 존재하고 마지막 노드에 `end=true`. 다른 문자열의 노드·플래그는 건드리지 않는다(공유 노드의
`end` 도 유지). ∎

*검색.* `search(s)` 는 같은 경로를 따라간다. 도중 자식이 없으면 `s` 경로가 없다는 뜻(집합에 없음).
끝까지 도달하면 그 노드의 `end` 를 반환 — 불변식에 의해 정확히 "`s` 가 단어인가". ∎

> **접두사 질의 정확성.** 뿌리에서 접두사 `p` 를 따라간 노드의 **부분 트리**가 `p` 로 시작하는 모든
> 문자열(의 나머지)을 정확히 담는다.

경로 대응 불변식을 부분 트리로 확장하면 된다 — 그래서 자동완성이 그 부분 트리 순회로 나온다.

## 복잡도

| 연산 | 시간 | 공간 |
|---|---|---|
| `insert(s)` / `search(s)` | `O(L)` | — |
| 접두사 `p` 로 시작하는 것 열거 | `O(L + 출력 크기)` | — |
| 전체 저장 | — | `O(총 글자 수 · Σ)` |

`L` = 문자열 길이, `Σ` = 알파벳 크기(자식 배열이면 노드당 `Σ`).

### 해시 집합과의 대비

| | 트라이 | 해시 집합 |
|---|---|---|
| 정확 일치 | `O(L)` | `O(L)` 기대(해시 계산) |
| **접두사 질의** | **자연스럽게 `O(L+출력)`** | 불가(전체 스캔) |
| 정렬 순서 열거 | 가능(DFS) | 불가 |
| 최악 보장 | `O(L)` 확정 | 충돌 시 저하 |
| 메모리 | 노드당 `Σ`(희소하면 낭비) | 대체로 콤팩트 |

트라이의 값어치는 "정확 일치" 가 아니라 **접두사·순서** 질의에 있다.

## 구현 노트

**자식 표현** — 조밀 알파벳은 `next[Σ]` 배열(빠름·메모리↑), 희소하면 `map`/`unordered_map`(느림·메모리↓).

**루트 = 0** — `next[c]==0` 을 "없음" 으로 쓰려면 루트를 0에 두고 실제 노드는 1부터.

**단어 개수·값 저장** — `end` 대신 카운트나 값을 저장하면 다중집합·사전(문자열→값)이 된다.

**삭제** — `end` 를 끄고, 자식 없는 노드를 위로 정리(참조 카운트). 공유 노드를 지우지 않도록 주의.

**정규화** — 대소문자·유니코드·비알파벳을 인덱스 전에 정규화(범위 밖 접근 방지).

## 변형과 확장

### 접두사 카운트·자동완성

노드에 "부분 트리의 단어 수" 를 캐시하면 "이 접두사로 시작하는 단어 몇 개" 를 `O(L)` 에.
자동완성은 접두사 노드에서 DFS 로 후보를 모은다.

### 아호-코라식 — 여러 패턴 동시 검색

트라이에 **실패 링크**(KMP 의 실패 함수를 트라이로 일반화)를 얹어, 텍스트 한 번 훑기로 모든 패턴을
찾는다. [KMP](#/algo/kmp) 의 다중 패턴 확장.

### 축약 트라이 (radix / Patricia)

자식이 하나뿐인 사슬을 하나의 간선으로 압축해 공간을 줄인다. IP 라우팅 테이블·접미사 트리의 기초.

### 비트 트라이 — 최대 XOR

수를 이진 문자열로 보고 트라이에 넣으면, "배열에서 x 와 XOR 이 최대인 원소" 를 `O(비트수)` 에.
정수 문제를 문자열 트라이로 푸는 대표 예.
