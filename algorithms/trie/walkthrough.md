## 어떤 문제인가

단어를 **아주 많이** 저장해 두고, "이 단어가 있나?", "이 접두사로 시작하는 단어가 있나?" 를 빠르게
답하고 싶다(사전, 자동완성, 맞춤법 검사).

해시 집합에 넣으면 "정확히 이 단어" 는 찾지만 **접두사 질의**("`ca` 로 시작하는 것들")는 못 한다.
정렬해 이분 탐색하면 접두사는 되지만 삽입이 번거롭다.

> 단어들이 **앞부분을 공유**한다는 사실(`cat`, `car`, `card` 는 모두 `ca…`)을 살릴 수 없을까?

## 손으로 해보기

기본 입력 `cat car card do dog` 를 트리로 쌓아 보자. **한 글자 = 한 간선**, 뿌리에서 내려가는
경로가 곧 접두사다.

### insert("cat")

뿌리에서 시작해 `c` → `a` → `t` 로 내려가며 없는 노드를 만든다. `t` 노드에 **단어 끝(●)** 표시.

```
(뿌리)─c─(·)─a─(·)─t─(●)
```

### insert("car") — 접두사 공유

`c`, `a` 는 이미 있으니 따라 내려가고, `r` 만 새로 만든다. **`ca` 를 재사용**했다.

```
(뿌리)─c─(·)─a─┬─t─(●)
               └─r─(●)
```

### insert("card") — 더 깊이

`c`, `a`, `r` 을 따라가 `d` 를 새로 붙인다.

```
(뿌리)─c─(·)─a─┬─t(●)
               └─r(●)─d(●)
```

`r` 은 "car" 의 끝(●)이면서 "card" 로 가는 길목이기도 하다.

### insert("do"), insert("dog")

`d` 는 뿌리의 새 자식. `do` 를 넣고(끝 ●), `dog` 는 `do` 를 따라가 `g` 를 붙인다.
**"do" 는 "dog" 의 끝이 아니라 중간에 있는 단어** 다 — 그래서 단어 끝 표시가 필요하다.

### search 세 가지

```
search("cat"): c→a→t 따라감, t 가 ● → 단어다 ✓
search("ca") : c→a 따라감, a 는 ● 아님 → 접두사일 뿐, 단어는 아니다
search("cap"): c→a 다음 'p' 자식이 없음 → 아예 없다
```

**끝까지 갔는지** 와 **거기가 단어 끝(●)인지** 는 다른 질문이다 — 이 구별이 트라이의 핵심이다.

### 비용

```
insert(s) / search(s): 글자 수 L 만큼만 내려간다 → O(L)
단어 개수·전체 크기와 무관 — 오직 그 문자열 길이에만 비례
```

## 아이디어 쌓기

### 1단계 — 글자를 간선으로

문자열을 통째로 저장하지 말고 글자 단위 경로로 쪼갠다. 뿌리→노드 경로 = 접두사.

### 2단계 — 접두사 공유

같은 접두사는 같은 경로를 재사용한다. `cat`·`car`·`card` 가 `ca` 를 공유.

### 3단계 — 단어 끝 표시

경로 도중 노드도 단어일 수 있다(`do` ⊂ `dog`). "여기서 단어가 끝난다(●)" 를 노드에 표시.

### 4단계 — 검색은 경로 따라가기

글자대로 자식을 따라간다. 길이 끊기면 없음, 끝까지 가면 ● 여부로 "단어" 와 "접두사" 를 가른다.

## 코드로 옮기기

```cpp
struct Node { int next[26]; bool end; };     // 26개 자식 + 단어 끝
vector<Node> t(1);                            // t[0] = 루트
void insert(string s) {
    int cur = 0;
    for (char ch : s) {
        int c = ch - 'a';
        if (t[cur].next[c] == 0) {            // 자식이 없으면 새로
            t[cur].next[c] = t.size();
            t.push_back({});
        }
        cur = t[cur].next[c];                 // 한 글자 내려간다
    }
    t[cur].end = true;                        // 여기서 단어가 끝난다
}
bool search(string s) {
    int cur = 0;
    for (char ch : s) {
        int c = ch - 'a';
        if (t[cur].next[c] == 0) return false; // 길이 끊기면 없음
        cur = t[cur].next[c];
    }
    return t[cur].end;                        // 접두사 말고 단어인가
}
```

각 노드는 자식 26칸(`a`~`z`)과 `end` 플래그를 든다. `next[c]==0` 이 "자식 없음"(0=루트라 자식일 수 없음).

## 자주 하는 실수

**단어 끝 표시를 안 한다.** `do` 와 `dog` 를 넣으면 `o` 노드가 단어 끝이면서 `dog` 의 길목이다.
`end` 플래그가 없으면 `do` 를 검색할 때 "단어" 인지 "접두사" 인지 구별 못 한다.

**search 에서 end 확인을 빠뜨린다.** 끝까지 도달 = 접두사 존재. **단어** 인지는 `end` 를 봐야 한다.

**메모리 낭비.** 노드마다 26칸 배열이면 희소할 때 낭비다. 맵(`unordered_map<char,int>`)이나
축약 트라이(radix/Patricia)로 줄인다.

**대문자·비알파벳.** 알파벳 범위를 벗어난 문자를 인덱스로 쓰면 배열 밖을 읽는다. 전처리로 정규화.

## 스스로 확인하기

1. **insert("car")** 에서 `c`, `a` 가 재사용(파랑)되고 `r` 만 새로(활성) 생기는 것을 보자.
2. **`ca` 를 공유**하는 세 단어 `cat/car/card` 가 한 갈래에서 갈라지는 것을 보자.
3. **`do`(●)가 `dog` 의 중간**에 놓이는 것을 보자 — 단어 끝이 리프가 아니어도 된다.
4. **search("cat")** 이 ● 노드에서 "단어" 로 끝나는 것을 보자.
5. **search 접두사 데모**에서 끝까지 갔지만 ● 가 아니라 "접두사일 뿐" 이 되는 것을 보자.
6. 단어를 `to tea ten ted` 로 바꿔 보자 — `te` 아래로 `a/n/d` 가 갈라진다.
