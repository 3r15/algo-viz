## 어떤 문제인가

파이프 망이 있다. 각 파이프(간선)엔 **용량**이 있고, **소스 S** 에서 물을 넣어 **싱크 T** 로 빼낸다.
한 번에 최대 얼마나 흘려보낼 수 있을까?

```
      16      12
   S ────▶ 1 ────▶ 3
   │       │       │ 20
13 │    10 │   9   ▼
   ▼       ▼ ◀──── 3?   … 각 간선의 숫자가 용량
   2 ────▶ 4 ────▶ T
      14      4
```

규칙: 각 간선의 유량 ≤ 용량이고, 소스·싱크를 뺀 정점은 **들어온 만큼 나가야** 한다(보존).
최대 유량은 얼마이고, 무엇이 그것을 **가로막는** 병목일까?

## 손으로 해보기

핵심 도구는 **잔여 그래프(residual graph)** 다. 간선마다 "아직 더 흘릴 수 있는 양(잔여 용량)" 을 들고,
거기서 **소스→싱크 경로(증가 경로)** 를 찾아 병목만큼 흘린다.

### 되돌리기가 가능해야 한다 — 역방향 잔여 간선

한 번 흘린 유량을 나중에 **되물릴** 수 있어야 최적에 도달한다. 그래서 간선 `u→v` 에 `f` 를 흘리면,
반대 방향 `v→u` 에 잔여 `f` 를 만들어 둔다. "필요하면 이만큼 되돌릴 수 있다" 는 뜻이다.

### 증가 경로를 반복해 흘린다

```
① 잔여 그래프에서 S→T 경로를 BFS 로 찾는다
② 그 경로의 최소 잔여 = 병목만큼 흘린다
③ 잔여를 갱신한다(정방향 −병목, 역방향 +병목)
④ 경로가 없을 때까지 반복
```

기본 네트워크에서 예를 들면:

```
경로 S→1→3→T, 병목 12  → 12 흘림   (누적 12)
경로 S→2→4→T, 병목  4  →  4 흘림   (누적 16)
경로 S→2→4→3→T, 병목 7 →  7 흘림   (누적 23)
더 이상 S→T 경로 없음 → 최대 유량 = 23
```

### 최대 유량 = 최소 컷

경로가 끊긴 순간, **소스에서 잔여로 닿는 정점들** `{S,1,2,4}` 과 나머지 `{3,T}` 로 갈린다.
이 둘을 가르는 간선 `1→3(12), 4→3(7), 4→T(4)` 의 용량 합이 **정확히 23**.

> **최대 유량 = 최소 컷.** 흘릴 수 있는 최대량은, 네트워크를 두 쪽으로 자를 때 가장 싼 절단면과 같다.

물을 막으려면 이 세 간선을 끊으면 되고, 그 비용(23)이 곧 최대로 흘릴 수 있는 양이다.

### 비용

```
증가 경로 한 번: BFS O(E)
경로 횟수: 에드몬드-카프(BFS)면 O(V·E) 번
합계: O(V·E²)
```

## 아이디어 쌓기

### 1단계 — 잔여 그래프

각 간선의 "남은 용량" 을 추적한다. 흘릴 수 있는 곳 = 잔여 > 0 인 간선.

### 2단계 — 되돌림용 역간선

흘린 만큼 반대 방향에 잔여를 만들어, 나중에 유량을 재배치할 여지를 남긴다.

### 3단계 — 증가 경로를 BFS 로

잔여 그래프에서 S→T 경로를 찾아 병목만큼 흘린다. **BFS(최단 경로)** 로 찾으면 반복 횟수가 `O(VE)` 로 묶인다.

### 4단계 — 끊기면 최소 컷

경로가 없을 때 소스 도달 집합이 최소 컷의 한쪽. 최대 유량 = 그 컷 용량.

## 코드로 옮기기

```cpp
int maxflow(int s, int t) {                  // s=소스, t=싱크
    int flow = 0;
    while (true) {
        vector<int> par(n, -1); par[s] = s;   // BFS 로 증가 경로
        queue<int> q; q.push(s);
        while (!q.empty()) {
            int u = q.front(); q.pop();
            for (int v = 0; v < n; v++)
                if (par[v] < 0 && cap[u][v] > 0)
                    par[v] = u, q.push(v);
        }
        if (par[t] < 0) break;                // 더 못 보내면 끝
        int bott = INF;                        // 경로의 최소 잔여 = 병목
        for (int v = t; v != s; v = par[v])
            bott = min(bott, cap[par[v]][v]);
        for (int v = t; v != s; v = par[v])    // 잔여 그래프 갱신
            cap[par[v]][v] -= bott, cap[v][par[v]] += bott;
        flow += bott;
    }
    return flow;                              // 최대 유량 = 최소 컷
}
```

`cap[u][v]` 가 잔여 용량. 흘릴 때 `cap[par[v]][v] -= bott`(정방향), `cap[v][par[v]] += bott`(역방향).

## 자주 하는 실수

**역방향 잔여를 안 만든다.** `cap[v][par[v]] += bott` 를 빼먹으면 유량 재배치가 막혀 최적에 못 간다.
"되돌릴 수 있다" 가 정확성의 핵심이다.

**증가 경로를 DFS 로 아무렇게나 찾는다.** 순수 포드-풀커슨은 용량이 무리수면 안 끝날 수도, 정수라도
느릴 수도 있다. **BFS(에드몬드-카프)** 면 `O(VE²)` 가 보장된다.

**용량과 유량을 헷갈린다.** 화면의 라벨은 "유량/용량". 잔여 = 용량 − 유량(정방향), 유량(역방향).

**반평행 간선.** `u→v` 와 `v→u` 가 모두 있으면 잔여 관리가 까다롭다(별도 간선 인덱스로 처리).
여기 예시 그래프는 이를 피해 구성했다.

## 스스로 확인하기

1. **증가 경로 스텝**에서 BFS 가 찾은 S→T 경로가 초록으로 강조되고 병목이 표시되는 것을 보자.
2. **유량 흘리기 스텝**에서 경로 간선의 라벨 "유량/용량" 이 갱신되는 것을 보자.
3. **세 번째 경로 `S→2→4→3→T`** 가 역방향 잔여를 활용하는지 관찰하자.
4. **경로가 끊긴 마지막**에서 소스 도달 집합(초록)과 최소 컷 간선(빨강)을 보자.
5. **컷 간선 용량 합 = 최대 유량 23** 임을 확인하자.
6. 그래프 편집기로 `4→T` 용량을 키워 보자 — 병목이 옮겨가고 최대 유량이 바뀐다.

아래 **깊이 보기**에서는 최대 유량 = 최소 컷 정리의 증명, 에드몬드-카프의 `O(VE²)` 근거,
디닉·이분 매칭·프로젝트 선택으로의 확장을 다룬다.
