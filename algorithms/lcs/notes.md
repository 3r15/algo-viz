## 한눈에

두 수열에서 **순서를 지키며 공통으로 뽑을 수 있는** 가장 긴 부분 수열을 구한다.
상태를 "양쪽의 앞부분(prefix) 길이 쌍" 으로 잡아 `(m+1) × (n+1)` 표를 채우는 2차원 DP다.

- **시간** `Θ(mn)` — 표의 칸마다 상수 시간
- **공간** `Θ(mn)` — 복원까지 하려면 표 전체가 필요하다. 길이만이면 `Θ(min(m,n))`
- **부분 수열이지 부분 문자열이 아니다** — 연속일 필요가 없다
- **대칭** — `LCS(A, B) = LCS(B, A)`. 표를 전치하면 같다

**언제 쓰나** — `diff`, 버전 관리의 3-way merge, DNA 서열 정렬, 표절 검사.
"두 열이 얼마나 닮았나" 를 **편집 없이** 재는 표준 도구다.

**언제 안 쓰나** — `m`, `n` 이 각각 10만이면 `10¹⁰` 칸이라 시간·공간 모두 불가능하다.
그럴 땐 Hunt–Szymanski(매칭 쌍이 적을 때)나 Myers 의 `O(ND)` 알고리즘(diff 가 쓰는 것)을 쓴다.
**연속**을 요구하는 문제라면 이 점화식이 아니라 다른 것이 필요하다.

## 동작 원리

핵심은 **양쪽 접두사 쌍으로 상태를 잡는 것**이다.

> `dp[i][j]` = `A[1..i]` 와 `B[1..j]` 의 최장 공통 부분 수열의 길이

`2^m` 개의 부분 수열이 `(m+1)(n+1)` 개의 상태로 접힌다.

### 점화식

```
dp[i][j] = 0                                       i = 0 또는 j = 0
         = dp[i-1][j-1] + 1                        A[i] = B[j]
         = max( dp[i-1][j], dp[i][j-1] )           A[i] ≠ B[j]
```

세 참조 `(i-1, j-1)`, `(i-1, j)`, `(i, j-1)` 이 모두 **위쪽 아니면 왼쪽**이므로,
행 우선으로 훑으면 위상 순서가 자동으로 지켜진다.

### 실행 예

`A = ABCBDAB`, `B = BDCABA`

```
              B   D   C   A   B   A
          ∅   1   2   3   4   5   6
    ∅ 0   0   0   0   0   0   0   0
    A 1   0   0   0   0   1   1   1
    B 2   0   1   1   1   1   2   2
    C 3   0   1   1   2   2   2   2
    B 4   0   1   1   2   2   3   3
    D 5   0   1   2   2   2   3   3
    A 6   0   1   2   2   3   3   4
    B 7   0   1   2   2   3   4   4
```

`dp[7][6] = 4`, 복원하면 `BCBA`. 최적해는 유일하지 않다 — `BDAB` 도 길이 4다.
역추적에서 동점(`dp[i-1][j] = dp[i][j-1]`)을 어느 쪽으로 푸느냐가 어느 답을 뽑을지 정한다.

### 표의 두 가지 성질

> **단조성.** `dp[i][j] ≤ dp[i+1][j]` 이고 `dp[i][j] ≤ dp[i][j+1]`.
> **립시츠 성질.** `dp[i+1][j] - dp[i][j] ∈ {0, 1}`. 열 방향도 같다.

글자 하나를 더 볼 수 있게 되었다고 LCS 가 2 이상 늘 수는 없기 때문이다.
이 성질이 역추적이 항상 성립하는 근거이자, 뒤에 나오는 Hirschberg 분할의 토대다.

## 정확성

### 보조정리 — 같은 글자는 반드시 짝지어도 손해가 없다

> `A[i] = B[j] = X` 이면, `A[1..i]` 와 `B[1..j]` 의 최적 공통 부분 수열 중
> **`A[i]` 와 `B[j]` 를 서로 짝지은 것**이 반드시 존재한다.

**증명(교환 논법).** 최적해 `S` 를 하나 잡고, `S` 가 `A` 쪽에서 쓴 인덱스를 `p₁<…<p_L`,
`B` 쪽에서 쓴 인덱스를 `q₁<…<q_L` 이라 하자.

- `p_L = i` 이고 `q_L = j` 이면 이미 짝지어져 있다.
- `p_L = i` 이고 `q_L < j` 이면, `q_L` 을 `j` 로 바꾼다. `B[j] = X = A[i] = S` 의 마지막 글자이고
  `q_{L-1} < q_L < j` 이므로 순서가 유지된다. 길이도 그대로다.
- `p_L < i` 이고 `q_L = j` 이면 대칭으로 `p_L` 을 `i` 로 바꾼다.
- `p_L < i` 이고 `q_L < j` 이면, `S` 뒤에 `X` 를 **덧붙일** 수 있어 길이 `L+1` 짜리가 되는데,
  이는 `S` 가 최적이라는 가정에 모순이다. 따라서 이 경우는 일어나지 않는다.

어느 경우든 길이 `L` 을 유지하면서 `(i, j)` 를 짝지은 최적해를 얻는다. ∎

이 보조정리가 **"같으면 `max` 를 볼 필요 없이 대각선 하나면 된다"** 의 근거다.

### 본 정리

> **불변식.** 반복이 `(i, j)` 를 지난 시점에 `dp[i][j]` 는
> `A[1..i]` 와 `B[1..j]` 의 LCS 길이와 같다.

`i + j` 에 대한 강귀납법으로 보인다.

**기저** — `i = 0` 또는 `j = 0`. 한쪽이 빈 수열이면 공통 부분 수열도 빈 수열뿐이므로 0. ✓

**귀납 단계** — `i, j ≥ 1` 이고, `i' + j' < i + j` 인 모든 상태에서 불변식이 성립한다고 하자.
참조하는 세 상태는 모두 이 조건을 만족한다.

*경우 1: `A[i] = B[j]`.* 보조정리에 의해 `(i, j)` 를 짝지은 최적해가 존재한다.
그 해에서 마지막 글자를 떼면 `A[1..i-1]` 과 `B[1..j-1]` 의 공통 부분 수열이므로
`LCS(i, j) = LCS(i-1, j-1) + 1`. 귀납 가정으로 `= dp[i-1][j-1] + 1`. ✓

*경우 2: `A[i] ≠ B[j]`.* 최적해 `S` 를 잡으면 `A[i]` 와 `B[j]` 가 **서로** 짝지어질 수는 없다
(글자가 다르므로). 따라서 `S` 는 `A[i]` 를 안 쓰거나 `B[j]` 를 안 쓴다.

- `A[i]` 를 안 쓰면 `S` 는 `A[1..i-1]` 과 `B[1..j]` 의 공통 부분 수열 → `|S| ≤ LCS(i-1, j)`
- `B[j]` 를 안 쓰면 대칭으로 `|S| ≤ LCS(i, j-1)`

그러므로 `LCS(i, j) ≤ max(LCS(i-1, j), LCS(i, j-1))`.
역으로 두 값 모두 `A[1..i]`, `B[1..j]` 의 공통 부분 수열을 그대로 실현하므로 `≥` 도 성립한다.
따라서 등호다. ✓ ∎

**종료성** — 두 반복문이 유한 범위의 단조 증가 카운터이므로 항상 종료한다.

### 역추적의 정당성

역추적은 `(m, n)` 에서 시작해 매 단계 `i + j` 를 최소 1 줄인다. 각 단계에서

- `A[i] = B[j]` 면 보조정리에 의해 `(i, j)` 를 짝지은 최적해가 있으므로 대각선으로 가도 안전하다
- 다르면 `dp[i][j]` 는 위·왼쪽 중 큰 쪽과 같으므로, 그쪽으로 이동해도 길이가 보존된다

`i` 나 `j` 가 0이 되면 멈춘다. 기록된 글자 수는 정확히 `dp[m][n]` 이다. ∎

## 복잡도

| | 시간 | 공간 |
|---|---|---|
| 최선 | `Θ(mn)` | `Θ(mn)` |
| 평균 | `Θ(mn)` | `Θ(mn)` |
| 최악 | `Θ(mn)` | `Θ(mn)` |

**시간** — 칸이 `(m+1)(n+1)` 개이고 각 칸은 비교 1회와 덧셈/최댓값 1회다.
조기 종료가 없어 **최선과 최악이 같다.** 두 문자열이 완전히 같아도 전부 채운다.

**공간** — 복원이 필요하면 표 전체 `Θ(mn)`. 길이만 필요하면 **직전 행 하나면 충분하다**:

```
dp[i][j] 는 dp[i-1][*] 과 dp[i][j-1] 만 참조한다
→ 행 두 개(또는 in-place 로 한 개 + 임시 변수 하나)
→ Θ(min(m, n))       짧은 쪽을 열로 두면 된다
```

역추적을 포기하지 않으면서 공간도 줄이려면 **Hirschberg 알고리즘**이 있다:
분할 정복으로 `Θ(mn)` 시간을 유지하면서 공간을 `Θ(min(m,n))` 으로 낮춘다.

**하한** — 부호 비교만 쓰는 모델에서 LCS 는 `Ω(mn)` 이 필요하다는 결과가 알려져 있고,
SETH 를 가정하면 일반 LCS 에 대해 `O((mn)^{1-ε})` 알고리즘은 없다.
즉 **일반적으로 이 이차 시간을 크게 개선할 수 없다.**

## 구현 노트

**1-based 표 vs 0-based 문자열** — 표의 `i`번째 행은 `A` 의 `i`번째 글자이지만
C++ 인덱스로는 `A[i-1]` 이다. 이 어긋남이 가장 흔한 버그다.

**메모리** — `m = n = 5000` 이면 `int` 로 `25,000,001 × 4 B ≈ 100 MB` 다.
`short` 로 줄이거나(값이 `min(m,n)` 이하라 안전), 롤링 배열로 바꿔야 한다.

**동점 처리** — 역추적에서 `dp[i-1][j] == dp[i][j-1]` 일 때 어느 쪽으로 가든 길이는 같지만
**나오는 수열이 달라진다.** diff 도구는 이 선택으로 "보기 좋은 diff" 를 만든다.

**LCS 길이와 편집 거리** — 삽입·삭제만 허용하는 편집 거리는

```
edit(A, B) = m + n - 2 · LCS(A, B)
```

교체를 허용하면 이 관계가 깨진다(레벤슈타인 거리는 별도의 점화식이 필요하다).

## 변형과 확장

### 공간 절약 — 롤링 배열

```cpp
vector<int> prev(n + 1, 0), cur(n + 1, 0);
for (int i = 1; i <= m; i++) {
    for (int j = 1; j <= n; j++)
        cur[j] = (A[i-1] == B[j-1]) ? prev[j-1] + 1
                                    : max(prev[j], cur[j-1]);
    swap(prev, cur);
}
return prev[n];
```

`Θ(n)` 공간. 대신 **역추적이 불가능하다** — 길이만 필요할 때 쓴다.

### 최장 공통 부분 문자열(연속)

연속을 요구하면 점화식이 달라진다.

```
dp[i][j] = dp[i-1][j-1] + 1     A[i] = B[j]
         = 0                     A[i] ≠ B[j]        ← max 가 아니라 0!
답 = 표 전체의 최댓값 (dp[m][n] 이 아니다)
```

끊기면 처음부터 다시 세야 하므로 0 으로 리셋한다. **완전히 다른 문제**다.

### 세 수열 이상

`dp[i][j][k]` 로 차원을 늘리면 `Θ(n³)`. 수열 개수가 늘면 지수적으로 나빠지고,
일반적인 개수의 LCS 는 NP-난해다.

### LIS 로의 환원

`B` 의 각 글자가 `A` 에 나타나는 위치들을 **내림차순**으로 나열해 이어 붙이면,
그 수열의 [LIS](#/algo/lis) 가 곧 LCS 다. 문자 종류가 적고 매칭 쌍이 적을 때
`O((r + n) log n)` 으로 유리하다(Hunt–Szymanski).
