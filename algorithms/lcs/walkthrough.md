## 어떤 문제인가

문자열 두 개가 있다. 양쪽 모두에서 **순서를 지키며** 골라낼 수 있는 가장 긴 글자열은 무엇일까?

```
A = A B C B D A B
B = B D C A B A
```

"연속"일 필요는 없다. 띄엄띄엄 골라도 되고, **왼쪽에서 오른쪽 순서만 지키면 된다.**

```
A =  · B C B · · ·      →  B C B
B =  B · C · B ·        →  B C B      ✓ 양쪽에서 순서대로 뽑힌다
```

이건 장난감 문제가 아니다. `git diff` 가 하는 일이 정확히 이것이다 —
두 파일의 **공통 부분**을 가장 길게 찾고, 나머지를 추가·삭제로 표시한다.

단순한 방법은 `A` 의 모든 부분 수열(`2^m` 개)을 만들어 `B` 에 있는지 확인하는 것이다.
`A` 가 30글자면 10억 개가 넘는다.

> 통째로 비교하지 말고, **앞에서부터 한 글자씩 늘려 가며 답을 쌓을 수 없을까?**

## 손으로 해보기

기본 입력 `ABCBDAB BDCABA` 로 끝까지 가 보자.

### 상태를 어떻게 잡을까

두 문자열을 통째로 보면 손을 댈 데가 없다. **앞부분(prefix)끼리** 짝지어 묻는다.

> `dp[i][j]` = `A` 의 **앞 `i` 글자**와 `B` 의 **앞 `j` 글자**만 볼 때의 LCS 길이

`i`, `j` 를 0부터 키우면 작은 문제에서 큰 문제로 올라간다.
그래서 표가 **`(m+1) × (n+1)`** 이다 — 0행·0열은 "한쪽이 빈 문자열" 인 경우다.

빈 문자열과의 공통 부분 수열은 당연히 없다. **0행과 0열은 전부 0.** 여기가 출발점이다.

### 마지막 글자만 보면 된다

`dp[i][j]` 를 구할 때 우리가 결정해야 하는 것은 **`A` 의 `i`번째 글자와 `B` 의 `j`번째 글자**뿐이다.
경우가 딱 둘이다.

**경우 1 — 두 글자가 같다.**

```
A = … X
B = … X       ←  둘 다 X 로 끝난다
```

이 `X` 를 짝지어 쓴다. 그러면 남는 문제는 "`A` 의 앞 `i-1` 글자 ↔ `B` 의 앞 `j-1` 글자" 다.

```
dp[i][j] = dp[i-1][j-1] + 1        ← 대각선 왼쪽 위 + 1
```

**경우 2 — 두 글자가 다르다.**

```
A = … X
B = … Y       ←  X ≠ Y
```

`X` 와 `Y` 를 서로 짝지을 수는 없다. 그러면 **둘 중 적어도 하나는 답에 안 쓰인다.**
어느 쪽인지 모르니 **둘 다 시도해 보고 큰 쪽**을 택한다.

```
dp[i][j] = max( dp[i-1][j],    ← A 의 마지막 글자를 버린 경우
                dp[i][j-1] )   ← B 의 마지막 글자를 버린 경우
```

### 표를 채운다

`A = ABCBDAB`(세로), `B = BDCABA`(가로).

**1행 (A 의 첫 글자 `A`)**

```
j=1 (B):  A ≠ B  →  max(위 0, 왼쪽 0) = 0
j=2 (D):  A ≠ D  →  0
j=3 (C):  A ≠ C  →  0
j=4 (A):  A = A  →  대각선 dp[0][3] = 0,  +1  →  1     ★ 첫 매칭
j=5 (B):  A ≠ B  →  max(위 0, 왼쪽 1) = 1
j=6 (A):  A = A  →  대각선 dp[0][5] = 0,  +1  →  1
```

`j=6` 을 보자. 같은 글자를 만나 `+1` 했는데 값이 1 그대로다. 이미 왼쪽이 1이었기 때문이다.
**같은 글자를 만난다고 답이 반드시 늘지는 않는다.**

**2행 (`B`)**

```
j=1 (B):  B = B  →  dp[1][0] + 1 = 1
j=2 (D):  다름   →  max(위 0, 왼쪽 1) = 1
j=3 (C):  다름   →  max(위 0, 왼쪽 1) = 1
j=4 (A):  다름   →  max(위 1, 왼쪽 1) = 1
j=5 (B):  B = B  →  dp[1][4] + 1 = 2                   ★ AB ↔ AB
j=6 (A):  다름   →  max(위 1, 왼쪽 2) = 2
```

### 완성된 표

```
              B   D   C   A   B   A
          ∅   1   2   3   4   5   6
    ∅ 0   0   0   0   0   0   0   0
    A 1   0   0   0   0   1   1   1
    B 2   0   1   1   1   1   2   2
    C 3   0   1   1   2   2   2   2
    B 4   0   1   1   2   2   3   3
    D 5   0   1   2   2   2   3   3
    A 6   0   1   2   2   3   3   4
    B 7   0   1   2   2   3   4   4
                                  ↑ 답
```

**`dp[7][6] = 4`.** 값이 왼쪽 위에서 오른쪽 아래로 **결코 줄지 않으며** 계단처럼 오른다.

### 수열 자체를 되찾기

길이만으로는 아쉽다. **오른쪽 아래에서 거슬러 올라간다.**

- 두 글자가 **같으면** → 그 글자가 답에 쓰인 것. 적어 두고 **대각선**으로
- **다르면** → 값이 어디서 왔는지 따라간다. 위쪽이 크거나 같으면 위로, 아니면 왼쪽으로

```
(7,6) B vs A  다름 → 위(4) ≥ 왼(4) → 위로
(6,6) A vs A  같다! → "A" 기록, 대각선
(5,5) D vs B  다름 → 위(3) ≥ 왼(2) → 위로
(4,5) B vs B  같다! → "B" 기록, 대각선
(3,4) C vs A  다름 → 위(1) < 왼(2) → 왼쪽
(3,3) C vs C  같다! → "C" 기록, 대각선
(2,2) B vs D  다름 → 위(0) < 왼(1) → 왼쪽
(2,1) B vs B  같다! → "B" 기록, 대각선
(1,0) 열이 0 → 끝
```

거꾸로 적혔으니 뒤집으면 **`BCBA`** — 길이 4다. ✓

## 아이디어 쌓기

### 1단계 — 완전탐색은 왜 안 되나

`A` 의 부분 수열이 `2^m` 개. 그런데 그중 대부분이 **같은 접두사를 다시 계산한다.**
겹치는 부분 문제를 한 번씩만 풀면 된다.

### 2단계 — 앞부분끼리 짝짓는다

문제를 `(i, j)` 두 정수로 표현한다. 상태가 `(m+1)(n+1)` 개뿐이다.
`2^m` 이 `mn` 으로 줄었다. **이 한 번의 상태 설계가 알고리즘의 전부**라고 해도 된다.

### 3단계 — 마지막 글자로 경우를 나눈다

`A[i]` 와 `B[j]` 가 같은가 다른가. 이 이분법이 점화식을 만든다.
같으면 대각선 +1, 다르면 위·왼쪽 중 큰 쪽.

### 4단계 — 채우는 순서

`dp[i][j]` 는 `dp[i-1][j-1]`, `dp[i-1][j]`, `dp[i][j-1]` 만 쓴다 — 전부 **위쪽 아니면 왼쪽**이다.
그러니 **위에서 아래로, 왼쪽에서 오른쪽으로** 채우면 필요한 값이 항상 준비돼 있다.

```
   ↖ ↑
   ←  ●        ● 를 채울 때 필요한 세 칸은 모두 이미 채워져 있다
```

### 5단계 — 0행·0열이 경계를 삼킨다

`i-1`, `j-1` 을 쓰는데 `i=1`, `j=1` 이면 0을 참조한다. 0행·0열을 **미리 0으로 깔아 두면**
"인덱스가 범위를 벗어났나" 검사가 통째로 사라진다. 표를 `(m+1) × (n+1)` 로 잡은 이유다.

### 6단계 — 발자국은 따로 저장하지 않아도 된다

LIS 와 달리 여기서는 `prev` 배열이 필요 없다. **표 자체에 발자국이 남아 있어서**,
값이 어디서 왔는지 역으로 판정할 수 있다.

## 코드로 옮기기

```cpp
int lcs(string A, string B) {
    int m = A.size(), n = B.size();
    vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));   // ← 5단계: 0행·0열 = 0
    for (int i = 1; i <= m; i++) {                          // ← 4단계: 위에서 아래로
        for (int j = 1; j <= n; j++) {                      //    왼쪽에서 오른쪽으로
            if (A[i-1] == B[j-1])                           // ← 3단계: 경우 1
                dp[i][j] = dp[i-1][j-1] + 1;
            else                                            //    경우 2
                dp[i][j] = max(dp[i-1][j], dp[i][j-1]);
        }
    }
    return dp[m][n];
}
```

**`A[i-1]` 의 `-1` 을 조심하자.** 표의 `i` 는 "앞 `i` 글자"라 1부터 세는데,
C++ 문자열 인덱스는 0부터다. `i`번째 글자 = `A[i-1]`. 이 어긋남이 가장 흔한 버그다.

## 자주 하는 실수

**표를 `m × n` 으로 잡는다.** 0행·0열이 없으면 `i-1`, `j-1` 이 음수가 된다.
반드시 **`(m+1) × (n+1)`** 이다.

**`A[i]` 와 `B[j]` 를 비교한다.** 표의 `i` 와 문자열 인덱스가 1 차이 난다.
`A[i-1] == B[j-1]` 이 맞다.

**같은 글자일 때 `max` 를 함께 본다.**

```cpp
// 이렇게 쓰고 싶어지지만 불필요하다
dp[i][j] = max({dp[i-1][j-1] + 1, dp[i-1][j], dp[i][j-1]});
```

답은 같지만 셋을 볼 이유가 없다. 글자가 같으면 **그 글자를 쓰는 게 절대 손해가 아니다**
(깊이 보기에서 증명한다). 대각선 하나면 충분하다.

**루프 순서를 뒤집는다.** `for(j) for(i)` 로 써도 이 점화식은 **우연히 동작한다**
(필요한 칸이 여전히 위·왼쪽이라서). 하지만 변형 문제에서 곧바로 깨지므로
`i` 를 바깥에 두는 표준 순서를 지키자.

**부분 문자열(substring)과 헷갈린다.** 이 문제는 **연속이 아니다.**
연속을 요구하는 "최장 공통 부분 문자열" 은 점화식이 다르다 —
글자가 다르면 `max` 가 아니라 **0** 이 된다.

## 스스로 확인하기

1. **`i=1, j=6` 스텝**을 찾아보자. `A` 와 `A` 가 같아서 `+1` 했는데 값이 1 그대로다.
   같은 글자를 만나도 답이 안 늘 수 있다는 걸 눈으로 확인하자.
2. **읽는 칸(회색)의 위치**를 보자. 글자가 같으면 **대각선 한 칸**, 다르면 **위·왼쪽 두 칸**이다.
   이 두 모양만 계속 반복된다.
3. **마지막 스텝**의 초록 칸들이 역추적 경로다. 대각선으로 내려가는 칸이 곧 매칭된 글자다.
4. 입력을 `ABCD ABCD` 로 바꿔 보자. 표의 **대각선이 1, 2, 3, 4 로 오르고**, 답은 4다.
5. 입력을 `ABC DEF` 로 바꿔 보자. 표가 전부 0 이다.
6. 입력을 `AB BA` 로 바꿔 보자. 답이 1 이다 — `A` 와 `B` 를 **둘 다** 쓸 수는 없다.
   순서를 지켜야 하기 때문이다.

아래 **깊이 보기**에서는 "글자가 같으면 반드시 써도 된다"를 교환 논법으로 증명하고,
공간을 `O(min(m,n))` 으로 줄이는 방법과 편집 거리로의 확장을 다룬다.
