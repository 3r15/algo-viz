## 어떤 문제인가

정렬되지 않은 배열에서 **k번째로 작은 원소**(예: 중앙값)를 찾고 싶다.

가장 쉬운 방법은 **정렬한 뒤 `a[k]`** 를 보는 것 — 하지만 `O(n log n)` 이고, 우리는 **하나만** 알면 된다.
나머지를 완전히 정렬하는 건 낭비 아닐까?

> [퀵 정렬](#/algo/quick-sort)의 **파티션**을 쓰되, **답이 있는 쪽만** 이어서 보면 안 될까?

## 손으로 해보기

기본 입력 `[7, 2, 9, 1, 5, 6, 3]` (n=7)에서 **중앙값**(k = ⌊7/2⌋ = 3번째 최솟값, 0-based)을 찾자.
정렬하면 `[1,2,3,5,6,7,9]` 이라 답은 `5` — 이걸 정렬 없이 찾는다.

### 파티션 한 번의 힘

마지막 원소를 **피벗**으로 삼아, 피벗보다 작은 값을 앞으로 모은다. 그러면 피벗은 **자기 최종 정렬
위치 `i`** 에 놓인다(앞은 다 작고, 뒤는 다 크다).

```
[7, 2, 9, 1, 5, 6, 3]  피벗 3
작은 값(2,1)을 앞으로 → [2, 1, 3, 7, 5, 6, 9]  피벗 3 이 자리 2 로
                              ↑ i=2
```

이제 **피벗 위치 `i=2` 와 `k=3` 을 비교**한다.

### 한쪽만 버린다

```
i = 2 < k = 3  →  답은 오른쪽에! 왼쪽 [0,2] 를 통째로 버리고 [3,6] 만 본다
```

왼쪽 절반을 **아예 안 본다.** 이게 정렬과의 결정적 차이다.

```
[7, 5, 6, 9] 범위에서 피벗 9 → 작은 값 다 앞으로 → 피벗 9 자리 6
i = 6 > k = 3 → 왼쪽 [3,5] 만
[7, 5, 6] 피벗 6 → [5, 6, 7]... 피벗 6 자리 4
i = 4 > k = 3 → 왼쪽 [3,3] 만
범위가 하나 → a[3] = 5   ← 찾았다
```

### 왜 평균 O(n) 인가

매 파티션은 그 범위를 한 번 훑는다(`O(범위 크기)`). 한쪽만 이어 보므로 크기가 대략 반씩 준다.

```
n + n/2 + n/4 + … = 2n = O(n)   (평균)
```

정렬(`O(n log n)`)보다 빠르다 — 나머지를 정렬 안 하기 때문.

## 아이디어 쌓기

### 1단계 — 파티션은 위치를 확정한다

피벗은 파티션 후 최종 정렬 위치 `i` 에 놓인다(앞 작고 뒤 큼).

### 2단계 — i 와 k 를 비교

`i == k` 면 답. `i < k` 면 오른쪽, `i > k` 면 왼쪽에 답이 있다.

### 3단계 — 한쪽만 이어서

답이 없는 쪽은 버린다. 크기가 반씩 줄어 평균 선형.

### 4단계 — 범위가 하나면 끝

`lo == hi` 면 그게 답.

## 코드로 옮기기

```cpp
int quickSelect(vector<int>& a, int k) {
    int lo = 0, hi = a.size() - 1;
    while (lo < hi) {
        int pivot = a[hi], i = lo;
        for (int j = lo; j < hi; j++)
            if (a[j] < pivot) swap(a[i++], a[j]);
        swap(a[i], a[hi]);              // 피벗을 제자리 i 로
        if (i == k) break;              // 찾았다
        else if (i < k) lo = i + 1;     // 오른쪽만
        else            hi = i - 1;     // 왼쪽만
    }
    return a[k];
}
```

[퀵 정렬](#/algo/quick-sort)과 파티션은 같지만, **재귀가 한쪽뿐**이다(그래서 반복문으로도 쓴다).

## 자주 하는 실수

**양쪽 다 재귀한다.** 그러면 퀵 정렬이라 `O(n log n)`. 퀵셀렉트는 **한쪽만**.

**최악 O(n²) 를 무시한다.** 항상 최악 피벗(이미 정렬 + 끝 피벗)이면 한 칸씩 줄어 `O(n²)`.
**무작위 피벗**(또는 median-of-medians)으로 평균/최악을 관리한다.

**k 인덱스(0-based vs 1-based)를 헷갈린다.** "k번째" 가 1-based 면 `k-1` 로.

**중복 값 처리.** 중복이 많으면 Lomuto 파티션이 한쪽으로 쏠릴 수 있다 — 3-way 파티션이 유리
([3-way 퀵 정렬](#/algo/quicksort-3way) 참고).

## 스스로 확인하기

1. **파티션 후 피벗이 자리 i 로 확정**되는 것을 보자(앞 작고 뒤 큼).
2. **i 와 k(★ 표시) 비교**로 한쪽을 버리는 것을 보자 — 버린 쪽은 어둡게.
3. **활성 범위가 반씩 좁아지는 것**을 관찰하자.
4. **최종 a[3] = 5**(중앙값)를 확인하자.
5. 입력을 `5 4 3 2 1` 로 바꿔 보자 — 이미 역정렬이면 파티션이 어떻게 도는지.
6. 입력을 `3 3 3 3 3` 로 바꿔 보자 — 중복만 있으면 한쪽으로 쏠린다(3-way 가 필요한 이유).

아래 **깊이 보기**에서는 평균 O(n)·최악 O(n²) 분석, 무작위 피벗·median-of-medians(최악 O(n)),
부분 정렬·top-k 응용을 다룬다.
