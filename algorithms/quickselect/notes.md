## 한눈에

정렬하지 않고 **k번째로 작은 원소**(순서 통계량)만 평균 `O(n)` 에 찾는다. [퀵 정렬](#/algo/quick-sort)의
파티션을 쓰되, 피벗이 확정 위치 `i` 에 놓이면 `i` 와 `k` 를 비교해 **한쪽만** 이어서 본다.

- **시간** 평균 `O(n)` / 최악 `O(n²)`(무작위 피벗이면 기대 `O(n)`) · **공간** `O(1)`(반복형)
- 퀵 정렬과 파티션은 같지만 **재귀가 한쪽뿐** → `n + n/2 + … = O(n)`
- 중앙값·백분위수·top-k 의 기본 도구
- 최악 `O(n)` 보장이 필요하면 **median-of-medians**

**언제 쓰나** — k번째 최솟값/최댓값, 중앙값, 백분위수, "가장 큰 k개"(부분 정렬 전처리).

**언제 안 쓰나** — 여러 k 를 반복 질의하거나 전체 순서가 필요하면 정렬이 낫다. 최악 보장이 절대적이면
median-of-medians 또는 힙.

## 동작 원리

```
lo = 0, hi = n-1
while lo < hi:
    파티션(lo, hi) → 피벗이 자리 i 에 확정(앞<피벗<뒤)
    if i == k: 답
    elif i < k: lo = i+1     # 오른쪽만
    else:       hi = i-1     # 왼쪽만
return a[k]
```

### 왜 한쪽만 보나

파티션 후 피벗은 **최종 정렬 위치** `i` 다. `k < i` 면 k번째는 반드시 왼쪽 `[lo, i-1]` 에, `k > i` 면
오른쪽 `[i+1, hi]` 에 있다(피벗 좌우의 대소 관계가 확정됐으므로). 답이 없는 절반은 볼 필요가 없다.

## 정확성

> **불변식.** 매 반복 시작 시, k번째 최솟값은 항상 현재 범위 `[lo, hi]` 안에 있다.

*유지.* 파티션으로 피벗이 `i` 에 확정되면 `a[lo..i-1] < a[i] ≤ a[i+1..hi]`. 전역 정렬에서 `a[i]` 는
정확히 `i`번째. `k < i` 면 k번째는 `a[i]` 보다 작으니 왼쪽에, `k > i` 면 오른쪽에. `hi/lo` 를 그렇게
좁혀도 k번째는 새 범위에 남는다. `i == k` 면 `a[k]` 가 답. ∎

*종료.* 매 반복에서 범위가 최소 1 줄거나(한쪽 버림) `i==k` 로 끝난다. 유한 종료.

## 복잡도

| | 시간 | 공간 |
|---|---|---|
| 평균 | `O(n)` | `O(1)` |
| 최악 | `O(n²)` | `O(1)` |

### 평균 O(n) 분석

무작위(또는 균형) 피벗이면 각 파티션이 범위를 상수 비율로 줄인다. 기대 작업량은

```
E[T(n)] = n + E[T(n·c)] ≈ n + n·c + n·c² + … = n / (1 − c) = O(n)
```

(`c < 1` 은 남는 비율의 기대). 정렬의 `O(n log n)` 보다 빠른 것은 "나머지를 정렬하지 않기" 때문.

### 최악과 대책

이미 정렬 + 끝 피벗이면 매번 한 칸씩 줄어 `O(n²)`. **무작위 피벗**이면 기대 `O(n)`, **median-of-medians**
(중앙값들의 중앙값을 피벗으로)면 **최악에도 `O(n)`** 보장(상수는 큼).

## 구현 노트

**반복형** — 한쪽만 재귀하므로 꼬리 재귀 → while 로. 스택 `O(1)`.

**무작위 피벗** — `swap(a[hi], a[rand(lo,hi)])` 후 파티션. 적대적 입력의 최악을 확률적으로 제거(라스베이거스).

**k 인덱스** — 0-based `a[k]`. "k번째"(1-based)면 `k-1`.

**중복** — Lomuto 는 중복이 많으면 쏠린다. **3-way 파티션**([3-way 퀵 정렬](#/algo/quicksort-3way))으로
같은 값 구간을 한 번에 건너뛰면 안정적.

## 변형과 확장

### median-of-medians (최악 O(n))

5개씩 묶어 각 그룹 중앙값 → 그 중앙값들의 중앙값을 피벗으로. 항상 일정 비율을 버려 **최악 `O(n)`**.
상수가 커 실전에선 무작위 퀵셀렉트가 보통 더 빠르다.

### top-k / 부분 정렬

k번째를 찾으면 그보다 작은(큰) k개도 파티션 경계로 얻는다 — "가장 큰 k개" 를 `O(n)` 에(순서 무관).

### nth_element

C++ `std::nth_element` 이 바로 이 알고리즘(인트로셀렉트: 퀵셀렉트 + median-of-medians 폴백).
