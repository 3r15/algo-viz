## 어떤 문제인가

[퀵 정렬](#/algo/quick-sort)은 빠르지만 **약점**이 있다. 같은 값이 많으면(예: `[3,3,3,3,3]`)
보통의 2-way 파티션은 같은 값들을 계속 한쪽으로 밀어, 최악 `O(n²)` 로 퇴화한다.

```
[3, 3, 3, 3, 3]  피벗 3
2-way: 3 == 피벗 인 것들을 어디로? → 한쪽으로 쏠려 파티션이 균형을 잃는다
```

> 피벗과 **같은 값**을 따로 모아 두면, 걔네는 이미 제자리 아닐까? 다시 정렬할 필요가 없다.

## 손으로 해보기

**네덜란드 국기 분할** — 배열을 세 색(구간)으로 나눈다: **작은 것(<) · 같은 것(=) · 큰 것(>)**.

기본 입력 `[5, 3, 8, 3, 1, 3, 9, 5]` (3이 세 번, 5가 두 번)로 가 보자. 피벗 = `a[0]` = 5.

### 포인터 셋: lt, i, gt

```
lt = 왼쪽 경계(= 구간의 시작),  gt = 오른쪽 경계(= 구간의 끝),  i = 현재 보는 위치
[ <5 | =5 | 아직 | >5 ]
      lt        i    gt
```

`i` 를 옮기며 `a[i]` 를 피벗과 비교한다:
- `a[i] < 5` → `a[lt]` 와 교환, `lt++, i++` (작은 것 왼쪽으로)
- `a[i] > 5` → `a[gt]` 와 교환, `gt--` (큰 것 오른쪽으로, i 는 그대로 — 바뀐 값 다시 봐야)
- `a[i] == 5` → `i++` (가운데 = 구간에 그냥 둠)

### 훑어 보기

```
[5,3,8,3,1,3,9,5] 피벗 5
i=1 a=3 <5 → 왼쪽   [3,5,8,3,1,3,9,5]
i=2 a=8 >5 → 오른쪽  [3,5,5,3,1,3,9,8] gt--
i=2 a=5 =5 → 가운데  i++
i=3 a=3 <5 → 왼쪽   [3,3,5,5,1,3,9,8] lt++
i=4 a=1 <5 → 왼쪽   [3,3,1,5,5,3,9,8] → 정리되며
… 결국  [ <5: 3,3,1,3 | =5: 5,5 | >5: 9,8 ]
```

### 같은 값 구간은 **확정**

`=5` 구간(`5,5`)은 **최종 위치**다 — 정렬돼도 5는 거기 그대로 있다. 그래서 **재귀에서 뺀다.**
`<5` 구간과 `>5` 구간만 다시 3-way 정렬한다.

```
sort3(<5 구간)   sort3(>5 구간)   ← =5 는 건드리지 않음
```

`[3,3,1,3]` 을 정렬하면 3이 또 세 개라 다시 `=3` 구간이 통째로 확정된다 — **중복이 많을수록 빨라진다.**

### 왜 중복에 강한가

같은 값을 한 번에 확정하니, 값의 종류가 `k` 개면 재귀 깊이가 사실상 `O(log k)`. 모두 같은 값이면
**한 번의 파티션으로 끝**(`O(n)`) — 2-way 의 `O(n²)` 와 대조적이다.

## 아이디어 쌓기

### 1단계 — 같은 값을 따로

피벗과 같은 값은 이미 제자리. 작은 것·큰 것과 분리한다.

### 2단계 — 세 구간, 세 포인터

lt/i/gt 로 <·=·> 를 유지하며 한 번 훑는다.

### 3단계 — 같은 구간 확정

`[lt..gt]` = 피벗. 최종 위치라 재귀 제외.

### 4단계 — 양옆만 재귀

`<` 구간과 `>` 구간만 3-way 로 다시.

## 코드로 옮기기

```cpp
void sort3(vector<int>& a, int lo, int hi) {
    if (lo >= hi) return;
    int pivot = a[lo];
    int lt = lo, gt = hi, i = lo + 1;
    while (i <= gt) {
        if (a[i] < pivot)      swap(a[lt++], a[i++]); // 작으면 왼쪽으로
        else if (a[i] > pivot) swap(a[i], a[gt--]);   // 크면 오른쪽으로
        else                   i++;                    // 같으면 가운데
    }
    // a[lt..gt] 는 피벗과 같음 → 최종 위치 확정
    sort3(a, lo, lt - 1);
    sort3(a, gt + 1, hi);
}
```

`>` 일 때만 `i` 를 **안 올린다** — `gt` 에서 가져온 값이 아직 안 본 값이라 다시 검사해야 한다.

## 자주 하는 실수

**`>` 교환 후 i 를 올린다.** `gt` 쪽에서 온 값은 미검사라 `i` 를 그대로 둬야 한다. `<` 교환은
`lt` 쪽에서 온 값이 이미 `<피벗`(지나온 것)이라 `i++` OK.

**같은 값 구간을 재귀에 포함한다.** `[lt..gt]` 는 확정. 재귀는 `[lo,lt-1]` 과 `[gt+1,hi]` 만.

**피벗 선택.** `a[lo]` 는 단순하지만 이미 정렬된 입력에서 최악. 무작위/median-of-three 로 완화.

**루프 조건.** `while (i <= gt)` — `gt` 도 포함해 검사. `i < gt` 로 하면 마지막 원소를 빠뜨린다.

## 스스로 확인하기

1. **세 구간(<파랑 · =초록 · >빨강)** 이 형성되는 것을 보자.
2. **`=피벗` 구간이 초록으로 확정**되고 재귀에서 빠지는 것을 보자.
3. **`>` 교환 시 i 가 안 올라가는 것**을 관찰하자.
4. **중복 3, 5** 가 각각 한 번에 확정되는 것을 보자.
5. 입력을 `3 3 3 3 3` 로 바꿔 보자 — **한 번의 파티션**으로 전부 확정(O(n)).
6. 입력을 `5 4 3 2 1` 로 바꿔 보자 — 중복이 없으면 일반 퀵 정렬처럼 동작.

퀵셀렉트로의 응용을 다룬다.
