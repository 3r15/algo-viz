## 어떤 문제인가

체스의 **나이트**는 "직선으로 2칸 + 직각으로 1칸" 을 뛴다. 그래서 이동 방향이 8가지다.

```
. × . × .
× . . . ×
. . ♞ . .
× . . . ×
. × . × .
```

나이트가 **모든 칸을 정확히 한 번씩** 밟는 경로를 만들 수 있을까?
이걸 **나이트 여행(Knight's Tour)** 이라 한다.

### 왜 어려운가

각 칸에서 갈 곳이 최대 8군데다. 25칸을 밟으려면

```
8 × 8 × 8 × … (24번)  ≈  4.7 × 10^21 가지
```

물론 대부분은 판 밖이거나 이미 밟은 칸이라 실제로는 훨씬 적지만,
**순진하게 백트래킹하면 `8×8` 판에서 사실상 끝나지 않는다.**

### 무엇이 문제인가 — 구석이 고립된다

```
♞ . . . .        (0,0) 에서 갈 수 있는 곳은 (1,2) 와 (2,1) — 딱 2곳
```

판 가운데 칸은 출입구가 8개인데, **구석은 2개**뿐이다. 출입구가 적은 칸을 뒤로 미루면,
그 칸으로 들어가는 통로가 다 막혀 **고립**된다. 그러면 물러나야 한다 — 아주 깊은 곳에서.

> 갈 곳이 적어서 위험한 칸을 **먼저** 처리하면 되지 않을까?

이게 **바른스도르프(Warnsdorff) 규칙**이다.

> 다음에 갈 후보 중 **거기서 또 갈 곳이 가장 적은 칸**부터 시도한다.

## 손으로 해보기

기본 입력 `5` — `5×5` 판이고 `(0,0)` 에서 출발한다.

### 1번째 — (0, 0)

구석이라 갈 곳이 둘뿐이다.

```
(1,2) 로 가면 → 거기서 갈 곳 5군데
(2,1) 로 가면 → 거기서 갈 곳 5군데
```

동점이다. 이 페이지는 동점일 때 **이동 번호가 작은 쪽**을 고른다(순수 함수로 만들기 위해).
`(1,2)` 로 간다.

### 2번째 — (1, 2)

갈 곳이 5군데인데, 그중 **출입구가 1개뿐인 칸**이 있다.

```
(0,4) 로 가면 → 거기서 갈 곳 1군데    ← 가장 위험하다. 먼저 간다
```

`(0,4)` 는 구석 근처라 통로가 하나다. **지금 안 가면 영원히 못 간다.**

### 3번째 — (0, 4)

갈 곳이 1군데다. 선택의 여지가 없다. → `(2,3)`

### 이 패턴이 반복된다

```
출입구 많은 칸(5곳) → 출입구 1곳인 칸으로 → 다시 많은 칸 → 다시 1곳인 칸 → …
```

플레이어에서 스텝을 넘기면 **"후보 N곳, 그중 출입구가 가장 적은 곳(M곳)부터"** 가
번갈아 5곳 ↔ 1곳으로 오가는 것이 보인다. 위험한 칸을 계속 먼저 처리하는 것이다.

### 완성된 경로

```
   1  20   9  14   3
  10  15   2  19  24
  21   8  23   4  13
  16  11   6  25  18
   7  22  17  12   5
```

**이동 25번, 물러남 0번.** 한 번도 되돌아가지 않고 한 번에 찾았다.

숫자를 1부터 따라가 보자. `1 → 2` 는 `(0,0) → (1,2)`, 나이트 이동이다.
`24 → 25` 는 `(1,4) → (3,3)` — 이것도 나이트 이동이다. 모든 연속 번호가 그렇다.

### 규칙이 없으면 어떻게 되나

바른스도르프 없이 **이동 순서를 고정**해 놓고 백트래킹하면, `5×5` 도 수천 번 물러난다.
`8×8` 이면 실용적으로 끝나지 않는다.

**순서만 바꿨는데** 물러남이 0이 됐다. 탐색 자체는 똑같은 백트래킹이다.

## 아이디어 쌓기

### 1단계 — 골격은 백트래킹이다

```
지금 칸에 번호를 적는다
전부 밟았으면 성공
아직이면: 갈 수 있는 칸을 하나씩 시도한다
전부 실패하면 번호를 지우고 물러난다
```

[N-퀸](#/algo/n-queens)과 완전히 같은 세 줄 구조다 — 놓고, 맡기고, 실패하면 거둔다.

### 2단계 — 문제는 순서다

백트래킹은 후보를 **어떤 순서로 보든** 결국 답을 찾는다(완전하다).
하지만 **얼마나 빨리** 찾을지는 순서가 결정한다.
나쁜 순서로 시작하면 잘못된 가지를 깊이 파고들었다가 되돌아온다.

### 3단계 — 위험한 칸을 먼저

`degree(r, c)` = 그 칸에서 **아직 안 밟은** 칸으로 갈 수 있는 가짓수.

```
degree 가 작다  =  통로가 곧 막힌다  =  지금 안 가면 고립된다
```

그래서 **degree 오름차순**으로 후보를 시도한다. "가장 제약이 심한 것부터" 라는 원칙이며,
스도쿠에서 후보가 가장 적은 칸부터 채우는 것과 같은 발상이다.

### 4단계 — degree 는 매번 다시 센다

이미 밟은 칸은 통로에서 빠지므로 `degree` 는 **계속 줄어든다.**
그래서 미리 계산해 둘 수 없고, 매 단계에서 다시 센다. 한 번 세는 데 8번만 보면 되니 싸다.

### 5단계 — 그래도 백트래킹은 남겨 둔다

바른스도르프는 **휴리스틱**이다. "보통 잘 된다" 뿐이고 **보장이 아니다.**
실제로 어떤 판·어떤 시작점에서는 막힌다. 그래서 물러나는 코드를 지우면 안 된다.

## 코드로 옮기기

```cpp
bool tour(int r, int c, int step, int total) {
    order[r][c] = step;                     // ← 1단계: 번호를 적는다
    if (step == total) return true;         //    전부 밟았다
    for (int k : movesByDegree(r, c)) {     // ← 3단계: 위험한 칸부터
        int nr = r + dr[k], nc = c + dc[k];
        if (!inside(nr, nc) || order[nr][nc]) continue;
        if (tour(nr, nc, step + 1, total)) return true;
    }
    order[r][c] = 0;                        // ← 5단계: 물러난다
    return false;
}

int degree(int r, int c) {                  // ← 4단계: 매번 다시 센다
    int count = 0;
    for (int k = 0; k < 8; k++) {
        int nr = r + dr[k], nc = c + dc[k];
        if (inside(nr, nc) && !order[nr][nc]) count++;
    }
    return count;
}
```

`order[r][c]` 가 **두 가지 일을 겸한다** — 방문 여부(0인지)와 방문 순서(몇 번째인지).
그래서 `visited` 배열이 따로 필요 없고, 물러날 때 `0` 으로 되돌리면 그만이다.

이동 8방향을 두 배열로 두는 것이 관례다.

```cpp
int dr[8] = {-2,-2,-1,-1, 1, 1, 2, 2};
int dc[8] = {-1, 1,-2, 2,-2, 2,-1, 1};
```

## 자주 하는 실수

**`order[r][c] = 0` 을 빼먹는다.** 물러날 때 번호를 지우지 않으면 그 칸이 영원히
"밟은 칸" 으로 남아 다른 경로에서 쓸 수 없다. 답이 있는데도 못 찾는다.

**`step` 을 0부터 센다.** `order` 에서 0이 "안 밟음" 을 뜻하므로 **1부터** 세야 한다.
0부터 세면 출발점이 "안 밟은 칸" 으로 취급된다.

**판 경계 검사를 잊는다.** `dr`, `dc` 를 더하면 쉽게 판 밖으로 나간다.
`inside(nr, nc)` 를 `order` 접근 **앞에** 두어야 한다(`&&` 의 단축 평가 순서가 중요하다).

**degree 를 미리 계산해 캐시한다.** 4단계의 문제. 밟을 때마다 이웃들의 degree 가 줄어든다.
고정값을 쓰면 규칙이 무의미해진다.

**바른스도르프가 항상 된다고 믿는다.** 휴리스틱이다. 백트래킹을 지우면 어떤 입력에서 실패한다.

**닫힌 여행(closed tour)과 헷갈린다.** 마지막 칸에서 **출발점으로 돌아올 수 있는** 경로를
닫힌 여행이라 한다. 더 어려운 조건이고, `5×5` 에는 닫힌 여행이 **존재하지 않는다**
(이 페이지가 찾는 것은 열린 여행이다).

## 스스로 확인하기

1. **스텝 1** 을 보자. `(0,0)` 은 구석이라 후보가 **2곳**뿐이다. 흰 테두리로 두 칸이 표시된다.
2. **스텝 2 → 3** 을 보자. 후보 5곳 중 **출입구가 1곳인 `(0,4)`** 로 간다.
   "많은 곳" 에서 "위험한 곳" 으로 가는 것이 규칙의 핵심이다.
3. **후보 수가 5 ↔ 1 로 번갈아 나오는 것**을 확인하자. 위험한 칸을 계속 먼저 처리하고 있다.
4. **경로 선(밝은 선)** 이 판을 어떻게 채워 가는지 보자. 구석과 가장자리를 먼저 훑는다.
5. **물러남이 0번**인 것을 마지막 스텝에서 확인하자.
6. 입력을 `6` 으로 바꿔 보자. 36칸을 37스텝에 끝낸다 — **여기서도 물러남이 없다.**
7. 입력을 `7` 로 바꿔 보자. 49칸을 50스텝. 판이 커져도 스텝이 칸 수에 비례한다 —
   휴리스틱이 통하는 동안은 사실상 `O(n²)` 이다.
8. 입력을 `4` 로 바꿔 보자. **1200스텝까지 찾다가 중단한다.**
   `4×4` 는 나이트 여행이 존재하지 않고, "없음" 을 증명하려면 전수 탐색이라 폭발한다.
   백트래킹의 최악을 그대로 보게 된다.
9. 입력을 `3` 으로 바꿔 보자. 32스텝에 "해답이 없다" 로 끝난다 —
   가운데 칸에서 나이트가 갈 곳이 없어 금방 소진된다.

아래 **깊이 보기**에서는 나이트 여행이 존재하는 판 크기의 조건(슈벵크 정리)과
바른스도르프가 왜 보장이 아닌지, 그리고 이 문제가 해밀턴 경로와 어떻게 이어지는지 다룬다.
