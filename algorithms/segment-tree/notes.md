## 한눈에

배열의 **구간 질의**(구간 합·최솟값·최댓값…)와 **원소 갱신**을 둘 다 `O(log n)` 에 처리한다.

배열을 반씩 쪼갠 구간들을 이진 트리의 노드로 삼고, 각 노드에 **자기 구간의 답**을 저장한다.
어떤 구간을 물어도 **O(log n)개의 노드로 정확히 덮을 수 있다**는 것이 이 자료구조의 전부다.

- 질의 O(log n) · 갱신 O(log n) · 공간 O(n)
- **모노이드**(결합법칙 + 항등원)면 무엇이든 얹을 수 있다 — 합, min, max, gcd, 행렬곱…

## 동작 원리

이 페이지는 **반복(iterative) 버전**을 쓴다. 리프 개수를 2의 거듭제곱 `sz` 로 올려
완전 이진 트리를 만들면 인덱스 규칙이 아주 단순해진다.

```
t[1]        = 루트 (배열 전체)
t[i] 의 자식 = t[2i], t[2i+1]
t[sz + i]   = a[i]              ← 리프
```

`n`이 2의 거듭제곱이 아니면 남는 리프는 **항등원**(합이면 0, min이면 +∞)으로 채운다.
항등원이므로 답에 아무 영향을 주지 않는다.

### build — 아래에서 위로 한 번

```cpp
for (int i = 0; i < n; i++)  t[sz + i] = a[i];      // 리프
for (int i = sz - 1; i >= 1; i--)                    // 내부 노드
    t[i] = t[2*i] + t[2*i + 1];
```

`i`를 큰 쪽에서 작은 쪽으로 훑으면 자식(`2i`, `2i+1` > `i`)이 항상 먼저 계산돼 있다.

### query — 아래에서 위로 올라가며 줍는다

`[l, r)` 반열린 구간을 리프 인덱스로 옮긴 뒤(`l += sz, r += sz`), 매 레벨에서 이렇게 한다.

```cpp
for (l += sz, r += sz; l < r; l >>= 1, r >>= 1) {
    if (l & 1) res += t[l++];      // l 이 오른쪽 자식 → 이 노드는 부모에 통째로 안 들어감
    if (r & 1) res += t[--r];      // r 이 오른쪽 자식 → 왼쪽 형제를 주워야 함
}
```

**왜 홀수(= 오른쪽 자식)일 때만 줍는가?**
`l`이 짝수면 `l`은 왼쪽 자식이라 그 부모가 `[l, l+2)` 를 전부 담고 있다. 굳이 지금 줍지 않고
한 레벨 올라가 부모를 보면 된다. 반면 `l`이 홀수면 부모에는 구간 밖인 왼쪽 형제도 섞여 있으므로,
**지금 이 노드를 확정해 두고 오른쪽으로 한 칸 비켜야** 한다. `r` 쪽은 대칭이다.

시각화에서 채택된 노드가 초록으로 남는다. 매 레벨에서 **양쪽 합쳐 최대 2개**만 초록이 되는 것을
확인해 보자.

### update — 리프에서 루트까지 한 줄만

```cpp
i += sz;  t[i] = v;
for (i >>= 1; i >= 1; i >>= 1)
    t[i] = t[2*i] + t[2*i + 1];
```

`a[i]` 를 담당 구간에 포함하는 노드는 **리프에서 루트까지의 경로 위 노드들뿐**이다.
그 경로의 길이가 트리 높이 `log₂ sz` 다.

## 정확성

### 트리 불변식

> 모든 노드 `i`에 대해 `t[i]` = 노드 `i`가 담당하는 구간의 원소들을 연산으로 접은 값.

build에서 리프는 정의상 참이고, 내부 노드는 자식들이 이미 참일 때 계산되므로 귀납으로 참이다.
update는 값이 바뀐 리프의 **조상만** 다시 계산하는데, 그 외의 노드는 담당 구간에 `i`가 없어
값이 바뀌지 않으므로 불변식이 유지된다.

### query가 구간을 정확히 분해한다

> 반복 루프가 채택하는 노드들의 담당 구간은 **서로 겹치지 않고**, 합집합이 정확히 `[l, r)` 이다.

**불변식**: 루프의 각 시점에 "아직 처리되지 않은 구간"은 현재 레벨에서 `[l, r)` 에 대응하고,
이미 채택한 노드들이 원래 구간의 나머지를 정확히 덮는다.

- `l & 1` 일 때 `t[l]` 을 채택하고 `l++` → 채택한 구간이 남은 범위에서 정확히 빠진다.
- `r & 1` 일 때 `--r` 후 `t[r]` 채택 → 마찬가지.
- 그다음 `l >>= 1, r >>= 1` 는 남은 범위를 한 레벨 위 좌표로 옮기는 것이다.
  이 시점에 `l`, `r` 은 모두 짝수이므로 부모 좌표로의 변환이 정확하다.

`l >= r` 이 되면 남은 범위가 비어 종료한다. 채택 시점마다 범위에서 뺀 뒤 진행하므로
겹침이 없다. ∎

### 왜 O(log n)개의 노드로 충분한가

각 레벨에서 `l` 쪽과 `r` 쪽에서 **각각 최대 하나**씩만 채택된다(위 코드의 두 `if`).
레벨 수가 `log₂ sz + 1` 이므로 채택 노드는 최대 `2 log₂ sz` 개다. ∎

### 연산에 필요한 조건 — 모노이드

노드를 합칠 때 `(A ∘ B) ∘ C = A ∘ (B ∘ C)` 여야 트리 모양대로 접어도 같은 답이 나온다.
빈 구간을 위한 **항등원** `e` 도 필요하다(패딩 리프와 `res` 초기값).

```
합:   (+, 0)        min:  (min, +∞)      gcd:  (gcd, 0)
max:  (max, -∞)     행렬곱: (×, 단위행렬)
```

**교환법칙은 필요 없다.** 행렬곱처럼 순서가 중요한 연산도 되지만, 그때는 `res` 에 붙이는
좌우 순서를 지켜야 한다(위 반복 버전은 왼쪽 결과와 오른쪽 결과를 따로 모아 마지막에 합쳐야 한다).

**역원은 필요 없다.** 이것이 [희소 배열](#/algo/sparse-table)이나 펜윅 트리와의 결정적 차이다.
`min` 은 역원이 없어 "빼기"가 불가능한데도 세그먼트 트리에서는 갱신이 된다.

## 복잡도

| 연산 | 시간 | 근거 |
|---|---|---|
| build | **O(n)** | 노드 수 `2·sz - 1 = O(n)`, 각 노드 O(1) |
| query | **O(log n)** | 레벨당 최대 2개 노드 |
| update | **O(log n)** | 리프→루트 경로 길이 |
| 공간 | **O(n)** | `2·sz < 4n` |

build가 `O(n log n)` 이 아니라 **`O(n)`** 인 점을 자주 놓친다. 노드 하나당 덧셈 한 번씩,
노드가 `O(n)`개이므로 전체가 선형이다. (원소를 하나씩 `update` 로 넣으면 `O(n log n)` 이 된다.)

`sz` 는 `n`을 2의 거듭제곱으로 올린 값이라 최악에 `2n` 미만이고, 배열 크기는 `2·sz < 4n` 이다.
재귀 버전에서 흔히 쓰는 `4n` 이라는 크기가 여기서 나온다.

## 구현 노트

**반복형 vs 재귀형.** 이 페이지는 반복형이다. 짧고 빠르고 상수가 작다. 하지만
**구간 갱신(lazy propagation)** 을 얹으려면 위에서 아래로 내려가는 재귀형이 훨씬 자연스럽다.
lazy가 필요할 게 뻔하면 처음부터 재귀형으로 쓰자.

```cpp
// 재귀형 뼈대 — node 가 담당하는 구간은 [nodeLo, nodeHi], 질의 구간은 [l, r]
long long query(int node, int nodeLo, int nodeHi, int l, int r) {
    if (r < nodeLo || nodeHi < l) return 0;               // 완전히 벗어남 → 항등원
    if (l <= nodeLo && nodeHi <= r) return t[node];       // 완전히 포함 → 그대로
    int mid = (nodeLo + nodeHi) / 2;
    return query(2*node,     nodeLo,  mid,    l, r)
         + query(2*node + 1, mid + 1, nodeHi, l, r);
}
```

**반열린 vs 닫힌 구간.** 반복형은 `[l, r)` 반열린 구간이 압도적으로 편하다
(`l < r` 종료 조건, `r++` 없음). 재귀형은 `[l, r]` 닫힌 구간이 관례다.
**두 관례를 한 코드에 섞는 것이 이 자료구조 최대의 버그 원인이다.**

**오버플로**: 구간 합은 금방 `int` 를 넘는다. `n = 10⁵`, 값이 `10⁹` 이면 합이 `10¹⁴` 다.
합에는 `long long` 을 쓰자.

**패딩 리프의 항등원**: `min` 트리에서 남는 리프를 0으로 두면 답이 전부 0이 된다.
반드시 `INT_MAX` 같은 항등원으로 채워야 한다. 이 페이지의 합 트리는 항등원이 0이라
`assign(2*sz, 0)` 한 번으로 끝나는 것이다.

## 변형과 확장

- **지연 전파(lazy propagation)**: 구간 전체에 같은 값을 더하거나 대입하는 **구간 갱신**을
  O(log n)에 처리한다. 노드마다 "아직 자식에게 안 내려보낸 작업"을 들고 있는다.
- **펜윅 트리(BIT)**: 구간 합에 한정하면 코드가 훨씬 짧고 상수도 작다. 다만 역원이 있는
  연산에만 쓸 수 있어 `min` 에는 부적합하다.
- **머지 소트 트리**: 각 노드에 담당 구간의 **정렬된 배열**을 저장하면 "구간 안에서 `x`보다
  큰 원소 개수" 같은 질의를 O(log² n)에 답한다.
- **퍼시스턴트 세그먼트 트리**: 갱신할 때 경로 위 O(log n)개 노드만 새로 만들면 과거 버전이
  모두 보존된다. "구간에서 k번째 수" 문제의 표준 해법.
- **2D 세그먼트 트리 / 세그먼트 트리 위 이분 탐색**: 루트에서 자식 값을 보며 내려가면
  "합이 처음으로 `x`를 넘는 위치"를 O(log n)에 찾는다.
