## 어떤 문제인가

수강 신청을 한다고 하자. 과목마다 선수 과목이 있다.

```
자료구조 를 들으려면 → 프로그래밍기초 를 먼저 들어야 한다
알고리즘 을 들으려면 → 자료구조 를 먼저 들어야 한다
```

**어떤 순서로 들어야 모든 선수 조건을 만족하는가?**

이걸 그래프로 옮기면, 화살표가 "먼저 → 나중"을 뜻하는 **방향 그래프**가 된다.
문제는 정점을 한 줄로 세우되 **모든 화살표가 앞에서 뒤를 향하도록** 하는 것이다.

이런 나열을 **위상 순서(topological order)** 라고 한다.

> 순서가 항상 존재하지는 않는다. "A 를 들으려면 B, B 를 들으려면 A" 라면 영원히 시작할 수 없다.
> 그런 **사이클**이 있으면 위상 순서는 존재하지 않는다.

## 손으로 해보기

기본 그래프를 선수 과목표로 읽어 보자.

```
0 ──▶ 1 ──▶ 3 ──▶ 5
│           ▲     ▲
└──▶ 2 ──────┘    │
     └──▶ 4 ───────┘
```

간선: `0→1`, `0→2`, `1→3`, `2→3`, `2→4`, `3→5`, `4→5`

### 진입 차수를 센다

각 정점에 **"나를 가리키는 화살표 개수"** 를 적는다. 이게 **진입 차수**이고,
곧 "내가 기다려야 하는 선행 조건의 개수"다.

```
0: 0개   ← 아무도 안 가리킴 = 지금 당장 들을 수 있다
1: 1개   (0에서)
2: 1개   (0에서)
3: 2개   (1과 2에서)   ← 둘 다 끝나야 열린다
4: 1개   (2에서)
5: 2개   (3과 4에서)
```

### 규칙

> 진입 차수가 **0인 정점**을 아무거나 꺼내 순서에 넣는다.
> 그 정점이 걸어 잠그고 있던 조건들을 풀어 준다(가리키던 정점들의 차수를 1 줄인다).

### 따라가 보기

```
차수:  0:0  1:1  2:1  3:2  4:1  5:2
큐 [0]                                    ← 차수 0 인 것만

0 을 꺼낸다 → 순서 [0]
  0→1: 1의 차수 1→0  → 큐에 넣는다
  0→2: 2의 차수 1→0  → 큐에 넣는다
큐 [1, 2]     차수:  3:2  4:1  5:2

1 을 꺼낸다 → 순서 [0, 1]
  1→3: 3의 차수 2→1  → 아직 1 남았다. 안 넣는다
큐 [2]        차수:  3:1  4:1  5:2

2 를 꺼낸다 → 순서 [0, 1, 2]
  2→3: 3의 차수 1→0  → 이제 열렸다! 큐에 넣는다
  2→4: 4의 차수 1→0  → 큐에 넣는다
큐 [3, 4]     차수:  5:2

3 을 꺼낸다 → 순서 [0, 1, 2, 3]
  3→5: 5의 차수 2→1  → 아직
큐 [4]        차수:  5:1

4 를 꺼낸다 → 순서 [0, 1, 2, 3, 4]
  4→5: 5의 차수 1→0  → 열렸다!
큐 [5]

5 를 꺼낸다 → 순서 [0, 1, 2, 3, 4, 5]
큐 []  → 끝
```

**결과: `0 → 1 → 2 → 3 → 4 → 5`**

확인해 보자. 모든 간선이 앞→뒤인가? `0→1` ✓ `0→2` ✓ `1→3` ✓ `2→3` ✓ `2→4` ✓ `3→5` ✓ `4→5` ✓

> **정점 3을 주목하자.** 차수가 2였다가 `1` 을 처리할 때 1로, `2` 를 처리할 때 0이 됐다.
> **두 선행 조건이 모두 끝나야** 비로소 큐에 들어간다.

## 아이디어 쌓기

### 1단계 — 시작할 수 있는 곳이 반드시 있다

사이클이 없다면 **진입 차수가 0인 정점이 적어도 하나 있다.**

없다고 해 보자. 그러면 모든 정점에 들어오는 화살표가 있으니, 아무 정점에서나
화살표를 **거꾸로** 계속 따라갈 수 있다. 정점은 유한하니 언젠가 같은 정점을 두 번 만나고,
그 구간이 곧 사이클이다 — 사이클이 없다는 가정에 어긋난다.

### 2단계 — 하나 빼내도 성질이 유지된다

차수 0인 정점을 순서에 넣고 그래프에서 지우면, 남은 그래프도 여전히 사이클이 없다.
그러니 1단계를 다시 적용할 수 있다. **이걸 반복하면 전부 뽑힌다.**

### 3단계 — "지운다"를 차수 빼기로 대신한다

정점을 실제로 지우는 대신, 그 정점이 가리키던 정점들의 **차수를 1씩 줄인다.**
차수가 0이 되는 순간이 곧 "선행 조건이 모두 사라진" 순간이다.

### 4단계 — 사이클 판정이 공짜로 따라온다

각 정점은 차수가 0이 될 때만 큐에 들어간다. 그러니

> **순서의 길이가 정점 수보다 작다 ⟺ 끝내 차수가 0이 안 된 정점이 있다 ⟺ 사이클이 있다**

그리고 **남은 정점들이 곧 사이클에 얽힌 부분**이라, 디버깅에도 바로 쓸 수 있다.

## 코드로 옮기기

```cpp
vector<int> topoSort(vector<vector<int>>& adj, int n) {
    vector<int> indeg(n, 0), order;
    for (int u = 0; u < n; u++)
        for (int v : adj[u]) indeg[v]++;        // ← 진입 차수 세기
    queue<int> q;
    for (int v = 0; v < n; v++)
        if (indeg[v] == 0) q.push(v);           // ← 1단계: 시작점들
    while (!q.empty()) {
        int u = q.front(); q.pop();
        order.push_back(u);                     // ← 순서에 추가
        for (int v : adj[u])
            if (--indeg[v] == 0) q.push(v);     // ← 3단계: 차수를 줄이고 0이면 넣는다
    }
    if (order.size() < n) return {};            // ← 4단계: 사이클
    return order;
}
```

`--indeg[v] == 0` 이 한 줄에 두 가지를 한다. 먼저 차수를 1 줄이고,
그 결과가 0이면 큐에 넣는다.

### 왜 큐인가?

사실 **스택을 써도 된다.** 차수 0인 것 중 **아무거나** 꺼내면 되기 때문이다.
꺼내는 순서가 다르면 다른 위상 순서가 나오는데, 둘 다 정답이다.

**위상 순서는 보통 여러 개**다. 우선순위 큐를 쓰면 "사전순으로 가장 빠른 순서"를 얻는다 —
문제에서 자주 요구하는 조건이다.

## 자주 하는 실수

**차수를 세면서 동시에 큐에 넣는다.** 반드시 **다 센 뒤에** 넣어야 한다.
세는 중에 넣으면 아직 반영 안 된 간선 때문에 차수 0으로 오판한다.

**시작점을 하나만 넣는다.** 차수 0인 정점이 여럿일 수 있다.
하나만 넣으면 연결되지 않은 부분이 통째로 빠진다.

**무방향 그래프에 쓴다.** 간선 하나가 양방향이라 정점 2개만 있어도 서로를 가리킨다 =
사이클이다. 그래서 이 페이지는 **방향 옵션이 켜져 있어야만** 의미가 있다.

**화살표 방향을 반대로 만든다.** "A 가 B 의 선수 과목"을 `B→A` 로 그리면 순서가 뒤집힌다.
한 방향을 정해 주석으로 못 박아 두자. 이 페이지는 `A→B` = **"A 먼저, 그다음 B"** 다.

## 스스로 확인하기

1. **정점 라벨을 보자.** 남은 진입 차수가 표시되고, 순서가 정해지면 `#0`, `#1` 로 바뀐다.
2. **정점 3을 주목하자.** 차수가 2 → 1 → 0 으로 두 번에 걸쳐 줄어든다.
   차수가 0이 되는 그 순간에만 큐에 들어간다.
3. **큐 표시**를 보자. 큐에 든 것들은 전부 "지금 당장 처리 가능한" 정점들이다.
4. 편집기에서 **`5 → 0` 간선을 추가**해 사이클을 만들어 보자.
   실행하면 "0/6 개만 나왔다 — 남은 정점 [...] 은 서로를 기다리는 사이클" 이라고 알려 준다.
5. 간선 `2→3` 을 지우고 실행해 보자. 정점 3의 차수가 1이 되어 순서가 달라진다.

DAG 위의 DP 같은 응용을 다룬다.
