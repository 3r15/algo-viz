## 한눈에

**변하지 않는 배열**에 대해 "구간 `[l, r]`의 최솟값"을 묻는 질문에 **O(1)** 로 답한다.
대신 `O(n log n)` 시간·공간의 전처리가 필요하고, **배열이 바뀌면 통째로 다시 만들어야 한다.**

핵심 아이디어는 **배가(doubling)** 다. 길이 1짜리 답에서 길이 2짜리 답을, 길이 2에서 길이 4를…
2의 거듭제곱 길이 구간의 답만 미리 모두 계산해 둔다.

- 전처리 O(n log n) · 질의 **O(1)** · 갱신 **불가**
- **멱등(idempotent)** 연산에만 쓸 수 있다 — min, max, gcd, AND, OR ○ / **합, 곱 ✗**

## 동작 원리

표의 정의는 딱 한 줄이다.

```
st[k][i] = a[i .. i + 2^k - 1] 의 최솟값        (길이 2^k 구간)
```

`k = 0` 행은 길이 1 구간이므로 배열 그 자체다. 그다음부터는 **길이 2^(k-1) 구간 두 개를
이어 붙여** 길이 2^k 구간을 만든다.

```
st[k][i] = min( st[k-1][i] , st[k-1][i + 2^(k-1)] )

  i                    i+2^(k-1)              i+2^k
  ├──── 앞 절반 ────────┼──── 뒤 절반 ─────────┤
       st[k-1][i]            st[k-1][i+2^(k-1)]
```

### 질의: 겹쳐도 되는 두 구간으로 덮는다

길이 `len = r - l + 1` 인 구간을 딱 두 번의 조회로 답한다.

```
k = ⌊log₂(len)⌋
answer = min( st[k][l] , st[k][r - 2^k + 1] )
```

앞에서 `2^k` 칸, 뒤에서 `2^k` 칸을 가져온다. 이 두 구간은 **겹칠 수 있지만** 상관없다.

```
l                                         r
├─────────────── len ──────────────────────┤
├──── 2^k ────┤                                  ← st[k][l]
              ├──── 겹침 ────┤
        ├──────────── 2^k ───────────────────┤   ← st[k][r-2^k+1]
```

## 정확성

### 표가 올바르다 — `k`에 대한 귀납

`k = 0`: `st[0][i] = a[i]` 는 길이 1 구간의 최솟값이므로 참이다.

`k-1`까지 참이라고 하자. 구간 `[i, i+2^k-1]` 은 `[i, i+2^(k-1)-1]` 과
`[i+2^(k-1), i+2^k-1]` 로 **빈틈없이 정확히 이등분**된다. 귀납 가정에 의해 두 조각의
최솟값이 각각 `st[k-1][i]`, `st[k-1][i+2^(k-1)]` 이고, 집합의 분할에 대해
`min(A ∪ B) = min(min A, min B)` 이므로 `st[k][i]` 도 참이다. ∎

### 질의가 올바르다

`k = ⌊log₂(len)⌋` 의 정의에서 `2^k ≤ len < 2^(k+1)` 이다. 두 가지를 보이면 된다.

**(1) 두 구간이 `[l, r]` 을 벗어나지 않는다.**
- 앞 구간의 끝 `l + 2^k - 1 ≤ l + len - 1 = r` ✓
- 뒤 구간의 시작 `r - 2^k + 1 ≥ r - len + 1 = l` ✓

**(2) 두 구간의 합집합이 `[l, r]` 전체를 덮는다.**
빈틈이 없으려면 앞 구간의 끝이 뒤 구간의 시작 바로 앞 이상이어야 한다.

```
l + 2^k - 1  ≥  (r - 2^k + 1) - 1
⟺  2·2^k  ≥  r - l + 1 = len
⟺  2^(k+1) ≥ len                    ← k 의 정의에서 참
```

따라서 두 구간의 합집합은 정확히 `[l, r]` 이다.

**(3) 겹쳐도 답이 변하지 않는다.**
겹치는 원소는 두 번 계산되지만, `min` 은 **멱등**이다.

```
min(x, x) = x
```

그래서 중복 계산이 답을 바꾸지 못한다. ∎

> **이 마지막 조건이 희소 배열의 적용 범위를 결정한다.**
> 구간 **합**에는 쓸 수 없다. `sum(x, x) = 2x ≠ x` 이므로 겹치는 부분이 두 번 더해진다.
> 합·곱처럼 멱등이 아닌 연산에는 [세그먼트 트리](#/algo/segment-tree)나 펜윅 트리를 쓴다.

## 복잡도

| | 시간 | 공간 |
|---|---|---|
| 전처리(build) | O(n log n) | O(n log n) |
| 질의(query) | **O(1)** | — |
| 갱신(update) | **불가** (전체 재구축 O(n log n)) | — |

전처리는 `⌊log₂ n⌋ + 1` 개의 행 각각에 대해 최대 `n`개 칸을 O(1)에 채우므로
`Σ_k (n - 2^k + 1) < n log n` 이다.

질의는 `log2` 한 번과 표 조회 두 번, 비교 한 번 — **입력 크기와 완전히 무관한 상수 시간**이다.

### 세그먼트 트리와 비교

| | 희소 배열 | 세그먼트 트리 |
|---|---|---|
| 질의 | **O(1)** | O(log n) |
| 갱신 | 불가 | **O(log n)** |
| 공간 | O(n log n) | **O(n)** |
| 연산 조건 | 멱등 + 결합 | 결합(모노이드)이면 무엇이든 |

**배열이 절대 안 바뀌고 질의가 아주 많다면** 희소 배열이, **갱신이 섞여 있거나 합이 필요하면**
세그먼트 트리가 답이다.

## 구현 노트

**`log2` 를 부동소수로 계산하지 마라.** `(int)log2(x)` 는 큰 `x`에서 반올림 오차로 1 어긋날 수 있다.
로그 테이블을 미리 정수 연산으로 만들어 두는 것이 표준이다.

```cpp
LOG[1] = 0;
for (int i = 2; i <= n; i++) LOG[i] = LOG[i / 2] + 1;   // ⌊log₂ i⌋
```

C++20 이라면 `std::bit_width(x) - 1` 또는 `31 - __builtin_clz(x)` 도 쓸 수 있다.
이 페이지의 생성기도 부동소수 대신 비트 시프트로 `⌊log₂⌋` 를 구한다.

**메모리 레이아웃**: `st[k][i]` 순서(레벨이 바깥)로 잡아야 build 루프가 캐시를 순차적으로 읽는다.
`st[i][k]` 로 뒤집으면 같은 복잡도인데도 눈에 띄게 느려진다.

**닫힌 구간 vs 반열린 구간**: 이 구현은 `[l, r]` **닫힌 구간**이다. `r - 2^k + 1` 의 `+1` 이
그 증거다. 반열린 `[l, r)` 로 쓰면 `k = ⌊log₂(r-l)⌋`, 두 번째 조회가 `st[k][r - 2^k]` 가 된다.
**여기서 off-by-one 이 가장 많이 난다.** 한 가지 관례를 정해 끝까지 밀고 가자.

## 변형과 확장

- **분리 희소 배열(disjoint sparse table)**: 구간을 겹치지 않게 나누는 다른 배치를 쓰면
  **멱등이 아닌 결합 연산(합, 곱, 행렬곱)도 O(1) 질의**가 가능하다. 전처리는 여전히 O(n log n).
- **2D 희소 배열**: `st[kr][kc][i][j]` 로 확장하면 부분 행렬의 최솟값을 O(1)에 얻는다.
  전처리 O(nm log n log m).
- **LCA에 응용**: 트리의 오일러 투어를 만들면 LCA가 구간 최솟값 문제(RMQ)로 바뀐다.
  희소 배열을 얹으면 **LCA 질의가 O(1)** 이 된다([이진 상승](#/algo/binary-lifting)의 O(log n)보다 빠르다).
- **선형 전처리 RMQ**: 블록 분할 + 희소 배열을 결합하면 `O(n)` 전처리 / `O(1)` 질의도 가능하다
  (Fischer–Heun). 이론적으로 최적이지만 상수가 커서 실전에서는 잘 안 쓴다.
