## 어떤 문제인가

배열이 하나 있고, **절대 바뀌지 않는다.** 대신 이런 질문이 아주 많이 들어온다.

```
"3번부터 7번까지 중 가장 작은 값은?"
"1번부터 5번까지 중 가장 작은 값은?"
...   질의가 10만 번
```

매번 훑으면 질의 하나에 O(n), 총 `10만 × 10만 = 100억` 번이다. 안 된다.

[세그먼트 트리](#/algo/segment-tree)를 쓰면 질의당 O(log n) 이라 훨씬 낫다.
그런데 **배열이 안 바뀐다는 조건**을 쓰면 더 줄일 수 있다.

> 갱신이 없다면, 미리 더 많이 계산해 둬도 되지 않을까?
> **질의를 O(1) 로 만들 수는 없을까?**

## 손으로 해보기

`a = [5, 2, 9, 1, 5, 6, 3, 8]`

### 모든 구간을 미리 계산하면?

구간이 `n²/2` 개라 `n = 10만` 이면 50억 칸. 메모리가 터진다.

### 2의 거듭제곱 길이만 계산하면?

길이 1, 2, 4, 8 짜리 구간만 미리 계산해 두자. 표 이름은 `st` 다.

```
st[k][i] = a[i] 부터 시작하는 길이 2^k 구간의 최솟값
```

**k = 0 (길이 1)** — 그냥 배열 그 자체다.

```
st[0]:  5  2  9  1  5  6  3  8
```

**k = 1 (길이 2)** — 길이 1짜리 둘을 합친다.

```
st[1][0] = min(a[0], a[1]) = min(5,2) = 2
st[1][1] = min(a[1], a[2]) = min(2,9) = 2
st[1][2] = min(a[2], a[3]) = min(9,1) = 1
...
st[1]:  2  2  1  1  5  3  3   (마지막 칸은 범위 밖)
```

**k = 2 (길이 4)** — 길이 2짜리 둘을 합친다.

```
st[2][0] = min(st[1][0], st[1][2]) = min(2, 1) = 1
           └ a[0..1] ┘  └ a[2..3] ┘   합쳐서 a[0..3]
st[2]:  1  1  1  1  3
```

**k = 3 (길이 8)**

```
st[3][0] = min(st[2][0], st[2][4]) = min(1, 3) = 1
st[3]:  1
```

표 크기는 `log n × n` — `n = 10만` 이면 약 170만 칸. 충분히 감당된다.

### 질의: [1, 6] 의 최솟값은?

길이가 `6 - 1 + 1 = 6` 이다. 6은 2의 거듭제곱이 아니다. 어떻게 하나?

**두 개의 길이 4짜리 구간으로 덮는다.**

```
        1  2  3  4  5  6        ← 원하는 구간 [1,6]
       ├──────────┤              st[2][1] = a[1..4] 의 최솟값 = 1
             ├──────────┤        st[2][3] = a[3..6] 의 최솟값 = 1
       └── 겹침 ──┘

답 = min(1, 1) = 1
```

**두 구간이 겹친다.** 앞에서 4칸, 뒤에서 4칸을 가져오니 `4 + 4 = 8 > 6` 이라
2칸이 두 번 계산된다.

### 겹쳐도 되는 이유

`min` 은 같은 값을 두 번 봐도 답이 안 바뀐다.

```
min(x, x) = x
```

이런 성질을 **멱등(idempotent)** 이라고 한다. `min`, `max`, `gcd` 가 그렇다.

> **합에는 이 방법을 못 쓴다!** `sum(x, x) = 2x ≠ x` 라서 겹친 부분이 두 번 더해진다.
> 합이 필요하면 [세그먼트 트리](#/algo/segment-tree)로 가야 한다.

## 아이디어 쌓기

### 1단계 — 표의 의미를 정한다

```
st[k][i] = a[i .. i + 2^k - 1] 의 최솟값
```

`k` 는 "길이의 지수"다. `k=0` 이면 길이 1, `k=3` 이면 길이 8.

### 2단계 — 배가(doubling): 절반 두 개를 이어 붙인다

길이 `2^k` 구간은 길이 `2^(k-1)` 구간 **두 개**로 정확히 반씩 나뉜다.

```
   i                    i + 2^(k-1)              i + 2^k
   ├──── 앞 절반 ────────┼──── 뒤 절반 ─────────┤
        st[k-1][i]            st[k-1][i + 2^(k-1)]

st[k][i] = min( 위 둘 )
```

칸 하나를 채우는 데 **비교 한 번**이다. 표 전체가 `n log n` 칸이니 build 가 `O(n log n)`.

### 3단계 — 질의는 항상 두 조각이면 된다

길이 `len` 인 구간을 덮으려면 어떤 `k` 를 쓰면 될까?

```
k = ⌊log₂(len)⌋      →  2^k ≤ len < 2^(k+1)
```

이 `k` 로 잡으면 다음 두 가지가 동시에 성립한다.

- **밖으로 안 나간다**: `2^k ≤ len` 이므로 앞 구간의 끝이 `r` 을 넘지 않는다
- **빈틈이 없다**: `2·2^k > len` 이므로 두 구간이 반드시 겹치거나 맞닿는다

```
answer = min( st[k][l],  st[k][r - 2^k + 1] )
              └앞에서 ┘   └── 뒤에서 ──┘
```

**표 조회 두 번. 구간 길이와 상관없이 O(1)** 이다.

### 4단계 — 갱신은 포기한다

원소 하나만 바뀌어도 그 원소를 포함하는 표의 칸이 전부 틀어진다.
결국 표를 **통째로 다시** 만들어야 한다.

그래서 이 자료구조는 **정적 배열 전용**이다. 그 대신 질의가 O(1) 이다.

## 코드로 옮기기

```cpp
int st[LOG][MAXN];                 // st[k][i] = a[i .. i+2^k-1] 의 최솟값

void build(vector<int>& a) {
    int n = a.size();
    for (int i = 0; i < n; i++)
        st[0][i] = a[i];                                   // ← k=0: 길이 1
    for (int k = 1; (1 << k) <= n; k++)                    // ← 2단계: 배가
        for (int i = 0; i + (1 << k) <= n; i++)
            st[k][i] = min(st[k-1][i], st[k-1][i + (1 << (k-1))]);
}

int query(int l, int r) {          // [l, r] 닫힌 구간
    int k = log2(r - l + 1);                               // ← 3단계
    return min(st[k][l], st[k][r - (1 << k) + 1]);
}
```

`(1 << k)` 는 `2^k` 다. 비트 시프트가 거듭제곱보다 훨씬 빠르고 정확하다.

바깥 루프가 반드시 `k` 여야 한다. `k-1` 층이 **전부** 완성돼야 `k` 층을 만들 수 있기 때문이다.

### 세그먼트 트리와 비교

| | 희소 배열 | [세그먼트 트리](#/algo/segment-tree) |
|---|---|---|
| 질의 | **O(1)** | O(log n) |
| 갱신 | **불가** | O(log n) |
| 공간 | O(n log n) | **O(n)** |
| 되는 연산 | min/max/gcd (멱등) | 합 포함 **아무거나** |

**배열이 안 바뀌고 질의가 많다** → 희소 배열.
**갱신이 있거나 합이 필요하다** → 세그먼트 트리.

## 자주 하는 실수

**합에 쓴다.** ★ 겹치는 부분이 두 번 더해져 틀린다. 조용히 틀리는 종류의 버그다.

**`log2` 를 부동소수로 계산한다.** `(int)log2(x)` 는 큰 `x` 에서 반올림 오차로 1 어긋난다.
정수로 미리 표를 만들어 두자.

```cpp
LOG[1] = 0;
for (int i = 2; i <= n; i++) LOG[i] = LOG[i/2] + 1;   // ⌊log₂ i⌋
```

**`st[i][k]` 로 인덱스를 뒤집는다.** 복잡도는 같지만 캐시 지역성이 나빠져 눈에 띄게 느려진다.
`st[k][i]` (레벨이 바깥) 순서를 지키자.

**닫힌 구간과 반열린 구간을 헷갈린다.** 이 코드는 `[l, r]` **닫힌** 구간이다.
`r - (1 << k) + 1` 의 `+1` 이 그 증거다.

## 스스로 확인하기

1. **표가 계단 모양으로 채워지는 것**을 보자. `k` 가 커질수록 유효한 칸이 줄어든다
   (길이 8짜리 구간은 시작점이 하나뿐이다).
2. **`k = 1` 행이 채워지는 과정**을 보자. 위 행의 두 칸(회색 강조)을 읽어 아래 행 한 칸을 만든다.
3. **질의 단계**에서 초록으로 표시되는 두 칸을 보자. 서로 **겹친다**는 걸 확인하자.
   그래도 답이 맞는 이유가 `min` 의 멱등성이다.
4. 입력을 `7 7 7 7` 처럼 전부 같게 넣어 보자. 표가 전부 같은 값으로 채워진다.
5. 길이를 바꿔 가며 표의 행 수(`K`)가 어떻게 변하는지 보자.
   `n = 8` 이면 4행, `n = 5` 면 3행이다.

아래 **깊이 보기**에서는 "두 구간이 정확히 덮는다"를 부등식으로 증명하고,
멱등이 아닌 연산에도 O(1) 질의를 가능하게 하는 **분리 희소 배열**을 소개한다.
