## 한눈에

여는 괄호를 스택에 쌓고, 닫는 괄호에서 스택 맨 위와 종류를 대조해 짝을 맞춘다.
끝에 스택이 비어 있으면 균형이다. **스택의 LIFO 성질이 그대로 문제의 답**이 되는 대표 예다.

- **시간** `Θ(n)` — 글자마다 상수 작업 · **공간** `O(n)` — 최악에 모든 여는 괄호가 스택에
- 실패를 **즉시** 알아챈다(첫 불일치에서 멈춘다)
- "가장 최근에 연 것을 가장 먼저 닫는다" 는 **중첩 구조**의 보편적 뼈대다

**언제 쓰나** — 괄호 검사 자체보다, 그 뒤에 오는 것들의 **입구**로 중요하다.
수식 파싱, HTML/XML 태그 검증, 컴파일러의 구문 분석, 편집기의 괄호 하이라이트가
모두 이 스택 골격 위에 있다.

**언제 안 쓰나** — 괄호가 **한 종류**뿐이면(`(` 만) 스택 없이 카운터 하나로 `O(1)` 공간에 된다.
정규식으로는 **풀 수 없다** — 임의 깊이의 중첩은 정규 언어가 아니라 스택(문맥 자유 문법)이 필요하다.
이 사실 자체가 이론적으로 중요하다.

## 동작 원리

핵심은 자료구조 선택이다. 닫는 괄호를 만나면 **가장 최근에 연, 아직 안 닫힌 괄호**와 짝지어야 하고,
그것을 꺼내 주는 것이 정확히 스택이다.

```
for c in s:
    c 가 여는 괄호  →  push(c)
    c 가 닫는 괄호  →  스택이 비었거나 top 과 종류가 다르면 실패;  아니면 pop
    그 외          →  무시
끝:  스택이 비어 있으면 균형
```

### 실행 예

`(a+[b*c])`

```
(   push        스택: (
[   push         스택: ( [
]   top=[ 짝맞음, pop   스택: (
)   top=( 짝맞음, pop   스택: (비어 있음)
끝: 비어 있음 → 균형 ✓
```

### 스택 높이의 의미

> **관찰.** 문자열의 각 위치에서 스택의 높이는 그 지점의 **중첩 깊이** —
> 열렸지만 아직 안 닫힌 괄호의 개수와 같다.

```
(  a  +  [  b  *  c  ]  )
1  1  1  2  2  2  2  1  0      ← 스택 높이 = 깊이
```

높이가 **음수가 되려는 순간**(빈 스택에서 pop)이 "열린 적 없는 것을 닫음" 이고,
끝에 **높이가 0이 아니면** "안 닫은 것이 남음" 이다. 두 실패가 모두 이 높이로 설명된다.

## 정확성

세 종류가 섞인 일반 경우를 다룬다. `open(c)`/`close(c)` 를 여는·닫는 괄호,
`match(o, c)` 를 짝 판정이라 하자.

> **정의.** 문자열 `s` 가 **균형**이라는 것은 다음 문법으로 생성된다는 뜻이다.
> `B → ε | B B | (B) | [B] | {B}` (괄호 아닌 문자는 무시).

> **불변식.** `i`번째 글자까지 처리한 뒤, 알고리즘이 아직 실패하지 않았다면
> 스택은 `s[0..i-1]` 에서 **열렸지만 아직 닫히지 않은 괄호들을, 연 순서대로 아래에서 위로** 담고 있다.

**기저** — `i = 0`. 아무것도 처리하지 않았고 스택이 비었다. 열린 괄호가 없으므로 성립. ✓

**유지** — `s[i]` 를 처리한다.

- *여는 괄호* — `push` 한다. 새로 열렸고 아직 안 닫혔으므로 스택 맨 위에 오는 것이 맞다.
- *닫는 괄호 `c`* — 이 `c` 와 짝지어질 여는 괄호는, 균형 정의상 `c` **직전에 열린, 아직 안 닫힌**
  괄호여야 한다. 불변식에 의해 그것이 곧 스택의 top 이다.
  - top 이 없으면(빈 스택) `c` 와 짝지을 여는 괄호가 없다 → 어떤 확장으로도 균형일 수 없다 → 실패가 옳다.
  - top 이 종류가 다르면 `(B]` 꼴이라 문법이 생성하지 못한다 → 실패가 옳다.
  - 종류가 맞으면 그 쌍 `(B)` 가 완성되므로 top 을 `pop` 한다. 나머지 스택은 여전히
    "열렸지만 안 닫힌" 것들이다.
- *그 외* — 스택 불변.

어느 경우든 불변식이 유지된다.

**종료 시** — `s` 를 다 읽었다. 불변식에 의해 스택은 "아직 안 닫힌 괄호들" 이다.

- 비어 있으면 모든 괄호가 닫혔고, 각 닫음이 문법 규칙 `(B)`/`[B]`/`{B}` 를 만족했으므로
  전체가 `B` 로 생성된다 → **균형**.
- 비어 있지 않으면 안 닫힌 여는 괄호가 있어 `B` 로 생성 불가 → **불균형**.

따라서 `return st.empty()` 가 정확히 균형 여부를 준다. ∎

**종료성** — 루프가 `n` 번으로 유한하고 각 반복이 상수 시간이다.

## 복잡도

| | 시간 | 공간 |
|---|---|---|
| 최선 | `Θ(1)` (첫 글자가 닫는 괄호 → 즉시 실패) | `O(1)` |
| 평균 | `Θ(n)` | `O(n)` |
| 최악 | `Θ(n)` | `O(n)` |

**시간** — 각 글자를 정확히 한 번 보고, `push`/`pop`/`top` 이 모두 `O(1)` 이다.
실패 시 조기 종료하므로 최선은 `O(1)`.

**공간** — 스택 최대 크기는 최대 중첩 깊이다. `((((...` 처럼 전부 여는 괄호면 `n` 까지 간다.
`()()()...` 처럼 얕으면 `O(1)` 에 머문다.

**정규 표현으로 안 되는 이유** — 임의 깊이의 중첩된 괄호 언어 `{ (ⁿ )ⁿ : n ≥ 0 }` 는
**펌핑 보조정리**로 정규 언어가 아님이 증명된다. 유한 상태(정규식/DFA)로는 깊이를 셀 수 없고,
무한한 깊이를 세려면 스택(푸시다운 오토마타)이 필요하다. 괄호 검사가 스택을 쓰는 것은
편의가 아니라 **이론적 필연**이다.

## 구현 노트

**빈 스택 검사를 top 앞에.** `st.empty() || !match(st.top(), c)` 의 순서가 중요하다.
`&&`/`||` 단축 평가가 빈 스택에서 `top()` 호출을 막는다.

**끝 검사를 잊지 마라.** `return st.empty()` 없이 `return true` 로 쓰면 `(((` 를 통과시킨다.

**여는 괄호를 저장한다.** 스택에 여는 괄호 문자를 담아야 종류를 대조할 수 있다.
`match` 는 보통 `map<char,char>` 나 `switch` 로 구현한다.

**괄호 하나만 있으면 카운터로.** 한 종류(`()`)면 `int depth` 하나로 `O(1)` 공간이다.
`depth` 가 음수가 되면 실패, 끝에 0이 아니면 실패.

**최소 삽입/삭제** — "몇 개를 넣거나 지워야 균형이 되나" 는 변형에서는 실패 시 멈추지 않고
안 맞는 것을 세며 끝까지 간다.

## 변형과 확장

### 가장 긴 균형 부분 문자열

`(()` 에서 가장 긴 균형 구간의 길이를 구한다. 스택에 **인덱스**를 담고, pop 후 남은
top 인덱스와의 거리로 길이를 잰다. 또는 DP 로 `O(n)`.

### 최소 삽입/삭제로 균형 만들기

`)(` 를 균형으로 만들려면 몇 번 넣거나 지워야 하나. 스택 골격에서 실패할 때마다
카운터를 올리며 끝까지 진행한다. 그리디로 `O(n)`.

### 와일드카드 `*`

`*` 가 `(`, `)`, 또는 빈 문자 아무거나 될 수 있을 때 균형 가능 여부. 스택 두 개(가능한
열림 개수의 하한·상한)를 유지하거나 그리디로 푼다.

### 수식 파싱으로

괄호 검사는 **파서의 뼈대**다. 여는 괄호에서 하위 식을 시작하고 닫는 괄호에서 마무리하면
[후위 표기법 계산](#/algo/postfix-eval)이나 중위→후위 변환(션팅 야드)이 된다.
스택이 "지금 어느 괄호 안인가" 를 추적하는 역할은 그대로다.

### HTML/XML 태그 검증

`<div>...</div>` 의 여는·닫는 태그 짝 맞추기가 정확히 같은 문제다.
`<b><i></b></i>` 가 `([)]` 와 같은 엇갈림이다. 브라우저·린터가 이 검사를 한다.

### 트리 순회와의 관계

균형 잡힌 괄호열은 **순서 트리와 1:1 대응**한다(여는 괄호 = 자식으로 내려감, 닫는 괄호 = 부모로
올라옴). 스택 높이가 곧 트리 깊이이고, 이 대응이 카탈란 수가 나오는 이유다 —
길이 `2n` 인 균형 괄호열의 개수가 `n`번째 카탈란 수다.
