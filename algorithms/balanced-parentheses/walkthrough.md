## 어떤 문제인가

수식에 괄호가 **올바르게 짝지어졌는지** 검사하고 싶다.

```
(a+[b*c])     ✓ 올바르다
([)]          ✗ 엇갈렸다 — ( 안에서 ] 를 닫으려 한다
(((           ✗ 열기만 하고 안 닫았다
```

`()`, `[]`, `{}` 세 종류가 섞여 있다. 두 가지를 동시에 확인해야 한다.

- **종류가 맞나** — `(` 는 `)` 로 닫혀야지 `]` 로 닫히면 안 된다
- **순서가 맞나** — 나중에 연 것을 먼저 닫아야 한다. `([)]` 는 `[` 를 열어 놓고 `(` 를 먼저 닫는다

### 개수만 세면 안 되나

여는 괄호 수와 닫는 괄호 수가 같으면 될까? `([)]` 는 각각 2개씩이지만 **틀렸다.**
`)(` 도 개수는 맞지만 틀렸다. **순서 정보**가 사라지기 때문에 개수 세기로는 부족하다.

> 열어 놓고 **아직 안 닫은 괄호**를 기억해야 한다. 그것도 **가장 최근 것부터** 닫아야 한다.

## 손으로 해보기

기본 입력 `(a+[b*c])` 로 끝까지 가 보자.

### 가장 최근에 연 것을 기억하는 그릇

닫는 괄호를 만나면 **바로 직전에 연, 아직 안 닫힌 괄호**와 짝을 맞춰야 한다.
"가장 최근에 넣은 것을 가장 먼저 꺼낸다" — 이게 **스택(LIFO)** 이다.

여는 괄호는 **쌓고**, 닫는 괄호는 **맨 위와 대조**한다.

### 왼쪽부터 훑는다

```
(  a  +  [  b  *  c  ]  )
```

글자를 하나씩 본다. 괄호가 아닌 `a`, `+`, `b`, `*`, `c` 는 그냥 지나간다.

**`(` (0번)** — 여는 괄호. 쌓는다.

```
스택:  (
```

**`[` (3번)** — 여는 괄호. 쌓는다.

```
스택:  (  [        ← 맨 위가 [
```

**`]` (7번)** — 닫는 괄호. 맨 위를 본다.

```
맨 위 = [ ,  ] 는 [ 와 짝이 맞는다  →  뺀다
스택:  (
```

**`)` (8번)** — 닫는 괄호. 맨 위를 본다.

```
맨 위 = ( ,  ) 는 ( 와 짝이 맞는다  →  뺀다
스택:  (비어 있음)
```

### 끝났다 — 스택이 비었나?

문자열을 다 봤고 **스택이 비어 있다.** 열린 괄호가 전부 닫혔다는 뜻이다 → **균형 잡혔다.**

> 짝이 맞을 때마다 스택에서 하나씩 사라지고, 열기만 한 괄호는 스택에 남는다.
> **끝에 스택이 비어 있으면** 모든 괄호가 제대로 닫힌 것이다.

### 틀리는 세 가지 방식

`([)]` 를 넣어 보자.

```
( → 쌓는다.  스택: (
[ → 쌓는다.  스택: ( [
) → 맨 위는 [ 인데 ) 는 ( 와 짝이어야 한다 → 종류 안 맞음 → 실패!
```

닫는 괄호를 만났는데 **맨 위와 종류가 다르면** 즉시 틀렸다.

`(((` 는 끝났을 때 스택에 `( ( (` 가 남는다 → **안 닫힌 괄호**가 있으니 실패.

`a)(b` 는 `)` 를 만났을 때 **스택이 비어 있다** → 열린 적 없는 괄호를 닫으려 하니 실패.

## 아이디어 쌓기

### 1단계 — LIFO 가 문제에 딱 맞는다

"가장 최근에 연 것을 가장 먼저 닫는다" 는 규칙이 스택의 정의 그 자체다.
자료구조를 고르는 순간 문제가 거의 풀린다.

### 2단계 — 세 가지 경우

왼쪽부터 글자를 보며 세 갈래로 나눈다.

```
여는 괄호  →  스택에 push
닫는 괄호  →  스택 top 과 짝 검사, 맞으면 pop
그 외      →  무시
```

### 3단계 — 실패를 즉시 알아챈다

닫는 괄호에서 실패하는 경우가 둘이다.

```
스택이 비어 있다        →  열린 적 없는 것을 닫으려 한다
top 과 종류가 다르다    →  엇갈렸다
```

둘 중 하나라도 걸리면 **더 볼 것 없이** 틀렸다.

### 4단계 — 끝에서 한 번 더 검사

문자열을 다 봐도 끝이 아니다. **스택이 비어 있어야** 균형이다.
`(((` 처럼 열기만 한 괄호가 남아 있으면 틀렸다.

## 코드로 옮기기

```cpp
bool balanced(string s) {
    stack<char> st;
    for (char c : s) {
        if (c == '(' || c == '[' || c == '{')
            st.push(c);                        // ← 2단계: 여는 괄호
        else if (c == ')' || c == ']' || c == '}') {
            if (st.empty() || !matches(st.top(), c))
                return false;                  // ← 3단계: 즉시 실패
            st.pop();                          //    짝이 맞으면 뺀다
        }
    }
    return st.empty();                         // ← 4단계: 다 닫혔나
}
```

`matches('(', ')')` 처럼 여는·닫는 괄호가 짝인지만 확인하면 된다.
`st.empty()` 검사를 `st.top()` **앞에** 두는 것이 중요하다 — 빈 스택에서 `top()` 을 부르면 오류다.

## 자주 하는 실수

**`st.empty()` 검사를 빠뜨린다.** `a)` 처럼 닫는 괄호가 먼저 오면 빈 스택에서 `top()` 을 불러
프로그램이 죽는다. 반드시 `st.empty() ||` 를 먼저 본다(단축 평가 순서가 중요하다).

**끝에서 스택 검사를 잊는다.** `(((` 를 "실패한 적 없으니 통과" 로 처리하면 틀린다.
`return st.empty()` 를 빠뜨리고 `return true` 로 쓰는 실수다.

**개수만 센다.** 여는 수 = 닫는 수 로 판정하면 `([)]`, `)(` 를 통과시킨다. **순서가 핵심**이다.

**종류를 안 본다.** `(` 를 `]` 로 닫아도 통과시키면 안 된다. 스택에 여는 괄호의 **종류**를 저장하고
맞는지 확인해야 한다.

**여는 괄호를 저장 안 하고 개수만 센다.** 종류가 하나뿐이면(`()` 만) 카운터로 되지만,
세 종류가 섞이면 무엇이 열렸는지 기억해야 하므로 스택이 필요하다.

## 스스로 확인하기

1. **`[` 를 쌓고 `]` 로 빼는 스텝**(2~4)을 보자. 안쪽 괄호가 먼저 닫힌다 — LIFO 다.
2. **마지막 `)` 로 `(` 를 빼는 스텝**을 보자. 스택이 비면서 끝난다.
3. **스택 맨 위(top)가 강조**되는 것을 보자. 닫을 때 항상 맨 위와만 비교한다.
4. 입력을 `([)]` 로 바꿔 보자. `)` 를 만났을 때 맨 위가 `[` 라 **종류 불일치로 즉시 실패**한다.
5. 입력을 `(((` 로 바꿔 보자. 실패 없이 끝나지만 **스택에 3개가 남아** 불균형이다.
6. 입력을 `a)(b` 로 바꿔 보자. `)` 를 만났을 때 **스택이 비어** 있어 실패한다.
7. 입력을 `{[()]}` 로 바꿔 보자. 세 종류가 겹쳐 쌓였다가 안쪽부터 차례로 빠진다.
