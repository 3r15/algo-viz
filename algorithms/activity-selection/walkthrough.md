## 어떤 문제인가

시작·끝 시각이 있는 활동(회의)이 여럿 있다. 한 방에서 **겹치지 않게** 최대한 많은 활동을 하려면
어느 것들을 골라야 할까?

```
[1,3)  [2,5)  [4,7)  [1,8)  [5,9)  [8,10)
```

`[1,3)` 과 `[2,5)` 는 시간이 겹쳐 둘 다는 못 한다. **개수를 최대로** 만드는 조합은?

## 손으로 해보기

직관적으로 여러 규칙이 떠오른다 — "짧은 것부터", "일찍 시작하는 것부터". 하지만 정답은 **끝나는 시각** 이다.

> **끝나는 시각이 이른 것부터** 고른다. 빨리 끝날수록 **남는 시간이 많아** 뒤에 더 넣을 수 있다.

### 끝 시각으로 정렬

```
[1,3)  [2,5)  [4,7)  [1,8)  [5,9)  [8,10)   ← 이미 끝 시각 오름차순
```

### 앞에서부터 안 겹치면 고른다

`lastEnd`(직전 선택의 끝 시각)를 들고, 새 활동의 **시작 ≥ lastEnd** 면 고른다.

```
[1,3): 시작 1 ≥ −∞ → 선택.  lastEnd=3
[2,5): 시작 2 <  3 → 겹침, 기각
[4,7): 시작 4 ≥  3 → 선택.  lastEnd=7
[1,8): 시작 1 <  7 → 기각
[5,9): 시작 5 <  7 → 기각
[8,10):시작 8 ≥  7 → 선택.  lastEnd=10
```

**선택: [1,3), [4,7), [8,10) — 3개.** 이보다 많이는 못 고른다.

### 왜 "끝 시각" 이 정답인가 (교환 논법)

어떤 최적해가 첫 번째로 고른 활동이 `X` 라 하자. `X` 를 **가장 빨리 끝나는 활동 `G`** 로 바꿔도,
`G` 는 `X` 보다 일찍(또는 같이) 끝나니 나머지 활동과 충돌하지 않는다 → 여전히 최적, 개수도 같다.
그러니 "가장 빨리 끝나는 것" 을 고르는 게 손해가 아니다. 이 논증을 반복하면 그리디가 최적이다.

### 왜 다른 규칙은 틀리나

- **일찍 시작하는 순**: `[1,8)` 을 먼저 고르면 하나로 하루를 다 잡아먹는다.
- **짧은 순**: 짧은 활동이 두 긴 활동 사이에 끼어 둘을 다 막을 수 있다.

## 아이디어 쌓기

### 1단계 — 끝 시각으로 정렬

빨리 끝나는 것부터 봐야 남는 시간이 최대.

### 2단계 — lastEnd 로 겹침 판정

새 활동 시작 ≥ 직전 선택의 끝이면 안 겹친다.

### 3단계 — 안 겹치면 무조건 고른다

교환 논법이 "지금 고르는 게 손해 아님" 을 보장한다.

### 4단계 — 한 번 훑기

정렬 뒤 한 번만 지나가면 된다. O(n log n)(정렬) + O(n).

## 코드로 옮기기

```cpp
int activitySelection(vector<Act>& a) {
    sort(a.begin(), a.end(), byEndTime);   // 끝나는 시각 오름차순
    int count = 0, lastEnd = -INF;
    for (Act act : a) {
        if (act.start >= lastEnd) {         // 직전 선택과 안 겹치면
            count++;                        // 선택한다
            lastEnd = act.end;              // 끝 시각 갱신
        }
    }
    return count;                           // 최대 개수
}
```

`byEndTime` 정렬이 전부다. 그 뒤 `lastEnd` 하나로 겹침을 판정한다.

## 자주 하는 실수

**시작 시각으로 정렬한다.** 일찍 시작하는 순은 틀린다. **끝나는 시각** 이 핵심.

**겹침 판정 부등호.** 반개구간 `[s,e)` 면 `start >= lastEnd`(닿아도 OK). 폐구간이면 `>`.

**"짧은 것 우선" 같은 직관.** 반례가 있다. 그리디는 증명(교환 논법)이 있어야 믿는다.

**가중치가 있으면 다르다.** 각 활동에 이익이 있어 **이익 합 최대**를 원하면 그리디가 아니라 DP
(가중 구간 스케줄링). 여기 문제는 **개수 최대**라 그리디가 통한다.

## 스스로 확인하기

1. **끝 시각 정렬** 뒤 활동이 간트 차트 행으로 놓이는 것을 보자.
2. **[1,3) 선택** 후 lastEnd=3 이 되는 것을 보자.
3. **[2,5) 기각**(시작 2 < 3, 겹침)을 보자 — 빨강.
4. **최종 3개 선택**(초록)이 서로 안 겹치는 것을 확인하자.
5. 입력을 `1 2 2 3 3 4 4 5` 로 바꿔 보자 — 딱 맞닿은 활동을 다 고른다.
6. 입력에 `0 20` 같은 긴 활동을 넣어 보자 — 하나가 여럿을 막는다(그래서 기각됨).

아래 **깊이 보기**에서는 교환 논법의 정확성 증명, 가중 구간 스케줄링(DP)과의 차이,
관련 그리디(최소 강의실·마감 스케줄링)를 다룬다.
