## 어떤 문제인가

집합 `{a₀, a₁, …, aₙ₋₁}` 의 **모든 부분집합**을 하나도 빠뜨리지 않고 훑고 싶다.
부분집합은 `2ⁿ` 개다 — `{}`, `{a₀}`, `{a₁}`, `{a₀,a₁}`, … 어떻게 **빠짐없이, 중복 없이** 셀까?

각 원소는 "넣는다 / 뺀다" 두 선택뿐이다. 그러면 부분집합 하나 = **n개의 0/1 결정** = **n비트 정수**다.

> `0` 부터 `2ⁿ−1` 까지 정수를 세기만 하면, 그 이진 표현이 곧 모든 부분집합을 한 번씩 준다.

## 손으로 해보기

기본 입력 `a = [3, 1, 4, 2]` (n=4)로 가 보자. 부분집합은 `2⁴ = 16`개.

### 비트 = 원소의 포함 여부

`mask` 의 **j번 비트가 1이면 aⱼ 를 넣는다.**

```
mask=0000₂ (0)  → {}            합 0
mask=0001₂ (1)  → {a₀=3}        합 3       (0번 비트 켜짐)
mask=0010₂ (2)  → {a₁=1}        합 1       (1번 비트)
mask=0011₂ (3)  → {a₀,a₁}=3,1   합 4
mask=0101₂ (5)  → {a₀,a₂}=3,4   합 7
…
mask=1111₂ (15) → {3,1,4,2}     합 10
```

`0000` 부터 `1111` 까지 이진수로 세면 16가지가 **정확히 한 번씩** 나온다. 빠짐도 중복도 없다.

### 비트를 읽는 법

`mask` 에서 `j` 번 비트가 켜졌는지는 **`mask & (1 << j)`** 로 안다.

```
1 << j   = j번 자리만 1인 수  (1<<0=0001, 1<<2=0100)
mask & (1<<j) ≠ 0  ⟺  j번 비트가 1  ⟺  aⱼ 가 부분집합에 있다
```

그래서 각 mask 마다 `j = 0…n−1` 을 돌며 켜진 비트의 원소를 모으면 그 부분집합이 나온다.

### 최대 합 부분집합 고르기

열거하면서 각 부분집합의 합을 보고 가장 큰 것을 기억한다. 여기선 원소가 모두 양수라
전체 집합 `{3,1,4,2}` 합 `10` 이 최대다. (핵심은 **모든 후보를 빠짐없이 봤다**는 것.)

### 비용

```
mask: 0 … 2ⁿ−1        → 2ⁿ 가지
각 mask 안: j 를 n번  → 비트 읽기 n번
합계: O(n · 2ⁿ)
```

`n=20` 이면 약 2천만 — 완전 탐색이 감당되는 경계다. `n` 이 더 크면 다른 방법이 필요하다.

## 아이디어 쌓기

### 1단계 — 부분집합 = 비트열

원소마다 넣기/빼기 = 1비트. n개 원소 = n비트 정수.

### 2단계 — 정수를 세면 전부 나온다

`0`~`2ⁿ−1` 을 세면 모든 비트 조합 = 모든 부분집합이 한 번씩.

### 3단계 — 비트 읽기

`mask & (1<<j)` 로 j번 원소의 포함을 확인한다.

### 4단계 — 열거하며 원하는 것을 집계

각 부분집합에서 합·크기·XOR 등을 계산해 답(최대·개수·존재)을 갱신한다.

## 코드로 옮기기

```cpp
// n개 원소의 모든 부분집합을 비트마스크로 열거 (2^n 가지)
int best = 0, bestMask = 0;
for (int mask = 0; mask < (1 << n); mask++) {
    int sum = 0;
    for (int j = 0; j < n; j++)
        if (mask & (1 << j))          // j번 비트가 켜졌나
            sum += a[j];              // j번 원소를 넣는다
    if (sum > best) {                 // 더 큰 합을 갱신
        best = sum;
        bestMask = mask;
    }
}
```

`1 << n` = `2ⁿ`. 바깥이 부분집합, 안쪽이 그 부분집합의 원소 훑기다.

## 자주 하는 실수

**`1 << j` 의 오버플로.** `n ≥ 31` 이면 `1 << j` 가 `int` 를 넘친다. `1LL << j`(64비트)를 쓴다.

**비트와 원소 인덱스를 헷갈린다.** `j`번 비트 ↔ `a[j]`. `(mask >> j) & 1` 과 `mask & (1<<j)` 는 같은 검사.

**`n` 이 큰데 완전 탐색.** `2ⁿ` 은 금세 폭발한다(`n=30` → 10억). `n ≲ 20` 일 때만 현실적.
더 크면 부분집합 DP·가지치기·수학적 방법으로.

**공집합·전체집합을 빠뜨린다.** `mask=0`(공집합)과 `mask=2ⁿ−1`(전체)도 유효한 부분집합이다.
루프 범위 `0 … 2ⁿ−1` 이 이를 포함한다.

## 스스로 확인하기

1. **mask 가 0000→1111 로 세지는** 것을 보며 선택 비트 행이 이진 카운터처럼 바뀌는 것을 보자.
2. **켜진 비트의 원소**만 값 행에서 강조되는 것을 보자.
3. **합이 갱신되는 순간**(best 갱신)이 설명에 표시되는 것을 보자.
4. **mask=0(공집합)과 mask=15(전체)** 둘 다 나오는지 확인하자.
5. 입력을 `5 -3 4` 로 바꿔 보자 — 음수가 있어 최대 합이 전체 집합이 아니게 된다.
6. 입력을 원소 5개로 바꿔 보자 — 부분집합이 32개로 늘어난다(2⁵).

부분집합 DP(외판원·집합 덮개)로의 확장을 다룬다.
