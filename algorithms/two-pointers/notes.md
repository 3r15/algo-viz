## 한눈에

정렬된 배열의 양 끝에서 포인터 둘을 마주 보게 두고, 합이 부족하면 왼쪽을 올리고 넘치면
오른쪽을 내린다. `n²/2` 개의 쌍 중 **최대 `n` 개만** 보고 답을 낸다.

- **시간** `Θ(n)` (배열이 이미 정렬돼 있을 때) · **공간** `O(1)`
- **전제**: 정렬. 안 돼 있으면 정렬 비용 `O(n log n)` 이 지배한다
- 버리는 근거는 **"남은 최댓값과 짝지어도 부족하다"** — 정렬이 이 판정을 가능하게 한다
- 해시 테이블 풀이(`O(n)`, 정렬 불필요)와 달리 **`O(1)` 공간**이고 중복·세 수 확장이 쉽다

**언제 쓰나** — 이미 정렬돼 있거나 정렬이 어차피 필요할 때. 세 수의 합, 가장 가까운 합,
정렬된 두 배열의 교집합, 회문 판정, 그리고 **슬라이딩 윈도우**(같은 골격의 변형)까지
"두 인덱스가 배열을 한 번 훑는" 문제 전반.

**언제 안 쓰나** — 정렬이 불가능하거나(원래 인덱스를 보존해야 하는 등) 정렬 비용이 아까울 때는
해시 테이블 풀이가 낫다. 배열이 아닌 자료구조(연결 리스트)에서는 임의 접근이 없어 불리하다.

## 동작 원리

핵심은 **한 번의 비교로 "쌍의 한 줄 전체" 를 지운다**는 것이다.

`a[lo] + a[hi] < target` 이면, `a[hi]` 가 남은 후보 중 최댓값이므로
`a[lo]` 를 포함하는 **모든** 쌍의 합이 `target` 미만이다. `a[lo]` 를 통째로 버려도 된다.

```
쌍의 격자에서 한 번에 한 행(또는 한 열)이 죽는다

        hi →
  lo ↓  ┌───────────────┐
        │ ××××××××××××× │  ← a[lo] 를 쓰는 쌍 전부 (합이 부족)
        │               │
```

### 규칙

```
sum = a[lo] + a[hi]
sum == target  →  답
sum <  target  →  lo++      (a[lo] 를 쓰는 쌍은 전부 불가능)
sum >  target  →  hi--      (a[hi] 를 쓰는 쌍은 전부 불가능)
lo == hi       →  없다
```

### 실행 예

`a = [1, 2, 3, 5, 5, 6, 8, 9]`, `target = 11`

```
lo=0 hi=7:  1 + 9 = 10 < 11  →  1 을 쓰는 쌍 7개 버림.  lo=1
lo=1 hi=7:  2 + 9 = 11       →  찾았다 (인덱스 1, 7)

쌍을 2번 봤다 (전부 보면 28번)
```

`target = 8` 이면 양쪽이 번갈아 줄어든다.

```
lo=0 hi=7:  10 > 8  →  hi=6
lo=0 hi=6:   9 > 8  →  hi=5
lo=0 hi=5:   7 < 8  →  lo=1
lo=1 hi=5:   8      →  찾았다
```

## 정확성

> **불변식.** 반복 시작 시점에, 합이 `target` 인 쌍 `(i, j)`(`i < j`)가 존재한다면
> 그런 쌍 중 적어도 하나는 `lo ≤ i < j ≤ hi` 를 만족한다.

**기저** — `lo = 0`, `hi = n-1` 이므로 모든 쌍이 구간 안에 있다. 자명하다. ✓

**유지** — `sum = a[lo] + a[hi]` 라 하고, 불변식을 만족하는 해 `(i, j)` 가 존재한다고 가정한다.

*경우 1: `sum == target`.* 즉시 `(lo, hi)` 를 반환한다. 이는 실제 해다.

*경우 2: `sum < target`.* `lo` 를 버려도 안전함을 보인다. `(i, j)` 중 `i = lo` 인 것이 있다면,
`j ≤ hi` 이고 `a` 가 비내림차순이므로 `a[j] ≤ a[hi]`. 따라서

```
a[lo] + a[j] ≤ a[lo] + a[hi] = sum < target
```

이는 `a[i] + a[j] = target` 에 모순이다. 그러므로 `i = lo` 인 해는 **존재하지 않는다**.
불변식이 주는 해는 모두 `i ≥ lo + 1` 을 만족하므로, `lo ← lo + 1` 로 갱신해도
`lo ≤ i < j ≤ hi` 가 유지된다. ✓

*경우 3: `sum > target`.* 대칭이다. `j = hi` 인 해가 있다면 `i ≥ lo` 이므로 `a[i] ≥ a[lo]` 이고

```
a[i] + a[hi] ≥ a[lo] + a[hi] = sum > target
```

모순이다. 따라서 모든 해는 `j ≤ hi - 1` 이고 `hi ← hi - 1` 이 안전하다. ✓

**종료** — 루프는 `lo == hi` 로 빠져나온다. 그 시점에 `lo ≤ i < j ≤ hi` 를 만족하는 쌍은
존재할 수 없다(`i < j` 인데 구간의 길이가 1이다). 불변식의 대우에 의해 **해가 없다**. ∎

### 종료성

각 반복은 `lo` 를 1 늘리거나 `hi` 를 1 줄인다. 따라서 `hi - lo` 가 매번 정확히 1 감소한다.
초기값이 `n - 1` 이므로 최대 `n - 1` 번 반복하고 반드시 종료한다.

이 논증이 곧 시간 복잡도 증명이기도 하다 — **불변식과 복잡도가 같은 사실에서 나온다.**

## 복잡도

| | 시간 | 공간 |
|---|---|---|
| 최선 | `Θ(1)` (첫 쌍이 답) | `O(1)` |
| 평균 | `Θ(n)` | `O(1)` |
| 최악 | `Θ(n)` | `O(1)` |

**시간** — `hi - lo` 가 매 반복 정확히 1 줄어들고 초기값이 `n-1` 이므로 반복 횟수는 `n-1` 이하다.
각 반복은 덧셈 1회·비교 1~2회로 상수 시간이다.

**정렬을 포함하면** `Θ(n log n)` 이 되고 정렬이 지배한다. 이미 정렬된 입력이 주어지는지가
이 방법을 고를지 말지의 핵심 기준이다.

**공간** — 인덱스 두 개와 합 하나. 완전한 `O(1)` 이다.

### 해시 테이블 풀이와 비교

| | 투 포인터 | 해시 테이블 |
|---|---|---|
| 시간 | `Θ(n)` (정렬 후) | 기대 `Θ(n)`, 최악 `Θ(n²)` |
| 정렬 | **필요** | 불필요 |
| 공간 | **`O(1)`** | `Θ(n)` |
| 원래 인덱스 | 정렬로 흐트러진다 | 보존 |
| 세 수의 합 확장 | **쉽다**(`O(n²)`) | 까다롭다 |

정렬이 이미 되어 있으면 투 포인터가 낫고, 원래 인덱스가 필요하면 해시가 낫다.

## 구현 노트

**`lo < hi` 여야 한다.** `lo <= hi` 로 쓰면 같은 원소를 두 번 쓰는 쌍을 허용한다.
`[3]` 에 `target = 6` 이면 "찾음" 이 되어 버린다. "한 원소를 재사용해도 된다" 는 문제라면
의도적으로 `lo <= hi` 를 쓴다.

**오버플로** — `a[lo] + a[hi]` 가 `int` 범위를 넘길 수 있다. 값이 `10⁹` 급이면 `long long`.

**모든 쌍을 찾으려면** 답을 만난 뒤 `lo++, hi--` 로 계속 진행하고, 중복 값을 건너뛴다.

```cpp
while (lo < hi) {
    int sum = a[lo] + a[hi];
    if (sum == target) {
        answers.push_back({lo, hi});
        int vl = a[lo], vr = a[hi];
        while (lo < hi && a[lo] == vl) lo++;      // 같은 값 묶음을 통째로 넘긴다
        while (lo < hi && a[hi] == vr) hi--;
    } else if (sum < target) lo++;
    else hi--;
}
```

**정렬 후 원래 인덱스가 필요하면** `(값, 원래 인덱스)` 쌍을 정렬한다.

## 변형과 확장

### 세 수의 합

바깥에서 첫 수를 고정하고 나머지를 투 포인터로 푼다. `O(n²)`.

```cpp
sort(a.begin(), a.end());
for (int i = 0; i + 2 < n; i++) {
    if (i > 0 && a[i] == a[i-1]) continue;        // 중복 답 방지
    int lo = i + 1, hi = n - 1;
    while (lo < hi) { /* target - a[i] 를 찾는 두 수의 합 */ }
}
```

완전탐색 `O(n³)` 을 `O(n²)` 로 줄인다. `k` 수의 합은 같은 방식으로 `O(n^{k-1})` 이다.

### 가장 가까운 합

정확히 `target` 이 없을 때 **가장 가까운** 합을 찾는다. 골격은 그대로 두고
매 단계의 `|sum - target|` 을 최솟값과 비교해 기록한다. 포인터를 옮기는 규칙은 같다 —
불변식이 "정확히 같은 해" 가 아니라 "최적해" 로 바뀌어도 같은 논증이 통한다.

### 슬라이딩 윈도우 — 같은 방향 두 포인터

두 포인터가 마주 보지 않고 **같은 방향**으로 갈 수도 있다.

```
"합이 target 이상인 가장 짧은 연속 구간"
  right 를 늘려 조건을 만족시키고, left 를 당겨 최소화한다
  두 포인터가 각각 최대 n 번 움직이므로 O(n)
```

양수 배열이라는 조건이 "left 를 당기면 합이 준다" 는 **단조성**을 준다.
마주 보는 형태든 같은 방향이든, 근거는 항상 **단조성**이다.

### 정렬된 두 배열의 병합·교집합

각 배열에 포인터 하나씩 두고 작은 쪽을 전진시킨다.
[병합 정렬](#/algo/merge-sort)의 merge 단계가 정확히 이 형태이고,
교집합·차집합·합집합이 모두 같은 골격이다.

### 회문 판정

양 끝에서 마주 보며 글자를 비교한다. 정렬과 무관하지만 "양쪽에서 조여 온다" 는 구조는 같다.
[최장 공통 부분 수열](#/algo/lcs)의 역추적도 두 인덱스를 함께 줄이는 형태다.

### 컨테이너에 담을 물

"가장 넓은 직사각형" 류에서도 같은 논증이 쓰인다 —
낮은 쪽 벽은 **어느 상대와 짝지어도** 지금보다 넓어질 수 없으므로 버려도 안전하다.
"버려도 안전하다" 를 정당화하는 부등식만 문제마다 다르다.
