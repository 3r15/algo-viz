## 한눈에

트리에서 "정점 `v`의 `k`번째 조상"을 매번 `k`번 걸어 올라가면 `O(k)` 가 걸린다.
**2의 거듭제곱 칸씩 점프하는 표를 미리 만들어 두면** 어떤 `k`든 `O(log n)` 에 도달한다.

`k`를 이진수로 쪼개서 1인 비트마다 그 크기만큼 한 번에 뛰는 것이다.
같은 도구로 **최소 공통 조상(LCA)** 도 `O(log n)` 에 구한다.

- 전처리 O(n log n) 시간·공간 · 질의 O(log n)
- [희소 배열](#/algo/sparse-table)과 **완전히 같은 배가(doubling) 아이디어** — 대상이 배열이 아니라 트리의 조상일 뿐

## 동작 원리

표의 정의도 한 줄이다.

```
up[k][v] = 정점 v 에서 2^k 칸 위에 있는 조상
```

`k = 0` 은 그냥 부모다. 그다음부터는 **절반짜리 점프를 두 번 이어 붙인다.**

```
up[k][v] = up[k-1][ up[k-1][v] ]

  v ──2^(k-1)──▶ 중간 ──2^(k-1)──▶ 목적지
  └────────────── 2^k ──────────────┘
```

루트를 넘어가면 어떻게 되나? **`up[*][root] = root`** 로 두어 "더 올라가면 루트에 머문다"로
처리한다(이 페이지의 `parent[0] = 0`). 덕분에 범위 검사 없이 무조건 점프해도 안전하다.

### k번째 조상

`k`를 이진수로 쓰고 1인 비트마다 점프한다. `k = 13 = 1101₂` 이면 8칸, 4칸, 1칸을 뛴다.

```cpp
int kth_ancestor(int v, int k) {
    for (int i = 0; i < LOG; i++)
        if (k >> i & 1) v = up[i][v];
    return v;
}
```

### LCA — 두 단계

**1단계, 깊이 맞추기.** 더 깊은 쪽을 `diff = depth[u] - depth[v]` 칸 올린다. 위의 k번째 조상 그대로다.
여기서 `u == v` 가 되면 `v`가 원래 `u`의 조상이었던 것이고, 그게 곧 LCA다.

**2단계, 갈라진 채로 최대한 올리기.** 큰 `k`부터 내려가며,

```cpp
for (int k = LOG - 1; k >= 0; k--)
    if (up[k][u] != up[k][v])          // 다르면 → 아직 LCA 아래 → 올려도 안전
        u = up[k][u], v = up[k][v];
return up[0][u];                        // 딱 한 칸 위가 LCA
```

**"같으면 건너뛰고, 다르면 올린다"** 가 전부다. 시각화에서 `u`·`v` 배지가 붙은 두 정점이
나란히 올라가다가 마지막에 한 칸 위에서 만나는 것을 볼 수 있다.

## 정확성

### 표가 올바르다 — `k`에 대한 귀납

`k = 0`: `up[0][v] = parent[v]` 는 정의상 1칸 위 조상이다(루트는 자기 자신).

`k-1`까지 참이라 하자. `w = up[k-1][v]` 는 `v`의 `2^(k-1)`번째 조상이고,
`up[k-1][w]` 는 `w`의 `2^(k-1)`번째 조상이다. 조상 관계는 경로를 이어 붙이는 것이므로
`up[k][v]` 는 `v`의 `2^(k-1) + 2^(k-1) = 2^k` 번째 조상이다.

루트를 넘는 경우에도 "루트에 머문다"는 규칙이 이어 붙이기와 잘 맞는다
(루트에서 몇 칸을 더 올라가도 루트다). ∎

### k번째 조상이 올바르다

`k = Σ_{i ∈ S} 2^i` (S는 `k`의 1인 비트 집합)로 유일하게 분해된다.
루프는 각 `i ∈ S`마다 정확히 `2^i` 칸 올라가고, 총 이동 거리는 `Σ 2^i = k` 다. ∎

### LCA 2단계가 올바르다 — 핵심 논증

`u ≠ v` 이고 `depth[u] = depth[v]` 인 상태에서 시작한다. `L = LCA(u, v)`,
`d = depth[u] - depth[L]` 이라 하자. `u ≠ v` 이므로 `d ≥ 1` 이다.

> **불변식**: 루프 내내 `LCA(u, v) = L` 이고 `u ≠ v` 다.

각 `k`에서 두 경우를 보자. `depth` 가 같으므로 `up[k][u]` 와 `up[k][v]` 의 깊이도 같다.

- **`up[k][u] == up[k][v]` 인 경우**: 두 정점의 `2^k`번째 조상이 같다는 것은
  `2^k ≥ d`, 즉 `L` 이상으로 올라간다는 뜻이다. 올리면 **LCA를 지나치므로 건너뛴다.**
  (실제로 `up[k][u] == up[k][v]` ⟺ `2^k ≥ d` 임을 보일 수 있다.
  `2^k < d` 라면 두 조상은 `L`의 서로 다른 자식 서브트리 안에 있어 다를 수밖에 없다.)
- **`up[k][u] != up[k][v]` 인 경우**: `2^k < d` 이므로 두 조상 모두 여전히 `L` **아래**에 있다.
  올려도 `LCA` 는 그대로 `L` 이고 여전히 서로 다르다. **불변식이 유지된다.**

`k`를 `LOG-1`에서 0까지 내리며 이 그리디를 수행하면, 올라간 총 거리는 `d - 1` 의 이진 표현을
정확히 재현한다. (`d-1 < 2^LOG` 이고, 각 비트에서 "가능하면 올린다"는 것은 곧
`d-1` 의 이진 자릿수를 큰 것부터 채우는 것과 같다.)

따라서 루프가 끝나면 `depth[u] = depth[L] + 1`, 즉 `u`와 `v`는 **`L`의 서로 다른 자식**이다.
그러므로 `up[0][u] = L` 이다. ∎

> 왜 `d`가 아니라 `d-1` 만큼만 올리는가? `d`만큼 올리면 `u`와 `v`가 **둘 다 `L`이 되어
> 구분이 사라진다.** 이 알고리즘은 "아직 다르다"를 신호로 쓰기 때문에, 마지막 한 칸은
> 남겨 두고 `up[0]` 으로 마무리하는 것이다.

## 복잡도

| | 시간 | 공간 |
|---|---|---|
| 전처리(build) | O(n log n) | **O(n log n)** |
| k번째 조상 | O(log n) | — |
| LCA | O(log n) | — |

`LOG = ⌊log₂ n⌋ + 1` 개의 행 × `n` 개의 열, 각 칸이 O(1)이므로 전처리가 `O(n log n)` 이다.
질의는 각 단계에서 `LOG`번 반복하므로 `O(log n)`.

공간 `O(n log n)` 은 이 방법의 유일한 약점이다. `n = 10⁶`, `LOG = 20` 이면 `2×10⁷` 개의
`int` = 80MB로, 메모리 제한에 걸릴 수 있다.

### 다른 LCA 방법과 비교

| 방법 | 전처리 | 질의 | 공간 |
|---|---|---|---|
| 이진 상승 | O(n log n) | O(log n) | O(n log n) |
| 오일러 투어 + [희소 배열](#/algo/sparse-table) | O(n log n) | **O(1)** | O(n log n) |
| 타잔 오프라인 | O(n α(n)) | 전체 O(n+q) | **O(n)** |

질의가 극단적으로 많으면 오일러 투어 + 희소 배열이, 메모리가 빠듯하면 타잔이 낫다.
그럼에도 이진 상승이 표준처럼 쓰이는 이유는 **구현이 짧고, 경로 최댓값 같은 확장이 자연스럽기**
때문이다.

## 구현 노트

**`LOG` 를 넉넉히 잡아라.** `2^LOG > 최대 깊이` 여야 한다. 최악의 트리는 한 줄로 늘어선
경로 그래프이고 그때 깊이가 `n-1` 이므로, `LOG = ⌊log₂ n⌋ + 1` 이면 항상 안전하다.
`LOG` 를 1 작게 잡으면 깊은 트리에서 조용히 틀린 답이 나온다.

**`up[k][root] = root` 를 반드시 지켜라.** 루트를 `-1` 로 두면 `up[k-1][-1]` 에서
배열 범위를 벗어난다. 루트를 자기 자신으로 두면 클램프가 공짜로 된다.

**`depth` 와 `parent` 는 DFS로 구한다.** 트리가 깊으면 재귀 DFS가 스택 오버플로를 낼 수 있으니
반복 DFS나 BFS를 쓰자([DFS 문서의 구현 노트](#/algo/dfs) 참고).

**표를 채우는 순서**: 바깥 루프가 `k`, 안쪽이 `v` 여야 한다. `up[k][*]` 를 계산할 때
`up[k-1][*]` 이 **모든 정점에 대해** 완성돼 있어야 하기 때문이다. 순서를 뒤집으면 틀린다.

**트리에서만 되는 것이 아니다.** 각 정점의 나가는 간선이 정확히 하나인 **함수형 그래프**
(순열, `f(x)` 반복 적용)에서도 그대로 쓸 수 있다. "`f` 를 `k`번 적용한 값"이 곧 k번째 조상이다.

## 변형과 확장

- **경로 위의 집계**: `up` 과 나란히 `mx[k][v] = v→2^k 조상 경로의 최대 간선 가중치` 를 채우면
  두 정점 사이 경로의 최댓값·최솟값·합을 O(log n)에 얻는다. 최소 신장 트리에서
  "이 간선을 추가하면 생기는 사이클의 최대 간선"을 찾는 데 쓰인다.
- **레벨 조상(level ancestor)**: "깊이가 정확히 `d`인 조상"은 `kth_ancestor(v, depth[v] - d)` 다.
- **트리에서의 거리**: `dist(u,v) = depth[u] + depth[v] - 2·depth[LCA(u,v)]`.
  이 페이지의 시각화가 질의할 두 정점을 고를 때 쓰는 식이기도 하다.
- **경로 압축과의 관계**: 이진 상승은 "미리 계산한 점프 포인터"이고, 유니온 파인드의 경로 압축은
  "쓰면서 만드는 점프 포인터"다. 같은 문제의식의 두 가지 답이다.
